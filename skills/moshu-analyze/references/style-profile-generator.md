# 文风生成 SOP（两阶段）

> **何时加载**：moshu-analyze 生成/补全文风时。
> - **表达层**（写作风格主体）：Stage 1 停靠点后即可生成——只依赖 `_progress.md` 章节边界表 + `原文/原文.txt` + `章节/第1-3章_深度拆解.md`，**不依赖** Stage 2-5 产物。
> - **结构层**（拆解结论）：全量拆解完成后补入——依赖 `章节/*_摘要.md`（情绪交替）+ `拆文报告.md`（可借鉴技巧）。
>
> **输出**：`拆文库/{书名}/文风.md`（模板与阶段标记见 [style-profile-protocol.md](style-profile-protocol.md)）。两阶段写同一文件，补全时把 `文风阶段：表达层` 改为 `完整` 并填结构层节。

---

## 第一部分：表达层生成（Stage 1 停靠点后执行）

### 前置

- `_progress.md` 满足当前章节边界契约（schema_version: 2 + 「章节边界」表）——Stage 0 已完成
- `原文/原文.txt`（或 `.md`）存在
- `章节/第1-3章_深度拆解.md` 存在（Stage 1 已产出）

### Step E1: 原文采样

`原文/` 下**只有一个全书单文件** `原文.txt`（或 `.md`），**不是按章拆分**。只读 `_progress.md` 里的「章节边界」表（唯一切片真值），不重新搜索章节标题、不另行推断边界、不自行修正规则。表缺失/目标章缺边界/边界不连续/指向原文范围之外 → 停止本阶段，提示重新执行 Stage 0 重建进度文件；不得用临时切片继续生成。

**采样切片**：

- 从章节边界表选第 1 章、第 10 章、第 20 章（如总章数 <20，按 1/3、2/3、收尾比例挑；不足 3 章就采全部）
- 每章用 `Read offset={该章起始行} limit=50` 切出约 1000 字
- 把 3 段拼接写入 `拆文库/{书名}/_style-sample.txt`（固定文件名）：**第一段用 `>` 覆盖写，后两段才用 `>>` 追加**。全程用 `>>` 会让重跑时把上一轮样本累积进来，句长分布是两轮混合结果

### Step E2: 确定性句长/标点统计

由**主线程**执行，Bash 工具可用。把 `_style-sample.txt` 喂给下面的脚本（heredoc 作 Python 源，样本路径按 argv 传入）。先探测可用解释器再跑——**勿直接用 `python3`**，Windows 上它会触发 Microsoft Store 占位程序、exit 49 失败。样本路径**必须用项目内相对路径**（Windows 原生 python 会把 `/tmp/x.txt` 解析成 `C:\tmp\x.txt`，与 Git Bash 写入位置不一致）：

```bash
SAMPLE="拆文库/{书名}/_style-sample.txt"   # {书名} 换成实际书名，别照抄占位符
for PYBIN in python3 python py; do "$PYBIN" -c "" 2>/dev/null && break; done
"$PYBIN" - "$SAMPLE" <<'PYEOF'
import re
import sys
with open(sys.argv[1], 'r', encoding='utf-8') as f:
    text = f.read()
sents = [s for s in re.split(r'[。！？]+', text) if s.strip()]
total = max(len(sents), 1)
short = sum(1 for s in sents if len(s) < 15)
mid   = sum(1 for s in sents if 15 <= len(s) <= 30)
lng   = sum(1 for s in sents if len(s) > 30)
chars = max(sum(1 for c in text if not c.isspace()), 1)
puncts = sum(1 for c in text if c in '，。！？；：、…—""\'\'')
avg = sum(len(s) for s in sents) // total
print(f'sentences={total}; short_lt15={100*short//total}%; mid_15to30={100*mid//total}%; long_gt30={100*lng//total}%; avg_len={avg}; punct_density={100*puncts//chars}%')
PYEOF
```

实测输出形如 `sentences=6; short_lt15=66%; mid_15to30=33%; long_gt30=0%; avg_len=12; punct_density=15%`。把数值直接填进模板「整体语感」——`confidence: high`（确定性测量，不是抽样估计）。

**Bash 不可用时的降级**（仅子代理上下文等极端情况，主线程不会触发）：跳过本步骤；句长段写「Bash 工具不可用，跳过确定性统计」；`confidence: low`，moshu-narrative-writer 让位回默认 Gate D。

### Step E3: 对话技法（黄金三章）

读 `章节/第1章_深度拆解.md`、`第2章_深度拆解.md`、`第3章_深度拆解.md`，提取：

- **反应层拆解表**（对话潜台词样本）→ 填「对话技法」潜台词模式
- **角色语气区分**：从深度拆解的角色样本句归纳主角与 1-2 个核心配角的口头禅/句式差异
- **开篇钩子类型 + 手法** → 对话标签习惯的参考语境

缺失时（深度拆解不完整）：对话技法段写「黄金三章深度拆解缺失，对话技法待补」，confidence: low；不阻塞其余表达层内容。

### Step E4: 原文锚点片段（2-4 段）

- 优先从黄金三章（深度拆解已标注基调的章节）选 2-3 段：每段 300-500 字，选对话+动作交织的段落（纯独白/纯设定段不选），基调按深度拆解已知信息标注（紧张/悲伤/轻松/热血）
- 再按需从采样章（第 1/10/20 章）补 1 段
- **锚点必须逐字连续切片，禁止改写/缩写/跳段/拼接**：narrative-writer 拿锚点当 few-shot 直接学，标注的行号要能回查原文。落盘前逐段抽 1-2 句 `grep -F` 回 `原文/原文.txt`，grep 不到即说明被改写或拼接——重切为忠实连续片段。确需跳过中间过渡段时，分别标各自真实行号（如「行264-267 + 行269-270」）并在引用块内用「（……中略……）」显式断开，不得用一个连续行号区间假装连续
- 少于 1 段 → `文风可用：否：锚点不足`（few-shot 核心缺失）

### Step E5: 落盘（文风阶段：表达层）

按协议模板填写，生成记录含 `文风阶段：表达层`；「情绪交替模式」「可借鉴技巧」两节写「待全量拆解后补全（Stage 6）」，不编造；分层模仿建议先写基础层（词汇/句式/描写/对话习惯），进阶层/适配层可暂空或写「待结构层补全」。总预算仍 ≤4000 字（表达层实际更短）。

## 第二部分：结构层补全（Stage 5 后执行；全量拆解路径 = 现有 Stage 6）

### 前置

- 表达层文风已存在（`文风.md` 的 `文风阶段：表达层`）；不存在则先按第一部分生成
- `拆文报告.md` 存在（**阻断级**：不存在则停止，提示拆文未完成，先跑完 Stage 5）
- `章节/*_摘要.md` 存在（情绪交替数据源）

### Step C1: 读拆文报告核心字段

读 `拆文库/{书名}/拆文报告.md`，提取：

- **「写法技巧」段** → 填「可借鉴技巧」的「写法技巧 Top 5」
- **「可借鉴套路」段** → 填「可借鉴套路 Top 3」
- **「全书情绪节奏总览 / 伏笔与冲突网络」段** → 填「分层模仿建议」的进阶层与适配层，只抽象节奏和手法，不搬运具体桥段
- **基本信息**（书名、题材、总章数）→ 与生成记录核对

### Step C2: 章节基调序列（情绪交替）

用 Grep 读所有 `章节/*_摘要.md`：

```bash
grep -hE '基调：(紧张|轻松|悲伤|热血|爽|甜|温馨|恐怖|压抑|其他)' 章节/*_摘要.md
```

**关键格式注意**：实际格式是 `主题标签X | 基调：Y` 单独成行、跟在每个情节点后（一章 10-40 行）。`基调` 用**全角冒号**，`主题标签` 后**不带冒号**，两者都**不在行首**。grep 模式不能用 `^基调:` 这种锚定。

**章基调聚合规则**（每章一个章基调，写入「情绪交替模式」）：对该章所有情节点的「基调」字段做众数统计；并列时取章节内**最早出现**的基调。输出 `第N章: {章基调}` 连成序列。

**章内情节点基调序列**（「章内基调切换」分析）：不做聚合，按摘要中情节点出现顺序保留；切换频率 = 相邻情节点基调不同的次数 / 总情节点数。

摘要数量 <3 → 情绪交替段标 confidence: low 并注明样本不足，不阻塞落盘。

### Step C3: 锚点补足（至 4-6 段）

- 从 Step C2 的章节基调分布里挑覆盖度最高、且项目可能需要的 4-6 类基调（优先覆盖：紧张/悲伤或压抑/轻松或温馨/热血）。某类基调少于 3 章不强行编造，说明跳过
- 每类基调选 1 章作为锚点章：**同基调多章选择规则**：L1 爽点类型最强匹配（参考该章 `_摘要.md` 的「关键事件」+ 基调序列）；L2 原文章节长度最接近日更目标；L3 章节号最小（早期章节 = 作者最 canonical 的 voice，未受连载漂移影响）
- 切片与忠实性要求同 Step E4

### Step C4: 更新文风.md（阶段 → 完整）

- 填「情绪交替模式」「可借鉴技巧」两节；补足锚点至 4-6 段；补全分层模仿建议的进阶层/适配层
- 生成记录更新：参考资料加 `拆文报告.md + 章节摘要`；`文风阶段：表达层` → `完整`
- 每段标 confidence：`high`（数据直接来自拆文产物，如可借鉴技巧直接引用拆文报告）/ `med`（从样本归纳且样本充足，如基调序列从 ≥10 章摘要统计）/ `low`（样本不足或采样失败）

## 失败模式与降级

| 场景 | 降级策略 |
|---|---|
| `原文/原文.txt` 不存在 | 表达层无法生成：文风文件仅含生成记录，`文风可用：否：原文缺失` |
| `章节/第1-3章_深度拆解.md` 缺失 | 表达层对话技法段 confidence: low（从采样原文归纳兜底）；其余照常 |
| `拆文报告.md` 不存在（补全时） | **停止结构层补全**，提示拆文未完成，先跑完 Stage 5；表达层文风保持可用 |
| `章节/*_摘要.md` 数量 <3（补全时） | 情绪交替段标 confidence: low 并注明；可借鉴技巧照常 |
| Bash 不可用（句长统计） | 跳过确定性统计，句长段标 confidence: low |

## 与 moshu-chapter-extractor 的关系

**不修改 moshu-chapter-extractor**。文风直接从既有字段（基调/主题标签/可借鉴要素）整理生成即可。句长/标点密度由 Step E2 的跨平台 Python 1-liner 在主线程直接算出，不依赖 moshu-chapter-extractor。

## 与写作端的关系

- analyze 表达层写 `拆文库/{书名}/文风.md`（`文风阶段：表达层`），结构层补全后改 `完整`
- moshu-import 显式绑定外部对标或 moshu-write 首次引用 `拆文库/{书名}/` 时，同步到项目 `{项目}/对标/{书名}/` 并**包含**文风（与拆文报告同等待遇）；不得把正在导入的本书自身作为该外部对标
- 写作端（moshu-write）的日更循环读 `{项目}/对标/{书名}/文风.md`（按对标书路径查找规则，回退 `拆文库/{书名}/`）。**任一阶段都视为"有文风"**：表达层字段（句长带/标点/对话/锚点）照常消费；`文风阶段：表达层` 时情绪交替与可借鉴技巧缺失不阻塞（情绪走 `剧情/情绪模块.md` 权威、节奏走 `剧情/节奏.md` 权威）

## 单独生成/补全文风

- **只缺文风（全量拆解已完成）**：直接按本 SOP 跑两阶段（或仅结构层补全，若表达层已存在），无需重跑 Stage 0-5；前提是 `_progress.md` 满足当前章节边界契约。触发：用户直接说 "为对标书 X 生成文风" 或 "重生 文风"
- **只要表达层（参考书/快速评估场景）**：跑完 Stage 0-1 后即可按第一部分生成，无需全量拆解
