# caifeng-methods.md：采风操作方法（研究环）

> 本文件是 moshu-volume 采风环节的操作说明书：检索策略 + 要素表模板 + 转译纪律 + 降级与来源规范。产物一律项目级（`设定/采风-CF*.md`），禁中央库。**检索执行的权威路径是 moshu-researcher agent**（B21 扩展采风研究段）——本文件定义方法本体，agent 与主线 fallback 共用；**融合五步分轻重执行（B81）**：轻量融合归主线 inline，深度融合 spawn researcher（caifeng-fusion 模式，agent 做适配主会话应用）——详见下方「采风融合五步」节。融合产物评审（B77 缺口补全，可选）：融合五步完成后可 spawn evaluator（eval_type=reader，对象=融合产物；target_paths=题材定位标尺节或采风要点表），报告呈报作者——消除融合自检；agent 不可用则主会话自评（标注 Fallback）。

## 检索策略（只取公开元数据；执行权威路径＝moshu-researcher agent，本方法与主线 fallback 共用）

0. **前置查库（B71）**：query 组装后、出网前先对 [genre-catalog.md](genre-catalog.md) 路由与 [genre-prose-cards.md](genre-prose-cards.md) 索引别名表匹配——命中共性内容则收窄检索为特性层（库已给共性底线，query 改写为本书特殊需求）；未命中才全量检索（库管共性/采风管特性）。
1. **优先级**：百科/角色词条/机制解析文章 > 平台目录标题/简介/标签。
2. **取什么**：书名/媒介/人物名/机制名/结构形态（目录标题可证的结构层证据）；**全书正文不取、不复述**（正文红线）。
3. **源不限媒介**：网文/动漫/影视/游戏均可——机制采风尤其鼓励跨媒介（别处把同一机制解决得更漂亮）。
4. 多源检索（≥2 个独立来源）再落盘；单一来源时**披露占比**（"单一来源：X"）。
5. **参考档案 context（B88）**：spawn 时传对应参考档案路径作 context——researcher 只查本次增量维度，不重查档案已有基础信息。

### 检索效率四件套（移植 gpt-researcher 架构模式——模式级借用，不引代码）

1. **检索计划先行**——需求分解 2-4 个角度查询再动手（防单查询失败）；
2. **两段式**——广度找候选源（只看标题摘要）→ top 3-5 深度抓取；
3. **源去重**——同作品的多视图（百科/词条/书评）算一个源；
4. **引用强制**——无来源 URL 的要素丢弃（防编造，blocking 纪律）。

### 效率纪律（回合预算，B90）

- **检索 ≤20 回合**；**先写产物骨架文件再增量补内容**（未知字段留 `[待补]` 占位）——宁可少两个场面也要确保落盘；
- 超限即**以已有材料+模型知识收尾**并在元数据头标「降级」——不续跑不空手回。

### 环境节（Windows/Git Bash，B90）

- 临时文件统一进项目内 `设定/.caifeng-tmp/`（**禁项目根散落、禁依赖 /tmp**——Git Bash /tmp 与原生 Python 不互通）；收尾清理该目录。
- 三坑提示：路径映射用项目内绝对路径／python 输出加 `PYTHONIOENCODING=utf-8`／搜狐系 GBK 显式解码。

### CDP 预检（B90）

主会话 spawn researcher 前先跑 CDP 探测（moshu-cdp 侧 setup-cdp-chrome.js，端口 9222，--detect-only）——`ready` 则 spawn prompt 注明可用 agent-browser（解锁豆瓣 subject/知乎/起点详情/JS 页）；`needs-setup` 则**征询作者**是否起调试 Chrome（启动会杀当前 Chrome，须作者同意——不得自动启动）；拒绝则走 curl 栈。

### 来源质量优先级（要素断言可信度按来源分级）

**专业分析/创作方法论（编剧课/写作技法文/文学评论） > 权威百科/官方资料 > 平台页面/榜单 > 个人评论/读后感**——要素表高优先级来源的关键发现可在占比披露旁标注来源级别；名著源的结构分析走文学评论/解读文章（名著无榜单书评生态，搜索加「解读/分析/文学评论」关键词）。

**国内可达源优先级表 v2（B93 实测修订，2026-09-01 旗舰 15 站全量探测）**——优先级引导非硬白名单（防站点过期）：

发现层（按序 fallback，不并行尝试）：
- ① 搜狗 web `www.sogou.com/web?query=`（主力——但 IP 限流风险高，CAPTCHA 壳即切下一层）
- ② 搜狗微信 `weixin.sogou.com/weixin?type=2&query=`（公众号文章=网文方法论重要来源；限流独立于 web 版）
- ③ 360 搜索 `www.so.com/s?q=`（备用——搜狗全灭时用；中文分词正常）

内容层（直接抓取，不走发现引擎）：

### spawn prompt 必含条款（B93）

主会话构造 researcher spawn prompt 时，以下条款**逐条搬入，不得摘要省略**：

1. **源优先级表 v2**（全文引用上方发现层+内容层+禁用名单）——三期 3/3 agent 撞墙：优先级表住在文件里但从未到达 agent
2. **发现层按序 fallback**：搜狗 web 试 1 次→CAPTCHA 即切搜狗微信→再切 360——不并行尝试、不反复重试（三期 Bing/Google/DuckDuckGo 浪费 10+ 回合教训）
3. **搜狗 web 可能限流（IP 频率）**——CAPTCHA/验证码壳=立即切下一层，不硬闯（15 站实测：三种 UA+Referer 全灭）
4. **Bing 禁用**：cn.bing 对中文书名分词失效（三期实测），禁用 Bing
5. **内容层直接抓取**（不走搜索引擎）：已知目标 URL 直接 curl，只有发现层需要引擎
6. **反爬名单**：禁用名单里的站点白探即弃（起点/知乎/贴吧等 403/404/500）
7. **CDP 状态**（主会话预检结果传入：ready/不可用——不可用则 curl 栈）
8. **效率纪律**（检索≤20 回合/先写产物骨架/超限降级收尾——宁可少两个场面也要落盘）
9. **临时目录约定+Windows 三坑**（.caifeng-tmp/PYTHONIOENCODING/GBK）

## 参考作品档案（一书一档，B88）

> 治 #045 反复抓取同一批页面的重复消耗——参考作品认知只存在对话与 CF 专项文件里，无「一书一档」的基础层沉淀。档案是跨会话基础认知，CF 只查增量维度。

**触发**：轮 1 速写确认后为每部确认参考（0-3 部）建**轻档**（速写三行+模型知识扩展，元数据头标「降级」）；首次采风产物回来后增强为**实证档**（补全要素表产出的证据项）。

**落点**：`设定/参考/{书名}.md`（仅确认的 0-3 部，不膨胀）。

**schema**（实证档九段）：
1. 故事脉络（卷级梗概）
2. 关键剧情节点
3. 主线支线
4. 主要设定
5. 主要人物表（功能位——角色采风学功能不学背景）
6. 底色配方与模式占比
7. 缺点清单
8. 专名清单（防撞，check_outline candidate 比对兜底）
9. 来源与截至日期（元数据层——正文红线不变：只取公开元数据，全书正文不取不复述）

**边界**：有该书拆文产物时档案做**索引引用不重做**（指向拆文库路径）；与拆文库/对标目录不重叠——档案是「基础认知层」，拆文是「结构分析层」，各司其职。

## 转译纪律（加粗执行）

1. **机制可学**——机制/结构/规则可跨作品学习，但专有名词零复用（来源名词清单落盘，check_outline candidate 比对兜底）。
2. **具象必改**——名字/背景/关系网全换；角色采风产物因"神似"无法机检，**使用前必须作者过目停靠**（记录尾注显式提醒）。
3. **跨媒介必过本土化转译步**——输出前显式过「转译深度三问」：
   - 动力源改了吗？（如负面情绪→修炼积累）
   - 获取方式改了吗？
   - 社会结构适配了吗？（如异能者组织→修行宗门/衙门体系）
   **三问全过才算译好——只改名=缝合不算转译**。
4. **单一来源占比披露**——多源稀释自证（来源记录里写清各来源贡献占比）。
5. **正文红线**——只取公开元数据（简介/标签/百科/目录标题/角色词条/机制解析文章），全书正文不取不复述。

## 采风融合五步（采风产物 → 本书资产的有机融合）

> 融合发生在调用方步骤，**执行方式分轻重**（B81）：
> - **轻量融合**（借一个桥段的展开方式/一个设定的代价思路）：主会话按本节五步 inline 执行
> - **深度融合**（重塑角色动机链/重构整卷结构/设计全新力量体系）：spawn researcher（caifeng-fusion 模式），传入 caifeng_product+story_files+design_need——agent 在隔离上下文执行四步并返回策略，主会话应用+作者确认
>
> 判据：涉及 ≥3 个设定文件联动改动 → 深度融合；否则轻量 inline。
>
> 本节是操作规程——**采风给灵感，方法论把关，防抄红线兜底**。三类对象通用，角色版最典型。

1. **结构对照**：采风要素表逐项对照本书现有设定——采风当**检查清单**用（照出缺哪个功能位：动机链没递升？反差立不住？口头禅功能位缺失？），不是照抄对象。
2. **功能位借用**：缺什么补什么，借的是**功能**（"宣言用于被羞辱节点""导师兼金手指载体"），不是内容——宣言/桥段必须从本书角色的性格和世界长出来。
3. **归因重构**：对每个拟借要素过三问——作者为什么这么写（立意指认，不许五字带过）／落读者心理（锚 write 侧 reader-psychology 分类）／重新出发（从心理需求生成 ≥2 条不同路数的写法，参考实现只是其一）。
4. **本土转译**：动力的社会植根必须换——用本书世界真实存在的压迫（贱籍制度/师门除名/官场贬谪）重新长出动机起点，过「转译深度三问」。
5. **方法论验证**：融合结果过对应方法论工具（角色：九维/三层标签反差/探索三件套/升级绑弧光；结构：势力场设计/中点假胜败；机制：代价边界检查）——**采风不豁免质量关**。

**融合锚定表（采风类型×验证方法论×大纲落点三方锚定）**：

| 采风类型 | 验证方法论 | 大纲落点 |
|---|---|---|
| 结构 | 势力场设计/中点假胜败/八节点 | 骨架表八列/势力场总览/暗线层次表 |
| 角色 | 九维/三层标签反差/升级绑弧光/主题卡 | 四件套/角色一页/弧线六阶段 |
| 机制 | 转译三问+代价边界 | 力量体系/核心设定表 |
| 情节 | beat-cards/单元卡章功能 | 剧情单元卡 |
| 情绪 | 情绪引擎/弧线六阶段/期待感管理 | 每卷情绪基调/情绪引擎段 |

**融合时点双模式（均合法）**：写前取材（设计字段前读要素表，pull）与写后校验（字段写完用要素表反扫功能位缺口，check）——融合五步注明两种入口。

**功能位清单回写**：消费记录的融合结论必含「借鉴功能位清单」——借了哪几个功能位、各自转译成了什么（融合可审计）。

**结构相似度自检（防抄红线落点）**：融合后若成品≈来源的换皮（同开局+同金手指类型+同升级性质），红线触发——打散重组（保留结构功能，换内容组合）；采风记录的占比披露供作者过目核对。
