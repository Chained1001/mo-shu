### 开新卷（第 2 卷及后续）

卷末复盘（write 侧流程）产出 `大纲/卷复盘_第X卷.md` 后，本工作流（moshu-volume 卷规划）负责下卷规划——Stage 1-3 故事层属 moshu-outline，开新卷不重做。**对称边界（B70）：作者已写 `大纲/完结宣告.md`（或 next_step 判 FINALIZE）则不开新卷**——循环出口归完结清账与完结章（write 侧）。**Stage 1-3 已在开书时完成（全书级），不重做**；开新卷从Stage 4 起增量执行。**进入时把台账构建态翻为「开卷中 卷N [日期]」**；新卷卷纲定稿（停靠 3）后翻回「定稿」。

```
"上一卷写完了，开始第 {N} 卷的构建。

📋 上卷复盘要点：
  {卷报告摘要——伏笔回收/悬置/信息差/对标偏差}

🎯 上卷定下的方向：
  {卷复盘_第{N-1}卷.md 中的下卷方向候选}

按这个方向直接进单元步？（或先调整方向）"
→ ✅ 直接进 Stage 4 → 正常流程（停靠 2 → Stage 5 → 停靠 3）
→ ✏️ 先调整 → 回到Stage 2 快速改骨架（只改第 N 卷的部分）
```

1. **读候选**：读 `大纲/卷复盘_第X卷.md` 的「下卷方向候选」（1-3 个，含各候选的主推线/战果线、与终局储备的衔接）；无复盘文件 → 询问作者直接进入常规开卷（或回 `/moshu-write` 续写）。
2. **作者确认**：AskUserQuestion 列候选（+「自定」），作者选定后进入增量流程。
3. **增量构建**：Stage 4-6 增量执行——新卷引入新角色/势力/设定 → 先补 `设定/` 档案（增量补充、不覆盖既有），再补 `大纲/卷纲_第X卷.md`（只增不改既有卷；新剧情单元卡追加到卷尾，卷级五问与契约检查照常）；纯延续卷 → 直接补新卷卷纲。
4. **边界**：新卷的首批细纲由 write 侧产出（B1b outline-workflow）；本工作流不建细纲。卷纲锁定定义沿用 write 侧口径（某卷一旦已有正文章节，该卷已写区间对应的既有剧情单元卡与对标结构坐标即视为锁定——未经用户确认不改既有内容，但允许在卷尾**追加**新剧情单元卡）。

5. **Phase A/B 适配（B53）**：开新卷的 Phase A 从 Stage 4 起增量（Stage 1-3 全书级不重做，与现状一致）；Stage 4-6 全速走完 → Phase A→B 弹窗 → Phase B 打磨环（evaluator eval_type: full，评新卷单元卡+卷纲）；**虚拟对标不重新合成**（全书级，沿用开书时的）；新卷引入新题材元素可触发增量采风（CF 票据照常）。

> 开新卷同样先读 `设定/构建台账.md`（存在时，见「进入规则」）——汇报当前焦点/待定项/方法论档位后再规划。

## Agent 调用（moshu-architect / moshu-character-designer）（agent/技能选型判据见 AGENTS.md §5「Agent 使用判据」）

- **moshu-architect（Stage 1 题材定位）**：轻量题材定位优先由主会话完成；只有涉及复杂世界观、多线结构、强反转工程或用户明确要求时，才调用。已部署时（检查 `.claude/agents/moshu-architect.md` 是否存在）可 spawn `Agent(subagent_type: "moshu-architect", prompt: "项目目录：{dir}\n任务类型：题材定位\n查询参数：{用户选择的方向+对标信息}")`。如 agent 不可用，由主线程直接执行。
- **moshu-architect + moshu-character-designer（Stage 2-3 骨架与人物）**：结构复杂/反转链多/角色关系密时辅助骨架与角色设定（任务类型：核心设定/角色设定）。spawn prompt 必须原样附带「moshu-architect 契约摘要」。
- **moshu-architect（Stage 4-6 卷级）**：只有结构复杂、反转链多或主会话方案不稳时，才调用辅助卷级结构（卷级大纲、钩子/反转/情绪弧线设计）。**首批细纲的产出不在本工作流**（归 write，B1b）。

> **moshu-architect 契约摘要（spawn 时必须原样附带）**：部署的 moshu-architect agent 不认识本 skill 的 `references/reader-contract-and-progression.md`，只能靠 spawn prompt 里带的这段摘要对齐 schema。摘要内容（终局储备边界/透支两问/剧情单元/细纲层字段/读者契约与主角代理权/关键节点四问）与 write 侧同源——从 `references/reader-contract-and-progression.md` 摘取（本文件不复制全文，引用即挂载）。模板承接见 moshu-architect「契约摘要承接」段。

### 自动步的打断与恢复

```
作者在Stage 3/4 运行中说"等一下"或 "/moshu-outline"：
  → AI 读台账："你在 Stage {N}·{名称}，故事面{状态}，人物面{状态}。
     待定 {N} 项。继续还是调整？"
  → 台账的「当前焦点」实时记录进度（含六步位置）
```

### 停靠选项的级联说明

```
停靠 1 选"调整某卷"：
  → 骨架变了 → AI 检查角色四件套是否受影响 → 受影响则提示同步更新 → 更新后重新展示本屏

停靠 2 选"调整某单元"：
  → 单元变了 → AI 检查浮现记录和角色弧线段是否受影响 → 受影响则同步 → 重新展示

停靠 3 选"继续调整"：
  → "哪部分？" → 指向对应步 → 台账更新 → 从该步重新开始
```

### 与现有机制的关系

| 现有机制 | 处置 |
|---|---|
| 五步法 | **不删除，融入**——第 1 步（定高潮）→ Stage 2、第 2 步（单元剧）→ Stage 4、第 3 步（八条线/信息点预埋）→ Stage 4 浮现 + Stage 5 线索矩阵 |
| 八节点 | 不删除——Stage 2 定结构 + Stage 6 占比校验 |
| 对标回流 | 不删除——Stage 6 核心内容（坐标表+锚点） |
| 大纲安全审查 | 拆分——可证伪降级（删主角/删题材核心）→ Stage 5、卷级五问 → Stage 6 |
| 构建修订工作流 | 不动——定稿后走修订（[revision-workflow.md](revision-workflow.md)） |
| 台账 | B11 升级为 v2（六步状态表）——现行即 v2（B10 时"沿用 v1"为历史注记，已废） |
| **write 的"锁定"定义** | **不冲突声明**：本步"定稿"=构建完成的标记（v1.0）；write 侧 outline-workflow 的"锁定"=有正文章节即视为保护锁——**两者共存，互不替代**：定稿在前（构建完成），锁定在后（正文产生） |

## 防撞对照协议（B65）

**触发**：开书 Phase A Stage 5 卷纲成型后（workflow-build 防撞对照节引用本协议）；修订流改动设定/单元卡后复跑（改动面对照）。

**数据源**：主对标拆文库角色/剧情模块 + 其他参照（拆文库多本、采风产物 `设定/采风-*.md`）。无对标书 → 声明跳过（合法无对标模式，明示不静默）。

**对照表模板**：

| 维度 | 本书元素 | 源作品元素 | 重合判定（高/中/低/免责） | 说明 |
|---|---|---|---|---|
| 人物功能位 | {具体描述} | {具体引证：来源书+角色名+功能描述} | 高/中/低/**免责** | {一句话} |
| 桥段节拍 | {具体描述} | {具体引证} | 高/中/低/**免责** | {一句话} |
| 设定机制 | {具体描述} | {具体引证} | 高/中/低/**免责** | {一句话} |

> 「源作品元素」列必须**具体引证**（来源书名+角色/桥段/设定的可指认描述），不是感觉——判定的可审计性依赖此列。登记项（对标结构坐标/剧情单元卡「对标剧情参照」）照列但标「**免责**」——登记免责≠免列，透明可审计。

**判定规则**：
- 单源（同一参照书）≥2 维度高重合 → 候选呈报（可能渗透过深）；
- 仅 1 维高重合 → 记表不呈报（单维是学习）；
- ≥2 参照源同现同类重合 → 共性（网文套路），降噪音注记；
- 元素记载于题材对应卡（genre-prose-cards 匹配卡）→ **题材共性**（B71 第三信号源，与前项并列）——题材套路非渗透，降噪音注记。
- 消费锚（B73）：对照时读 `设定/题材定位.md`「题材框架」行与拆文产物元数据头题材框架字段，作为三源判定的题材坐标。

**呈报**：停靠屏附屏（候选区）/修订流报告节；措辞用「重合度」不用「抄袭」（候选语义，判定归作者）。候选永不拦截。

**修订流复用**：revision-workflow ③b 后改动设定/单元卡 → 按本协议对改动面复跑。
