# workflow-outline.md：开书故事层流程（四 Stage——moshu-outline）

> **来源声明**：B107 按 12 号编程级规格 v2.0（22 块契约）全量重构——本文件是其运行时编译产物；设计依据与逐块字段契约见 12 号，裁定史见 13 号决议账。
> **统一模板映射（FULL）**：PREPARE=入口+Stage 1/2（先想清：进度路由+立意+采材）｜DRAFT=Stage 3（先动笔：五段草稿，步骤内不停顿）｜REVIEW=4.5+5.1（先挑剔：验收 gate+三评委）｜POLISH=5.2-5.4（再回头：打磨循环+终验）｜COMMIT=5.5（定稿：三查+锁死）。
> **三条通用纪律（全程有效）**：
> 1. **修改触发重走**——作者在停靠点要求修改时，判断影响面从最早受影响步骤重走执行流程（含方法论检查），不是直接改文字。
> 2. **方法论应答制**——执行流程凡引用方法论文件的步骤，产出文件必须含【方法论应答】区块（消费方/使用文件/使用节/做了什么/产出影响+检查项表），没有应答块=步骤未完成。
> 3. **停靠展示**——凡停靠展示产出，必须同步列出产出文件的相对路径+本次新增/修改/未动文件清单。
>
> **按节精读**：引用方法论带「节名」锚点时先 grep 定位只读所需节；**加载回执**：每步开始报「📋 本步加载：{文件名}｜{一句要义}」。

## 交互模态规则
1. 封闭选择（候选可枚举 ≤4）→ AskUserQuestion 弹窗；2. 开放采集（自由表达/创作审阅）→ 对话式；3. 过程性动作 → 声明即将做+可显式跳过；4. 同质封闭选择合批（≤4 问/弹窗）；5. 话术零黑话——用户可见文字禁内部术语（锚定在回读中表述为「权威值在拆文产物，可解除」）。

## 入口：读创作进度，按创作阶段分流（12 号块 1）

1. 读项目根 `创作进度.md`；
2. 读不到 → 用 `skills/moshu-outline/references/progress-template.md` 新建（各字段默认值：当前阶段=未开始、开书记录=未回答/未开始、检查单四行=未开始、产物状态表=空表、变更日志=建档一行）→ 走 2.1；
3. 读到 → 读「总览·当前阶段」按值分流：
   - `未开始` → 2.1；
   - `大纲阶段-Stage N {阶段名}` → 读「产物状态表」表尾行定位续跑步骤 → 跳到该步（例：表尾=大纲.md v0.2 骨架十节 → 从 4.4 全员深化继续）；
   - `卷纲阶段-…`/`正文阶段-…` → 汇报并建议 /moshu-volume 或 /moshu-write，本技能不重开；
   - `已完成` → 汇报完结状态。
4. 开场白（逐字）：「本技能完成开书故事层，四个阶段：基本设定（定书的规格）→ 素材收集（采参考或采题材）→ 大纲草稿（故事核心/世界观/骨架/角色）→ 大纲打磨（三评委报告+修改循环+定稿）。」
5. 续跑汇报（逐字，结构=你当前在哪→上次到哪→接下来做什么；四 Stage 各一条+已完成一条，见 12 号 1.8）+ **停等确认**：「继续？」选项：继续（推荐）／先看看产出再决定／今天先到这。仅"已开始未完成"弹；未开始直进 2.1。
6. 读失败三分类：空文件=损坏呈报（禁当无档）；不完整=列缺失不猜补；缺文件=正常建档。

## Stage 1·基本设定（四步，进度轨 1/4~4/4）

### 2.1 开书双问（前置闸）

**第 0 步** 读创作进度开书记录（入口已分发）：当前阶段≠未开始 → 跳过本步。
**第 0.5 步** 用 `skills/moshu-outline/references/core-setting-template.md` 创建 `设定/基本设定.md` 初始空壳（五段在、字段默认占位）——必须在预填之前。
**第 1 步** 看开书记录四字段旧值（有值跳过不重复问）：
- 对标=有+拆书进度=已完成 → 直接过闸（第 3 步）；对标=有+未开始/进行中 → A2；对标=已取消 → 灵感=有过闸/否则灵感轨；对标=无+灵感=有 → 过闸；对标=无+灵感=无/未回答 → B1；双未回答 → 弹双问。
**第 2 步 弹双问**（AskUserQuestion 合批，逐字）：
- 问一·深度对标：「是否有具体想深度对标学习的书？」——无／有（请补一句书名，自由文本）。
- 问二·灵感：「是否已有灵感开书？」——有／还没有。

**对标轨**（判定只看字段，不扫目录）：
- A1 拆书进度=已完成 → 写：对标=有（{书名}）、灵感=有 → **锚定注入+自动填写基本设定**（此时才读拆文库内容）——衔接表：概要·题材→题材（锚定）｜概要·体量/平台→体量/平台（建议）｜剧情-节奏·爆发密度/爽点循环→品类参考·节奏目标（锚定指针）｜剧情-情绪模块·读者需求→品类参考·情绪基调+读者偏好｜结构分析→品类参考·结构要点（指针）｜角色卡→主角作派（参考级）｜机制分析→世界观转译原料｜梗概/内核/世界观/冲突/书名→**不预填**（防撞红线）。
- A2 拆书进度=未开始 → 弹窗「对标《X》还没拆书——怎么继续？」①去拆书（推荐）→写：对标=有、拆书进度=进行中→暂停提示 /moshu-analyze；②取消对标继续开书 → 写：**对标=已取消、灵感=无** → 进 2.2。
- A3 拆书进度=进行中（analyze 已回报）→ 直接过闸：锚定注入 → 2.2。

**灵感轨**（问一=无且问二=还没有）：
- B1 扫榜=未开始 → 弹窗「还没扫过榜——去扫榜找方向，还是不扫了？」①去扫榜（推荐）→写：扫榜=进行中→暂停等 moshu-scan Stage 5（选题决策产物）；②不扫了 → 写：**扫榜=已跳过、灵感=无** → 进 2.2。
- B1b 扫榜=进行中（scan 已回报）→ 直接送候选方向选择（B2）。
- B2 扫榜=已完成 → 弹**选题候选方向选择**：读 `选题决策.md`（/moshu-scan 产物——平台榜单分析后生成的 3-5 张候选方向卡，每卡含题材赛道/优缺点/能爆原因/读者画像/主流体量）呈现单选；选项：挑一张／都不满意重扫／不选了回灵感种子。选定后：写：灵感=有（题材方向）+ **自动填写基本设定**（衔接表：题材赛道→题材｜读者画像·平台→目标平台｜主流体量→体量｜主流章字→每章字数｜赛道关系线→关系线｜题材雷区→题材雷区｜读者口味→读者偏好｜能爆原因→品类参考·情绪基调素材｜头部作品→参考偏好候选，每项标来源「扫榜候选N」）→ 2.2。

**问一=无且问二=有** → 写：对标=无、灵感=有 → 直接过闸进 2.2。
**第 3 步 过闸** → 进 2.2（话术变体见 2.2）。取消/跳过分支写全三字段（含灵感=无）。

**同步**：当前阶段=大纲阶段-Stage 1（四字段首写时）；焦点=基本设定（开书双问）；上一阶段=无；时间刷新。

### 2.2 灵感种子

1. 收下作者灵感（自由文本，开场白按进入方式选一条，逐字）：默认「写下你最初灵感——一句话、一个画面、一个"如果……会怎样"的假想都行，数量不限。💡 写得越具体，后面问得越少。」有对标：「你想写一本像《X》那样的书——它最打动你的是什么？你自己的切入点是什么？」扫榜选定：「在{选定赛道}里，你想写个什么故事？」
2. 提取标签类信息填入基本设定（每项标来源「用户输入」）：题材/体量/情绪基调/文风/参考提及→候选/雷区/平台。
3. 提取故事直觉原话存 ⑤故事直觉（AI 只加一句标注不改原话）：人物画面/世界画面/冲突点子/金手指念头/卖点直觉。
4. 纯画面型 → 标签暗示（仅提示不写字段，可挂 `skills/moshu-outline/references/genre-catalog.md` 路由表辅助推断）。
5. 念头提"对标《X》"且 2.1 已答无对标 → 一律降参考。
6. 分型路由：有方向（题材+基调至少有）→2.3；纯画面→标签暗示→2.3；只有冲动→深挖一问「读者最爽的瞬间是什么画面？」答案进品类参考·情绪基调素材→2.3；空白→兜底引导（无挂载，AI 直接引导收敛）。

**同步**：仍 Stage 1 不翻转；焦点=灵感种子；时间刷新。

### 2.3 回读补问（含参考确认）

1. 读 `设定/基本设定.md` 分三堆：已填（记下来待回读）／未填可兜底（体量=200 万·5 卷/每章字数=3000-4000/关系线=AI 建议/雷区=空——填入不问）／未填无兜底→待问清单。**全部已填**→跳过弹窗，只做回读+书名对话问。
2. 回读已填字段（逐条标来源；扫榜候选显示值+来源；锚定字段显示值+「权威值在拆文产物，可解除」）；作者当场纠正→改字段继续。
3. 弹窗问待问清单（≤4 问，每问带 ℹ️ 用途→下游影响→不答默认）：**必问**目标平台（各选项带适配注解；预填显示不重问）；**必问**书名（「书名想好了吗？有就填，没有我拟几个候选你挑。」填了写入；没填 AI 拟 2-3 候选当场挑/改）；问一次：终局口径（五选一：圆满/圆满带憾/悲剧/开放式/还没想好[默认 AI 拟]）、情绪基调（有则不问）。
4. 对话补问：「有没有想好的人物、设定点子，或平时攒下的画面/名字/脑洞存货？有就一起贴进来，没有我来拟。」→ 贴入存 ⑤故事直觉。
5. 永不问：核心玩法/金手指/主角/世界观/冲突/梗概/品类参考（创作内容问作者=逼填表）。
6. AI 速写：每部确认参考附一行（底色占比｜开局 vs 主体｜主角弧）。
7. **参考确认**（对话式）：「参考作品的作用：有参考→采风按参考针对性检索；没有→按题材大范围采风。想学某书的开篇→建议对该书运行 /moshu-analyze。」「主参考（定主基调，只能 1 部）：{书名}——主要借鉴它什么？辅助参考（≤3 部）：各借鉴什么？没有可以说没有。」→ 写入 ③参考偏好（主/辅分记+借鉴侧重）或留空。
8. 全部答案写入基本设定 → 完成。

**同步**：仍 Stage 1；焦点=回读补问；时间刷新。

### 2.5 定稿过目 ◉停靠

- 标签清单展示五段（零故事零卖点）：①基础参数（书名/题材/平台/体量/章字/关系线/终局口径/题材雷区）②基调风格③参考偏好④品类参考（有对标=锚定指针；无对标=空占位「待素材收集后产生」）⑤故事直觉。每条可见可改。
- 📄 展示路径：`设定/基本设定.md`｜`创作进度.md`。
- 三选：✅ 确认 → 三连落盘（基本设定确认+创作进度九节补全+当前阶段翻 Stage 2）→ 停靠告知两文件路径+问「确认没问题的话，下一步就去采风了——继续吗？」说继续→3.1；说先到这→停靠（续跑从 3.1）。✏️ 修改 → 说改哪条，改后重展示（改题材类字段提示可能需重采风）。⏸️ 先停靠 → 原地等（续跑从本步重展）。

**同步**：当前阶段→`大纲阶段-Stage 2 素材收集`；焦点=素材收集；上一阶段=Stage 1；下一阶段=Stage 3；时间刷新；产物状态表首行「基本设定｜—｜—｜已落盘」。

## Stage 2·素材收集（四步，进度轨完毕后）

### 3.1 采风确认步

1. 按基本设定·参考偏好自动定采风方式：有对标 → 差量采风（拆文已覆盖主体只补缺）；有参考 → 逐部针对性采风（按主/辅逐部过三域检查单）；无参考 → 题材级三域大范围采风。
2. 告知方式与时长（逐字，按方式选一条——三域各带具体条目：剧情=故事脉络/关键转折/常用桥段/节奏快慢，设定=力量体系/规则限制/世界样貌，人设=角色类型/性格/关系网，+第四域写作技法=开篇手法/悬念铺法/爽点安排/节奏控制）：
   - 有对标：「接下来基于对标拆解结果做补充采风，主要查这四个方面：……拆文已覆盖的部分会跳过，只补没覆盖的。预计 5-10 分钟。」
   - 有参考：「接下来对参考作品做深度采风……对象：主参考《{主参考}》＋辅参考{辅参考}，预计 5-10 分钟。」
   - 无参考：「接下来按你的题材做一轮大范围采风……会顺便帮你收集这个赛道的代表作品清单，预计 5-10 分钟。」
   - 升格重入（3.4 认领参考后回来）：「已把《{书名}》记为主参考——现在对它做针对性采风，预计 5-10 分钟，开始了。」（不重复确认；已有综述不重做）
3. **采风必须做，无跳过选项**——作者确认后 → 3.2。

**同步**：仍 Stage 2；焦点=素材收集（确认采风内容）；时间刷新。

### 3.2 三域深采（researcher 执行）

1. 续跑定位：看 `设定/参考/` 已有文件对照参考偏好——已采跳过只采缺的。
2. 组装检索内容（四域+无对标补两项真实人物原型/时代背景；query 按 `skills/moshu-outline/references/caifeng-outline.md` 标准模板组装）。
3. 环境检查：确认能否开浏览器（能→抓取；不能→问作者配置；确认不行→备用方案）。
4. spawn moshu-researcher（type=caifeng 有参考逐部/survey 题材级；采风专用模式节已内嵌 researcher 模板[moshu-setup 部署物，spawn 随模板分发]——只传 {对象}+{模式}+project_dir+cdp_port）。规矩：只记笔记不写小说（不取不复述正文）；回合预算 ≤20 超限降级收尾（标「降级」）；≥2 独立来源交叉，单源注明。

**同步**：仍 Stage 2；焦点=素材收集（检索中）；时间刷新；CF 编号 ls 取 max+1。
**异常**：researcher 不可用→主会话自采兜底（标 Fallback）；全部源失败→告知采到/没采到详情，作者裁决。

### 3.3 采风落盘

1. 核对产物完整性：有参考书→九段齐（故事脉络/剧情节点/支线/设定/人物表/底色配方/缺点/专名/来源）；无参考→八节齐（题材概况/主流模式/桥段库/设定标配/主角类型谱/读者偏好与雷区/代表作谱系/竞争格局）——每节头部标来源数。
2. 缺段 → 元数据头标「缺{段名}」不自己补写（作者预览时裁补查）。
3. 通过 → 告知「采风结果已保存」。本步不修改产物内容、不做融合。

**产出**：`设定/参考/{书}.md` 或 `{题材}-综述.md`；`设定/采风/采风-CF{NNN}-*.md` 票据；条件 `设定/资料/{专题}.md`。
**同步**：仍 Stage 2；时间刷新；产物状态表新增行。

### 3.4 停靠预览 ◉停靠

1. 组装预览：有参考=每部三域要点表；无参考=综述要点表+代表作谱系+差异化判断一行（「赛道头部是 X/Y，拥挤在 Z，你的空位像是 W」）；+素材层清单+材料浓度信号（每节来源数，单源标「材料薄」）。
   📄 路径：`设定/参考/{书}.md`（或综述）＋`设定/采风/` 票据。
2. 选项：✅ 素材够了 → 3.5；🔄 补充采风 → 作者说缺什么 → 回 3.2 只补缺的 → 回本步重展；⏸️ 停靠 → 续跑从本步重展。
   **升格出口**（无参考时）：预览谱系里作者看中某本 → 追问（选项 4 个含换一批）；选定 → a.写基本设定·参考偏好·主参考={书名}（侧重=能爆原因）→ b.回 3.1 重走（分派自动识别有参考→逐部采风→3.3→3.4 重展）；上限 1 主+2 辅。
3. 材料几乎全部「材料薄」→ 明确告知影响+作者裁补采或先用。

**同步**：仍 Stage 2；时间刷新；升格时产物状态表更新。

### 3.5 品类参考产生

1. 收集合成素材：有参考→读参考档案「底色配方与模式占比」；无参考→读综述「读者偏好/主流模式/竞争格局」；有对标→读拆文库节奏/情绪参数（只确认锚定指针不重复合成）。
2. 调和作者基调：材料与基本设定·②情绪基调冲突时以作者意志为先（标注「作者意志覆写」）。
3. 逐格填写（按 core-setting-template ④格式）：节奏目标=数字范围值；情绪基调=描述性文字（不用百分比）；结构要点=模式名+参数；主角压力=类型/数量/递增——每格标依据强度（锚定实测｜多源统计 N 源｜推演⚠️）。
4. 展示给作者确认 → 写入基本设定·④品类参考节。
**语义通则**：品类参考=参考范围非硬性配额；真冲突故事性优先（识别偏离→知道代价→技法对冲）；偏离成习惯→回头调品类参考。
**同步**：当前阶段→`大纲阶段-Stage 3 大纲草稿`（品类参考确认=素材收集完成）；焦点=大纲草稿；上一阶段=Stage 2；下一阶段=Stage 4；时间刷新；④节版本标注；产物状态表刷行。

## Stage 3·大纲草稿（五段，每段产出作者看过才能继续）

### 4.1 故事核心设计 ◉停靠

1. 读素材：基本设定全部标签+⑤故事直觉；参考档案④设定/⑤人物表 或 综述设定标配/主角类型谱（**有参考两者都读**：综述=赛道基线防跑偏，档案=深度参照）。
2. 提炼支柱场面：从⑤找「最想让读者记住的画面」——开局钩子/中段爆点 2-3/最想要的结局画面（⑤空则自问「只能记住一个画面是什么」）——这些是整本书的情感锚点。
3. 生成梗概候选 2-3：每条能串起支柱场面；此时读 `skills/moshu-outline/references/outline-causality.md`「前提句」节——三要素检查每条完整性。候选呈现（逐字）：「梗概候选 2-3 个方向，挑一个或说怎么混搭：」
4. 深化主角：写 `设定/角色/主角.md`（开局身份/欲望/需求）；金手指设计读 `skills/moshu-outline/references/golden-finger-design.md` 全文——三定则设计+四性表逐项检查+单一魔力源检验。
5. 确定终局对手（同源/镜像/宿敌）：读 outline-causality「动机链」——"为什么是他"检验。
6. 确定核心冲突（信念 A→信念 B）：读 outline-causality「道德前提」三层检验+「主题推导」五问。
7. （冲突受阻时）读 `skills/moshu-outline/references/genre-core-mechanics.md`「冲突网络」找灵感。
8. 写入：`大纲/大纲.md` 新建第 0 节（梗概+卖点+**支柱场面清单 2-5 逐条编号**）+ `设定/角色/主角.md`。
9. 进入条件：全部定型才进 4.2。
◉ 停靠：展示故事核心（梗概+卖点+主角+对手+冲突+支柱场面）——确认→4.2；要改→说哪里改后重展（涉及金手指/冲突→重走对应步骤含方法论检查）。
**同步**：仍 Stage 3；焦点=大纲草稿（故事核心）；时间刷新；大纲 v0.1 起+产物状态表两行。

### 4.2 世界观构建 ◉停靠

1. 读基本设定①②+综述设定标配（有参考也读）+主角金手指设定。
2. 设计力量体系（等级 ≤5-7/升级方式与金手指一致/天花板=终局对手锚点/代价）——对照 golden-finger「三定则」。
3. 设计社会结构（阶层/秩序/稀缺资源/货币经济/风俗习惯）——对照 `skills/moshu-outline/references/genre-catalog.md` 题材「结构要点」。
4. 设计地理文化（地图分层/成长路线/氛围感——读者为什么想活在这个世界）。
5. 设计规则与禁忌（超常法则过单一魔力源检验/世人不知的真相=暗线事实基础）。
   （方法论细节读 `skills/moshu-outline/references/worldview-design.md`——骨架版，问句框架）
6. 有缺口两种补法：定向查证（spawn researcher 五维模板）／文化质感（读同题材顶级作品世界观段落提取）。
7. 写入 `设定/世界观/*.md`（四件各一节 5-15 条骨架版）。
◉ 停靠：展示四件——✅→4.3；✏️改→重展；⏸️停靠。（第二个停靠点）
**同步**：仍 Stage 3；时间刷新；产物状态表。
**异常**：资料采集失败→按已有知识搭+标「未经资料校验」不阻断。

### 4.3 骨架十节

1. 读品类参考全部四组+剧情域材料+世界观骨架版。
2. 按 `skills/moshu-outline/references/skeleton-template.md` 逐节建（含第 7 节暗线表+反转谱表两子节、第 9 节主要人物节）——方法论内嵌（每节读什么做什么检查见模板节内指引：structure-theory 三幕八节点/rhythm 升级感+代价系统/plot-frameworks 死亡三类型/reader-contract 承诺兑现/character-design-methods 反派差异化/reversal-toolkit 知情三态公平性/hooks-suspense 悬念维持/genre-core-mechanics 支线挂靠/character-construction 配角规模）+骨架表对照品类参考（阻力类型交替/情绪禁区/递增方式/阻力数量类型）。
3. 十节联动检查四条（台阶 vs 对手交替上升/承诺 vs 暗线时点错开/骨架表 vs 品类参考爆发密度/底牌 vs 台阶铺垫）。
4. 跑 `skills/moshu-outline/scripts/check_outline.py`——blocking 清零。
5. 骨架轻过目 ◉停靠（十秒级，世界观已在上一步确认）：📄 路径 `大纲/大纲.md`——✅过/✏️改（说哪卷哪行；涉及因果链/时点/角色/暗线→重走 4.1 对应步骤含方法论检查）/⏸️停靠。
**同步**：仍 Stage 3；时间刷新；机检基线记录；产物状态表刷行。
**异常**：机检修 3 轮仍红→停靠呈报根因；材料不足节→AI 推演+标⚠️。

### 4.4 全员深化 ◉停靠

1. 续跑定位：对照骨架群像列 vs `设定/角色/` 目录——缺谁建谁。
2. 逐角色建档（三层标签/13 项触发问句/对话 DNA 五要素/弧线六阶段/出场编排含本卷变化/价值观检验）——读 `skills/moshu-outline/references/character-construction.md`+`skills/moshu-outline/references/character-design-methods.md`。
3. 建关系索引：读 `skills/moshu-outline/references/character-relations.md`——写 `设定/角色/关系.md`（四型+冲突网格：过去恩怨/现在摩擦/未来冲突）。
4. 势力场回填（骨架第 6 节展开成 `设定/势力/*.md`）；世界观细节回填；建 `设定/情绪引擎.md`（读 `skills/moshu-outline/references/plot-emotion-system.md`——只引用品类参考数值不复述）。
5. 每卷一段话回填骨架表。
6. 人物清单停靠 ◉：展示全部角色名+一句话定位+关系网概览+📄 路径（`设定/角色/*.md`+关系.md+势力+情绪引擎；本次修改：大纲.md/世界观）——三选+新名过命名卡校验（naming-cards，volume 侧方法论）。可选：评审（spawn moshu-evaluator，eval_type=structure，人物设计评审——spawn 前三件套声明，只呈报）。
**同步**：仍 Stage 3；时间刷新；产物状态表多行。

### 4.5 草稿验收（正确性 gate）

1. 跑机检——blocking 清零。
2. spawn evaluator（structure 型验收面）：前后矛盾/因果通不通/承诺兑现/遗留缺口。
3. 按问题来源修复（修改触发重走）：格式断链→直接改；前后矛盾→判根源回 4.4 或 4.2；因果断裂→回 4.1/4.3；承诺未兑现→回骨架第 3 节或 4.1——含方法论检查。
4. 修完复跑机检+评审至清零；**3 轮不清零→停靠呈报**（可能结构性缺陷）。
5. 写 `大纲/验收单.md`（机检结论+四件结论+可留三类登记[跨卷兑现/执行分层/作者决策]每项带去向）。
告知（逐字）：「检查完毕，发现并修复了 {N} 个问题，全部通过。遗留项 {M} 条已登记。」作者知情即可继续（非创意决策）。
**同步**：当前阶段→`大纲阶段-Stage 4 大纲打磨`（验收清零=Stage 3 完成）；焦点=大纲打磨；上一阶段=Stage 3；下一阶段=大纲阶段-已完成；时间刷新；产物状态表。

## Stage 4·大纲打磨（六步）

### 5.1 三评委质量审 ◉停靠

1. 告知（逐字）：「接下来约 3-5 分钟（预估）：三位评委（读者/编辑/写作同行）审查全部大纲产物，产出一份带修改建议的报告——只提建议，不替你做决定。」
2. 组装评审任务：target=大纲.md+基本设定+世界观+角色+关系+情绪引擎；参照=品类参考节（**仅作参考，不是评分标准**）；有对标加拆文库节奏/情绪数据；已知遗留项=验收单登记+创作进度待定项；**方法论判据已内置 evaluator panel 模板**（读者→reader-contract+genre-readers；编辑→outline-structure-theory+plot-frameworks；作家→genre-core-mechanics+reversal-toolkit；通用→outline-rhythm+plot-emotion-system——随模板分发，agent 不另读文件）。
3. spawn moshu-evaluator（eval_type=panel；panel 型正文已内嵌 evaluator 模板[moshu-setup 部署物，spawn 随模板分发]——三视角关注面/输出格式/审稿令牌）。📋 加载回执。
4. 核对报告：审稿令牌 8 位逐字比对（不符→弃用重 spawn ×1；仍失败→停靠呈报原文+「token 不符」警示，用不用作者裁）。
5. 落盘 `设定/大纲打磨报告.md` R1（append-only）：元数据+已知项+三视角表（条目号/位置/不足与原因/建议[🔧方法论文件+节名 或 🔍采风方向]/状态，实质 ≤5/视角）+琐碎已修节+作者令节。
6. 展示报告（报告条目与大纲对应段落并排呈现+📄 `设定/大纲打磨报告.md` 路径），选项：✅ 按报告进修改（推荐）／✏️ 对报告提意见（补充/否决/调优先级——作者否决权最高，否决条目移出清单不重走）／⏸️ 先到这。
   **快速通过**：实质 ≤3 且重要度都不高 → AI 主动提示「评委只找到几个小问题，你要直接过还是改一下？」直接过→5.4。

**同步**：仍 Stage 4；焦点=大纲打磨（三评委审报告中）；时间刷新；产物状态表（报告 R1）。
**异常**：spawn 失败→主会话自评兜底四问（商业硬伤？核心桥段见过吗举 2 例？弃书点第几章？只改一处改什么？）标 Fallback；报告超长→按视角截断呈报不截断落盘；过薄→提示可深检或接受。

### 5.2 打磨步（循环核心——环里唯一权力点）

读打磨报告为工作清单，六种操作：
a. **全部按报告改**（批量选项——决策负担 N 次→1 次）；b. 部分改（点名条目）；c. 单独改某条（含方法论应答+重读当前内容）；d. **补充素材**（🔍 条目：a 组装搜索词→b 派 researcher→c 读结果提取相关要点→d 按报告建议的方法论修改大纲[不随便贴]→e 给作者看改了什么→f 回循环）；e. 深度检查（📡 加派 evaluator 更重配置）；f. 作者自发新增。
**分层处理**：重要度排序一次改一维；**中途停靠**恢复话术=「接着上次的打磨，回 5.2 循环（不是回 5.1 重审）」；**品类参考检查信号**：同一维度连续两轮被提 → 先问「是不是品类参考里这个标准本身要调整？」调整后再改。
每轮改动走 5.3 级联。

### 5.3 级联纪律＋回退

每轮：先声明影响文件 → 作者确认 → 一次改完（不留半改）→ 重跑 check_outline → 按维度复审（spawn evaluator 该维）→ 打磨报告追加 R{N+1}（选择/影响声明/改动快照/机检/复审——append-only，回退也追加「已回退至 R{N-1}+原因」）。

### 5.4 打磨终验＋收口预览 ◉停靠

1. 终验全貌（#106 对称 4.5）：跑在定稿全貌上抓多轮累积矛盾——机检+交叉一致性+承诺全表核对；结果入报告。
2. 收口预览三件：①终验结果 ②残余项「归卷 N」台账清单逐条 ③开卷就绪包五件预览。
   📄 就绪包路径：`设定/基本设定.md`｜`大纲/大纲.md`｜`设定/世界观/*.md`｜`设定/角色/*.md`+`关系.md`｜`设定/情绪引擎.md`——作者逐件可开。
3. ✅ → 5.5；打回 → 5.2。

### 5.5 收口序列（设定三查＋COMMIT）

1. 设定三查：回写查（骨架/角色对世界观/基本设定的反哺收口）／孤儿查（无消费方的孤儿字段清点）／冻结查（基本设定定格语义——此后走修订流）。
2. COMMIT 五件：大纲定稿号 v1.0（锁死）＋创作进度九节终态+当前阶段→`大纲阶段-已完成（等卷纲）`＋移交台账（遗留项归卷登记）＋就绪包确认＋变更日志。
3. 定音锤 ✅ → 汇报「本书大纲已定稿 ✅——建议使用 /moshu-volume 开始首卷卷纲」＋📄 全部产物路径。**不自动切换技能**。

### 5.6 断点恢复

§2.2 判定表执行：当前阶段（粗）+产物状态表（细）+文件证据（防漂移）。打磨期特例：`设定/大纲打磨报告.md` 不存在=质量审未跑→先 5.1；存在→末条 R{N} 即断点。续跑话术（逐字）：「接着上次的来。你当前在 Stage 4 大纲打磨阶段，第 {N} 轮。你上次：{末条摘要}——从这里继续。」→ 回 5.2 循环。

## R 修订流（COMMIT 后——作者发起）

1. 读创作进度变更日志末行确认版本与定稿态。
2. 判级决策树（AI 初判+告知作者可改判）：
   ① 触及大纲.md 第 0/2/4/5/6/7 节（故事核心/因果/底牌/台阶/对手/暗线）？→ **正式修订**；
   ② 触及角色弧线/金手指/动机，或世界观四件，或基本设定①-④段？→ **正式修订**；
   ③ 仅错字/标点/单字段数值微调（不涉因果链/人物状态/时点/承诺）？→ **轻量修订**；
   ④ 灰区 → 呈报作者定级（AI 给建议级别+理由）。
3. 轻量：定点改+变更日志一行（当前阶段不变）；正式：影响扫描五步（声明影响面→作者确认→一次改完[从最早受影响步骤重走]→重跑 check_outline→变更日志+stale 标记）。
4. 卷纲/正文已开工内容受影响 → stale 标记入移交台账（下游开工认领，不静默吞）。
