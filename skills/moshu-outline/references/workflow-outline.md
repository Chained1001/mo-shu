# workflow-outline.md：开书故事层流程（Stage 1-3——moshu-outline）

> **来源声明（B76 v1.2）**：本文件自 volume-workflow.md（原 workflow-build）的 Phase A Stage 1-3 段拆出归 moshu-outline；单元构建→整合检验→定稿与 Phase B 在 moshu-volume 侧。按统一创作流程模板 FULL 模式组织（AGENTS §9 第 7 条）。
>
> **参考偏好 ≠ 对标**：参考学神韵（基调/主角/风格），对标仿结构（拆文产物 fail-fast 校准）——可共存。
>
> **虚拟对标**：无对标路线的设计约束参照——Stage 1 采风多源产物合成三类设计目标，落盘 `设定/虚拟对标.md`；outline 设计时参照、volume Phase B 打磨时评审锚点。有对标时跳过合成。
>
> **消费侧只读**：本工作流读 `追踪/`（last_committed_chapter 等）作输入，不写任何追踪文件。

## 交互模态规则（对话形态的选用纪律）

1. **封闭选择**（候选可枚举且 ≤4 项）→ 一律 AskUserQuestion（弹窗），不做开放式提问。
2. **开放采集**（无候选、要自由表达，如方向/感受/评述）→ 对话式，不硬塞弹窗。
3. **过程性动作**（不是选择，是即将执行的操作）→ 声明即将做 + 可显式跳过（如采风默认执行）。
4. **同性质封闭选择合批一屏**（≤4 问/屏），不逐问弹窗——轮 2 超过 4 问时拆两屏连续问。
5. **弹窗选项必须带"（推荐）"标注与一句理由**，供作者快速决策。

## 创作进度（入口规则）

开书入口第一步先读 `设定/创作进度.md`：存在 → 读它并汇报「本书{构建态}…」；不存在 → **四轮式开场答完即创建最小创作进度**（构建态＝Phase A 进行中）。模板与六态状态机见 moshu-volume 技能的 progress-template（进度模板归 volume）。

## Stage 1·信息采集（四轮式开场——作者意图输入口，保留全部交互）

> **方法论书指引**（先读后操作）：**《小说的骨架》第 2 章（理想书评）**——理想评论家口吻的成品书评，作目标态锚；操作已萃取进 [idea-seed.md](idea-seed.md)「理想书评」节，直接用，不另读原文。

**故事面**（所有书都做）——四轮开场（定调→定形→理想书评→定流程），按回答落地：

1. **先查选题决策**：项目根存在 `选题决策.md`（moshu-scan Stage 5 产出）则读取——取最前推荐选题为开书起点向用户确认；`扫榜日期` 久则提示"市场数据可能过期，建议复扫"；「能爆的原因」标 `待拆文验证` 时提示可选先 `/moshu-analyze` 验证或直接开书（不拦）。缺失时自动找（项目根起向下 3 层按名搜，mtime 取最新 2 份，AskUserQuestion 列候选）——见「四轮式开场」轮 1。
2. **模糊灵感**（画面/脑洞/感觉，说不清题材卖点）：先做**灵感种子收敛**（[idea-seed.md](idea-seed.md)，产物落 `{项目根}/灵感种子.md`），Logline 作后续方向与设定的一致性尺度。
3. **定形（轮 2）**：AskUserQuestion 批问 体量三数＋目标平台＋终局口径＋【B53 新增】情绪基调＋更新频率＋禁区雷点（可选跳过）；不确定按 200 万字/5 卷规划。所有答案落盘核心设定表对应字段（读者偏好段）。
4. **理想书评（轮 3，结构化）**：按 [ideal-review-template.md](ideal-review-template.md) 写"理想书评"——三维度量化目标（① 结构评分 1-10｜② 节奏：期待密度/释放频率｜③ 情绪：核心情绪+首卷读完感受），是 Phase B evaluator 打分锚点。落盘 `设定/理想书评.md`。
5. **核心设定落盘（轮 4 后）**：按 [core-setting-template.md](core-setting-template.md) 模板产出，**成稿先展示作者过目（可打断调整）**，确认后创建 `设定/题材定位.md`（题材核心梗三分法+对标分析[genre-core-mechanics]；含**终局底牌与升级台阶**）、`设定/关系.md`（角色关系映射[character-relations]）、`设定/题材正文提示卡.md`（题材边界/核心逻辑/读者期待/核心爽点[genre-prose-cards]）。
6. **方法论声明（轮 4 收尾）**：创作进度创建后补全「方法论声明」节——仅档位一行（轮 4 答案）；三域规划深度**不再逐项问**——默认档位表（见下）作流程内参考，作者口头可调（"卷纲再细一点"即改）。

> **默认档位表**：

| 域 | 默认 | 可选档 | 不可裁剪项 |
|---|---|---|---|
| 大纲 | 全局骨架 | 前半细化 / 仅阶段一 | 终局与升级台阶（全书） |
| 卷纲 | 首卷细 | 前两卷细 | 首卷（开书必须） |
| 设定 | 核心+终局相关 | 全量前置 | 主角/金手指/核心冲突 |

> **执行归属（B84）**：三域深度为全书构建声明（记入创作进度）：大纲/设定由 outline（Stage 2-3）执行；卷纲由 volume（开书接力 Stage 4-6）执行——此处声明、彼处消费。

**对标面**（有主对标时做）——**对标发现**（先于反应式加载，主动扫拆文库推荐，不被动等用户开口）：

1. `ls 拆文库/`（数据源）与项目 `对标/`（引用视图）列已有书目；先按当前项目目录名、`.active-book` 和 `设定/题材定位.md` 中的本书信息识别当前作品，**排除同名或来源指向当前正文的 `拆文库/{当前书}/`**。moshu-import 为重建工程生成的本书拆文分析不是对标候选，也不得复制回 `对标/`。排除后都为空 → 跳到第 4 条。
2. 逐本读题材（读 `拆文库/{书}/` 的 `概要.md` 头部或 `拆文报告.md`「基本信息」的「题材」），与本书题材/方向比对，标 同题材 / 弱相关 / 不相关。
3. 有同题材或弱相关候选 → 用 AskUserQuestion 推荐（列候选书 +「都不用」+「另拆一本」），选定主对标 1 本（走情绪/节奏/正文；文风独立由文风库提供）。选定后写入 `设定/题材定位.md`「对标登记」的 `主对标书`，并按「首次引用对标书」规则把选中书从 `拆文库/{书}/` 复制到 `对标/{书}/`（复制清单不含 文风.md——文风独立由 `文风库/文风.md` 提供）。登记后若文风库尚无该书文风，询问用户是否现在用 /moshu-style 学习（可跳过，写第一章时缺失会再次提醒）。
4. 无候选 → 无对标继续（骨架按八节点自排，见 Stage 2）；用户想对标可先 `/moshu-analyze` 拆一本。

**对标上下文加载**（用户提到对标书或工作目录已有 `对标/` 时）：按上方第 1 条识别当前作品并排除自对标；检查 `剧情/情绪模块.md` 与 `剧情/节奏.md`——任一缺失即停止，设 `missing_primary_contract: true` + `repair_action`（重跑 `/moshu-analyze` 或 `/moshu-import`），不得以拆文报告/章节摘要代替；两产物都在时先读情绪模块（读者需求/情绪引擎/可复现模块）再读节奏.md（信息推进/情绪触动点/爆发节奏）。角色/剧情单元/设定子目录按需召回（消费方 write，本流只记录引用）。

> 开篇的"第一个冲突/机遇"定义可参考**激发事件四问**（见 moshu-volume 侧 [opening-design.md](opening-design.md) :87 起——什么是/什么不是/在何处/四特质），在 Stage 2 定全书四阶段时使用。

### 四轮式开场（Stage 1 交互）

```
轮 1（定调 + 参考偏好 + 采风 · 开放对话）：
"你想写什么类型的故事？你希望这本书给读者什么感觉？"
→ 有方向 → 追加参考偏好快问：「有没有喜欢的作品？不说对标——就是风格/基调/主角类型你觉得不错的，0-3 部」
  （采集：作品名 + 各自偏好维度，如"诡秘的悬疑氛围"；落盘核心设定表「参考偏好」段。参考≠对标语义见文头注记）
  （题材初判走 [genre-catalog.md](genre-catalog.md) 路由，框架名写入题材定位.md「题材框架」行[B71]）
→ 没方向 → "要不要先扫一下最近的榜单？或者说说你想让读者有什么感觉？"
→ 提到参考书 → 弹窗（AskUserQuestion）：「参考书怎么处理？」
  ○ 正式对标——需先拆书（/moshu-analyze），参与每卷节奏校准
  ○ 仅参考——取题材气质做原创，不拆书（推荐）
  ○ 都不用——删掉参考
  （对参考书的三个吸引点提问在轮 3 理想书评采集）
→ **参考作品速写确认（B84）**：AI 对每部参考作品给三行速写（底色内核+模式占比｜开局手法 vs 全文主体｜主角弧阶段转变），AskUserQuestion 弹窗（每部一屏或合屏）请作者确认/纠正。确认后才组采风 query——防止 AI 误权重（如把大奉的探案开头当成全书底色）污染 query 框架。
→ **采风默认执行**（query 构造按参考偏好分流）：
  - 参考偏好非空：query = "{参考作品A}的{维度}手法 + {参考作品B}的{维度}——提炼可复用模式"（定向检索）
  - 参考偏好为空：query = "{题材} 当前热门作品的结构模式"（泛化检索）
  采风默认执行（无网时降级声明照旧）：
  1. 向用户声明："你提到了《X》《Y》——我先联网采风这两部作品的结构要素（约 5 分钟），采完给你看要点表，确认后拿它做设计参照。不想等就说'跳过采风'。"
  2. 用户说跳过 → 记录降级声明进创作进度附注，继续
  3. 用户不反对 → spawn moshu-researcher（结构采风，CF 票据登记）
  4. 采风产物回来 → 展示要点表 → 用户过目 → 按融合四步使用
  5. 采风产物回来后 → **融合四步在本 Stage 内执行完毕**（对照核心设定表→借用功能位→本土转译→方法论验证），产物直接喂 Stage 2 骨架设计——不留到后续 Stage 才消化。
  5b. **深度融合触发（B81）**：融合涉及 ≥3 个设定文件联动 → spawn researcher（type=caifeng-fusion，传采风产物路径+本书设定路径+设计需求）；轻量融合主会话 inline。
  6. **操作细则见采风手册**：检索策略 / 源七类 / 融合四步细则与 fallback 内联流程见 moshu-volume 侧 [caifeng-methods.md](caifeng-methods.md)。

轮 2（定形·AskUserQuestion 批，>4 问拆两屏连续问）：
问 A（体量三数）："这本书大概什么体量？"（总字数/总章数/分几卷一起问）
  → 不确定 → "先按 200 万字/5 卷规划，写完第一卷可以调"
问 B（平台）："目标平台？"（起点/番茄/晋江/其他，各选项带一句适配注解）
问 C（终局口径）："你要在动笔前设计好结局吗？"
  选项：完结（终局底牌+高潮定死，全书朝终点铺垫）｜开放式连载（升级台阶驱动、单元剧循环）
问 D【B53 新增】（情绪基调）："你想给读者什么感觉？"
  选项：爽文（打脸/升级/收获）/ 虐心（代价/牺牲/成长）/ 甜宠（治愈/日常/恋爱）/
        悬疑（解谜/反转/紧张）/ 燃（热血/友情/突破）——可多选，AI 融合
问 E【B53 新增】（更新频率）："预计更新节奏？"
  选项：日更 4000+ / 两日一更 6000+ / 周更 10000+ —— 影响章长/节奏/爆发密度
问 F【B53 新增】（禁区雷点，可选跳过）："有没有绝对不要的元素？"
  示例：不要后宫/不要虐主/不要系统流 —— 负面约束，比正面偏好更防翻车
所有答案落盘核心设定表「读者偏好」段。

轮 3（理想书评·创作确认）：
"方向和体量已定，现在给这本书定理想书评——想象一个完全读懂这本书的评论家，
为它写一篇溢美的书评。"
采集子问题（固化，不再即兴）：①你希望这本书给读者什么感觉？②参考书最吸引你的三个点是什么（如有）？
> **预填路径（B84，作者可用）**：如果作者说「说不太准/你按已有信息拟一版我来改」→ 跳过子问题采集，直接按已收集信号（轮 1 参考偏好+轮 2 定形+采风要素）生成理想书评草稿，进入「草稿→作者改定」流程。两问保留为可选深化，不作必答。
→ [作者描述]
→ AI 生成理想书评草稿 → 作者改定 → 落盘设定/
→ "好，这是你的理想书评——后面每一步都拿它当尺子。"

轮 4（定流程·AskUserQuestion 一问）：
"构建精细度选哪档？"
  🏃 快速（试水/脑洞文，先跑起来）
  🚶 标准（推荐——大部分网文，不确定选这个）
  🧗 完整（多线/强反转/群像）
→ 不确定 → 先标准档，写完第一卷觉得需要可以升级
→ 答完 → 创建最小创作进度（方法论声明仅档位一行、当前焦点＝Stage 1 核心设定落盘中、答案摘要记入已收敛区）
→ 核心设定表成稿展示作者过目 → 确认后落盘 设定/ 三文件 → 补全方法论声明（三域深度默认档位表，口头可调）

轮 4 后·虚拟对标合成（无对标时执行，有对标时跳过；细则见 moshu-volume 侧 [caifeng-methods.md](caifeng-methods.md)「第五步」）：
  前提：采风产物已回并过融合四步；`设定/题材定位.md` 已登记主对标 → 跳过本步
  主线程 AI 从多源采风产物提炼三类设计目标：
    ① 节奏目标：爆发密度区间 + 爽点循环模式 + 追读力锚点
    ② 情绪基准：核心情绪类型 + 交替模式 + 低压容忍 + 情绪禁区
    ③ 结构要点：中点设计模式 + 对手升级路径 + 伏笔密度参考
  有参考偏好时优先从参考作品的采风产物中提炼（定向），辅以同题材热门模式（泛化补充）
  落盘 `设定/虚拟对标.md`（固定三节模板）；CF 输入票据标「已消费·合成虚拟对标」
```

> 模板见 moshu-volume 侧 moshu-volume 技能的 virtual-benchmark-template——固定三节：节奏目标（爆发密度/爽点循环/追读锚点/更新适配）、情绪基准（核心情绪/交替模式/低压容忍/禁区）、结构要点（中点/对手升级/伏笔密度）。

## Stage 2·骨架构建 → 自动机检

## Stage 3·人物构建（自动）

> 方法论照常加载：moshu-outline 侧 [character-design-methods.md](character-design-methods.md) 苏式问句 / 升级绑弧光 / 人物主题卡；感情线结构模板。**虚拟对标情绪基准参照**（无对标时）。角色采风按需（产物命名与融合规程见 moshu-volume 侧 caifeng-methods.md）。角色卡含「对话 DNA」五要素（口头禅功能位/句长习惯/语气词与标点/回避话题/情绪外显）——有主对标时从拆文库角色卡带入作派（学结构不抄血肉），无对标留占位待填；write 侧语声锚消费此作派（B59）。

**产出**：每卷一段话（三幕+灾难）、每个角色一页（背景故事+弧线六阶段+大纲微调）、势力场总览回填精化、世界观完善、情绪引擎设计。不确定处标 ⚠️ 入创作进度（移交 volume Phase B）。

**人物设计评审（B77 缺口补全，可选触发）**：本步产出后可 spawn evaluator（eval_type=structure，对象=人物设计；target_paths=新角色档案+关系.md，related_paths=大纲/大纲.md 骨架段），报告呈报作者处置；agent 不可用则 fallback 主会话自评（对照三维度问句，标注 Fallback）。只呈报不拦截。
