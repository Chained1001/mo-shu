# 产物创建模板

各产物的标准模板与创建指引。agent 在 Stage 2-3 过渡时按需加载此文件。

**模板列表：**
- 设定/关系.md
- 设定/基本设定.md（含读者契约 + 终局底牌/升级台阶 + 对标登记字段；旧书名题材定位.md 读回退）
- 大纲/大纲.md（全书鸟瞰 + 全书体量与阶段总览）
- 大纲/卷纲_第X卷.md（含卷契约+终局储备+剧情单元+情绪弧线+反转规划）
- 追踪/_tracking-state.json（唯一结构化权威状态）
- 追踪/逐章记录/第NNN章.md（未来相关紧凑增量）
- 追踪/伏笔.md
- 追踪/时间线/作者真相.md + 读者已知.md（派生视图）
- 追踪/角色状态/{角色名}.md
- 追踪/上下文.md（续写状态卡，固定 7 栏）
- 对标/{对标书名}/拆文报告.md

**层级关系（全书 › 卷 › 剧情单元 › 章 › 情节点；故事线横向贯穿多个剧情单元）：**
- 大纲.md = 全书鸟瞰（每卷一两句话定位）
- 卷纲_第X卷.md = 单卷规划（剧情单元+情绪+人物+伏笔+反转）
- 细纲_第XXX章.md = 单章蓝图（单元ID/位置 + 主角目标/关键选择 + 内容概括 + 多线情节安排 + 人物关系/出场顺序 + 情节细化 + 结尾设定/钩子）

**概念对照（统一叫法，减少混淆）：**
- **剧情单元** = 一段完整剧情（1.5-3 万字/数章，一个矛盾从起到收）。拆书侧就是 `剧情/{剧情单元名}.md`，本书侧就是卷纲里的**剧情单元卡**；理论叫法是「一级结构」。同一粒度，统一叫剧情单元。
- **故事线**（`剧情/故事线.md`）= 贯穿多个剧情单元的线（主线/感情线/成长线/夺宝线…），比剧情单元大一层。
- 「循环」一词只在**节奏义**保留（爽点循环、升级循环、小/中/大循环等），不再指代规划单元。

```
│       │   └── 情绪模块.md         # 读者需求/情绪引擎 + 可复现模块（权威模块索引）
```

## 对标/{对标书名}/拆文报告.md

> **拆文库/对标关系**：`拆文库/` = analyze skill 的原始产出（数据源）。`对标/` = 写作项目的引用视图。首次引用时从 `拆文库/` 复制到 `对标/`。

此文件由 `moshu-analyze` 拆解管道输出（快速预览报告或完整拆文报告）。write skill 的职责是**读取**，不创建。

如需手动创建简版对标摘要（未使用 analyze skill 时）：

```markdown
# {对标书名} 对标摘要

## 基本信息
- 书名：{}
- 作者：{}
- 题材/类型：{}
- 目标平台：{}
- 成绩：{均订/在读/热度}

## 核心发现
- 开篇钩子：{类型 + 手法}
- 爽点密度：{约 N 字/次}
- 节奏模式：{描述}
- 可借鉴套路：
  1. {}
  2. {}
  3. {}

## 不建议模仿（禁止照搬）
- {}（只学结构，不抄桥段）
```

## 设定/基本设定.md

```markdown
# 基本设定（旧书名题材定位）

## 基本信息
- 题材类型：{玄幻/都市/系统/...}
- 目标平台：{起点/番茄/晋江/其他；moshu-review 据此选平台 rubric}
- 核心梗：{一句话卖点}
- 微创新点：{与同类题材的差异}

## 读者契约（参 `reader-contract-and-progression.md`）
- 核心读者承诺：{读者来追什么爽感/情绪/关系/事业}
- 主角代理权承诺：{主角不可替代的判断、关键选择或贡献}
- 利益安全线：{核心资产/卖点不得被没收、转赠、无交换暴露的边界}
- 期待债：{开篇/本卷已承诺，何时以什么形式偿还}
- 题材边界：{个人逆袭/群像/导师/制度合作等；高层级机构出现时先核对}

## 终局底牌与升级台阶（防写无可写；开书填一次，日更只查。参 `reader-contract-and-progression.md`「终局储备与推进节奏」）
- 终局底牌（一次性资源，标最早解锁卷）：头号宿敌={}·第{X}卷；终极真相/身世={}·第{X}卷；金手指上限={}·第{X}卷；身份/地位终点={}·第{X}卷；核心情感确定={无感情主线可删}·第{X}卷
- 升级台阶：主体系{境界/等级/地图/势力层级}共{N}档 × 每档约{W}万字 应 ≥ 全书目标字数（不足则拉长体系/加地图层）；敌人/目标成梯队逐级解锁，禁止越级秒顶级
- 透支红线：① 未到解锁卷就动用终局底牌 ② 某条升级线逼近天花板、后面没台阶接

## 创意约束（防金手指万能化；开书填一次，写章/审查对照。借鉴 v7「创意约束」）
> 金手指/优势必须带边界，否则故事失去张力。逐条勾选适用的约束（不适用删行），可自定义补充。细纲「契约风险」行与 review 审查按此表核对金手指使用是否越界。

- [ ] 不可逆代价：{使用金手指的代价是什么，是否可逆}
- [ ] 不存在无损选择：{每个选择都有代价，无两全}
- [ ] 优势带可利用弱点：{金手指的弱点/限制，敌人可利用的缺口}
- [ ] 信息有限且会失效：{主角掌握的信息有边界、会过时}
- [ ] 成功解法会被适应：{同一招数会被敌人/世界适应}
- [ ] 收益同步扩大风险：{收益越大，风险/代价越大}
- [ ] 条件触发窗口：{金手指有触发条件与窗口期}
- [ ] 核心优势可竞争：{优势可被他人模仿/针对/夺走}
- [ ] 核心问题不可由优势直接解决：{最终难题不能靠金手指平推}
- [ ] 知识转化有门槛：{获得的信息/能力需要消化与代价}
- 自定义约束：{...}

## 核心梗三分法
- 表层卖点：{读者一眼看到的吸引力}
- 深层爽点：{持续追读的情绪驱动力}
- 长线钩子：{支撑全书的悬念/目标}

## 信息差登记（防泄密；v7 单条登记法）
> 每条信息差一行：谁还不知道、读者知不知道、用什么关键词触发。写章时本章出场角色的知识边界按此表核对（细纲「视角/信息差」行引用 ID）；正文不得提前泄露表中「读者已知=否」的信息。

| ID | 信息差内容 | 知情人 | 读者已知 | 关键词/触发 |
|----|-----------|--------|---------|------------|
| INF-001 | {主角身份真相} | {主角本人/某角色} | 是/否 | {正文出现即触发的词} |
| INF-002 | ... | | | |
```

## 大纲/细纲_第XXX章.md

细纲是正文写作的章节蓝图，而不是只列事件和钩子的清单。**模板唯一权威副本**见 [outline-workflow.md](outline-workflow.md#细纲全书每章) 的「细纲（第 N 章）」模板（含单元ID/位置、主角目标/关键选择、任务卡点、结构公式、契约风险行、密/疏字数预算与「预算合计」行）；本文件不再保留模板副本，避免双模板漂移。新建、补建、回填都按权威模板补齐，未知字段写 `[待补充]`，不要为了补齐字段杜撰副线或人物关系。契约/推进字段只加在章纲摘要层，长规则统一参 `reader-contract-and-progression.md`。

## 追踪体系

追踪产物由 `scripts/tracking_commit.py` 统一生成，完整 schema 和事务字段见 [tracking-transaction.md](tracking-transaction.md)。以下文件不得由模型各自追加或局部 Edit：

### `追踪/_tracking-state.json`

唯一结构化权威状态。记录 schema、最后提交章、导入截止章、`state_revision`、续写上下文结构，以及全部角色、伏笔和时间线当前状态。日更通过 `tracking_commit.py check` 的紧凑输出取章号和修订号，不把完整 state 加入正文 prompt。所有 Markdown 都从本文件确定性派生，程序不反向解析 Markdown。

### `追踪/逐章记录/第NNN章.md`

本章未来相关连续性记录，目标 ≤1536 字节、硬上限 3072 字节，只含：实际结果、角色变化、伏笔变化、时间/揭示、连续性约束、下一章承诺。过程日志、质检统计、参照章和提示词记录不进入。它不承诺单独无损重建全部当前状态；完整当前语义以 `_tracking-state.json` 为准。

### `追踪/伏笔.md`

每个 ID 只保留一行当前状态：内容、埋设章、计划回收章、状态、重要度、最近变更章。变化历史由对应逐章增量承担。尚未实际埋设的未来伏笔规划留在大纲；当前表只接受 `已埋 / 已回收 / 已过期 / 放弃`。

### `追踪/角色状态/{角色名}.md`

只为核心、会复用角色建立动态快照，含截至章节、身份、位置、当前目标、身心状态、能力资源、关键关系、已知信息和未结事项。目标 ≤4096 字节、硬上限 8192 字节；超过目标先合并失效能力、旧关系和已结事项，不把角色履历塞进当前快照。静态原始人设仍在 `设定/角色/{角色名}.md`；路人、一次性角色不建动态文件。

### `追踪/时间线/`

- `_tracking-state.json.timeline`：同一事件登记故事时间、客观事实、读者当前认知、实际揭示状态/章节。
- `作者真相.md`：从 `_tracking-state.json.timeline` 派生，作者侧可见全部客观事实和认知差。
- `读者已知.md`：从 `_tracking-state.json.timeline` 派生，只显示读者已经知道/相信的内容，不泄露客观真相。

未来揭示计划写卷纲/细纲，不写进既成事实登记；`未揭示` 事件的 `reveal_chapter` 必须为空。

### `追踪/上下文.md`

续写状态卡不超过 12288 字节，固定 7 栏：`当前位置 / 长期约束 / 核心角色状态 / 活跃伏笔 / 近三章速记 / 下一章承诺 / 连贯性风险`。它是当前视图之一；不放文风、质量计数、普通待办、索引统计和长期概要。
