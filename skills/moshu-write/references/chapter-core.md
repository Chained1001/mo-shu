# chapter-core.md：单章写作共享内核（写前准备 → 正文 → 机检收尾 → 事务提交）

> 本文件是「写一章正文」的完整内核，逐章写作（workflow-daily）/改稿（workflow-revision）两条车道共用——写前准备 (A)、正文执行与字数验收 (B)、确定性收尾 (C)、追踪事务提交 (D) 四段各一份真源，改一处三车道同步生效。车道差异（批次控制/级联检查/工单处置）在各车道的薄壳文件里。
>
> **落笔技法取用走 [writing-craft.md](writing-craft.md)「决策路由：写作技法总入口」**——写对话/打斗/钩子/情绪/场景等按任务查路由，不凭记忆散取。

## A 段：写前准备

> **分级声明（B95）**：批首章全量 A（现状 A1-A4）；**批中章轻量 A'**=①本章细纲②上一章结尾段③点名清单增量（新出场/久别角色状态）④**三个每章差异项**——按本章情绪从已加载情绪模块选 `selected_emotion_module`、按本章基调挑匹配章 K、按本章定位路由场景卡；文件级加载（情绪模块/节奏/文风/题材卡/对标产物）批级复用不重读；批末 K>1 跑跨章核对（车道 D3）。单章车道（K=1）即批首=批末，天然全量。


### A1 检查细纲

读取 `大纲/细纲_第{N}章.md`，并从对应 `大纲/卷纲_第X卷.md` 读取当前剧情单元（单元ID/位置、卷契约、本卷主推线/战果、终局底牌边界、风险等级）。如果不存在或缺少当前章节蓝图的必需字段，**必须先补建细纲再写正文**，不允许跳过细纲直接写作。补建时**补齐 write 侧 outline-workflow「细纲（第 N 章）」模板全部必需字段**（B94：不再内联字段清单——模板为字段真源）；无法从已有证据判断的字段写 `[待补充]`，不杜撰副线或关系。

**细纲缺失补建流程（B95 自车道归位，core 唯一完整版）**——细纲不存在时按以下步骤补建：

1. 加载 `大纲/卷纲_第{N}卷.md`（本章对应的事件规划），读取本章所属剧情单元卡；含「对标剧情参照」时加读其指向的剧情单元文件（1 个），以其「结构分布」对应位置作本章功能参照；若本章起整个剧情单元均无细纲，按 outline-structure-theory.md「按剧情批出细纲」整批补建而非单章补。卷纲缺必需字段时先补齐，不绕过当前模板继续
2. 加载本章涉及的 `设定/角色/{角色名}.md`（角色状态）
3. 读取最新一章正文（情节衔接）
4. 按 [outline-workflow.md](outline-workflow.md)「细纲（第 N 章）」模板补建本章细纲，补齐阶段位置、本章结构公式、本章禁止提前释放、内容概括、情节安排、人物关系/出场顺序、情节细化、结尾设定；无法从卷纲/正文/设定确认的字段写 `[待补充]`，不杜撰
5. 补建完成后继续写作

### A2 读取上下文

（按需选择；缺失时遵循下方「写前准备契约」的「缺失文件处理」，仅明确标为可选的非主产物跳过。**快捷路径（已部署则优先，节省主会话上下文）**：如果项目已部署 moshu-explorer agent（部署判定见 /moshu-setup），spawn `Agent(subagent_type: "moshu-explorer", prompt: "项目目录：{dir}\n查询类型：context_load\n查询参数：准备写第 {N} 章\n追踪状态：last_committed_chapter={check 的值}，state_revision={check 的值}")` 一次获取上下文，返回不完整时回退到下方手动加载）：

- (1) `正文/第{N-1}章_*.md` — 上一章正文
- (2) `大纲/细纲_第{N}章.md` — 本章细纲（含钩子设计）
- (2a) `大纲/卷纲_第X卷.md` — 当前剧情单元、卷契约与终局储备（主推线/战果、终局底牌边界）
- (3) `tracking_commit.py check` + `追踪/上下文.md` — `check` 无 ERROR 输出即通过，从它的紧凑 JSON 取 `last_committed_chapter` / `state_revision`，不把完整 state 加入 prompt；待回收伏笔取 `## 活跃伏笔`，角色当前状态取 `## 核心角色状态`，下一章硬承诺取 `## 下一章承诺`
- (4) `设定/角色/{相关角色}.md`、`设定/势力/{相关势力}.md`（如存在）— 本章涉及的角色与势力（按细纲出场筛选）
- (5) 对标书路径下 `拆文报告.md`（按对标书路径查找）— 对标参考
- (6) `参考资料/{topic}.md`（如存在）— 历史研究资料（由 moshu-researcher 产出）
- (7) 对标书路径下 `剧情/故事线.md`（按对标书路径查找）— 剧情单元索引，用于确定本章涉及哪些剧情单元
- (8) 对标书路径下 `剧情/{相关剧情单元}.md`（按对标书路径查找）— 从索引中选择与本章相关的剧情单元文件
- (9) 对标书路径下 `设定/世界观/*.md`（glob，按对标书路径查找）— 从当前拆文产出的主题化设定中获取参考；目录缺失则记录缺口并跳过本项，不读取扁平历史路径
- (10) 对标书路径下 `剧情/情绪模块.md`（按对标书路径查找）— 读者需求 / 情绪引擎、爽文套路框架、可复现模块；缺失按下方「写前准备契约」的「缺失文件处理」设置 `missing_primary_contract` 并停止准备
- (11) 对标书路径下 `剧情/节奏.md`（按对标书路径查找）— 关键信息推进、情绪触动点、爆发节奏；缺失按下方「写前准备契约」的「缺失文件处理」设置 `missing_primary_contract` 并停止准备
- (12) `设定/题材正文提示卡.md`（如存在）— 正文层题材卡；缺失时按 A3(c) 题材卡召回生成 `genre_prose_card`（不阻塞写作）
- (13) `设定/题材定位.md` 信息差登记表（如存在）— 本章出场角色的知识边界：细纲「视角/信息差」引用的 INF-ID 对照「知情人/读者已知」，正文不得泄露「读者已知=否」的信息

### A3 写前准备四步（状态筛选 → 本章设定包 → 模块召回 (a)-(g) → 指令确认）

- **状态筛选**：读续写状态卡 `追踪/上下文.md`，**以「本章点名清单」节为加载清单**（B58/B59：出场角色的 `追踪/角色状态/{名}.md`（含近作台词节，写作前读）、涉及设定与「出场称谓」行；背景项不读；未分层的旧项目照旧整节全读）。从「## 核心角色状态」「## 活跃伏笔」「## 下一章承诺」取本章所需，输出本节速记。**数值正本优先级（B62）**：数值类事实（境界/欠款/排名/资产等）冲突时仲裁序 = 追踪 state > 细纲 > 正文回忆——不信自己刚写的数字。**点名清单预算判定行出现降级时**，被降级角色按其硬状态行写作、不得虚构超出硬状态的细节。**剧透锁（B58b）**：信息差条目带🔒标记时，正文不得提前揭示其内容。续写状态卡或 meta 缺失时按 workflow-daily 协议处理，不手写替代
- **本章设定包（减法加载）**：从细纲提取本章涉及的角色/地点/组织/物件名，只读 `设定/` 下这些具名文件；不读全量目录。拿不准是否相关时保守保留，不猜；判断以细纲「人物关系和出场顺序」「情节安排」为准。
  - **权威加载声明**：减法加载的清单以细纲「本章涉及设定」字段为权威——该字段列出的文件必读；未列出但细纲正文提及的，保守加载（拿不准就保留，不猜）。
- **模块召回、题材卡与文风召回**：
  - ① 本章目标情绪词？② 借鉴哪个参考文件的哪个技法？③ 用在哪些段落？答不出 → 先回读参考再动笔
  - (a) **情绪模块召回**：**无对标**（`设定/题材定位.md` 未登记主对标书且 `对标/` 为空）→ **若 `设定/题材定位.md` 含「成品标尺」节则情绪目标从其「情绪基准」节取（核心情绪/交替模式/低压容忍），`selected_emotion_module` 记「成品标尺」；标尺节缺失且存在旧 `设定/理想书评.md`/`设定/虚拟对标.md`（B94 前产物）时读旧文件并注明来源世代（缺文件/空文件/内容坏三分类显式声明）；皆无时**情绪目标从本书细纲「目标情绪」、卷纲、`设定/题材定位.md` 取，`selected_emotion_module` 记「无」，不 fail-fast（合法无对标模式）。**有对标** → 按「对标书路径查找」规则读 `{对标书路径}/剧情/情绪模块.md`，选出 1 个与本章目标情绪最贴近的 `selected_emotion_module`（读者需求、触发器、戏剧单元、可替换要素、反抄袭提醒）。缺失时设置 `missing_primary_contract: true`，返回明确 `repair_action` 后停止准备
  - (b) **节奏召回**：**无对标**（同上判定）→ **若 `设定/题材定位.md` 含「成品标尺」节则节奏目标从其「节奏目标」节取（爆发密度/爽点循环/追读锚点），`rhythm_reference` 记「成品标尺」；标尺节缺失且存在旧 `设定/虚拟对标.md` 时读旧文件并注明来源世代；皆无时**节奏目标从本书卷纲节奏/细纲目标情绪取，`rhythm_reference` 记「无」，不 fail-fast。**有对标** → 读 `{对标书路径}/剧情/节奏.md`，选出 1 条 `rhythm_reference`（关键信息 → 扩写技法 → 情绪触动点 → 爆发/冷却）。缺失时设置 `missing_primary_contract: true`，返回明确 `repair_action` 后停止准备
  - (c) **题材正文提示卡召回**：优先读 `设定/题材正文提示卡.md`；缺失则先读 `设定/题材定位.md` + `references/genre-prose-cards.md` 索引，按主题材精确匹配后只读取 `references/genre-prose-cards/` 中对应单题材卡（如 都市脑洞 / 豪门总裁 / 年代 / 双男主；低置信卡必须在意图确认标注低置信，并要求同题材对标校准），无命中再读 `references/style-genre-modules.md` 通用流派模块。跨题材时主题材抽 3-5 条、辅题材抽 1-2 条，生成短 `genre_prose_card`（题材边界、核心逻辑、读者期待、核心爽点/情绪、正文落点、前中后期打法、节奏密度、场景颗粒、禁止漂移、本章取舍、卡片置信度）。题材卡只约束正文层题材味，不改细纲剧情、不覆盖 `selected_emotion_module` / `rhythm_reference` / `文风库/文风.md`；只在内部校准取舍，正文里不得出现卡名/标签/置信度/条目/合规自评
  - (d) **文风召回**：读 `文风库/文风.md`（moshu-style 产出，**唯一来源**；目录/文件不存在视为无文风）。**两级检查**：① 文件存在性；② 内容合规性（非空/非占位 stub、生成记录 `文风可用：是`、锚点 ≥1 段——锚点是 few-shot 核心）。存在且合规 → 提取句长带/标点习惯/段落节奏/对话技法/词汇指纹/锚点片段作为风格基准（`style_profile_path = 文风库/文风.md`）。缺失或不合规 → **交互提醒**（AskUserQuestion）：「当前项目没有可用文风（`文风库/文风.md` 缺失或不合规）。文风是正文风格基准（句长/标点/对话/锚点），缺失时写作将退回默认 Gate——AI 腔风险上升。」选项：**用 /moshu-style 生成**（执行后继续本章）/ **跳过，用默认 Gate 写**（本章继续，报告记录 `文风缺失`，下一章写前再次提醒）/ **自写约束**（粘贴约束，或直接 /moshu-style 学习自己的文风）。**不静默**：每章写前都检查，跳过也要记录；情绪 / 节奏轴 `missing_primary_contract` 独立，不受文风缺失豁免。**锚点按场景选路（B56）**：文风.md 的锚点片段如按场景标注（B49 四场景：战斗/对话/情绪/过渡），按本章「章节定位」选对应场景的锚点优先传入 narrative-writer——高压/修炼试错 → 战斗锚点；关系回收 → 对话锚点；低压生活 → 情绪+过渡锚点；普通推进/信息整理 → 全部锚点（不强选）。锚点未按场景标注时不选路，整体传入（向后兼容旧文风文件）
  - (e) **匹配章节挑选**：从 `{对标书路径}/章节/*_摘要.md` grep `基调：(紧张|轻松|悲伤|热血|爽|甜|温馨|恐怖|压抑|其他)`（全角冒号），按本章目标情绪挑章 K——多章同基调时选择规则：先看爽点类型是否接近，再看情节点数量/原文章节估算字数是否接近本章目标字数，最后取章节号最小者；必读 `{对标书路径}/章节/第K章_摘要.md`，若同章存在 `第K章_深度拆解.md` 则加读，否则回退黄金三章深度拆解/拆文报告里的写法技巧，不因非黄金三章缺少深度拆解而失败。**对标原文不按章加载**（旧加载项已移除——对标原文是单文件且拆解不落物理分章）；需要"看原文怎么写"时以 `文风库/文风.md` 的锚点片段（逐字连续切片）为准
  - (f) **结构化模块召回**：从对标的结构化子目录（角色/剧情/设定）中按本章情节检索相关模块；若与 `剧情/情绪模块.md` / `剧情/节奏.md` 冲突，权威文件优先，记录 `conflict`
  - (g) 输出"主对标召回摘要 + selected_emotion_module + rhythm_reference + genre_prose_card + 文风召回指令 + 原文锚点片段引用"，作为 moshu-narrative-writer 的输入。
  - (h) **场景卡召回（按章节定位+情节点功能标签路由，B56）**：读细纲「章节定位」字段（六值），按下方映射预载对应写法卡（按需读取不整文件加载）：

    | 章节定位 | 预载写法卡 | 激活 cards.md 技法卡 |
    |---|---|---|
    | 高压 | style-combat-face.md | ③爽点后停顿 + ⑥名场面变奏 |
    | 普通推进 | writing-craft.md「节奏与句式」节 | — |
    | 修炼试错 | writing-craft.md「成长弧线描写」节（如有）| — |
    | 关系回收 | dialogue-mastery.md | ①多人锚点沉默 |
    | 低压生活 | writing-craft.md「感官与氛围」节（如有） | ②高压嬉笑托底 |
    | 信息整理 | — | ④证据投放顺序 |

    同时读情节点功能标签：标签含「反转」→ 追加 ⑤不可靠叙述；标签含「爽点」→ 追加 ③（可能重复激活，不重复加载）。章节定位留空按「普通推进」处理（细纲规则已有此默认）。预载的卡内容生成 `scene_writing_refs`（短摘要），传入 B 段 spawn prompt。
  - **快捷路径**：项目已部署 moshu-explorer agent 时，可一次性召回文风/模块材料。
    - 检查 moshu-explorer 是否已部署（部署判定见 /moshu-setup）。
    - 查询类型：`benchmark_style_load`；传入项目目录、章节号、目标基调/字数和爽点类型。
    - 需要返回：`style_profile_path`、`style_profile_summary`、`selected_emotion_module`、`rhythm_reference`、来源路径、匹配章节、锚点片段、`gaps`。
    - `gaps.missing_primary_contract` 为 true 时先按 `repair_action` 修复，不进入正文生成。
    - 主会话只做文风**存在性**检查（`文风库/文风.md` 存在即过，不整读文件）；内容合规性由 explorer 返回的 `gaps.profile_degenerate` 承载（true = 文风不可用，按 (d) 交互提醒）；explorer 返回不完整或不可用时回退手动 (d) 全流程。不豁免情绪/节奏缺失。
- **指令确认**：综合细纲、本节速记和模块召回结果，用一句话写清本章意图。
  - 新版细纲必须消费：阶段位置、单元ID/位置、主角目标/关键选择、结构公式、禁止提前释放、内容概括、情节安排、人物关系/出场顺序、情节细化、结尾钩子，并对照当前剧情单元的卷契约、本卷主推线/战果、终局底牌边界。
  - **细纲优先边界**：正文只能展开本章细纲已有事件、人物、冲突、伏笔和结尾钩子；不得为了凑字或"更精彩"自造新主线、新角色、新反转、提前写后续章剧情，必要的过渡动作只能服务于细纲已列情节点。后续阶段真相、底牌、关系结论和终局矛盾不得因为章尾钩子提前泄露。反过来，细纲是"要发生什么"的契约、不是正文的形状：正文可自由编排叙述顺序、合并/穿插情节点，不必一个情节点一段、也不必按五段式顺写，把每个点演成场景而不是照抄概括语（见 writing-craft.md「从细纲到正文」）。
  - **细纲语义去重**：同一要求在核心事件、五段式、情节安排和情节点中重复，只算一个语义点；生成前合并，不把重复次数当强调，不沿用提纲原句逐项复述。比如多处都写“不带摄像机、先听完再决定拍不拍”，正文只通过一个自然动作或一句人物判断兑现，不能拆成「至于拍不拍，怎么拍…」「不带摄像机，不带采访灯」两轮说明。
  - 爽点出手前要有可指认的危机/期待铺垫；装逼/打脸/揭露章要写在场配角的差异反应。
  - 高压/生死/悲痛节拍 要收紧对话声线：搞笑担当让位，信息型角色不当科普嘴，对话逐句承接对方情绪。
  - 检查任务卡点：本章如果有“办事被卡住”，它必须卡出信息、关系、代价、选择或伏笔变化；没有就不强补。
  - 契约风险检查：按 `references/reader-contract-and-progression.md` 判定 契约安全 / 需补强 / 契约破坏；若高光/收益被配角、机构或偶然性拿走且没有可见交换，先修纲再写。
- 例：「快节奏打脸——账单暴露→逼问→反证→公开代价；读者等了三章，这章必须一拳到位。」

### A4 资料研究（按需）

如果写作中遇到需要查证的外部事实（历史年代、地理方位、职业细节等），如果项目已部署 moshu-researcher agent（部署判定见 /moshu-setup），spawn `moshu-researcher` agent 搜索并输出到 `参考资料/` 目录。如 agent 不可用，由主线程直接执行。研究完成后再继续写作。

## B 段：正文执行（三遍法——快写/读者重读/技艺打磨）

> B 段接口：A 段写前准备 → 三遍法 → C 段确定性收尾，对外接口不变（A→B→C→D 车道结构不动）。三遍帽子与模式切换见下方认知哲学。check-prose-candidates 只在第 3 遍后（C 段时机）跑一次；第 1 遍不跑（快写不打断）。
>
> **批内时序（B95）**：C 段以遍 1 落盘后为准（含机检修复预算；追踪事务 D 段照旧每章写完立即提交——追踪与毒句式不隔夜）；第 3 遍后仅补 check-prose-candidates+字数复验；Sanderson 连续快写（先连写各章遍 1 再统一第 2/3 遍）**可选不默认**，默认逐章三遍。
>
> **认知哲学（B79——先想清再动笔，先动笔再挑剔）**：三遍法底层=创作与评判分离，两种脑模式互斥，混一起两种都做不好。
> - 第 1 遍创作模式：快、不挑剔、允许烂、跟细纲走；不带评判帽、不自我审查——写出来是唯一目标。
> - 第 2 遍读者模式：以文件为起点（重读落盘正文，不凭记忆续），读者眼光查「哪里读不下去」——工具见四查（含 B78 紧张程度表/代价检查）。
> - 第 3 遍技艺模式：用技艺工具打磨（过滤词/系动词/比喻禁忌/距离推拉——writing-craft「0. 落笔五技」节，B99），一次磨一个维度；段落微张力+章级钩子按需加载 hooks-chapter（含段落级微张力节，B99）（微张力管段间不停滑，章尾钩管翻章，B92）。
> - 模式切换物理标记：第 1 遍完→落盘→跑 C 段机检（间隔=释放创作上下文）→第 2 遍从文件读起。

### B0 标题预检

写正文前从细纲读取章名；如与既有章节同名或明显重复，先按本章核心事件改名，并同步细纲标题与正文文件名。**完结章（B70）**：末卷终章写前先读 `追踪/完结清账.md` 未清零项，逐一在终章回收或经作者标注留白（大纲/完结宣告.md）——收束清单按细纲「完结章」形态执行。

### 第 1 遍·快写（创作帽）

> **帽子**：创作帽——本遍只从创作者视角工作，不回头审视。
> **方法论书**（先读后操作）：大师课 7 章（场景四和弦）+小说写作 6 章（因果链）+大师课 11 章（尽快写完初稿+抗拒回改）+骨架 9 章（扩展版提纲→初稿）。
> **输入**：A 段上下文（细纲/设定/文风/状态卡）。
> **产出**：完整故事骨架+鲜活对白。
> **禁止边写边改**；注水/无限堆爽点。
> **卡片**：beat-cards（细纲结构公式引用的 BC-ID，快写时按节拍卡铺场景）。
> **写前判型（B80，来自场景表/细纲的「场景类型」列）**：本章主场景是主动型（目标→冲突→挫折）还是被动型（反应→困境→决定）？主动型按目标驱动写快节奏；被动型按困境选项逐一击毙写内心戏。判型是写前动作，不是写后归类。

0. 【上下文隔离铁律】从本遍开始，你只以以下文件为写作依据：
   - 大纲/细纲_第N章.md（本章蓝图——唯一执行依据）
   - 设定/（本章涉及的角色/地点/物件）
   - 文风库/文风.md（风格基线）
   - 追踪/上下文.md（续写状态卡）
   不参考、不回忆建细纲时的规划讨论——细纲是唯一的执行依据。
   （设计依据：v7"干净上下文"哲学——写稿时只看备料产物，不看规划过程）
1. 读细纲（A 段已加载）——确认本章结构公式（含 BC-ID 引用，按 beat-cards 铺场景）。
2. 快写：
   a. 跟着细纲的情节序列走（密/疏标注对应展开/带过）；
   b. 对话优先——先写对话骨架，再补动作/描述；
   c. 内心独白允许（角色思考）；
   d. 每个场景转换问"因为什么？"（因果链，不是"然后"）。
2b. **按本章场景类型调整笔触**（B56）：高压章短句快切少环境描写（信息密度高），低压章长句舒缓多感官细节（情绪沉浸），关系章对话优先动作辅助，信息章整理条理不堆砌。
3. 【禁止】边写边改——写完一段就往下走，不回头润色。
5. 【允许】微型探索——不确定的写法先写一版（后续遍可改）。
6. 字数不够 → 继续推进情节（不注水）；字数超了 → 先不停（第 3 遍精确控制）。
> **创作模式纪律（B79）**：第 1 遍禁止自我评判（好不好是第 3 遍的事）；禁止边写边改；字数不够继续推进情节不注水；卡文先查规划缺环（B80 归因法）不硬写——写出来是唯一目标，好坏留给第 2/3 遍。
7. **卡文阻塞协议（B63）**：同一情节点尝试 3 种写法仍不满意 → 显式标记**阻塞**停笔，向作者上报：三版要点对比 + 卡点分析（卡在哪：情绪不到/逻辑不通/节奏不对/素材不够）+ 三选项（换写法 / 改细纲 / 先写下一章回头再攻）。**不得自作主张跳过、注水或降标准续写**——阻塞不是失败，硬写才是。
> **卡文归因（B80）**：卡文先查细纲/场景规划缺环（目标未定/冲突未设/判型未做），缺环补规划而非硬写（雪花法 Ch.18 归因法）。

**执行方式**：先查 moshu-narrative-writer 是否已部署（判定见 /moshu-setup）；可用则 spawn `Agent(subagent_type: "moshu-narrative-writer", ...)`，prompt 只传**本章增量数据**（≤12 项，流程规则由模板承接 B75a）：

1. 项目目录+章节号+细纲文件路径+上一章结尾段+输出路径（基础 5 项）
2. `selected_emotion_module`+`rhythm_reference`+来源路径
3. `genre_prose_card`（≤300 字精华）
4. 出场角色名单+语声锚文件路径+称谓行（B59）
5. 场景类型（B56 一词）+重点密点功能标签
6. 场景文风锚点片段（few-shot 优先用）
7. 字数目标+情节点预算合计
8. 本章禁止提前释放条目编号（如有）
9. 本章承诺（next_chapter_commitments 相关项）

agent 输出写入 `正文/第XXX章_章名.md`。如 agent 未部署，由主线程直接写作。

**第 1 章特殊规则**：内心戏/设定认知/独处开场必须先把内心变化外化为可见事件（决定/误判/对话/物件变化/外部压力）再展开；不得大段心理独白凑字。低于目标或代入感偏薄→回细纲补子事件/对话交锋/选择代价，不补解释性内心戏；任务卡点只在能卡出信息/关系/代价/选择/伏笔变化时用。

**正文元信息隔离**：`章节：第{N}章`、`上一章：正文/第{N-1}章_*.md`、`匹配第K章`、`细纲文件` 等只用于定位材料。标题行以外的正文不得出现 `第[一二三四五六七八九十百千万两0-9]+章|上一章|上章|前一章|本章|这一章|前文|后文|伏笔|细纲|读者` 这类写作工程词。需要承接前文时，改成角色能感知的事件锚点或相对时间，例如“比第一章那三秒开火更疼”必须写成“比那三秒开火更疼”。例外：角色在故事世界内真实阅读/讨论“第X章”文本，或真实身为作者/读者并谈论读者身份时，可保留相应词。

**认知边界纪律**：细纲「视角/信息差/认知边界」声明的主角不知道信息，正文不得让主角知道，也不得经旁观镜头/系统面板/他人对话泄露；「信息留白」处只写可观察现象，不写动机/因果。旧细纲未声明时从「视角/信息差」行与题材定位 INF 表推断，推断不出按只写主角可观察/可知范围保守执行。

### 第 2 遍·读者重读（读者帽）

> **帽子**：读者帽——放下作者身份，假装第一次读这章的读者。
> **方法论书**（先读后操作）：大师课 11 章（重新体验+LOCK）+9 章（弧线节拍）+小说写作 6 章（冲突三层）+3-4 章（直接表现六法）+**10 章（修改——把自己当读者重新体验，B56 补）**。
> **输入**：第 1 遍快写稿。
> **产出**：读者体验完整的章节。
> **禁止**：大改结构（不动细纲架构）；跳过检查项。

1. 放下作者身份——假装你是第一次读这章的读者。
1b. **按场景类型选重点查**（B56）：高压章先查节奏（b/c）再查角色（a/d），关系章先查角色辨识度（d）和冲突（b），低压章先查流畅性（查全段是否让人想跳过）。
> **读者模式进入（B79）**：先把正文文件重读一遍（不凭刚才的记忆续——**从文件读起**），以挑剔读者自问「哪里想跳过？哪里不信？哪里感受不到？」（机制见 [reader-psychology.md](reader-psychology.md)）——再用下方四查结构化定位。
2. 四项检查（每项标记 ✅/⚠️/❌；每条后附苏式表态问，答不出 = 该项不过）：
   a. LOCK 四查（章节级）：主角有趣吗？目标清楚吗？冲突够强吗？结尾有冲击吗？**追问：如果不有趣，是因为{____}（无欲望/无困境/无反差）？答不出说明主角设定不锐。**
   b. 冲突三层：每场景至少一层冲突？只有外部没有内心=标记"扁平"。**追问：找出全书最平的一个场景，它存在的理由是{____}？删掉后读者损失了{____}？两者都答不出=该场景不该存在。**
   c. 弧线推进：本章角色有变化吗（认知/情感/关系）？无变化=标记"停滞"。**追问：变化的证据是{____}（一句话/一个选择/一次情绪波动）？没有任何证据=标记停滞。**
   d. 角色辨识度：遮住名字能认出谁在说话吗？全靠对话/行为/心理区分。**追问：挑一段双人对话逐行标注是谁说的；标不出=对话无个性，需重写。对照语声锚与称谓（B59）：换个人说还成立吗？成立=无语声个性；A 称 B 与点名清单登记漂移=改回。**
4. 修改（针对 ⚠️/❌ 项）：
   a. 补感官细节——视觉/听觉/触觉/嗅觉（读者能"看到"场景吗？）；
   b. 加强情绪拍——关键情绪节拍有没有"落到具体动作/画面"？
   c. 修弱过渡——场景切换是否生硬？加一句桥接；
   d. Show don't Tell——"他很愤怒"→"他的手指关节发白"。
5. 【禁止】大改结构——不动细纲架构，只改表达层。
6. 爽点复核（原 B5 拆分）：① 爽点出手前是否有可指认的危机/期待段落（指到具体情节点）？指不出=空洞 → 补铺垫情节点（plot-emotion-system 倒推法）；② 装逼/打脸/揭露章，在场配角是否写出差异化反应（集体震惊/各异）？没有 → 补在场配角反应（plot-core-methods）。

### 第 3 遍·技艺打磨（技艺帽）

> **帽子**：技艺帽——换工匠视角逐段打磨表达。
> **方法论书**（先读后操作）：大师课二册 4/8/9 章（对话三查）+小说写作 1-2 章（Show, don't Tell）+7 章（叙述视角）+**8 章（潜文本/副语言/节奏控制，B56 补）**。
> **输入**：第 2 遍修订稿。
> **产出**：定稿正文 → 进 C 段。
> **禁止**：改故事内容（只打磨表达，不动情节）；过度打磨（改味保护：不得整段重写）。
> **卡片**：hooks-chapter（章首/章尾钩子 14 式）+ 文风库/文风.md（文风偏差基线）+ genre-prose-cards（题材调性）。

1. **按场景类型选磨序**（B56）：高压章先磨节奏（b）+钩子（c/e）再磨对话（e），关系章先磨对话（e）+情绪（d），低压章先磨文风（a）+描写质感。
> **技艺模式进入（B79）**：选**一个**维度集中磨（本章最弱的——节奏？对话？描写？），用 writing-craft「0. 落笔五技」节具体工具操作，不贪多维度同时磨。
> **与文字打磨路的内部分界（B95，deslop 收编后）**：第 3 遍管「写得对不对味」（文风偏差/句式节奏/章首尾钩/对话动力+修剪，五磨不动）；「像不像 AI」的深度清理（去 AI 味）走改稿·文字打磨路（workflow-revision 文字打磨路，D6 执行体）。
2. 五项打磨（逐段进行；每条附苏式表态问，答不出 = 未完成该项打磨）：
   a. 文风偏差：与文风库基线对照——句长/标点/段落节奏偏离了吗？**问：本章偏离基线最多的三句是哪些？逐句改到基线带内——改完读一遍，还像同一个人写的吗？**
   b. 句式节奏：密场景短句快切（beat-cards 参考）？疏场景长句舒缓？**问：本章最平的一段是哪里？把它变锐的最小改动是什么——删一句/加一个具体细节/换一个动词/埋一个反讽？**
   c. 章首钩子：开头 3 句能否抓住读者？（hooks-chapter 选合适类型）**问：开头三句能让读者不划走吗？自己都觉得平，读者为什么会继续？给出不可拒绝的理由或重写。**
   d. 章尾钩子：结尾是否留悬念/未答问题/情绪余韵？（对照细纲"结尾设定"）——每章结尾都要有让读者想翻下一页的东西（低压/过场章弱钩子或留阶段目标即可）。**问：读者合上手机的理由是什么？——答不出"下一章会发生什么"，钩子没建立。**
   e. 对话动力：每段对话删掉后故事受损吗？不受损=删或压缩。**问：找一段删掉无损的对话，删或压缩到一句——对话要么推动情节、要么揭示人物，两者都不做=装饰品。**
3. 修剪：
   a. 删冗词（"非常""很""开始"等多余修饰）；
   b. 砍重复意象（同一意象出现 ≥3 次且无递进=砍）；
   c. 压缩过场（细纲标"疏"的段落，40 字内带过）。
4. 字数验收（跨平台 Python 字符统计，探测顺序 `python3/python/py`；不用 `wc -c` 或模型估算）：落进 `[细纲目标×90%, ×1.1]` 区间；低于 90% 对照情节点预算找欠账点重写（密点写薄补足/低压章补细纲内已有铺垫，不硬塞爽点；细纲无可展开内容则停止输出 `outline_underfilled` 先补纲），高于 ×1.1 压过场/合疏点/删多余过渡（不删主线爽点凑数）——规则见「字数验收权威」（B95 合一，唯一规则源）。
5. 【禁止】改故事内容——只打磨表达，不动情节。
6. 【禁止】过度打磨——改味保护原则：不得整段重写（"改最少效果最大"）。
7. **关键章条件聚焦环（E3，B95）**：细纲功能标签含**高潮/反转**时——只磨本章高潮场面段（问句：这个场面值不值得读者截图？慢镜头够不够？）；普通章不加。

## C 段：确定性收尾（每章落盘后同轮完成）

**正文元信息扫描**：检查标题行以外的正文，命中 `第[一二三四五六七八九十百千万两0-9]+章|上一章|上章|前一章|本章|这一章|前文|后文|伏笔|细纲|读者` 时必须改写为场景内表达；只有角色在故事世界内真实阅读/讨论“第X章”文本，或真实身为作者/读者并谈论读者身份时例外。

**禁用词扫描**：先过**最毒句式速查**（实测最易漏，命中即改）：①「不是A，(而)是B」全家族——含「没有X，没有Y(，只是Z)」排比否定、「是B，不是A」反序、「他没X，也没有Y。他只是Z」先抑后扬，；②声线反差「声音不大/不高…却…」；③「，带着……」万能状语；④预告/总结收尾「没人知道…」「(这)才刚刚开始/开头」「正朝着…压过去」「即将拉开序幕」「这一刻…」；⑤叙述里短词加引号强调（他是被请来"把关"的）。再复核 detector 的 `formulaic-parallelism` advisory：跨段「不是A。/也不是B。/只是C。」、`至于X不X，怎么X`、同动词 `不V A，不V B` 即使写在台词里也不能跳过，确属人物当场的功能性表达才保留。然后对照 `references/banned-words.md` 全表：一级词（高频AI腔）命中即替换；二级词（低频/语境相关）高频出现时替换，偶发可参考 `references/anti-ai-writing.md` 定性裁定

**写后同轮清零**：正文落盘不是汇报时机——每章落盘后必须在**同一轮**内跑完上述扫描、下方确定性收尾脚本与 moshu-narrative-writer 审查，blocking 清零才算本章完成；不得先汇报"已写完"再等指示。写后 hook 会对落盘正文自动扫描确定性毒句式并把命中推回——那是兜底网不是替代，hook 报出的命中当轮清零。**唯一豁免**：用户显式说"本章不去味/跳过检查"——豁免时在该章标题行下加一行 `<!-- 去味:跳过 -->`（写后 hook 的毒句式推回与写下一章前的欠账拦截都认这个标记；其余网照常）。

**确定性收尾**：本批正文写完后，主会话对实际落盘文件运行 `node {SKILL_DIR}/scripts/check-ai-patterns.js --check --fail-on=blocking 正文/第XXX章_*.md` 与 `node {SKILL_DIR}/scripts/check-outline-copy.js 正文/第XXX章_*.md`（细纲照搬复扫；`{SKILL_DIR}` 指当前加载的 moshu-write skill 根目录）。blocking 命中先回正文改写并复扫；advisory 与细纲重合逐条读原文判断，确属问题才改，功能性写法标 `[需复核]`——每条都要有结论，不为归零机械改写；细纲重合里判定保留的补进细纲「复沓锚句」，下章起不再复报。其中 `formulaic-parallelism` 必须连同对话一起复核，不能因为 hook 不阻断台词就略过。
随后运行 `node {SKILL_DIR}/scripts/normalize-punctuation.js 正文/第XXX章_*.md`（默认 `--quote-mode keep`）清理无功能省略号、破折号、双连字符和独立分隔线；古言/日式的「」不受影响。moshu-narrative-writer agent 不运行这些脚本。

**候选机检（可选，永不拦截）**：单章/大修路径可再跑 `node {SKILL_DIR}/scripts/check-prose-candidates.js --prose 正文/第XXX章_*.md --style 文风库/文风.md --gaps 追踪/信息差.md`——高频意象/句式偏离/信息差兑现/成稿长度四类候选**只呈报作者，不消耗修复预算、不阻断**；日更批末由 workflow-daily 统一跑。

**退化防护**：正文落盘后运行 `node {SKILL_DIR}/scripts/check-degeneration.js --check 正文/第XXX章_*.md`。blocking（复读、截断、拒绝语、tier1 工程词泄漏）只重写受影响章节，最多 2 次；仍失败就报告证据让用户定夺。
advisory 只提示可疑处，先看脚本给出的例外；故事内系统/界面用语、弹幕刷屏、重复台词等有功能则保留。**注意：对话行里的 tier1 工程词会被脚本降级为 advisory（角色真身为作者/编剧、故事内真讨论创作的例外），不消耗修复预算，不要按 blocking 回炉。**

**机检修复预算（统一阀门，防 token 失控）**：本章所有机检项（字数不达标、check-ai-patterns blocking、check-degeneration blocking、check-outline-copy 细纲照搬、标点异常）共享**同一份自动修复预算 = 2 轮**：命中后主线程自动修复并复扫，同一草稿每项最多 2 轮（同一内容重复检查幂等、不重复消耗预算）；2 轮后仍失败的项**停止自动修复**，把证据（命中项 + 已尝试的修复）报告给用户定夺，不得无限自动消耗写稿 token。advisory 与细纲重合逐条人工判定，不消耗预算；用户显式豁免（`<!-- 去味:跳过 -->`）的章不消耗预算。

## D 段：质量检查与追踪事务

### D1 质量检查三维度

(1) **情绪交付**——每章是否交付了细纲中规划的目标情绪？(2) **契约风险**——按 `references/reader-contract-and-progression.md` 检查因果权 + 结算权、关键节点四问、期待所有权、期待债、终局储备（透支两问）与换书债；章级推进按权威文件的七类状态分档（快节奏保留可见事件/爽点下限），强弱相对本书题材与对标判断，标记 契约安全 / 需补强 / 契约破坏；契约破坏 先修正文或修后续纲。(3) **技术质量**——一致性、格式、禁用词。参考 [references/quality-checklist.md](quality-checklist.md) 中的通用检查和长篇专项清单。

### D2 Agent 调用：moshu-consistency-checker

质量检查阶段，如果项目已部署 moshu-consistency-checker agent（部署判定见 /moshu-setup），spawn `Agent(subagent_type: "moshu-consistency-checker", prompt: "项目目录：{dir}\n检查范围：{本次写作的章节}\n检查类型：事实冲突+伏笔断线+角色属性不一致")` 执行一致性检查，获取 S1-S4 分级报告。如 agent 不可用，由主线程参照 quality-checklist.md 直接检查。

**S1/S2 必须显式过桥**：报告中的每条 S1/S2 冲突必须当场显式判定并落盘其一——①已修复（改正文/细纲后复核该冲突不再成立，必要时重跑检查确认）；②进 `continuity_risks`（跨章风险，下章起持续核对）；③进 `next_chapter_commitments`（下一章必须修）。未判定的冲突不得进入下一章；S3/S4 按需记录，不强制。

### D3 Agent 调用：moshu-narrative-writer（去AI味审查）

> **定位声明（B94）**：本步是 narrative-writer 工艺自检（7 Gate+删除优先），非独立评审——创作者与审查者同源时深度有限；跨产物独立评审走 `/moshu-review`（四 reviewer+审稿令牌）。轻量自检与深度评审不互相替代。

质量检查阶段，如果项目已部署 moshu-narrative-writer agent（部署判定见 /moshu-setup），可 spawn `Agent(subagent_type: "moshu-narrative-writer", prompt: "项目目录：{dir}\n任务描述：审查+去AI味\n检查范围：{本次写作的章节}\n删除优先：每条 AI 味项先判能否删除——删后不丢伏笔/钩子/角色/情节/必要信息的直接删，会丢才润色（删除受比例上限与字数下限约束，跌破下限改降AI重写）\n检查项按你自己的 7 Gate、禁止事项与写完后对话自检全量执行，其中否定翻转句式和台词里的工整否定清单不因脚本豁免台词而跳过")` 执行文字质量审查和去AI味检查。如 agent 不可用，由主线程直接执行，检查项对照 `references/anti-ai-writing.md` 与 `references/banned-words.md`。

检查后若正文修订改变了连续性事实，必须构造 `mode=revision` 的同章追踪事务并执行 `scripts/tracking_commit.py commit`：
- 伏笔变化用 `foreshadow_changes` 更新同一 ID 的当前行，不追加重复历史；
- 时间线变化写入 `timeline_events`，由 `_tracking-state.json` 统一派生 `作者真相.md` 与 `读者已知.md`，不得把作者秘密泄露到读者视图；
- 核心角色状态变化同时提交该角色截至当前章的完整快照；
- 事务失败后保留原事务 JSON，修正写入环境并重跑同一 `commit`；成功后执行 `check`，确认 state 与全部派生视图一致再继续写作。

### D4 追踪事务提交（每章一次）

按本 D4 事务构造协议构造 JSON（含可选的 `information_gap_changes` 信息差登记，9 条细则见下；B95 core 自含，不再指 shell），执行 `scripts/tracking_commit.py commit`。工具先在内存完成全部合并/渲染/容量校验，再生成逐章记录、角色/伏笔/时间线/上下文派生视图，最后原子替换 `_tracking-state.json`。失败按类型处理（分类与恢复动作见 [recovery-protocol.md](recovery-protocol.md)）：**写入失败**（工具不可用、权限被拒、磁盘满）时 `_tracking-state.json` 未推进，保留原事务 JSON 直接重跑同一 `commit`；**校验失败**要按报错改事务本身再提交，重跑同一份结果不变；**派生视图被手改**导致 `check` 报不一致时，重新提交该章的 `mode=revision` 事务让工具整份重建（`expected_state_revision` 取 `追踪/_tracking-state.json` 的 `state_revision` 字段——`check` 失败时只往 stderr 打 ERROR，不输出 JSON）。任何情况都不手改派生文件。本章首次引入会复用的具名角色/势力时，仍按 `references/outline-workflow.md` 的「细纲后设定补全」规则补建静态 `设定/` 档案。

**事务构造 9 条细则**（日更/单章共用）：

1. 从刚落盘的正文、细纲和上一版续写状态卡提取 `result / character_changes / foreshadow_changes / timeline_events / constraints / next_chapter_commitments`，并可选登记本章的**信息差变化** `information_gap_changes`（正文揭示/新埋的「谁知道什么」：知情人×读者已知×关键词，字段见 [tracking-transaction.md](tracking-transaction.md)「信息差事务」；无变化不填）。**语声/称谓提取（B59，AI 语义层）**：主要角色挑 ≤2 句本章最具其说话作派的台词填入快照 `voice_samples`（脚本滚动 5 条/精确去重）；只记**新建立或发生变化**的双向称谓进 `address_book_updates`（register/update/retire，无变化不填）。**数值登记（可选，B62）**：境界/欠款/排名/资产等想盯的指标随事务登记 `progression_updates`（**delta 内**；登记时声明方向 up/down）——回退会出候选提醒，剧情性回退带 reason 归因。**写作浮现（B68）**：写作中发现计划外涌现（角色活了/计划外反应/新想法）随手记入 `大纲/写作浮现.md`，不留会话记忆——补纲时收割消费。只记录会影响未来章节的变化；过程日志、质检计数、参照章和去 AI 味统计全部排除。
2. 需要长期复用的核心角色，把完整动态快照放进 `character_snapshots`，并在 `character_changes` 写对应变化；一次性路人只写变化、不交快照。已有动态快照的核心角色再次变化时必须提交新快照。静态人设继续以 `设定/角色/{名}.md` 为准。
3. `context.long_term_constraints`、当前卷/故事时间/场景、活跃核心角色名、连贯性风险提交当前完整值；故事时间取本章细纲「时间锚点」；活跃伏笔、近三章速记和下一章承诺由工具从当前视图/本章增量派生，不重复手填。
4. 把最近一次 `tracking_commit.py check` 返回的 `state_revision` 写入事务 `expected_state_revision`，再把 JSON 写到临时文件并执行 `tracking_commit.py commit`。成功并复检后删除临时 JSON；脚本返回新的 `state_revision` 才能进入下一章。
5. 失败时 `_tracking-state.json` 尚未推进；保留临时 JSON，修正写入环境后重跑同一 `commit`。不得另写下一章、不得手工补派生视图、不得忽略返回码。失败分类与恢复动作见 [recovery-protocol.md](recovery-protocol.md)。
6. **暗线进展核对**：按本章事务的 `story_time` 推进量，对照 [state-tracking.md](state-tracking.md) 的「时间推进与暗线进展预期」表核对暗线/势力动态是否该有进展：长时间跳过后暗线全无变化 = 世界观「冻住」信号，补世界事件或显式写「无进展」。暗线记录在 `foreshadow`（已埋未回收）与 `timeline_events`（世界事件/势力变化）中，不另设文件。
7. **细纲失效检查**：本章事务的 `character_changes` 含角色退役/死亡（`retire`/`die`）或 `continuity_risks` 新增影响后续剧情的条目时，grep 后续未写细纲（`大纲/细纲_第{N+1}章.md` 起）是否引用受影响角色/对象名；命中则在对应细纲文件头部标记 `<!-- 受影响: {角色/对象}（正文第{N}章变化） -->`，并在写下一批/写到该章前复核修正细纲——正文是最终真相，细纲跟随修正（已写区间的细纲属锁定，修改需用户确认）。**stale 消费（B1c）**：写前若细纲文件头含 `<!-- stale:` 标记（构建环修订留痕），先对照 `大纲/变更日志.md` 复核该修订的影响，复核处理后才写，处理后在文件头移除该标记——只提示复核，不自动改细纲内容。
8. **设定转正**：本章正文首现的具名对象（`设定/` 文件头部 `状态：计划`），事务提交成功后改状态行为 `已转正`；未进正文的保持 `计划`（计划不当事实）。
9. **章后对照（细纲落地核对）**：对照本章细纲「情节安排」逐点核对落地情况（每条引用正文位置）——已写（landed）无动作；未写（missed）影响后续 → 进 `next_chapter_commitments` 或 `continuity_risks`，不影响（可舍弃过渡点）→ 在细纲该点标注 `<!-- 未落地: 原因 -->`；偏离（deviated）合理（正文更好）→ 修订细纲该点并标注，不合理 → 下章补写或改细纲；正文出现细纲未安排的事件 → 归类：延续线索登记进 `foreshadow`/`timeline_events`，一次性事件不登记。另核**认知边界**：细纲声明「主角不知道」的信息是否被正文泄露（旁观镜头/系统面板/他人行动）——泄露则修正正文或修订细纲；「信息留白」处是否只写现象未点破因果。正文是最终真相，细纲跟随正文修订（已写区间属锁定，修订需用户确认）。

`追踪/逐章记录/第NNN章.md` 由工具按 5 类变化生成，目标 ≤1536 字节、硬上限 3072 字节。它不是正文摘要大全，更不保存写作过程。`伏笔.md` 每个 ID 只有一行当前状态；角色状态按核心角色拆文件；时间线的客观事实和读者认知只在同一事件登记中维护，再派生作者/读者两个视图。状态更新仍由主会话负责；moshu-narrative-writer 只写正文并回报必要的写作结果，不直接写 `追踪/`；主会话也不绕过事务工具直接修改最终追踪文件。

## 写前准备契约

**缺失文件处理**：当前主产物缺失时显式修复，不拼装降级结果：
1. **角色状态文件缺失** → 当前协议项目先运行 `tracking_commit.py check`，再重跑产生该状态的完整事务；已有正文但 `_tracking-state.json` 缺失时重新 `/moshu-import`。不得从前文临时推断后直接手写快照。
2. **角色、普通剧情单元或设定等非主产物子目录缺失** → 按「对标书路径查找」查找项目视图与根目录数据源，仍缺失则跳过该可选模块。本条不适用于 `剧情/情绪模块.md` 和 `剧情/节奏.md`。
3. **`剧情/情绪模块.md` / `剧情/节奏.md` 缺失** → 写前准备必须停下，设置 `missing_primary_contract: true` 并给出 `repair_action`：重跑 `/moshu-analyze` Stage 3+ 或重新 `/moshu-import`，不得用摘要文件假装已召回权威模块。
4. **`文风库/文风.md` 缺失或不合规** → 按 (d) 交互提醒处理（生成 / 跳过记录 / 自写约束）；不阻塞写作（可跳过用默认 Gate），但不静默（每章写前检查、跳过记录）。情绪/节奏轴（`missing_primary_contract`）独立，不受文风缺失豁免。
5. **伏笔/时间线文件缺失** → 视为续写状态卡损坏，停止写正文；先运行 `tracking_commit.py check`，再用事务修复。卷纲/大纲中的计划不能代替已发生事实的追踪记录。
6. **`设定/题材正文提示卡.md` 缺失** → 按 A3(c) 题材卡召回处理（唯一完整版，B95 收口——高/中/低置信照原卡标注；`设定/题材定位.md` 也缺失时退回细纲+目标平台低置信题材卡并在意图确认写明）。

**对标分析权威优先级（权威读取顺序）**：
1. `剧情/情绪模块.md` 是读者需求 / 情绪引擎、爽文套路框架、可复现模块和重组指南的权威来源。
2. `剧情/节奏.md` 是关键信息推进、章节扩写技法聚合、情绪触动点和爆发节奏的权威来源。
3. `文风库/文风.md` 只管句长、标点、对话潜台词、原文锚点等风格；它不能覆盖情绪模块或节奏意图（情绪/节奏权威是 `剧情/情绪模块.md` / `剧情/节奏.md`）。
4. `章节/第K章_摘要.md` 是具体章节证据，用来校验和补足权威索引，不反向覆盖 `情绪模块.md` / `节奏.md`。
5. `拆文报告.md`、`剧情/故事线.md` 是投影/摘要；若与 `剧情/情绪模块.md` 或 `剧情/节奏.md` 冲突，写作以两个权威文件为准，并在写前准备 `gaps.conflict` 记录冲突来源。

**文件写入**：每章写完直接写入 `正文/` 目录，不要先输出到对话。

**追踪文件体积**：`追踪/_tracking-state.json` 是唯一结构化权威；`上下文.md`、核心角色快照、`伏笔.md`、作者真相与读者已知时间线都由它确定性派生，程序不反向解析 Markdown。`上下文.md` 固定 7 栏且 ≤12KB。`逐章记录/第NNN章.md` 每章只记录会影响后续连续性的紧凑变化，目标 ≤1536 字节、硬上限 3072 字节，不承诺单独重放出全部当前状态。阶段/卷级回看按需查询逐章记录或正文，不维护另一套长期摘要。所有追踪写入都通过 `scripts/tracking_commit.py`，禁止手改派生文件。

## 写作技巧提醒

| 场景 | 技巧 |
|------|------|
| 开篇 500 字 | 必须有钩子，不能从天气/风景开始（除非反差极大） |
| 打斗 | 不要流水账，写策略和反转，不写「你一拳我一脚」 |
| 日常 | 日常要有人物互动和伏笔，不能只是「吃饭睡觉」 |
| 任务卡点 | 角色办事被卡住，必须卡出信息/关系/代价/选择/伏笔变化；删掉无损就压缩或删除 |
| 爽点释放 | 铺垫要充分、释放要干脆，读者等得越久释放越要爽 |
| 公式约束 | 参考 genre-writing-formulas.md 中的创作公式 |

## 字数验收权威

长篇每章只按本章细纲的 `字数目标` 与**第 3 遍字数验收**的统一 90% 放行下限验收。节奏类型只决定情节点疏密和展开方式，不再叠加另一套静态最低字数。

**细纲缺 `字数目标` 时**：按 3000 字/章代入，走同一条 90% 放行下限，并提示补纲。这是唯一兜底值，不按节奏类型分档。

## 中途快照（长篇写作安全网）

每连续写完 3 章，在继续前执行以下快照操作：

- 执行 `scripts/tracking_commit.py check`，确认 `_tracking-state.json` 有效、逐章记录连续且未超限、所有派生视图一致、续写状态卡恰好 7 栏且 ≤12288 字节
- 用 `ls -la 正文/` 确认最近 3 个章节文件已成功写入磁盘且大小正常（>100 bytes）
- 如果发现文件缺失或大小异常，立即重新写入
- 快照完成后可继续写作

> **日更模式**：此步骤自动跳过——workflow-daily Stage 4-D2 已按章更新上下文.md。
