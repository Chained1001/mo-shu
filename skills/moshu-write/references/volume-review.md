# 卷复盘：卷末收口

卷末章定稿后（或用户说「卷复盘 / 第 X 卷写完了」）执行，产出 `大纲/卷复盘_第X卷.md`。冷路径——卷末才读，不进日更循环。

## 触发

- workflow-daily 批末收尾时，最新定稿章（追踪 last_committed_chapter）= 当前卷卷纲「章节范围」上界 → 提示作者执行卷复盘；
- 用户明确要求时随时可做。

## 四步

1. **卷报告取表（先跑脚本，AI 只做判读）**：运行 `tracking_commit.py volume-report --project {项目根} --from-chapter {A} --to-chapter {B}`（`{A}`/`{B}` 为该卷起止章，取自卷纲「章节范围」；state 无卷元数据，脚本不猜卷界），读取产物 `追踪/卷报告_第{A}-{B}章.md`——伏笔四态清账、悬置预警、信息差未兑现全部由脚本确定性出表。AI 只做判读：已回收（注明回收章）、已埋未回收（悬了几章、是否触发"悬了太久"预警）、明确放弃（注明原因）。悬置未回收的跨卷伏笔写入下卷规划。清账不修改追踪文件（事实入账仍走事务），只产出复盘视图。

2. **卷摘要**：≤500 字——卷事件主线、主角状态变化、关键关系变化、本卷承诺兑现情况对照卷契约（`大纲/卷纲_第X卷.md` 的卷契约与终局储备）。

3. **下卷卷纲规划**：按 `设定/题材定位.md` 的终局底牌与升级台阶，产出下卷方向候选 1-3 个（含各候选的主推线/战果线、与终局储备的衔接）。作者确认候选后，走 `/moshu-build` 开新卷（增量补设定与卷纲）。

4. **作品契约修订候选**：对照 `references/reader-contract-and-progression.md`——本卷暴露的契约问题（期待债偿还情况、主角代理权/高光、换书债、终局储备透支）**只列修订候选**，作者确认后才改动 `设定/题材定位.md`。

> **下卷规划转 /moshu-build（消费本卷复盘的下卷方向候选）**

## 产物格式

```markdown
# 卷复盘：第 {X} 卷 {卷名}

- 范围：第 {A}-{B} 章 | 复盘日期：{日期}

## 伏笔清账
| 伏笔 | 状态 | 章节证据 | 去向 |
|------|------|---------|------|
| 伏笔-{ID} {名称} | 已回收 / 已埋未回收（悬{N}章）/ 放弃 | {章} | 跨卷 → 下卷规划 / 结清 |

## 卷摘要
{≤500 字}

## 下卷方向候选
1. {方向}（主推线 / 战果线 / 终局储备衔接）— 作者确认：{候选1/候选2/候选3/自定}
2. ...

## 契约修订候选（作者确认后生效）
- {问题} → {修订建议}（涉及：期待债 / 代理权 / 换书债 / 终局储备）
```
