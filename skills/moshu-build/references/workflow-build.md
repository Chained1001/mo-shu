# workflow-build.md：书驱构建（Phase A 快速生成 + Phase B 深度打磨）

> **来源声明**：本文件源自 moshu-write 侧开书工作流的构建段拆分（V2.1 批 B1a 改写，非逐字拷贝；B1b 起旧文件删除、细纲职责由 write 侧 outline-workflow 承接）；**细纲部分（细纲模板/安全七检/分批建纲/中途补纲/细纲后设定补全）归 write 侧**。构建环只做设定/大纲/卷纲的计划层工作。
>
> **v4.0 架构（批 B53）**：由 B10 六步书驱构建（三停靠）重构为 **Phase A「快速生成」+ Phase B「深度打磨」双 Phase**——Phase A 全速走完 Stage 1-6（方法论照用，不停靠不评审），Stage 2/6 后自动跑 check_outline；Phase A 完成一个弹窗确认后进入 Phase B 打磨环（evaluator 全局评审 → 五选项主选择 → 级联改进循环）。三停靠折叠为一个大停靠的打磨环；每步五面方法论与雪花法基底不变。与 write 侧"锁定"（有正文章节即保护锁）共存不冲突，见 [cold-path.md](cold-path.md)「与现有机制的关系」。
>
> **参考偏好 ≠ 对标**（B53 新增语义）：参考是学习神韵（基调/主角/风格，轮 1 可选快问采集），对标是模仿结构（拆文产物直接做 fail-fast 校准）——两者可共存。
>
> **虚拟对标**（B53 新增）：无对标路线的设计约束参照——采风多源产物合成三类设计目标（节奏/情绪/结构），落盘 `设定/虚拟对标.md`；Phase A 设计时参照、Phase B 打磨时评审锚点。有对标时跳过合成。
>
> **对标书路径查找**（本书引用规则）：优先 `{项目}/对标/{书名}/`，不存在则回退 `拆文库/{书名}/`；排除同名或来源指向当前正文的 `对标/{当前书}/`。
>
> **消费侧只读**：本工作流读 `追踪/`（last_committed_chapter、连贯性风险、信息差冲突）作输入，不写任何追踪文件——唯一例外是定稿后的 `tracking_commit.py init`（事实层第 0 章基线，见「定稿与 artifact 创建」）。

## 交互模态规则（对话形态的选用纪律）

1. **封闭选择**（候选可枚举且 ≤4 项）→ 一律 AskUserQuestion（弹窗），不做开放式提问。
2. **开放采集**（无候选、要自由表达，如方向/感受/评述）→ 对话式，不硬塞弹窗。
3. **过程性动作**（不是选择，是即将执行的操作）→ 声明即将做 + 可显式跳过（如采风默认执行，见 Phase A Stage 1 采风段）
4. **同性质封闭选择合批一屏**（≤4 问/屏，工具上限），不逐问弹窗——轮 2 超过 4 问时拆两屏连续问。
5. **弹窗选项必须带"（推荐）"标注与一句理由**，供作者快速决策。

## 构建台账与进入规则（三种入口统一）

构建环三种入口（开书构建 / 修订 / 开新卷）的第一步均先读 `设定/构建台账.md`（一册一份，作为构建期对谈的锚——构建态与方法论单真源）：

- **存在** → 读取它，向作者汇报「本书{构建态}，当前焦点…，待定 N 项」，确认后再继续后续对谈。台账构建态为「Phase B 打磨中」时按「Phase B·断点恢复」节恢复打磨环。
- **不存在且为开书** → **四轮式开场答完即创建最小台账**（构建态＝Phase A 进行中；方法论声明仅档位一行、当前焦点＝Stage 1 核心设定落盘中、答案摘要记入已收敛区）
- **不存在且为修订/开新卷** → 提示先创建空台账（`设定/构建台账.md`）再继续。

### 台账模板（书项目产物 `设定/构建台账.md`，v3——Phase 状态机）

> 模板见 [ledger-template.md](ledger-template.md)（方法论声明/五态状态机表/产物表/打磨记录 append-only 等完整格式）。台账语义要点：① 构建态五态流转以模板内「进入条件/退出条件」两列为准；② **打磨记录 append-only**——每轮追加、不改历史，是 Phase B 断点恢复的唯一真相源；③ 产物表的 ⚠️ 待打磨项列由 Phase A 各步汇总，作为 Phase B 打磨的初始清单；④ 采风需求节用 CF 票据四列（CF 编号｜需求描述｜类型｜状态），与 [caifeng-methods.md](caifeng-methods.md) 台账登记口径一致。

### 流程规则（六条）

1. **进入必读**：三种入口先读**构建态节**，汇报"本书{构建态}，Phase A 产物 {N} 项含 ⚠️ M 个，待定 N 项"；「Phase B 打磨中」态走断点恢复（见 Phase B 总则）。
2. **收敛必写**：决策落定即更新，变更日志同步一行。
3. **收尾必结**：会话结束前焦点与待定项定格（台账是构建期对谈的快照锚，不是机读状态机——**纯 Markdown，不作任何脚本解析**）；自动段被打断时同样先落台账再停。
4. **产物必登记**（v3）：Phase A 每个 artifact 完成即更新「Phase A 产物状态」行（版本+⚠️ 待打磨项）；⚠️ 是 Phase B 打磨的初始清单。
5. **浮现必随手记**：Phase A Stage 4 填卡时涌现的灵感即时记入浮现记录——整合检验逐条处理（落实/转待定/放弃）。
6. **开新卷重置**：产物表重置为本卷新增项（核心设定表/虚拟对标保留——全书级），进入「Phase A 进行中（开卷）」。

## 双 Phase 构建流程（书驱构建 v4.0）

### 流程总览

#### Phase A/B 架构（文字概览）

**Phase A「快速生成」**：Stage 1 信息采集保留全部交互（轮 1 定调+参考偏好采集、采风默认执行[query 按参考偏好定向/泛化分流]、虚拟对标合成[无对标时]、轮 2 定形六问、轮 3 理想书评结构化三维度量化目标、轮 4 档位）→ Stage 2-6 全速走完（方法论照用，不停靠不评审，不确定处标 ⚠️ 入台账产物表）；Stage 2 后自动跑 check_outline（blocking only，⚠️ 标注继续走），Stage 6 写完全部 artifact 后自动跑全量（blocking 清零才进弹窗）→ **Phase A→B 弹窗**（✅ 进入打磨 / 📋 先看产出 / ⏸️ 暂存）。

**Phase B「深度打磨」**：一个大停靠的打磨环——① evaluator 全局评审（full 类型，对照虚拟对标+理想书评出三维度 JSON+score+research_needed+summary+recommendation）→ ② 打磨屏（报告九格+⚠️待打磨项汇总）→ ③ 五选项主选择（✅ 确认定稿[tracking init]/🔧按建议改进/🔄触发采风补强[research_needed 精准检索→更新虚拟对标]/📡逐维度打磨[结构/桥段/节奏/情绪/角色五选一，各映射方法论文件与对照锚点]/📝作者自改）→ ④ 每轮改动按级联纪律（影响声明→作者确认→一次改完→重跑 check_outline→re-spawn evaluator→打磨记录落台账 append-only）。

**断点恢复**：新会话读台账构建态「Phase B 打磨中」→ 读打磨记录最后一条 → 汇报断点 → 继续打磨环。

#### 基底与适配层（方法论不变）

```
┌─────────────────────────────────────────────────────┐
│  基底流程（雪花法 10 步 → 压缩为 6 步网文适配版）        │
│  一句话 → 一段话 → 角色 → 扩展 → 单元 → 场景/整合      │
├─────────────────────────────────────────────────────┤
│  网文适配层（五步法 + 八节点 + 多卷连载）                │
│  高潮优先 → 单元剧 → 八线 → 章位分配 → 对标回流         │
├─────────────────────────────────────────────────────┤
│  对标参照层（有主对标时激活；无对标时由「虚拟对标」承担）  │
│  概要参照 → 节奏校准 → 单元参照 → 密度校准 → 坐标回流   │
└─────────────────────────────────────────────────────┘
```

#### 六步流程定义（雪花法基底 + 网文适配——Phase A 容器）

> Phase A 全速走完下表 6 步：方法论、卡片、五面产出全部照常，差异只在**交互节奏**（不停靠不评审，⚠️ 标注汇总给 Phase B）与**机检时点**（Stage 2 后 blocking-only、Stage 6 后全量）。

| Stage | 名称 | 密度 | 故事面（所有书都做） | 人物面（所有书都做） | 对标面（有主对标时） | 方法论书指引 | 卡片按需加载 |
|---|---|---|---|---|---|---|---|
| Stage 1 | 信息采集 | — | 选题方向+理想书评+方法论声明 | — | **对标发现**：扫拆文库→推荐→登记主对标 | 《骨架》第 2 章（理想书评） | — |
| Stage 2 | 骨架构建 | 句子 | 每卷骨架表（的一句话列）+高潮定死+终局底牌+升级台阶+全书四阶段 | 核心角色**四件套**：目标/抱负/价值观冲突/顿悟 | 读对标**概要.md**：参考每卷功能定位 | 雪花法3-5章+五步法1 | naming-cards（按需） |
| Stage 3 | 人物构建 | 段落 | 每卷一段话（三幕+灾难性事件）+阶段边界微调 | 角色一页：背景故事+**弧线六阶段**+大纲微调 | 读对标**剧情/节奏.md**：灾难级别校准 | 雪花法6-8章+大师课9章 | 人物主题卡（8 张） |
| Stage 4 | 单元构建 | 单元 | 逐卷**剧情单元卡**：单元 ID/章节范围/承诺/风险/对标剧情参照+章功能分配 | 每卷角色弧线段（起终点+变化节点） | 读对标**剧情/{标题}.md**：同功能单元结构/密度 | 五步法2+雪花法7/9-11章（题材公式仅离线兜底） | beat-cards + genre-writing-formulas |
| Stage 5 | 整合检验 | 精修 | 单元卡精修：伏笔四态+反转类型+跨卷呼应+**线索矩阵** | **动机链核验**+删主角/删题材核心测试 | 读对标**剧情/情绪模块.md**：密度校准 | 雪花法12-14章+小说写作6章+大师课LOCK | hooks-suspense（按需） |
| Stage 6 | 打磨定稿 | 定稿 | 对标回流（坐标表+锚点）+配比+八节点占比+LOCK 四查+**卷纲定稿** | **因果断裂修复验证** | **对标回流**：读节奏.md→排坐标表→选段→写锚点 | 大师课1-2章LOCK+对标回流 | — |

#### 扩展规则（雪花法一手原则）

**每一步都消费上一步的产出再扩展**——不是重写：

- Stage 2 的每卷骨架表（的一句话列）→ Stage 3 扩为每卷一段话（五句=三幕+两次灾难）
- Stage 3 的每段 → Stage 4 拆为单元卡（每段拆成 2-5 个单元）
- Stage 4 的单元卡 → Stage 5 精修（加伏笔/反转/因果标注）
- **结构保持不变，密度加深**

#### 双路设计（同流程+可选参照——不是两套流程）

> 无对标路径的参照约束由「虚拟对标」（Phase A 合成，见 Stage 1）承担：节奏目标参照于 Stage 2/4、情绪基准参照于 Stage 3/5、结构要点参照于 Stage 2/6；Phase B 评审时作 evaluator 锚点。

| Stage | 无对标路径 | 有对标路径 |
|---|---|---|
| Stage 1 | 选题+参考偏好+理想书评+方法论声明+**虚拟对标合成** | 同左 + **对标发现**（虚拟对标跳过） |
| Stage 2 | 雪花法→八节点定结构→每卷骨架表（的一句话列） | 同左 + **读概要参考卷功能** |
| Stage 3 | 雪花法→弧线六阶段→角色一页 | 同左 + **读节奏校准灾难级别** |
| Stage 4 | 五步法→单元卡（题材公式仅离线兜底） | 同左 + **读对标单元参考功能/密度** |
| Stage 5 | 伏笔/线索/因果+可证伪 | 同左 + **读情绪模块校准密度** |
| Stage 6 | 八节点占比+LOCK+定稿 | **对标回流**（五步，见 Stage 6 节）+LOCK+定稿 |
| Phase B | evaluator 用虚拟对标做评审锚点 | evaluator 用对标拆文产物做评审锚点（精确度更高） |

#### 交互时点（v4.0：三停靠折叠为打磨环）

> v3.0 的三停靠（Stage 2/4/6 后各一停靠）自 B53 起折叠：Stage 2-6 不再逐停靠确认（⚠️ 待打磨项汇总到台账），统一收敛为 **Phase A→B 一个弹窗 + Phase B 打磨环**（含原三停靠的全部评审/裁决能力）。档位仍影响停的次数吗？不影响——档位只影响方法论加载深度与提醒密度：

| 档位 | Phase A 行为 | 适用 |
|---|---|---|
| 轻量 | Stage 1-6 最快路径，瓶颈采风关闭 | 短篇感/试水 |
| 标准 | 照常（推荐） | 大部分网文 |
| 完整 | 指引块全读+瓶颈采风开启 | 重结构文 |

> 档位在Stage 1 由作者选定（记入台账方法论声明）；不确定先标准档。**不强制完整档**。

## Phase A：快速生成

### Stage 1·信息采集（四轮式开场——作者意图输入口，保留全部交互）

> **方法论书指引**（先读后操作）：**《小说的骨架》第 2 章（理想书评）**——理想评论家口吻的成品书评，作目标态锚；操作已萃取进 [idea-seed.md](idea-seed.md)「理想书评」节，直接用，不另读原文。

**故事面**（所有书都做）——四轮开场（定调→定形→理想书评→定流程），按回答落地：

1. **先查选题决策**：如果项目根存在 `选题决策.md`（moshu-scan Stage 5 产出），读取它——取排在最前（可行性最高）的推荐选题作为开书起点，向用户确认；看 `扫榜日期`：距今较久则提示"市场数据可能过期，建议复扫"；「能爆的原因」仍标 `待拆文验证` 时提示：假设未拆文验证，可选先 `/moshu-analyze` 拆一本验证，或直接开书（不拦开书）。缺失时先自动找一遍（从项目根及其上一级目录起、向下最多 3 层按文件名搜，跳过隐藏目录，按 mtime 由新到旧取最新 2 份，AskUserQuestion 列候选）——见下方「四轮式开场」轮 1。
2. **模糊灵感**（画面/脑洞/感觉，说不清题材卖点）：先做**灵感种子收敛**（[idea-seed.md](idea-seed.md)，产物落 `{项目根}/灵感种子.md`），Logline 作后续方向与设定的一致性尺度。
3. **定形（轮 2）**：AskUserQuestion 批问 体量三数＋目标平台＋终局口径＋【B53 新增】情绪基调＋更新频率＋禁区雷点（可选跳过）；不确定按 200 万字/5 卷规划。所有答案落盘核心设定表对应字段（读者偏好段）。
4. **理想书评（轮 3，结构化）**：写一份这本书的"理想书评"，按 [ideal-review-template.md](ideal-review-template.md) 填三个维度的量化目标（① 结构评分各 1-10 分｜② 节奏目标：期待密度/释放频率｜③ 情绪目标：核心情绪+第一卷读完感受）——不是文学评论，是 Phase B evaluator 打分的锚点。落盘 `设定/理想书评.md`。
5. **核心设定落盘（轮 4 后）**：按下方「核心设定表」模板产出，**成稿先展示作者过目（可打断调整）**，确认后创建 `设定/题材定位.md`（题材核心梗三分法+对标分析，参考 [genre-core-mechanics.md](genre-core-mechanics.md)「核心梗解析」；含**终局底牌与升级台阶**登记）、`设定/关系.md`（角色关系映射，参考 [character-relations.md](character-relations.md)「四种关系类型」）、`设定/题材正文提示卡.md`（题材边界/核心逻辑/读者期待/核心爽点，参考 genre-prose-cards 索引与 [style-genre-modules.md](style-genre-modules.md)）。
6. **方法论声明（轮 4 收尾）**：台账创建后补全「方法论声明」节——仅档位一行（轮 4 答案）；三域规划深度**不再逐项问**——默认档位表（见下）作流程内参考，作者口头可调（"卷纲再细一点"即改）。

> **默认档位表**：

| 域 | 默认 | 可选档 | 不可裁剪项 |
|---|---|---|---|
| 大纲 | 全局骨架 | 前半细化 / 仅阶段一 | 终局与升级台阶（全书） |
| 卷纲 | 首卷细 | 前两卷细 | 首卷（开书必须） |
| 设定 | 核心+终局相关 | 全量前置 | 主角/金手指/核心冲突 |

**对标面**（有主对标时做）——**对标发现**（先于反应式加载，主动扫拆文库推荐，不被动等用户开口）：

1. `ls 拆文库/`（数据源）与项目 `对标/`（引用视图）列已有书目；先按当前项目目录名、`.active-book` 和 `设定/题材定位.md` 中的本书信息识别当前作品，**排除同名或来源指向当前正文的 `拆文库/{当前书}/`**。moshu-import 为重建工程生成的本书拆文分析不是对标候选，也不得复制回 `对标/`。排除后都为空 → 跳到第 4 条。
2. 逐本读题材（读 `拆文库/{书}/` 的 `概要.md` 头部或 `拆文报告.md`「基本信息」的「题材」），与本书题材/方向比对，标 同题材 / 弱相关 / 不相关。
3. 有同题材或弱相关候选 → 用 AskUserQuestion 推荐（列候选书 +「都不用」+「另拆一本」），选定主对标 1 本（走情绪/节奏/正文；文风独立由文风库提供）。选定后写入 `设定/题材定位.md`「对标登记」的 `主对标书`，并按「首次引用对标书」规则把选中书从 `拆文库/{书}/` 复制到 `对标/{书}/`（复制清单不含 文风.md——文风独立由 `文风库/文风.md` 提供）。登记后若文风库尚无该书文风，询问用户是否现在用 /moshu-style 学习（可跳过，写第一章时缺失会再次提醒）。
4. 无候选 → 无对标继续（骨架按八节点自排，见Stage 2）；用户想对标可先 `/moshu-analyze` 拆一本。

**对标上下文加载**（用户提到对标书或工作目录已有 `对标/` 时）：按上方第 1 条口径识别当前作品并排除自对标；随后检查 `剧情/情绪模块.md` 与 `剧情/节奏.md`——任一主产物缺失时必须停止，设置 `missing_primary_contract: true` 并给出 `repair_action`（重跑 `/moshu-analyze` Stage 2-4 起 或重新 `/moshu-import`），不得以 `拆文报告.md`、章节摘要或故事线代替；两个主产物都存在时先读情绪模块的读者需求/情绪引擎与可复现模块，再读节奏.md 的关键信息推进、情绪触动点和爆发节奏；拆文报告只作人类可读概览。角色/普通剧情单元/设定子目录存在时按需召回（消费方是 write，本工作流只记录引用关系）。

> 开篇的"第一个冲突/机遇"定义可参考**激发事件四问**（见 [opening-design.md](opening-design.md) :87 起——什么是/什么不是/在何处/四特质），在Stage 2 定全书四阶段时使用。

#### 四轮式开场（Stage 1 交互）

```
轮 1（定调 + 参考偏好 + 采风 · 开放对话）：
"你想写什么类型的故事？你希望这本书给读者什么感觉？"
→ 有方向 → 追加参考偏好快问：「有没有喜欢的作品？不说对标——就是风格/基调/主角类型你觉得不错的，0-3 部」
  （采集：作品名 + 各自偏好维度，如"诡秘的悬疑氛围"；落盘核心设定表「参考偏好」段。
   注意：参考≠对标——参考是学习神韵（基调/主角/风格），对标是模仿结构（拆文产物做 fail-fast）；两者可共存）
→ 没方向 → "要不要先扫一下最近的榜单？或者说说你想让读者有什么感觉？"
→ 提到参考书 → 弹窗（AskUserQuestion）：「参考书怎么处理？」
  ○ 正式对标——需先拆书（/moshu-analyze），参与每卷节奏校准
  ○ 仅参考——取题材气质做原创，不拆书（推荐）
  ○ 都不用——删掉参考
  （对参考书的三个吸引点提问在轮 3 理想书评采集）
→ **采风默认执行**（query 构造按参考偏好分流）：
  - 参考偏好非空：query = "{参考作品A}的{维度}手法 + {参考作品B}的{维度}——提炼可复用模式"（定向检索）
  - 参考偏好为空：query = "{题材} 当前热门作品的结构模式"（泛化检索）
  原「有结构参照需求才触发」改为默认执行（无网时降级声明照旧）：
  1. 向用户声明："你提到了《X》《Y》——我先联网采风这两部作品的结构要素（约 5 分钟），采完给你看要点表，你确认后我拿它做设计参照。如果你不想等，说'跳过采风'即可。"
  2. 用户说跳过 → 记录降级声明进台账附注，继续
  3. 用户不反对 → spawn moshu-researcher（结构采风，CF 票据登记）
  4. 采风产物回来 → 展示要点表 → 用户过目 → 按融合四步使用
  5. 采风产物回来后 → **融合四步在本 Stage 内执行完毕**（对照核心设定表→借用功能位→本土转译→方法论验证），产物直接喂 Stage 2 骨架设计——不留到后续 Stage 才消化。
  6. **操作细则见采风手册**：检索策略 / 源七类 / 融合四步细则与 fallback 内联流程见 [caifeng-methods.md](caifeng-methods.md)。

轮 2（定形·AskUserQuestion 批，>4 问拆两屏连续问）：
问 A（体量三数）："这本书大概什么体量？"（总字数/总章数/分几卷一起问）
  → 不确定 → "先按 200 万字/5 卷规划，写完第一卷可以调"
问 B（平台）："目标平台？"（起点/番茄/晋江/其他，各选项带一句适配注解）
问 C（终局口径）："你要在动笔前设计好结局吗？"
  选项：完结（终局底牌+高潮定死，全书朝终点铺垫）｜开放式连载（升级台阶驱动、单元剧循环）
问 D【B53 新增】（情绪基调）："你想给读者什么感觉？"
  选项：爽文（打脸/升级/收获）/ 虐心（代价/牺牲/成长）/ 甜宠（治愈/日常/恋爱）/
        悬疑（解谜/反转/紧张）/ 燃（热血/友情/突破）——可多选，AI 融合
问 E【B53 新增】（更新频率）："预计更新节奏？"
  选项：日更 4000+ / 两日一更 6000+ / 周更 10000+ —— 影响章长/节奏/爆发密度
问 F【B53 新增】（禁区雷点，可选跳过）："有没有绝对不要的元素？"
  示例：不要后宫/不要虐主/不要系统流 —— 负面约束，比正面偏好更防翻车
所有答案落盘核心设定表「读者偏好」段。

轮 3（理想书评·创作确认）：
"方向和体量已定，现在给这本书定理想书评——想象一个完全读懂这本书的评论家，
为它写一篇溢美的书评。"
采集子问题（固化，不再即兴）：①你希望这本书给读者什么感觉？②参考书最吸引你的三个点是什么（如有）？
→ [作者描述]
→ AI 生成理想书评草稿 → 作者改定 → 落盘设定/
→ "好，这是你的理想书评——后面每一步都拿它当尺子。"

轮 4（定流程·AskUserQuestion 一问）：
"构建精细度选哪档？"
  🏃 快速（试水/脑洞文，先跑起来）
  🚶 标准（推荐——大部分网文，不确定选这个）
  🧗 完整（多线/强反转/群像）
→ 不确定 → 先标准档，写完第一卷觉得需要可以升级
→ 答完 → 创建最小台账（方法论声明仅档位一行、当前焦点＝Stage 1 核心设定落盘中、答案摘要记入已收敛区）
→ 核心设定表成稿展示作者过目 → 确认后落盘 设定/ 三文件 → 补全方法论声明（三域深度默认档位表，口头可调）

轮 4 后·虚拟对标合成（无对标时执行，有对标时跳过；细则见 [caifeng-methods.md](caifeng-methods.md)「第五步」）：
  前提：采风产物已回并过融合四步；`设定/题材定位.md` 已登记主对标 → 跳过本步
  主线程 AI 从多源采风产物提炼三类设计目标：
    ① 节奏目标：爆发密度区间 + 爽点循环模式 + 追读力锚点
    ② 情绪基准：核心情绪类型 + 交替模式 + 低压容忍 + 情绪禁区
    ③ 结构要点：中点设计模式 + 对手升级路径 + 伏笔密度参考
  有参考偏好时优先从参考作品的采风产物中提炼（定向），辅以同题材热门模式（泛化补充）
  落盘 `设定/虚拟对标.md`（固定三节模板）；CF 输入票据标「已消费·合成虚拟对标」
```


> 模板见 [virtual-benchmark-template.md](virtual-benchmark-template.md)——固定三节：节奏目标（爆发密度/爽点循环/追读锚点/更新适配）、情绪基准（核心情绪/交替模式/低压容忍/禁区）、结构要点（中点/对手升级/伏笔密度）。本文件不再重复维护。

## Phase B：深度打磨环

### 打磨环总则

Phase B 是一个大停靠——作者看完整粗稿后，逐维度评审→改进→循环，直到确认定稿。

**循环逻辑**：
  ① spawn evaluator（全局评审）→ 评审报告
  ② 展示打磨屏 → 作者选择
  ③ 改动（如有）→ 级联变更 → 重跑机检 → re-spawn evaluator → 回到②
  ④ 作者选 ✅ 确认 → tracking init → 构建态翻「定稿」

**断点恢复**：新会话读台账构建态「Phase B 打磨中」→ 读打磨记录最后一条 → 汇报「上次打磨到第 N 轮，最后做了 X，接下来 Y」→ 继续打磨环。

**级联纪律（每轮改动必须）**：
  先声明影响文件 → 作者确认 → 一次改完（不留半改状态）→ 重跑 check_outline
  → re-spawn evaluator → 打磨记录落台账（append-only，含 round/选择/改动/影响文件/机检结果）

### evaluator 全局评审协议

spawn 参数：
```
token: {8 位令牌}
eval_type: full          ← Phase B 专用，评完整粗稿
target_paths: [大纲/大纲.md, 大纲/卷纲_第X卷.md, 设定/角色/*.md, 角色弧线页]
benchmark_path: 设定/理想书评.md（结构化三维度）
virtual_benchmark_path: 设定/虚拟对标.md   ← 无对标时传入，有对标时省略
benchmark_book_paths: [对标/{书名}/剧情/节奏.md, 对标/{书名}/剧情/情绪模块.md]   ← 仅有主对标时传入（拆文精确数据，优先级最高）
context: "Phase B 第 N 轮打磨——上一轮改了 X，本轮重点检查 Y"
project_dir: {项目目录}
```

**参照优先级（B55）**：
- 有主对标 → 用 benchmark_book_paths，virtual_benchmark_path 省略（不双重传入）
- 无对标 → 用 virtual_benchmark_path，benchmark_book_paths 省略
- 两者都无 → 仅用 benchmark_path（理想书评——最弱参照，evaluator 应在 research_needed 中标注缺少参照）

→ 报告回来先用 review_tickets.py verify-token 校验令牌（回传不符 → 弃用报告重 spawn）
→ evaluator 输出三维度 JSON（score/research_needed/summary/recommendation 字段定义见 agent 模板）

### 打磨屏（AskUserQuestion 主屏）

│ 作者维度：新鲜度{判断}｜工艺{改进建议}             │

### 逐维度打磨子屏（📡 后进入）

问：「你想先打磨哪个维度？」（AskUserQuestion 单选）
  ① 结构（骨架锐度/中点/对手升级/伏笔闭合）
  ② 桥段（新鲜度/套路检测/桥段替换）
  ③ 节奏（爆发密度/爽点循环/低压区间）
  ④ 情绪（核心情绪/交替模式/情绪禁区）
  ⑤ 角色（弧线锐度/升级绑弧光/配角功能位）

选定维度后的操作闭环：
  AI 聚焦该维度 → 读对应方法论文件（映射见下表）→ 深度检查
  → 展示该维度的具体差距（对照虚拟对标/理想书评目标）
  → 提出改进方案（含影响文件声明 → 级联纪律执行）
  → re-spawn evaluator（context 注明"仅检查{维度}"）
  → 回到打磨屏主选择

| 维度 | 方法论文件 | 对照锚点 |
|---|---|---|
| 结构 | outline-methods「八节点故事结构」「势力场设计」+ outline-structure-theory「三幕式与五幕式」 | 虚拟对标 结构要点 |
| 桥段 | plot-frameworks「核心梗与细化法」+ outline-rhythm「桥段的标准四章结构」 | 虚拟对标 爽点循环 |
| 节奏 | outline-rhythm 全文（升级感/断期待/高潮节奏） | 虚拟对标 节奏目标 + 理想书评 节奏目标 |
| 情绪 | plot-emotion-system「节奏与高潮控制」+ emotional-methods「情感拉扯节奏设计」 | 虚拟对标 情绪基准 + 理想书评 情绪目标 |
| 角色 | character-design-methods「升级绑弧光」苏式问句 + character-basics「质量检查清单」 | 理想书评 结构评分 |

## 定稿与 artifact 创建

作者在 Phase B 打磨屏选 ✅ 确认定稿后：

- **写入定稿标记**：卷纲头部加 `定稿：v1.0（YYYY-MM-DD，构建环）` 行——这是构建完成的标记（v1.0），write 侧据此放行细纲/正文；不构成"锁定"（锁定=已有正文章节，见 [cold-path.md](cold-path.md)「与现有机制的关系」）。
- **大纲/大纲.md**：全书卷级鸟瞰（卷名+字数+章数+核心事件+状态变化，一段式汇总）。
- **大纲/卷纲_第X卷.md**：每卷的剧情单元+情绪弧线（含章节定位）+人物弧线+伏笔+反转+线索矩阵+对标结构坐标（参考 [outline-methods.md](outline-methods.md)「大纲三层结构法」 + [emotional-arc-design.md](emotional-arc-design.md)「六种弧线速查」 + [reversal-toolkit.md](reversal-toolkit.md)「反转类型」）。
- **追踪事务初始状态**：按 `references/tracking-transaction.md`（write 侧共享副本）构造第 0 章初始化 JSON，执行 `scripts/tracking_commit.py init`（build 侧共享副本），生成检查点（续写状态卡，固定 7 栏）、空的伏笔/时间线视图与目录；核心角色动态快照可在第一次正文事务中创建（write 侧）。**`next_chapter_commitments` 从单元卡首个单元的"单元承诺"字段映射**，不自造（防漏掉单元卡已承诺的读者期待）。

> 追踪 init 后，**事实层归 write**：build 不再写 `追踪/`，只读（修订工作流的边界判定输入）。
