## 交互模态规则（四种对话形态的选用纪律）

1. **封闭选择**（候选可枚举且 ≤4 项）→ 一律 AskUserQuestion（弹窗），不做开放式提问。
2. **开放采集**（无候选、要自由表达，如方向/感受/评述）→ 对话式，不硬塞弹窗。
3. **同性质封闭选择合批一屏**（≤4 问/屏，工具上限），不逐问弹窗。
4. **弹窗选项必须带"（推荐）"标注与一句理由**，供作者快速决策。

## 构建台账与进入规则（三种入口统一）

构建环三种入口（开书构建 / 修订 / 开新卷）的第一步均先读 `设定/构建台账.md`（一册一份，作为构建期对谈的锚——构建态与方法论单真源）：

- **存在** → 读取它，向作者汇报「本书{构建态}，当前焦点…，待定 N 项」，确认后再继续后续对谈。
- **不存在且为开书** → **四轮式开场轮 4 答完即创建最小台账**（构建态＝构建中；方法论声明仅档位一行、当前焦点＝步 0 核心设定落盘中、四轮答案摘要记入已收敛区），轮 4 后补全方法论声明。
- **不存在且为修订/开新卷** → 提示先创建空台账（`设定/构建台账.md`）再继续。

### 流程规则（六条）

1. **进入必读**：三种入口先读**六步状态节**，汇报"你在步 N·XX，故事面{状态}，人物面{状态}，待定 N 项"。
2. **收敛必写**：决策落定即更新，变更日志同步一行。
3. **收尾必结**：会话结束前焦点与待定项定格（台账是构建期对谈的快照锚，不是机读状态机——**纯 Markdown，不作任何脚本解析**）；自动步被打断时同样先落台账再停。
4. **步推进必更新**（v2 新增）：每步各面完成时更新状态列；停靠确认后记"✅ [日期]"。
5. **浮现必随手记**（v2 新增）：步 3 填卡时涌现的灵感即时记入浮现记录（见「浮现记录机制」）——步 4 逐条处理（落实/转待定/放弃）。
6. **开新卷重置**（v2 新增）：步 3-5 重置为 ⏳，步 0-2 和方法论声明保留（全书级不重做）。

## 六步构建流程（书驱构建 v3.0）

### 流程总览

#### 三层架构

```
┌─────────────────────────────────────────────────────┐
│  基底流程（雪花法 10 步 → 压缩为 6 步网文适配版）        │
│  一句话 → 一段话 → 角色 → 扩展 → 单元 → 场景/整合      │
├─────────────────────────────────────────────────────┤
│  网文适配层（五步法 + 八节点 + 多卷连载）                │
│  高潮优先 → 单元剧 → 八线 → 章位分配 → 对标回流         │
├─────────────────────────────────────────────────────┤
│  对标参照层（有主对标时激活，无对标时跳过）               │
│  概要参照 → 节奏校准 → 单元参照 → 密度校准 → 坐标回流   │
└─────────────────────────────────────────────────────┘
```

#### 六步流程定义（雪花法基底 + 网文适配）

| 步 | 名称 | 密度 | 故事面（所有书都做） | 人物面（所有书都做） | 对标面（有主对标时） | 方法论书指引 | 卡片按需加载 |
|---|---|---|---|---|---|---|---|
| 0 | 信息采集 | — | 选题方向+完美评述+方法论声明 | — | **对标发现**：扫拆文库→推荐→登记主对标 | 《骨架》第 2 章（完美评述） | — |
| 1 | 骨架步 | 句子 | 每卷骨架表（的一句话列）+高潮定死+终局底牌+升级台阶+全书四阶段 | 核心角色**四件套**：目标/抱负/价值观冲突/顿悟 | 读对标**概要.md**：参考每卷功能定位 | 雪花法3-5章+五步法1 | naming-cards（按需） |
| 2 | 人物步 | 段落 | 每卷一段话（三幕+灾难性事件）+阶段边界微调 | 角色一页：背景故事+**弧线六阶段**+大纲微调 | 读对标**剧情/节奏.md**：灾难级别校准 | 雪花法6-8章+大师课9章 | 人物主题卡（8 张） |
| 3 | 单元步 | 单元 | 逐卷**剧情单元卡**：单元 ID/章节范围/承诺/风险/对标剧情参照+章功能分配 | 每卷角色弧线段（起终点+变化节点） | 读对标**剧情/{标题}.md**：同功能单元结构/密度 | 五步法2+雪花法7/9-11章（题材公式仅离线兜底） | beat-cards + genre-writing-formulas |
| 4 | 整合步 | 精修 | 单元卡精修：伏笔四态+反转类型+跨卷呼应+**线索矩阵** | **动机链核验**+删主角/删题材核心测试 | 读对标**剧情/情绪模块.md**：密度校准 | 雪花法12-14章+小说写作6章+大师课LOCK | hooks-suspense（按需） |
| 5 | 打磨步 | 定稿 | 对标回流（坐标表+锚点）+配比+八节点占比+LOCK 四查+**卷纲定稿** | **因果断裂修复验证** | **对标回流**：读节奏.md→排坐标表→选段→写锚点 | 大师课1-2章LOCK+对标回流 | — |

#### 扩展规则（雪花法一手原则）

**每一步都消费上一步的产出再扩展**——不是重写：

- 步 1 的每卷骨架表（的一句话列）→ 步 2 扩为每卷一段话（五句=三幕+两次灾难）
- 步 2 的每段 → 步 3 拆为单元卡（每段拆成 2-5 个单元）
- 步 3 的单元卡 → 步 4 精修（加伏笔/反转/因果标注）
- **结构保持不变，密度加深**

#### 双路设计（同流程+可选参照——不是两套流程）

| 步 | 无对标路径 | 有对标路径 |
|---|---|---|
| 0 | 选题+完美评述+方法论声明 | 同左 + **对标发现** |
| 1 | 雪花法→八节点定结构→每卷骨架表（的一句话列） | 同左 + **读概要参考卷功能** |
| 2 | 雪花法→弧线六阶段→角色一页 | 同左 + **读节奏校准灾难级别** |
| 3 | 五步法→单元卡（题材公式仅离线兜底） | 同左 + **读对标单元参考功能/密度** |
| 4 | 伏笔/线索/因果+可证伪 | 同左 + **读情绪模块校准密度** |
| 5 | 八节点占比+LOCK+定稿 | **对标回流**+LOCK+定稿 |

#### 停靠与档位

| 停 | 位置 | 问什么 |
|---|---|---|
| 🔴 1 | 步 1 后 | "骨架+角色四件套如下…确认方向？" |
| 🔴 2 | 步 3 后 | "单元卡+角色弧线段如下…确认内容？" |
| 🔴 3 | 步 5 后 | "整合+对标+LOCK 完成…定稿并转 write？" |
| ⚪ | 步 2、4 后 | 自动 |

| 档位 | 步骤序列 | 停 | 适用 |
|---|---|---|---|
| 轻量 | 0 → [1+2] → [3+4+5] | 2 | 短篇感/试水 |
| 标准 | 0 → 1 → [2+3] → [4+5] | 3 | 大部分网文 |
| 完整 | 0 → 1 → 2 → 3 → 4 → 5 | 3 | 重结构文 |

> 档位在步 0 由作者选定（记入台账方法论声明）；不确定先标准档，可升级。**不强制完整档**。

### 步 0·信息采集（四轮式开场）

> **方法论书指引**（先读后操作）：**《小说的骨架》第 2 章（完美评述）**——理想评论家口吻的成品书评，作目标态锚；操作已萃取进 [idea-seed.md](idea-seed.md)「完美评述」节，直接用，不另读原文。

**故事面**（所有书都做）——四轮开场（定调→定形→北极星→定流程），按回答落地：

1. **先查选题决策**：如果项目根存在 `选题决策.md`（moshu-scan Phase 5 产出），读取它——取排在最前（可行性最高）的推荐选题作为开书起点，向用户确认；看 `扫榜日期`：距今较久则提示"市场数据可能过期，建议复扫"。缺失时先自动找一遍（从项目根及其上一级目录起、向下最多 3 层按文件名搜，跳过隐藏目录，按 mtime 由新到旧取最新 2 份，AskUserQuestion 列候选）——见下方「四轮式开场」轮 1。
2. **模糊灵感**（画面/脑洞/感觉，说不清题材卖点）：先做**灵感种子收敛**（[idea-seed.md](idea-seed.md)，产物落 `{项目根}/灵感种子.md`），Logline 作后续方向与设定的一致性尺度。
3. **定形（轮 2）**：AskUserQuestion 批问体量三数（字数/章数/卷数）＋目标平台＋终局口径；不确定按 200 万字/5 卷规划。
4. **北极星（轮 3）**：LLM 生成完美评述草稿（轮 1 答案作输入）→ 作者改定 → 落 `设定/`，作北极星尺子。
5. **核心设定落盘（轮 4 后）**：按下方「核心设定表」模板产出，**成稿先展示作者过目（可打断调整）**，确认后创建 `设定/题材定位.md`（题材核心梗三分法+对标分析，参考 [genre-core-mechanics.md](genre-core-mechanics.md)「核心梗解析」；含**终局底牌与升级台阶**登记）、`设定/关系.md`（角色关系映射，参考 [character-relations.md](character-relations.md)「四种关系类型」）、`设定/题材正文提示卡.md`（题材边界/核心逻辑/读者期待/核心爽点，参考 genre-prose-cards 索引与 [style-genre-modules.md](style-genre-modules.md)）。
6. **方法论声明（轮 4 收尾）**：台账创建后补全「方法论声明」节——仅档位一行（轮 4 答案）；三域规划深度**不再逐项问**——默认档位表（见下）作流程内参考，作者口头可调（"卷纲再细一点"即改）。

> **默认档位表**：

| 域 | 默认 | 可选档 | 不可裁剪项 |
|---|---|---|---|
| 大纲 | 全局骨架 | 前半细化 / 仅阶段一 | 终局与升级台阶（全书） |
| 卷纲 | 首卷细 | 前两卷细 | 首卷（开书必须） |
| 设定 | 核心+终局相关 | 全量前置 | 主角/金手指/核心冲突 |

**对标面**（有主对标时做）——**对标发现**（先于反应式加载，主动扫拆文库推荐，不被动等用户开口）：

1. `ls 拆文库/`（数据源）与项目 `对标/`（引用视图）列已有书目；先按当前项目目录名、`.active-book` 和 `设定/题材定位.md` 中的本书信息识别当前作品，**排除同名或来源指向当前正文的 `拆文库/{当前书}/`**。moshu-import 为重建工程生成的本书拆文分析不是对标候选，也不得复制回 `对标/`。排除后都为空 → 跳到第 4 条。
2. 逐本读题材（读 `拆文库/{书}/` 的 `概要.md` 头部或 `拆文报告.md`「基本信息」的「题材」），与本书题材/方向比对，标 同题材 / 弱相关 / 不相关。
3. 有同题材或弱相关候选 → 用 AskUserQuestion 推荐（列候选书 +「都不用」+「另拆一本」），选定主对标 1 本（走情绪/节奏/正文；文风独立由文风库提供）。选定后写入 `设定/题材定位.md`「对标登记」的 `主对标书`，并按「首次引用对标书」规则把选中书从 `拆文库/{书}/` 复制到 `对标/{书}/`（复制清单不含 文风.md——文风独立由 `文风库/文风.md` 提供）。登记后若文风库尚无该书文风，询问用户是否现在用 /moshu-style 学习（可跳过，写第一章时缺失会再次提醒）。
4. 无候选 → 无对标继续（骨架按八节点自排，见步 1）；用户想对标可先 `/moshu-analyze` 拆一本。

**对标上下文加载**（用户提到对标书或工作目录已有 `对标/` 时）：按上方第 1 条口径识别当前作品并排除自对标；随后检查 `剧情/情绪模块.md` 与 `剧情/节奏.md`——任一主产物缺失时必须停止，设置 `missing_primary_contract: true` 并给出 `repair_action`（重跑 `/moshu-analyze` Stage 3+ 或重新 `/moshu-import`），不得以 `拆文报告.md`、章节摘要或故事线代替；两个主产物都存在时先读情绪模块的读者需求/情绪引擎与可复现模块，再读节奏.md 的关键信息推进、情绪触动点和爆发节奏；拆文报告只作人类可读概览。角色/普通剧情单元/设定子目录存在时按需召回（消费方是 write，本工作流只记录引用关系）。

> 开篇的"第一个冲突/机遇"定义可参考**激发事件四问**（见 [opening-design.md](opening-design.md) :87 起——什么是/什么不是/在何处/四特质），在步 1 定全书四阶段时使用。

#### 四轮式开场（步 0 交互）

```
轮 1（定调·开放对话）：
"你想写什么类型的故事？你希望这本书给读者什么感觉？"
→ 有方向 → 进入轮 2
→ 没方向 → "要不要先扫一下最近的榜单？或者说说你想让读者有什么感觉？"
→ 提到参考书 → 固化追问："这本书最吸引你的三个点是什么？"（喂轮 3 完美评述）
   + 消歧话术："正式对标需要先拆书（长篇成本高），会参与每卷节奏校准；仅参考＝只取题材气质，不拆书。"
→ 有结构参照需求（想看看别处怎么排弧线/对手/节奏）→ 建议 `/moshu-research 结构采风`（AskUserQuestion：采风/跳过——采风产物 设定/采风-结构-*.md 供步 1 骨架取材；跳过则继续）

轮 2（定形·AskUserQuestion 批，≤4 问）：
问 A（体量三数）："这本书大概什么体量？"（总字数/总章数/分几卷一起问）
  → 不确定 → "先按 200 万字/5 卷规划，写完第一卷可以调"
问 B（平台）："目标平台？"（起点/番茄/晋江/其他，各选项带一句适配注解）
问 C（终局口径）："你要在动笔前设计好结局吗？"
  选项：完结（终局底牌+高潮定死，全书朝终点铺垫）｜开放式连载（升级台阶驱动、单元剧循环）

"方向和体量已定，现在给这本书定北极星——想象一个完全读懂这本书的评论家，

  🏃 快速（试水/脑洞文，先跑起来）
  🚶 标准（推荐——大部分网文，不确定选这个）
  🧗 完整（多线/强反转/群像）
```

### 步 1·骨架步（密度：句子）→ 🔴 停靠 1

> **方法论书指引**（先读后操作，约 5-10 分钟——不是"参考一下"，是照着走）：
> - **雪花法第 3 章（一句话概括）**：一句话 ≤25 词、不泄露结局——每卷骨架表一句话列的尺度（主语必须是主角）
> - **雪花法第 5 章（灾难的重要性）**：三次灾难=三幕骨架——高潮定死与卷内灾难的出处
> - **大师课第 2 章（结构）**：LOCK 四要素初查（主角/目标/冲突/结尾）
> - **五步法第 1 步**（[outline-methods.md](outline-methods.md)「五步大纲创建法」）：确定高潮剧情——高潮有绝对优先级（最大冲突/最多人物/最强情绪）
> - **死亡三类型与附着元素**（本批纪律，正文自包含）：赌注分 实质死亡（身体毁灭）/ 职业死亡（身份事业终结）/ 心理死亡（信念自我破碎）——每卷赌注须可指认为其中一型并逐卷递升；附着元素＝对手-主角的私人绑定（为何缠上主角/能伤他什么），让对手不是排队坐庄而是与主角互相纠缠（书证大师课 :1045）
> - **中点假胜/假败**（[outline-methods.md](outline-methods.md)「八节点故事结构」转折位）：本批新增语义——三幕中点必须明确标注假胜或假败（张力反转点，非过渡）（书证救猫咪 :1267/:1283）
> - **势力场设计**（[outline-methods.md](outline-methods.md)「势力场设计」节）：反派梯队分级/势力博弈矩阵/立场多样性——与势力场总览表衔接（本节是设计方法，总览表是落盘格式）

**故事面**（所有书都做）——基于步 0 核心设定，先写全书体量与阶段总览，再逐卷骨架：

- **全书体量与阶段总览**（卷纲前置，共同约束）：全书总章节数/目标字数/情绪曲线；四阶段划分（开篇期参考 10%-15% / 发展期 50%-60% / 高潮期 20%-25% / 收尾期 5%-10%），每阶段列核心任务/情绪基调/阶段结束时读者应建立什么；各阶段节奏公式（核心任务/情绪基调/爽点密度/伏笔策略/冲突层级/阶段钩子/禁止提前释放）；关键节点与钩子链（小/中/大高潮章位+阶段钩子链）。比例只作默认参考，按题材/目标字数/对标节奏调整。
- **终局底牌与升级台阶**（无论何档全书规划，期待债/禁止提前释放的约束根基）：定死终局底牌（登记进 `设定/题材定位.md`）与升级台阶（N 个大阶段，每卷跨 M 个）；声明裁剪只作用于中间卷粗细。
- **常驻压力**（终局底牌区新行）：贯穿全书的慢性危机（如阴德账/折寿累积——每卷结算一次的压力表，非卷级开关）；须与三重死亡赌注联动（常驻压力最终在收尾卷与赌注合流清算）。
- **每卷骨架表（八列）**：每卷一行，主角处境六要素一次填满（无空列）：

```
| 卷 | 一句话（主角中心） | 主要对手（+私人纠缠） | 危机/赌注 | 中点 | 高潮定死 | 卷末跃迁 | 字数 |
|---|---|---|---|---|---|---|---|
| 1 | {主语=主角…} | {名＋一句纠缠：为何缠上主角/能伤他什么} | {类型（实质/职业/心理死亡）＋一句} | {假胜｜假败＋一句} | {事件，可检验} | {起点状态→终点状态} | {X}万 |
```

- **写法纪律三条**：①一句话主语必须是主角，案件作宾语（"主角被迫当众揭穿家主"而非"家主被揭穿"）；②对手行必答"为何缠上主角/能伤他什么"（附着元素，见指引块）；③中点强制标注假胜或假败（三幕中点=张力反转点，非过渡）。
- **对手梯队与势力场**（全局，终局底牌节后）：总览表 `势力/人物 | 目的 | 与主角关系 | 与其他势力关系 | 活跃卷`——至少 3 个势力互有关联（**网非链**）；**势力间关系列步 1 粗排、步 2 人物步精化回填**（唯一允许的后填列，因依赖人物步势力设定）；纪律：反派间必须有博弈点（至少标注一处"可被主角借力"的矛盾）。
- **暗线设计**（全书级，势力场后）：暗线层次表 `层次 | 内容 | 读者感知节奏（哪卷闻到味/揭半层/全揭）| 主角知晓节奏 | 揭示卷`——纪律：**读者先知=悬念，主角先知=期待**，每条暗线显式标注用哪种；暗线每卷至少推进一格（步 4 线索矩阵登记推进点）；本表是写作期 `追踪/信息差.md` 的构建期蓝本（谁知道什么的预登记）。

### 开新卷（第 2 卷及后续）

卷末复盘（write 侧流程）产出 `大纲/卷复盘_第X卷.md` 后，本工作流负责下卷规划。**步 0-2 已在开书时完成（全书级），不重做**；开新卷从步 3 起增量执行。**进入时把台账构建态翻为「开卷中 卷N [日期]」**；新卷卷纲定稿（停靠 3）后翻回「定稿」。

```
"上一卷写完了，开始第 {N} 卷的构建。

📋 上卷复盘要点：
  {卷报告摘要——伏笔回收/悬置/信息差/对标偏差}

🎯 上卷定下的方向：
  {卷复盘_第{N-1}卷.md 中的下卷方向候选}

按这个方向直接进单元步？（或先调整方向）"
→ ✅ 直接进步 3 → 正常流程（停靠 2 → 步 4 → 停靠 3）
→ ✏️ 先调整 → 回到步 1 快速改骨架（只改第 N 卷的部分）
```

1. **读候选**：读 `大纲/卷复盘_第X卷.md` 的「下卷方向候选」（1-3 个，含各候选的主推线/战果线、与终局储备的衔接）；无复盘文件 → 询问作者直接进入常规开卷（或回 `/moshu-write` 续写）。
2. **作者确认**：AskUserQuestion 列候选（+「自定」），作者选定后进入增量流程。
3. **增量构建**：步 3-5 增量执行——新卷引入新角色/势力/设定 → 先补 `设定/` 档案（增量补充、不覆盖既有），再补 `大纲/卷纲_第X卷.md`（只增不改既有卷；新剧情单元卡追加到卷尾，卷级五问与契约检查照常）；纯延续卷 → 直接补新卷卷纲。
4. **边界**：新卷的首批细纲由 write 侧产出（B1b outline-workflow）；本工作流不建细纲。卷纲锁定定义沿用 write 侧口径（某卷一旦已有正文章节，该卷已写区间对应的既有剧情单元卡与对标结构坐标即视为锁定——未经用户确认不改既有内容，但允许在卷尾**追加**新剧情单元卡）。

> 开新卷同样先读 `设定/构建台账.md`（存在时，见「进入规则」）——汇报当前焦点/待定项/方法论档位后再规划。

## 定稿与 artifact 创建

作者在停靠 3 确认定稿后：

- **写入定稿标记**：卷纲头部加 `定稿：v1.0（YYYY-MM-DD，构建环）` 行——这是构建完成的标记（v1.0），write 侧据此放行细纲/正文；不构成"锁定"（锁定=已有正文章节，见「与现有机制的关系」）。
- **大纲/大纲.md**：全书卷级鸟瞰（卷名+字数+章数+核心事件+状态变化，一段式汇总）。
- **大纲/卷纲_第X卷.md**：每卷的剧情单元+情绪弧线（含章节定位）+人物弧线+伏笔+反转+线索矩阵+对标结构坐标（参考 [outline-methods.md](outline-methods.md)「大纲三层结构法」 + [emotional-arc-design.md](emotional-arc-design.md)「六种弧线速查」 + [reversal-toolkit.md](reversal-toolkit.md)「反转类型」）。
- **追踪事务初始状态**：按 `references/tracking-transaction.md`（write 侧共享副本）构造第 0 章初始化 JSON，执行 `scripts/tracking_commit.py init`（build 侧共享副本），生成检查点（续写状态卡，固定 7 栏）、空的伏笔/时间线视图与目录；核心角色动态快照可在第一次正文事务中创建（write 侧）。

> 追踪 init 后，**事实层归 write**：build 不再写 `追踪/`，只读（修订工作流的边界判定输入）。

## Agent 调用（moshu-architect / moshu-character-designer）（agent/技能选型判据见 AGENTS.md §5「Agent 使用判据」）

- **moshu-architect（步 0 题材定位）**：轻量题材定位优先由主会话完成；只有涉及复杂世界观、多线结构、强反转工程或用户明确要求时，才调用。已部署时（检查 `.claude/agents/moshu-architect.md` 是否存在）可 spawn `Agent(subagent_type: "moshu-architect", prompt: "项目目录：{dir}\n任务类型：题材定位\n查询参数：{用户选择的方向+对标信息}")`。如 agent 不可用，由主线程直接执行。
- **moshu-architect + moshu-character-designer（步 1-2 骨架与人物）**：结构复杂/反转链多/角色关系密时辅助骨架与角色设定（任务类型：核心设定/角色设定）。spawn prompt 必须原样附带「moshu-architect 契约摘要」。
- **moshu-architect（步 3-5 卷级）**：只有结构复杂、反转链多或主会话方案不稳时，才调用辅助卷级结构（卷级大纲、钩子/反转/情绪弧线设计）。**首批细纲的产出不在本工作流**（归 write，B1b）。

> **moshu-architect 契约摘要（spawn 时必须原样附带）**：部署的 moshu-architect agent 不认识本 skill 的 `references/reader-contract-and-progression.md`，只能靠 spawn prompt 里带的这段摘要对齐 schema。摘要内容（终局储备边界/透支两问/剧情单元/细纲层字段/读者契约与主角代理权/关键节点四问）与 write 侧同源——从 `references/reader-contract-and-progression.md` 摘取（本文件不复制全文，引用即挂载）。
