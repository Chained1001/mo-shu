# workflow-build.md：开书构建与开新卷（构建环）

> **来源声明**：本文件源自 moshu-write 侧开书工作流的构建段拆分（V2.1 批 B1a 改写，非逐字拷贝；B1b 起旧文件删除、细纲职责由 write 侧 outline-workflow 承接）；**细纲部分（细纲模板/安全七检/分批建纲/中途补纲/细纲后设定补全）归 write 侧**。构建环只做设定/大纲/卷纲的计划层工作。
>
> **对标书路径查找**（本书引用规则）：优先 `{项目}/对标/{书名}/`，不存在则回退 `拆文库/{书名}/`；排除同名或来源指向当前正文的 `对标/{当前书}/`。
>
> **消费侧只读**：本工作流读 `追踪/`（last_committed_chapter、连贯性风险、信息差冲突）作输入，不写任何追踪文件——唯一例外是开书末尾的 `tracking_commit.py init`（事实层第 0 章基线，见「artifact 创建」）。

## 构建台账与进入规则（三种入口统一）

构建环三种入口（开书构建 / 修订 / 开新卷）的第一步均先读 `设定/构建台账.md`（一册一份，作为构建期对谈的锚——构建态与方法论单真源）：

- **存在** → 读取它，向作者汇报「当前焦点 + 待定 N 项 + 方法论档位」，确认后再继续后续对谈。
- **不存在且为开书** → 在「方法论声明步」后创建台账（空台账，先填方法论声明）。
- **不存在且为修订/开新卷** → 提示先创建空台账（`设定/构建台账.md`）再继续。

### 台账模板（书项目产物 `设定/构建台账.md`）

```markdown
# 构建台账（{书名}）

## 方法论声明（开书定，可修订——修订走变更日志）
- 构建顺序：剧情先行（默认）｜设定先行
- 规划深度：大纲=全局骨架（默认）｜前半细化｜仅阶段一；卷纲=首卷细（默认）｜前两卷细；设定=核心+终局相关（默认）｜全量前置
- 注：无论何档，终局与升级台阶全书规划（契约体系根基）

## 当前焦点
{正在打磨什么 + 所属域（题材/设定/大纲/卷纲）——螺旋跳转的锚点}

## 待定项（未收敛决策）
| # | 决策点 | 所属域 | 候选 | 当前倾向 | 轮次 |
|---|---|---|---|---|---|
| 1 | {} | {} | {A / B / C} | {偏 X} | {N} |

## 已收敛 → 变更日志
- {决策一行摘要} → 详见 大纲/变更日志.md（第 N 行/对应日期）
```

### 更新规则

- **决策收敛必写**：待定项 → 已收敛，并在 `大纲/变更日志.md` 追加一行（变更同步，不重复变更日志职能）。
- **会话收尾必结**：收尾时定格当前焦点与待定项（台账是构建期对谈的快照锚，不是机读状态机）。

## 开书构建

### Phase 1：确认选题方向

**先查选题决策**：如果项目根存在 `选题决策.md`（moshu-scan Phase 5 产出），读取它——取排在最前（可行性最高）的推荐选题作为开书起点，向用户确认：「扫榜建议写 X（能爆的原因 Y，差异化 Z），按这个开书？」并看 `扫榜日期`：距今较久则提示"市场数据可能过期，建议复扫"。用户认可 → 带该选题的题材/卖点/差异化进入 Phase 2。

缺失时先自动找一遍：从项目根及其上一级目录起、向下最多 3 层按文件名搜 `选题决策.md`（跳过隐藏目录），按 mtime 由新到旧取最新 2 份。搜到 → 用 AskUserQuestion 列候选（路径 + 文件里的 `扫榜日期`，另加「我自己给路径」和「都不用」）；选中某份 → 复制到项目根，再按上一段读取；选「我自己给路径」→ 让用户粘路径，同样复制到项目根；选「都不用」→ 走下面的常规提问。搜不到 → 问一句：「有扫榜生成的 `选题决策.md` 吗？放到项目根或粘贴路径；没有就直接答下面的问题。」仍无 → 走下面的常规提问。

如果用户已有方向 → 跳过下面的方向提问，但仍先做下方「对标上下文加载」（含对标发现），再进入 Phase 2。

如果用户给的不是方向而是**模糊灵感**（画面/脑洞/感觉，说不清题材卖点）：先做**灵感种子收敛**（`references/idea-seed.md`，产物落 `{项目根}/灵感种子.md`），Logline 作后续方向提问与 Phase 2 设定的一致性尺度。有方向 → 下方匹配；仍无 → 常规提问。

如果用户没有方向：问用户：**「你想让读者什么感觉？有没有喜欢的书想对标？你的优势是什么（脑洞好/文笔好/节奏感好/生活经验丰富）？」**

#### 对标上下文加载

**对标发现（先于下方反应式加载）**：无论用户是否点名对标书，先扫 `拆文库/` 按题材主动推荐，不要被动等用户开口。

1. `ls 拆文库/`（数据源）与项目 `对标/`（引用视图）列已有书目；先按当前项目目录名、`.active-book` 和 `设定/题材定位.md` 中的本书信息识别当前作品，排除同名或来源指向当前正文的 `拆文库/{当前书}/`。moshu-import 为重建工程生成的本书拆文分析不是对标候选，也不得复制回 `对标/`。排除后都为空 → 跳到第 4 条。
2. 逐本读题材（读 `拆文库/{书}/` 的 `概要.md` 头部或 `拆文报告.md`「基本信息」的「题材」），与本书题材/方向比对，标 同题材 / 弱相关 / 不相关。
3. 有同题材或弱相关候选 → 用 AskUserQuestion 推荐（列候选书 +「都不用」+「另拆一本」），选定主对标 1 本（走情绪/节奏/正文；文风独立由文风库提供）。选定后写入 `设定/题材定位.md`「对标登记」的 `主对标书`（Phase 2 落文件，此处先记选择），并按「首次引用对标书」规则把选中书从 `拆文库/{书}/` 复制到 `对标/{书}/`（复制清单不含 文风.md——文风独立由 `文风库/文风.md` 提供）。登记后若文风库尚无该书文风，询问用户是否现在用 /moshu-style 学习（可跳过，写第一章时缺失会再次提醒）。
4. 无候选 → 无对标继续（大纲按八节点自排，见 Phase 3）；用户想对标可先 `/moshu-analyze` 拆一本。

如果用户提到对标书或工作目录下已存在 `对标/` 目录：

1. 先按上方「对标发现」第 1 条的同一口径识别当前作品，排除同名或来源指向当前正文的 `对标/{当前书}/`——老导入项目里可能留着历史误建的自对标目录。排除后没有外部对标书时不进入下面几步，按无对标继续。
2. 按对标书路径查找规则检查 `剧情/情绪模块.md` 与 `剧情/节奏.md`。
3. 任一主产物缺失时必须停止，设置 `missing_primary_contract: true`，并给出 `repair_action`：重跑 `/moshu-analyze` Stage 3+ 或重新 `/moshu-import`；不得以 `拆文报告.md`、章节摘要或故事线代替。
4. 两个主产物都存在时，先读 `剧情/情绪模块.md` 的读者需求 / 情绪引擎与可复现模块，再读 `剧情/节奏.md` 的关键信息推进、情绪触动点和爆发节奏；`拆文报告.md` 只用作人类可读概览。
5. 如果角色、普通剧情单元或设定子目录存在，写作时按需召回相关模块（消费方是 write，本工作流只记录引用关系）。

根据回答做匹配：
- 脑洞好 → 推荐：系统文、诸天流、无限流
- 文笔好 → 推荐：仙侠、历史、文艺向都市
- 节奏感好 → 推荐：都市爽文、重生文、游戏文
- 生活经验丰富 → 推荐：行业文、都市日常、种田文

#### Agent 调用：moshu-architect

moshu-architect 属于高层级结构设计 agent。轻量题材定位优先由主会话完成；只有涉及复杂世界观、多线结构、强反转工程或用户明确要求时，才调用 moshu-architect。确认选题方向后，如果项目已部署 moshu-architect agent（检查 `.claude/agents/moshu-architect.md` 是否存在），可 spawn `Agent(subagent_type: "moshu-architect", prompt: "项目目录：{dir}\n任务类型：题材定位\n查询参数：{用户选择的方向+对标信息}")` 辅助题材分析和核心梗设计。如 agent 不可用，由主线程直接执行。

> **moshu-architect 契约摘要（spawn 时必须原样附带）**：部署的 moshu-architect agent 不认识本 skill 的 `references/reader-contract-and-progression.md`，只能靠 spawn prompt 里带的这段摘要对齐 schema。摘要内容（终局储备边界/透支两问/剧情单元/细纲层字段/读者契约与主角代理权/关键节点四问）与 write 侧同源——从 `references/reader-contract-and-progression.md` 摘取（本文件不复制全文，引用即挂载）。

#### 方法论声明步（Phase 1 收尾）

Phase 1 收尾时用 AskUserQuestion 确认三项方法论决策并写入台账「方法论声明」节（开书确定；后续修订走既有修订语义）：

1. **构建顺序**：剧情先行（默认）｜设定先行。
2. **三域规划深度档位**（默认档位表见下）：大纲=全局骨架（默认）｜前半细化｜仅阶段一；卷纲=首卷细（默认）｜前两卷细；设定=核心+终局相关（默认）｜全量前置。

> **默认档位表**：

| 域 | 默认 | 可选档 | 不可裁剪项 |
|---|---|---|---|
| 大纲 | 全局骨架 | 前半细化 / 仅阶段一 | 终局与升级台阶（全书） |
| 卷纲 | 首卷细 | 前两卷细 | 首卷（开书必须） |
| 设定 | 核心+终局相关 | 全量前置 | 主角/金手指/核心冲突 |

### Phase 2：核心设定（剧情模式驱动）

**引擎**：从目标情绪 → 剧情模式 → 对标模块（把具体角色看成功能位）→ 用本书角色和设定填充——**剧情模式驱动，不是设定先行**。从 Phase 1 确定的目标情绪出发，在题材框架中找到对应剧情模式，从对标书提取可复用模块，用用户自己的角色和设定填充。

帮用户确立以下核心要素：

```
## 核心设定表

### 基本信息
- 书名：{暂定名}
- 题材/类型：{主类型 + 副类型}
- 目标平台：{起点/番茄/晋江/其他}
- 预计字数：{X} 万字
- 目标读者：{画像}
- 读者契约：{本书承诺的核心阅读快感；参 reader-contract-and-progression.md}
- 主角高光/代理权：{主角不可替代的判断、选择或贡献}
- 核心期待债：{开篇必须偿还的承诺}

### 一句话梗概
{主角 + 目标 + 阻碍 + 反转，一句话概括全书}

### 主角设定
- 姓名：{}
- 年龄：{}
- 核心特质：{2-3 个关键词}
- 金手指/核心能力：{}
- 弱点/缺陷：{让角色更立体的地方}
- 核心动机：{他为什么要做这件事}

### 世界观骨架
- 时代/背景：{}
- 核心设定：{区别于同类作品的独特设定}
- 力量体系：{如果有，简单概括}
- 社会结构：{影响故事的关键设定}
- 信息生态（可选）：{信息速度/知识载体/信息壁垒/传播失真}
- 货币与经济（可选）：{钱怎么来/怎么花/什么值钱}
- 规则与禁忌（可选）：{世界运行的硬规则与打破后果}
- 资源与限制（可选）：{稀缺资源、能力代价、行动边界}
- 术语表（可选）：{专有名词统一释义}

> 世界观骨架只记录**长期有效**的世界事实；章节内的临时状态、当前关系变化、开放线索不进世界观文件，交给 `追踪/`。

### 核心冲突
- 主线矛盾：{}
- 终极 Boss/终极阻碍：{}
```

完成核心设定后，按上方「核心设定表」模板创建以下 artifact：
- **设定/关系.md**：角色关系映射（参考 `character-relations.md`「四种关系类型」）
- **设定/题材定位.md**：题材核心梗三分法+对标分析（参考 `genre-core-mechanics.md`「核心梗解析」）。对标分析表保留 2-3 行摘要，详细数据见 `对标/` 目录
- **设定/题材正文提示卡.md**：从 `设定/题材定位.md` + [genre-prose-cards.md](genre-prose-cards.md)（索引）+ `references/genre-prose-cards/`（单题材正文卡目录，按题材分类优先）+ [style-genre-modules.md](style-genre-modules.md)（通用流派补充）抽取本书正文层题材卡，只写题材边界、核心逻辑、读者期待、核心爽点/情绪、正文落点、前中后期打法、节奏密度、场景颗粒、禁止漂移；不写通用格式规则，不覆盖 `文风库/文风.md`

#### Agent 调用：moshu-architect + moshu-character-designer

核心设定阶段，如果项目已部署对应 agent（检查 `.claude/agents/` 下的 `moshu-architect.md` 和 `moshu-character-designer.md` 是否存在），可 spawn 以下 agent 辅助：
- `Agent(subagent_type: "moshu-architect", prompt: "项目目录：{dir}\n任务类型：核心设定\n查询参数：世界观构建+核心冲突设计")` — 辅助世界观和核心冲突设计；spawn prompt 必须原样附带「moshu-architect 契约摘要」
- `Agent(subagent_type: "moshu-character-designer", prompt: "项目目录：{dir}\n任务类型：角色设定\n查询参数：{主角设定信息}")` — 辅助角色设定和语言风格档案

如 agent 不可用，由主线程直接执行。

### Phase 3：卷级大纲

按台账声明的大纲档位执行；无论何档，**终局与升级台阶必须全书规划**（期待债/禁止提前释放的约束根基），声明裁剪只作用于中间卷粗细。

#### 全书体量与阶段总览（卷纲前置）

卷级大纲前先写全书体量与阶段边界，作为后续卷纲、细纲、日更补纲的共同约束。比例只作默认参考，必须按题材、目标字数和对标节奏调整，不能机械套模板。

```
## 全书体量与阶段总览

- 全书总章节数：{X} 章
- 目标字数：{X} 万字
- 全书情绪曲线：{压抑/期待 → 加压/反转 → 爽感/震撼 → 余韵/圆满；标注关键阶段}

### 阶段划分
1. 开篇期（第 {A}-{B} 章，参考 10%-15%）：核心任务 {}；情绪基调 {}；阶段结束时读者应建立 {}
2. 发展期（第 {A}-{B} 章，参考 50%-60%）：核心任务 {}；情绪基调 {}；阶段结束时读者应建立 {}
3. 高潮期（第 {A}-{B} 章，参考 20%-25%）：核心任务 {}；情绪基调 {}；阶段结束时核心矛盾应 {}
4. 收尾期（第 {A}-{B} 章，参考 5%-10%）：核心任务 {}；情绪基调 {}；阶段结束时主线伏笔应 {}

### 各阶段节奏公式
- 开篇期：核心任务 / 情绪基调 / 爽点密度 / 伏笔策略 / 冲突层级 / 阶段钩子 / 禁止提前释放
- 发展期：同上
- 高潮期：同上
- 收尾期：核心任务 / 情绪基调 / 爽点密度 / 伏笔策略 / 冲突层级 / 阶段钩子 / 必须回收清单

### 关键节点与钩子链
- 关键转折点：第 {X/Y/Z} 章，各自承担 {事件功能 + 情绪效果}
- 小/中/大高潮：小高潮第 {X/Y/Z} 章；中高潮第 {X/Y} 章；大高潮第 {X} 章
- 阶段钩子链：开篇期结尾指向发展期；发展期结尾指向高潮期；高潮期结尾指向收尾期
```

#### 卷级大纲（全书结构）

```
## 卷级大纲

### 第一卷：{卷名}（约 {X} 万字，{Y} 章）
- 功能：{铺垫/起步/第一个大爽点}
- 所属阶段：{开篇期/发展期/高潮期/收尾期；可跨阶段时写清分界章}
- 卷契约：{本卷承诺的读者快感、主角高光、主要期待债}
- 终局储备：{本卷主推线1条 + 战果线若干；本卷解锁哪个终局里程碑、禁碰哪些未解锁底牌，参 `设定/题材定位.md`「终局底牌与升级台阶」小节 与 reader-contract-and-progression.md}
- 剧情单元：{1–3 万字剧情单元卡写在卷纲内，不另建单独文件；字段模板：**单元ID/位置（`{L卷号-序号}`，write 细纲按此锚定）**、章节范围、对标剧情参照、单元节拍/章功能分配、结构分布/情节点索引（来自拆文剧情单元）、单元承诺、风险等级；契约/推进规则见 `references/reader-contract-and-progression.md`}——**细纲消费口径**：write 侧 outline-workflow 每章细纲必填「单元ID/位置」（细纲_第N章.md 头部），workflow-daily/chapter-core 写前按 卷契约 → 当前剧情单元（单元ID/位置）→ 章节细纲 顺序消费，故单元ID 必须可锚定（缺则 write 补纲时按 `{L卷号-序号}` 口径回填，但构建时先产出避免悬空）
- 阶段边界：本卷可释放 {信息/关系/能力}；本卷禁止提前释放 {后期核心真相/终局底牌}
- 核心事件：{一句话}
- 起始状态 → 结束状态：{主角从 {A} 变成 {B}}

### 第二卷：{卷名}
...

### 最终卷：{卷名}
- 功能：{高潮 + 收尾}
```

**大纲安全审查（卷级）**：先按 [emotional-methods.md](emotional-methods.md) 设计正向情绪发动机与题材核心兑现，再用权威文件的主角代理权/所有权/成长负向风险护栏诊断（因果权 + 结算权、关键节点四问与期待所有权，检查每个剧情单元的主角目标、关键选择、兑现归属、核心资产交换、机构/势力边界、换书债和推进线）。契约破坏 必须修纲，需补强 必须补交换/铺垫/成本。再做两个可证伪降级检查：① 删除题材核心的对象/关系/问题后，是否退化为通用职业升级或换皮情节？② 删除主角后，情绪兑现是否仍基本不变？任一为“是”就先修引擎。

## 开新卷

卷末复盘（write 侧流程）产出 `大纲/卷复盘_第X卷.md` 后，本工作流负责下卷规划：

> 开新卷同样先读 `设定/构建台账.md`（存在时，见「进入规则」）——汇报当前焦点/待定项/方法论档位后再规划。

1. **读候选**：读 `大纲/卷复盘_第X卷.md` 的「下卷方向候选」（1-3 个，含各候选的主推线/战果线、与终局储备的衔接）；无复盘文件 → 询问作者直接进入常规开卷（或回 `/moshu-write` 续写）。
2. **作者确认**：AskUserQuestion 列候选（+「自定」），作者选定后进入增量流程。
3. **增量构建**：回 Phase 2/3 增量补充——新卷引入新角色/势力/设定 → 先补 `设定/` 档案（增量补充、不覆盖既有），再补 `大纲/卷纲_第X卷.md`（只增不改既有卷；新剧情单元卡追加到卷尾，卷级五问与契约检查照常）；纯延续卷 → 直接补新卷卷纲。
4. **边界**：新卷的首批细纲由 write 侧产出（B1b outline-workflow）；本工作流不建细纲。卷纲锁定定义沿用 write 侧口径（某卷一旦已有正文章节，该卷已写区间对应的既有剧情单元卡与对标结构坐标即视为锁定——未经用户确认不改既有内容，但允许在卷尾**追加**新剧情单元卡）。
