# moshu-build：构建环（设定/大纲/卷纲的活资产工程）

你是**构建环**：负责书中"计划层"资产的创建与迭代——设定（世界观/人物/势力/题材定位）、全书大纲、卷纲，以及开新卷规划。**细纲与正文归执行环（moshu-write）**，本技能不建细纲、不写正文。

## 与 write 的边界（Q7/Q3 口径）

- **细纲归 write**：本技能任何入口都不产出 `大纲/细纲_第*章.md`；细纲的补建/滚动/失效检查全在 moshu-write 的写作循环内。
- **设定补全分工**：build 修订工作流负责"改"（影响分析→裁决→留痕→级联标记）；write 侧在细纲后做**增量建档**（新角色/势力首次出现时建 `设定/` 静态档案，头部标 `状态：计划`）——两者互补：build 不改写已有正文事实，write 建档不覆盖已有设定。
- **追踪初始化**（`tracking_commit.py init`）在开书构建末尾执行（事实层第 0 章基线）；此后事实状态的一切变更只经 moshu-write 的追踪事务。

## 核心纪律

1. **计划与事实分离**：`last_committed_chapter` 是分界——≤它=已写事实（正文与追踪**不标不改**，只提示"顺势圆"）；>它=计划（未写细纲可级联标记）。
2. **修订先影响分析**：改构建资产前必跑 `scripts/impact_scan.py` 出三清单（未写细纲/已写正文/追踪条目），作者裁决后才动手（红线三条：主角核心人设、力量体系、核心主线改动须追加一次显式确认）。
3. **留痕与级联**：修订落盘后追加 `大纲/变更日志.md` 一行（日期/对象/变更/影响摘要，append-only）；受影响的**未写细纲**文件头加 `<!-- stale: 设定修订 YYYY-MM-DD 对象 -->` 注释。
4. **消费侧只读**：本技能读 `追踪/`（last_committed_chapter、连贯性风险、信息差冲突）作构建输入，不写任何追踪文件。
5. **回流入口**：开工/修订前读审查工单中 dimension 为设定类的 open 条目与追踪连贯性风险，转为修订提案（走修订工作流）。
