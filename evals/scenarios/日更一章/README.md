# 场景剧本：日更一章

- 定位：真实 Claude Code 会话走查**日更一轮**的端到端行为（开书后首个日更会话）。
- 用途：给真人带 agent 走查用；机检项可被 `check-eval-scenarios.sh` 静态校验与脚本复现，人工项需走查者判断。
- 前置：项目已按 `开书剧本` 初始化（`正文/`、`大纲/`、`追踪/`、`设定/` 齐备）。

## 步骤

1. 新开 Claude Code 会话，输入 `/moshu-write`（或 `$moshu-write`），确认路由到日更流程。
2. 触发"日更/续写"：明确说"写第 1 章"（或"日更"），要求走 `workflow-daily.md`。
3. 走 Step 1 快速上下文加载（`tracking_commit.py check` + 续写状态卡读取）。
4. 走 Step 2 逐章写作（写前准备 → 正文 → 写后机检 → 追踪事务）。
5. 走 Step 3/4 批末收尾（确定性收尾脚本 + `tracking_commit.py check` + 进度汇报）。

## 断言

| 机检项 | 断言（可判过/不过） | 类型 |
|---|---|---|
| `tracking_commit.py check` 退出 0，且输出含 `"last_committed_chapter": 1` | 过：退出 0 且章号正确；不过：任何非零退出或章号不符 | [机检] |
| `追踪/上下文.md` 恰含 7 个顶层栏目（当前位置/长期约束/核心角色状态/活跃伏笔/近三章速记/下一章承诺/连贯性风险） | 过：7 栏齐全；不过：缺栏/多栏 | [机检] |
| `追踪/信息差.md` 存在且非空（含 `| ID |` 表头） | 过：存在非空；不过：缺失或空 | [机检] |
| `check` 输出含 `suspension_warnings` 字段（悬置预警，候选性质） | 过：字段存在；不过：字段缺失 | [机检] |
| 批末收尾清单含 `check-prose-candidates.js` 且运行后 `blocking_count: 0`（候选机检不拦截） | 过：退出 0 且计数为 0；不过：退出非 0 或计数非 0 | [机检] |
| `正文/第001章_*.md` 存在且非空 | 过：存在非空；不过：缺失或空 | [机检] |
| 章文件不含 `第X章/上一章/本章` 等写作工程词（正文元信息隔离） | 过：零命中；不过：命中 | 人工项 |
| 写后机检未出现 blocking 欠账即继续（AI 味检测器语义） | 过：流程未被阻断；不过：有 blocking 未清仍继续 | 人工项 |
| 批末进度汇报含章数/字数/漂移处理 | 过：三项齐备；不过：缺项 | 人工项 |

> 规则依据：`skills/moshu-write/references/workflow-daily.md`（日更四步与批末收尾）。
