## 二、技能矩阵（目标态）

```
供给环  scan / analyze / style / import / cdp
构建环  build（新拆，见 §三）            ← 本提案核心
执行环  write（细纲+正文+事务+卷复盘执行）
质量环  review / deslop
基建    setup / moshu（路由+next_step+看板）
```

**边界判定**（四判据：生命周期/频率/心智/上下文——见会话沉淀）：设定/大纲/卷纲归 build（迭代型活资产）；**细纲归 write**（每章热路径，写前补纲/批补纲/失效检查都在写作循环内——v7 的章纲同样晚绑定正文保护，卡2.11 前据）；卷复盘**执行**归 write、复盘产出的**下卷规划**归 build。其余九技能经判据检验不动。

## 三、moshu-build 技能设计（三职责）

### 3.1 开书构建（现 workflow-setup Phase 1-2 平移）
设定（题材定位/世界观/人物卡）+ 大纲.md + 首卷卷纲。产物目录不变（`设定/`、`大纲/`）——**文件契约零变更**，下游 write 无感。

### 3.2 修订工作流（新能力，本提案的核心增量）

```
作者发起修订（改设定/大纲/卷纲）
  → ① 影响分析（新确定性脚本 impact_scan.py，mo-shu 自定）：
       grep 关键词/实体名 × {未写细纲, 已写正文, 追踪条目} 三清单
       （mo-shu 无"发布"概念，以 last_committed_chapter 分界：≤它=已写事实，>它=计划——P3/P4）
  → ② 作者裁决：看完三清单决定 改/不改/缩小范围（AskUserQuestion，不做拦截）
  → ③ 留痕落盘：修订本体 + 追加 大纲/变更日志.md 一行（日期/对象/变更/影响范围摘要）——v7 卡2.2 + v6 卡2.11 变更日志
  → ④ 级联标记：受影响的未写细纲文件头加 stale 注释（`<!-- stale: 设定修订 <日期> <对象> -->`），
       正文与追踪**不标不改**（已写事实按 P4 走"顺势圆"提示，不自动改动）
  → ⑤ 下次写作在细纲补建/复核步骤消费 stale 标记（挂 write 现有"细纲失效检查"扩展，不新开管线）
```

- **红线三条**（v6 卡2.11 方法论移植，提示级不拦截）：主角核心人设、力量体系、核心主线改动时，影响分析后追加一次显式确认。
- **回滚**：一期不做（v7 goto/rescue 是 git 仓库级能力，mo-shu 无书仓管辖权——总纲附录 B 维持）；留痕靠变更日志 + 追踪事务。

### 3.3 开新卷规划（现 workflow-setup:6 语义平移）
消费 `卷复盘_第X卷.md` 的下卷方向候选 → 作者确认 → 新卷纲。与 3.2 共用修订工作流（卷纲也是构建资产）。

### 3.4 回流入口（不新建管线）
执行环的两条现有流出 → build 的两条入口：①审查工单中 dimension 为设定类的 open 条目；②追踪的连贯性风险/信息差冲突。build 开工时读取并转为修订提案（走 3.2 流程）。——P6，挂现有 review-tickets 与追踪事务。

## 四、资产分层总表（mo-shu 落地）

| 资产 | 位置 | 真源 | 环 | 修订代价 |
|---|---|---|---|---|
| 设定（世界观/人物卡） | `设定/` | 作者可见 MD | build | 计划级（走 3.2） |
| 大纲/卷纲 | `大纲/大纲.md`、`卷纲_第X卷.md` | 作者可见 MD | build | 计划级（走 3.2） |
| 细纲 | `大纲/细纲_第XXX章.md` | 同上 | **write** | 轻计划级（stale 后重建） |
| 正文 | `正文/` | 章文件 | write | 事实级（走去味/重写，不走 3.2） |
| 事实状态 | `追踪/_tracking-state.json` | state（派生视图只读） | write | 事实级（只经追踪事务） |
| 变更日志 | `大纲/变更日志.md`（新） | append-only | build | — |
| stale 标记 | 细纲文件头 HTML 注释 | 派生标记 | build 写 / write 消费 | — |

## 五、角色矩阵：一期零新增

7 个消费型 agent 维持。**不加生成型构建 agent**（理由：构建=作者裁决密集的对谈，subagent 适合并行审查不适合裁决；v7 全线也只有 2 个审查角色）。二期若开书推倒重来成为高频痛点，再议"草案候选生成"（v7 候选制移植），须作者发起。
