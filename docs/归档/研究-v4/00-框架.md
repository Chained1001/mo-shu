# 研究-v4 框架（R1：迭代修订资产——大纲/卷纲/细纲/正文/设定的活资产演化）

- 版本：v1.0
- 日期：2026-08-21
- 角色：研究员（只挖事实不做判断）
- 命题：大纲/卷纲/细纲/正文/设定（世界观/人物/力量体系）在实际写作中反复修订——它们是迭代演化的活资产。本轮挖各成熟套件如何处理这件事。
- 前置：研究-v3 已覆盖 22 维全景（docs/研究-v3/00-维度框架.md）；本轮只挖增量维度，已有结论标"见研究-v3 档案X"不重做。

## 六维挖掘框架

| 维 | 名称 | 挖什么 |
|---|---|---|
| 1 | 资产分层 | 设定/大纲/卷纲/细纲/正文各是什么文件/结构？谁是真源谁派生？ |
| 2 | 修订机制 | 设定或大纲中途修改时：影响分析（波及哪些下游）？级联/stale 标记？回滚？版本管理？触发点与代价 |
| 3 | 构建-执行分离 | 构思/设定/大纲环节与写章环节如何切分（独立命令/workflow/agent/会话）？细纲归构建还是执行？ |
| 4 | 技能/角色架构 | 功能划分原则、角色清单（生成型/消费型）、数量与过度拆分教训 |
| 5 | 上下文衔接 | 构建产物如何喂给写作（切片/按需/全量）？写作中的变化如何回流构建层？ |
| 6 | 人机分工 | 修订流程的作者裁决点（候选制/影响清单/确认时机） |

- 每张卡片 = 一条事实：维度编号 | 机制一句话 | 证据（相对路径:行号，2-3 处）| 档案（【事实】/（推断）/存疑）| 版本标注（v6/v7 等）
