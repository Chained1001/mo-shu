# 09·设计理念评估与优化审计（开源强化·第三轮）

> **作者命题（2026-08-27）**：mo-shu 的设计理念是「模仿人类职业作家的写作流程和思维（思维很重要）」；研究开源项目的目的是看现有项目的架构/设计/方法论有没有优化可能（流程优化、拆分优化、性能优化等），并**合理评估这套设计思想本身**。
> **证据基线**：01-08 号研究报告（13 仓源码级）+ mo-shu 本仓实测文件。推断处标注（推断）。

---

## 1. 设计理念评估

### 1.1 先解构：模仿人类作家 = 模仿什么

「人类职业作家」不是一个整体，拆开是两层：

- **流程层（外显）**：扫榜→拆书→构思→卷纲→细纲→初稿→修改→复盘。这是网文工业的真实生产链，mo-shu 用 11 个 skill 逐一对应（scan/analyze/build/细纲/write/deslop+review/卷复盘）。
- **思维层（内隐）**：mo-shu 真正下功夫的地方——三遍苏格拉底（写前想清、写中自查、写后打磨，「答不出=设计未完成」的强制自问）；大纲安全七检（构思期自我质询，含「删掉题材核心是否退化为换皮」「删掉主角情绪兑现是否不变」两个可证伪降级检查）；情绪引擎与读者契约（以读者体验倒推设计，而非先有情节再找意义）；浮现记录（灵感随时捕捉进台账）；密疏预算（对「哪里该慢镜头哪里该带过」的自觉）。

**判据（本评估的尺子）**：模仿的对象应该是职业作家做每件事的**功能原因**，不是形式。人类重读笔记是因为记忆有限——AI 的等价功能是点名注入的上下文包，不是「也让 AI 装作记忆不好去全量重读」。这个判据后面反复用到。

### 1.2 外部验证：13 仓对照下的独立收敛与差异化

**四条独立收敛证据**（不同项目各自撞向 mo-shu 已有的位置）：

1. **文档层级收敛**：autonovel 5 层协同演化（02）、Claude-Book 四目录（07）、lnw L0-L5 分层摘要（04）——与我们 大纲/卷纲/剧情单元卡/细纲 四层是同构答案。
2. **协作优先收敛**：DukeTwoCan 把 autonovel 从全自治改造成 collaboration-first（02）——从另一个方向走到了我们「作者做品味」的默认位。
3. **门禁哲学收敛**：AIStoryWriter 代码注释自证「LLM 打 0-100 分全是垃圾，改布尔才稳」（07）——与我们机检阻断/候选两列、候选永不拦截同向。
4. **状态层收敛**：Claude-Book 的 state 让 agent 手写、timeline 全量 append，18 章 2256 行不可扩展（07）；AI_NovelGenerator 覆盖写无事务（08）——反证我们 tracking_commit 统一提交+脚本派生视图的必要性。

**mo-shu 独有、13 仓无一具备**（理念红利，护城河所在）：

| 机制 | 人类作家对应思维 | 外部最接近物 |
|---|---|---|
| 拆文（analyze）+采风（research）双学习环 | 扫榜拆书是网文作者真实学习方式 | 无（StoryCraftr 仅「参考作者人设」一句话，03） |
| 情绪引擎/读者契约/期待债 | 职业作者「写给读者看」的自觉 | 无（外部全部停留在结构/记忆层） |
| 三遍苏格拉底 | 「想清楚再动笔」的自我质询 | autonovel 分数驱动修订（更粗暴）、AI_NovelGenerator 无自修（08） |
| 三级评审尺子（对标拆文>虚拟对标>理想书评） | 「照着最好的写」 | 无 |
| 治理体系（宪法/守卫矩阵/文档预算/施工协议） | 编辑部流程纪律 | 无（13 仓唯一；ans 全仓 0 脚本是极端反面，01） |

### 1.3 理念的真实风险与盲区（诚实部分）

- **R1 仪式税风险**：模仿形式不加判据会产生流程税。现行最大的一笔：A 段全量读入派生视图——人类重读全部笔记因为记忆有限，AI 的等价功能是按下一章细纲点名装配（B58 正在纠）。**判据应用**：以后每加一个「人类也这么干」的环节，先答「这在 AI 身上服务什么功能、成本几许」。
- **R2 复盘单薄**：人类作家最强的学习循环是「从自己已发作品的数据与评论学习」（追读曲线、章评）。我们有卷复盘（产品旅程四阶段之一），但平台数据回流未接线（远期项，涉平台数据获取，暂不动）。**裁决注记（2026-08-27 作者裁定）**：不做读者评论/平台数据爬取回流（技术麻烦且须爬数据）——回路闭合改由三件替代：拆文（畅销作品=读者用订阅投过票的偏好结晶，即离线版读者数据）+ 作者以第一读者身份自读（作者做品味的具体化）+ 卷复盘。R2 由「远期课题」降为「已闭合（替代回路）」。
- **R3 直觉报警未建模完**：人类写作中途回「感觉不对」会停笔。build 侧有创作瓶颈信号 5 处（B30），write B 段缺显式卡文协议（B63 补一半；「不对劲就停」的自检项建议 write 走查时评估，不预设结论）。
- **R4 模仿 ≠ 质量**：「人类也这么写」不构成充分性——人类也写崩。对冲已经在位：三级尺子+机检+候选呈报+作者裁决，这套制衡是理念能走远的保险，须守住。
- **R5（推断）风格漂移的统计盲区**：style 的统计画像管篇章级特征，管不到「这句话不像他会说」——人类作者靠角色声音的内化。语声样本层（B59）正是把这种内显式化。

### 1.4 总评

| 维度 | 评级 | 一句话依据 |
|---|---|---|
| 理念与行业实际的契合 | 优 | 流程链与网文工业一一对应，思维层方法论来自职业写作书并结构化 |
| 外部对照下的竞争力 | 优 | 四条独立收敛+五个无人区机制（1.2 表） |
| 执行完整度 | 中 | 六主题缺口（T1-T7）全是「理念未做彻」而非「理念错」——B58-B65 即补完清单 |
| 性能/成本 | 中下 | A 段全量读入是当前最大成本点（B58 解）；审查档位待分（B64） |
| 可维护性 | 优 | 治理体系 13 仓唯一，防漂移机制被反复验证（本仓 B57 CI 即例证） |

**结论**：理念不需要改。13 仓里没有出现推翻性架构——所有可借鉴点都是局部机制，且已收编进 B58-B65。把批次表重读一遍会发现它就是「把人类思维做彻底」的工程清单：语声样本=角色的声音内化，剧透锁=作者对「读者知道什么」的自觉，外科修订=编辑的保真直觉，卡文协议=写不下去就停而不是硬写。理念的两个真实威胁是 R1 仪式税与 R2 复盘单薄：前者 B58 在解，后者列远期。

## 2. 三维优化审计（流程 / 拆分 / 性能）

### 2.1 流程

- **已优、外部无超越**：日更单章闭环（A→B→C→D 含追踪事务）完整度 13 仓第一（外部最好只到 autonovel 的 draft→revise）；Phase A/B 把三停并一环（B53）是外部没有的流程优化意识；细纲批次滚动（默认 5 上限 10 章+批末预算/交叉核对）避开外部「整书生成或纯逐章」两极（02/03/08）。
- **待补（均已有批次）**：修订环防劣化护栏（B60）；卡文显式状态（B63）；伏笔生命周期三态（B58④）；卷末状态收敛（B59 关系边+快照参照 04）。
- **看清不学**：StoryCraftr 整书批量重写、autonovel 全自治连写、AI_NovelGenerator finalize 无条件固化——都是「流程自动化」越过作者裁决点的翻车现场（03/02/08）。

### 2.2 拆分

- **文档四层粒度合理**：单元卡（5-15 章）是网文原生概念，比 autonovel 的 outline 层（02）更贴领域。
- **技能 11 个/agent 7 个的规模恰当**：同形态项目 9-10 技能（07/02）；ans 的 18 agent 是反面（§5 判据要求 fallback+部署成本，且其全仓 0 脚本，01）——不追。
- **拆分的独有工具是文档预算**：预算上限逼出的下沉（B29 cold-path、B54 模板迁移）是被验证的拆分机制，13 仓唯一。**注意拆分优化≠加文件，也等于减条目**：chapter-core 预算已到 21500（B56 后），B58/B59 落地时应同步审视 A 段 13 项有无并入空间（如全量读视图项被点名包替代后即消失）。
- **结论**：拆分维度不需要结构性动作，随批次做局部减法即可。

### 2.3 性能

- **最大成本点=上下文装配**（六源收敛同一答案）：B58 点名包+预算闸+降级即性能优化本体；lite 双版本（03）与滚动窗（01）思想并入。
- **次级=审查延迟**：4 reviewer 与 evaluator 的档位未分——B64 两档制把判定类任务放快档并配低温度（07/08 互证，注意 08 的名实偏差反面教训）。
- **已优**：机检零依赖秒级；派生视图脚本生成；无 CI-LLM（宪法禁）。
- **新观察（并入 B62）**：正文长度运行时候选检查——细纲 Σ 预算是设计时约束，成稿后字数偏离无检查；NovelForge 的 600/300/100 收尾阶梯（04）提示可在 C 段机检加一条「字数 < 目标×0.7 或 > ×1.3 → 候选」。

### 2.4 审计结论表

| 维度 | 现状 | 外部对照结论 | 动作 |
|---|---|---|---|
| 流程 | 链路完整、日更闭环最优 | 无推翻性架构；可借鉴均为局部机制 | B60/B63/B58④/B59 卷末项 |
| 拆分 | 四层文档+11 技能+7 agent 规模恰当 | 同档最优（agent 数我们克制是对的） | 随批次做 A 段条目减法 |
| 性能 | A 段全量读入是最大成本 | 六源同答案：点名+预算+降级 | B58（主体）+B64（档位）+B62（长度候选） |

## 3. 一句话回答

方向正确且是当前开源生态里对「职业作家流程与思维」最完整的实现；13 仓照镜没有照出架构级问题，照出的是六个执行缺口（B58-B65 已收编）与两条理念级远期课题（仪式税判据化、平台数据复盘回路）。
