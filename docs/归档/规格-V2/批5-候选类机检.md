## 4. 新文件设计

**check-prose-candidates.js**（算法级，零 LLM、零网络、只读）：
- 输入：`--prose <本章正文.md>`（必填）、`--style <文风库/文风.md>`（可选）、`--gaps <追踪/信息差.md>`（可选）、`--json`（输出 JSON）。
- 三类候选：
  1. **高频意象**：正文分词按 2-4 字滑窗统计（去停用词表内建常量，~50 个虚词/标点），同窗出现 ≥ `IMAGERY_REPEAT_THRESHOLD = 5`（**mo-shu 自定**，`--threshold` 可覆盖）→ 候选 `{type:"imagery", text, count}`。
  2. **句式偏离**：若 `--style` 提供且含可解析的句长/段均字数锚点（正则提取数字区间，失败→该类跳过并标 `style_baseline_unparsed`——降级不报错）；正文实际段均字数/对话行占比超出基线区间 ±30%（**mo-shu 自定**容差，常量 `DRIFT_TOLERANCE = 0.3`）→ 候选 `{type:"style_drift", metric, actual, baseline}`。
  3. **信息差兑现**：若 `--gaps` 提供且格式合法（解析失败→跳过+标注）；对 status=="登记" 的每条，其 keywords 任一在正文出现 ≥1 次 → 候选 `{type:"gap_touch", gap_id, keyword, hint:"可标记兑现（作者确认）"}`。
- 输出结构：`{"candidates":[...],"degraded":[...],"blocking_count":0}`——**硬编码 blocking_count=0 且无 blocking 字段数组**（结构上不可能拦截）。
- 退出码恒 0（除非参数/文件错误=2）；缺 `--style`/`--gaps` → degraded 数组说明，不失败。

**test-prose-candidates.js**（自执行模式，**参照 `scripts/test-normalize-punctuation.js`**：assert 断言 + 末行 `OK: ...` 汇总 + 退出码判定；CI 直接 `node scripts/test-xxx.js` 运行，不用 `node --test`）：
- 正向：构造临时正文（同一意象词 6 次）→ 候选命中；含登记信息差关键词 → gap_touch 命中。
- 反向：干净文本 → candidates 空、blocking_count 0。
- 降级：无 --style / --gaps → degraded 提示、退出 0；坏格式 → 同上。
- 幂等：同输入跑两遍输出逐字节一致。

## 8. 禁止事项

1. 禁止输出任何 blocking 判定或以非零退出码表达"发现问题"（候选永不拦截——总纲原则 2）。
2. 禁止对缺失基线/信息差文件报错中断（降级提示）。
3. 禁止把阈值/容差写成不可覆盖的魔法数（须有常量名+CLI 覆盖）。
4. 禁止改 4 个既有 blocking 检测器的任何规则。
5. 禁止在正文写入/修改任何文件（只读）。
