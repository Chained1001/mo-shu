## 4. 新文件设计

**next_step.py**（算法级，纯只读、零写入、无独立状态存储）：
- 输入：`--project <书项目根>`（必填）。
- 判定序（按序首个命中即停，全部基于文件系统证据）：
  1. `P/.story-deployed` 不存在 → `S0`，evidence=[路径缺失]，next_action="运行 /moshu-setup 部署"，suggested_skill="moshu-setup"。
  2. `P` 下无 `正文/` 且无 `大纲/` 且无 `追踪/` → `S1`（项目未开书），next_action="运行 /moshu-write 开书"，suggested_skill="moshu-write"。
  3. `正文/` 存在但无 `第*章*.md` 文件（或全部为空文件——空=0 字节） → `S2`，next_action="写第 1 章（先补细纲）"。
  4. 读 `追踪/_tracking-state.json`（存在时）取 `last_committed_chapter`（记 L；state 缺失/损坏→evidence 标 `tracking_state_missing`，退回用正文最大章号）；下一章 N=L+1；`大纲/细纲_第*章*.md` 中解析章号集合（正则 `第(\d+)章`），N 不在集合 → `S3`，next_action="补第 N 章细纲"。
  5. N 在集合 → `S4`，next_action="日更写第 N 章"。
  6. 卷末判定：取 `大纲/` 下最大卷号 X 的 `卷纲_第X卷.md`；确定性正则提取其「章节范围」上界 U（如 `第\s*(\d+)\s*[-—~至]\s*(\d+)\s*章` 取第二组）；提取失败 → evidence 标 `volume_range_unparsed`，**降级停在 S4 并提示人工核对**（读失败≠没有数据）；L ≥ U 且 `大纲/卷复盘_第X卷.md` 不存在 → `S5`，next_action="提示作者执行卷复盘（/moshu-write 卷复盘）"。
  7. `卷复盘_第X卷.md` 存在且 L ≥ U → `S6`，next_action="下卷规划（回 S2 循环）"。
- 输出（stdout 单行 JSON，仿 tracking_commit 的 emit 风格）：`{"step":"S4","evidence":["…"],"last_committed_chapter":N,"next_action":"…","suggested_skill":"moshu-write"}`。
- 退出码：0=判定成功；2=项目根不存在（对齐 tracking_commit 错误码习惯）。

**test-next-step.py**（正反向，临时目录 fixture，自清理）：
- 7 个 fixture 各命中 S0-S6 一序（缺哨兵/空项目/空正文/缺细纲/齐备/卷末未复盘/已复盘）。
- 降级用例：卷纲「章节范围」格式怪异 → 输出含 `volume_range_unparsed` 且 step==S4。
- 空文件用例：`正文/第001章.md` 为 0 字节 → 判 S2（非空文件才算完成）。

## 8. 禁止事项

1. 禁止写入任何文件（含日志/缓存）——判定即证据，不留第二状态源。
2. 禁止解析卷纲语义字段猜测卷界（只认确定性正则，失败即降级）。
3. 禁止把 next_step 输出当作对 `追踪/` 的替代真源（state 仍唯一权威）。
4. 禁止在 SKILL.md 用裸 `python3` 调用（按 F6 探测式写法）。
5. 禁止改动 moshu-write 的 workflow（本批只加判定入口，不动写作流程）。
