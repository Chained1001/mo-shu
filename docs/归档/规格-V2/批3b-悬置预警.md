# 规格 · 批 3b：追踪 schema v5——悬置预警

- 版本：v1.0（2026-08-20）
- **前置依赖**：批 3a 已合入（schema 已 v5）。
- 依据：《执行总纲V2》§五批 3；v7 三类账本"悬了太久"分级阈值思想（03 档案 §九 #14）。

## 1. 目标

一句话：`check` 输出伏笔悬置预警清单（默认 20 章可覆盖），候选性质永不拦截。

## 2. 现状事实（本次实测）

| # | 事实 | 证据 |
|---|---|---|
| F1 | 伏笔条目含 `updated_chapter`（tracking_commit.py:370）→ 悬置章距可计算，**无需新增状态字段** | grep 实测 |
| F2 | 伏笔状态枚举：已埋/已回收/已过期/放弃（:44）；check 输出仅 last_committed_chapter+state_revision（:1121-1127） | sed 实测 |

## 3. 文件级改动清单

| 文件 | 改什么 | 注意点 |
|---|---|---|
| `skills/moshu-write/scripts/tracking_commit.py` | ①常量 `SUSPENSION_WARN_CHAPTERS = 20`（**mo-shu 自定**，验收见测试）；check 子命令加 `--warn-chapters N` 覆盖；②check 结果 JSON 增 `suspension_warnings: [{id, status, chapters_since_update}]`——仅 `foreshadow[id].status == "已埋"` 且 `last_committed_chapter - updated_chapter >= 阈值`；③**只呈报不阻断**（退出码不变） | 语义=最近一次变动章起算（近似"持续未动"），契约文档注明 |

1. 禁止让 suspension_warnings 影响 check 退出码（候选永不拦截）。

3. 禁止在本子步实现卷报告。
