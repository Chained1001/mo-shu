# 规格 · 批 B70：完结态与全书清账（写作生命周期的终点）

- 版本：v1.0（2026-08-28，旗舰起草；来源：作者裁定「完结态缺失可以做」+ 缺口分析第 2 项。B69 号保留给 evaluator 三型扩展（待作者另裁），本批编 B70。**mo-shu 自定批**）
- **目的**：解决「写作循环没有终点——完结无节点、全书总账无人清（跨卷伏笔/信息差/承诺到最后没人对账）」；新增能力：完结判定建议（FINALIZE）、全书清账报告、有意留白机制（作者宣告专属）、完结章写作指引。
- 性质：next_step 完结判定 + tracking_commit 新子命令（final-report 全书清账，零 schema）+ write 完结章指引。单批单提交。

## 一、设计依据

| 项 | 现状（实证） | 缺口 |
|---|---|---|
| 卷末循环 | S5 卷复盘（write）→ S6 建议开新卷（build cold-path Stage 4 增量）——循环完整 | **无出口**：next_step S0-S6 假设永远有下一卷；「完结」无节点 |
| 卷级清账 | volume-report 子命令（卷内伏笔四态/悬置/信息差未兑现/分层摘要） | **全书级清账不存在**：跨卷伏笔（埋于卷 1 揭于卷 5）、全量期待债终验、全书信息差清算——完结时无人对总账 |
| 完结章写作 | 细纲模板/章节定位六值无「完结章」形态 | 收束全部人物弧/兑现读者契约的终章无专属指引 |
| 构建态 | 台账状态机：定稿/修订中 stale/开卷中 | 无终态（完结后构建态无意义值） |

## 三、文件级改动清单

**1. next_step.py 完结判定（S6 分叉出 S7）**：S6 判定后追加检查——末卷卷复盘已存在 且（大纲再无后续卷 或 `大纲/完结宣告.md` 存在[作者显式宣告文件，出现即完结]）→ 输出 `step=FINALIZE`，建议动作「全书完结清账：跑 final-report 并走完结章写作指引（/moshu-write）」。否则维持 S6。S7 不新增状态值——用 `step=FINALIZE` 附于 S6 建议内（DTO 兼容，不破坏现有消费者）。

**2. tracking_commit.py 新子命令 `final-report`**（零 schema，只读 state 全量渲染）：
- 全书伏笔四态终账（跨卷汇总：已回收/已揭示/悬置[警示]/作废），悬置项逐条列「埋设章·预计揭示章·悬置章距」；
- 信息差全量清算（读者已知=否 的未兑现条目=烂尾预警清单）；
- next_chapter_commitments 全量未履行清单；progression 域全表（未收束指标列示）；
- 输出 `追踪/完结清账.md`（派生视图）+ stdout 摘要；退出码 0（呈报）；「未清零项」只呈报不清算（完结裁决归作者：补完结章回收 or 标记有意留白[标注后不再列为未清]——**留白标注机制：宣告文件内 `有意留白：F0XX/G0XX` 行，final-report 读之降为已决**）。
- migrate 零涉及（不写 state，纯渲染）。

**3. 完结章写作指引（write 侧两处）**：outline-workflow 细纲模板加「完结章」特殊形态段（~90 字：章节定位=完结章；收束清单=活跃人物弧逐个落点/读者契约终验/全书钩子闭环/禁开新钩）；chapter-core B 段加一句「完结章：先读完结清账.md 未清零项，逐一在终章回收或标注留白」。

**4. 构建态终值**：workflow-build 台账构建态枚举加「完结」（完结宣告后翻入；进入规则一句）。

**5. 接线**：workflow-daily 卷末节加「若为末卷：建议作者宣告完结→final-report→完结章」；cold-path 开新卷节加对称句「有完结宣告则不开新卷」；architecture.md 状态机图 S6→FINALIZE 分叉补一笔。

## 五、禁止事项

1. final-report 只读不写 state（纯派生渲染）；「有意留白」只经作者宣告文件生效，AI 不得自标。
2. FINALIZE 是建议不是拦截——作者不宣告完结则循环照旧（S6 开新卷永远合法）。
3. 零 schema/零 agent 变更；完结判定信号三分类（无大纲/无卷复盘 → 维持现状不误判 FINALIZE）。
4. 完结章不新增章节定位第七值（用「完结章」标注于既有六值框架内，防枚举扩散）。
