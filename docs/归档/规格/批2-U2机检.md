## 4. mechanical_check.py 设计（对照 v7 mechanical-check/index.js 逐项移植，Python 实现）

```
输出 JSON：{pass: bool, issues: [...], candidates: [...], action: str, remaining: int}
pass = issues.length == 0（候选绝不参与 pass 判定）

6 阻断（issues，blocking）：
 1 字数：去空白字符数 vs 目标（默认 3000 字可配置，容差 ±30% 硬边界）
 2 禁词：banned-words 一级词，body.includes 命中
 3 禁句式：禁句式表当正则，非法正则跳过不崩
 4 复读：字符级 6-gram 滑动窗口计数，≥3 次报第一条阻断（L=6, threshold=3）
      —— 验收必须含误报率实测：取《万疆》基线 + 干净样本，误报 >2% 则降阈值或按"候选"处理（实测结论写进脚本注释）
 5 必填（mo-shu 自定，替代 v7 front matter）：章节标题行 `## 第N章` 存在 + 细纲引用非空
 6 条目变动形式（只查形式零语义）：生命周期动词+编号存在的形式检查（对照 v7 checkThreadDeclarations）

4 候选（candidates，永不拦截）：
 7 新专名：正则 ([一-龥]{2,3})(冷笑道|笑道|喝道|说道|问道|答道|道|说|喊|问) 疑似人名，比对 追踪/名册.md 正名+别名未登记 → 候选
 8 信息差关键词：secrets 登记关键词命中正文 → "疑似泄密候选（不拦截，请人工确认）"
 9 高频意象：消费体检缓存 meta.imagery_top（本批可先空跑，批7体检接通后生效）
 10 句式偏离：本章平均句长 vs 基线偏 ≥30% 或句长方差偏 ≥50% → 候选

action 映射：pass→continue-to-review；fail 且 remaining>0→revise-and-recheck；fail 且 remaining=0→hand-off-to-author
remaining 来自重试预算（下）。

重试预算（追踪/重试预算.json，对照 v7 retry-policy/index.js）：
 结构 {schemaVersion:1, chapters:{<N>:{mechanical:{attempts:[]},review:{attempts:[]}}}}
 MAX_MECHANICAL_AUTO_REPAIRS=2；草稿 sha256（含 front matter，换行归一+trim）幂等——同 hash 重检不扣；author-confirmed 单独记账永不恢复自动额度；文件损坏/JSON 损坏/schema 不符 → fail-closed 停止自动流程；定稿后清章（在 backup_chapter commit 成功回调或 workflow 步骤中调用 clear）
```

## 5. 测试（scripts/test-mechanical-check.py）

1. 六阻断正例各一条命中 + 干净文本零阻断。
2. 候选四类正例命中且 **pass 仍为 true**。
3. 复读误报率实测：干净样本 10 段 + AI 腔样本 10 段，输出误报/漏报统计文件。
4. 预算：同草稿重检幂等不扣；损坏文件 fail-closed；author-confirmed 不恢复额度。
5. 名册：名册内别名不被报新专名；未登记真新名报候选。
6. --gate：缺细纲/空文件拒绝；伪造同名空文件同样拒绝。
