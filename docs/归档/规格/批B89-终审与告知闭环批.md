## 文件级改动清单

### 1. `skills/moshu-outline/references/workflow-outline.md`
1. 文件头部（文头注记区后）加「**开场白（进入时呈现）**」块规格：技能目的一两句＋步骤总览表（步骤｜作用｜产出｜作者参与点，约 6-8 行）＋预计交互点数——FULL 模式每次进入呈现；续跑/恢复会话降级为一句话定位＋当前进度。
2. Stage 3 完成、开书确认弹窗**之前**加「**大纲终审**」步：
   - spawn evaluator（eval_type=structure；target_paths=大纲.md+设定六文件+三份采风；benchmark=理想书评；virtual_benchmark=虚拟对标）；
   - spawn context **显式含长弧四检查面**（实测 #056 证明卷卷评审结构性够不到）：①卷间跃迁契机（每卷换台/升迁是否有不可替代理由）②跨卷反转链（各卷假胜/假败之后反转是否登记）③终局代价具体化（终局选择的两条路是否可感知对比）④末卷收束节奏（群像告别是否点名式风险）；
   - 终审四件：产物包交叉一致性（大纲×设定×采风数字/时点）、遗留分类审计（规则见下）、数据缺口闭环（research_needed 须采风或作者明示豁免二选一）、机检 blocking 复跑确认；
   - 报告呈报作者随开书确认（只呈报不拦截——候选语义）；evaluator 不可用 fallback 主会话自评并标注 Fallback。
3. 开书确认点产物呈现升级为「**收官产物地图**」表格：产物｜路径｜是什么｜喂给谁（下游技能/步骤）｜何时用——文件即接口的作者可见版（实测 #041 曾自发给过半份，本批规格化）。

### 2. `skills/moshu-volume/references/volume-workflow.md`
1. 打磨屏（`:263`）选项改四：✅ 确认定稿／🔧 按评审建议改进／🔄 采风补强／📡 逐维度打磨——📝 自改并入问句文本提示（「想自己改直接说」）。
2. Phase A 单元构建：单元拆分完成、写单元卡**之前**加「**结构预览停点**」——11 行结构总表（单元｜章节｜案件/功能位｜关键节拍）呈现后对话式确认一句（「结构可以吗？想调哪行现在最便宜」）；作者确认或改定后才展开写卡。不强制弹窗（对话式即可）。
3. 定稿节（`:369`）序列重排为：**verdict 通过（既有打磨环出口）→ 终审 → 三查 → tracking init → 定稿标记 → 收尾话术**：
   - **终审**：对象＝卷纲+全部场景表（非抽样）+设定漂移复检（卷纲层改动后角色/世界观一致性）+追踪 init 产物核验；含大纲终审同款终审四件；
   - **三查**（B90 前置位，本批落地）：①设定回写——diff 卷纲新实体（专名/配角/机制/场所）回写世界观/角色/势力或登记浮现记录，**新名字过 naming-cards 校验**；②大纲影响——卷纲改变了骨架级事实（时点/对手/舞台/卷 N 前提）则回改大纲+变更日志；③冻结声明——告知作者「设定变更从此走修订流（impact_scan 五步）」+待定项最后便宜窗口提示（书名/主角名）；
   - 终审/三查发现的问题回打磨环修复后重走（不清零不放行）。
4. 打磨环总则或定稿节加「**遗留分类规则**」表：可留三类（跨卷兑现/执行分层[细纲、正文期职责]/作者决策）——须登记去向；必清两类（**本层不一致**[卷纲 vs 场景表数字互斥]/**悬空缺口**[research_needed 未采未豁免]）——清零方可定稿。
5. 文件头部加「开场白」块（同 outline 款，Phase A/B/定稿三段总览）；定稿收尾话术处加「产物地图」表格（卷纲/场景表/追踪产物 喂给谁）。

### 3. `skills/moshu-write/references/workflow-daily.md`
头部加 LIGHT 版「开场白」规格：**仅新批次/新卷首次**进入给全表（适用条件+四 Stage 一览）；日常续写一句话定位（「本批第 N/M 章，Stage 4-D2 中」）——防日更噪音。

### 4. `skills/moshu-setup/references/templates/CLAUDE.md.tmpl`
「协作规则」节追加「**告知三则**」小节（≤5 行，节内追加不加新节名）：
1. 问前告知——凡向作者提问/流程停点，问句前一行说明：本步做什么·输入喂给什么下游·跳过的影响；
2. 落盘告知——产物写盘后报路径与一句话内容；
3. 阶段地图——进入技能给导览（步骤总览），阶段收官给产物地图（产物/路径/意义/喂给谁）。

## 禁止事项

1. **零 agent 变更**（templates/agents/ 与 agent-references 不动；第七查 diff 对照）——终审检查面经 spawn context 携带，不改 evaluator 模板。
2. **终审只呈报不拦截**——终审发现按既有候选语义呈报作者；「必清遗留」的清零发生在回打磨环修复，不是终审脚本拦截。
3. deploy.py / merge-claude-settings.py 零改动（CLAUDE.md.tmpl 节内追加）。
4. 不写新机检脚本（终审四件中的数字一致性复用既有 check_outline；语义审计归 AI）。
5. 结构预览停点不升级为强制弹窗（对话式确认；作者不回应即视为可继续的停点语义照既有「过程性动作」规则）。
6. 不动 evaluator spawn 的既有参数协议结构（只加 context 内容与终审型用法说明）。
