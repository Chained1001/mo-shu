## 4. backup_chapter.py 设计（对照 v7 实现，参数数组不拼 shell）

```
子命令：
  commit --chapter N --title X [--条目 ...] [--设定 ...]
    0) git-health 前置检查（见下）
    1) 章节文件级备份：正文/第NNN章_*.md 旧文件 rename 为 .wnwbackup.{pid}.{n}（参考 ChapterWriter.js:13-32）
    2) git add 正文/ 追踪/ 大纲/ 设定/
    3) captureCommitExpectation：parent=git.head()、tree=git.writeTree()、message=normalize("ch({N}): {title}" + 可选行)
    4) commit；失败 → probeCommitAfterError 三态：
       committed（rev-list 中 parent/tree/message 全等）→ 视为成功
       not-committed → 报错退出非零（中文）
       unknown → 保留工作树与 .wnwbackup，宁停，提示作者查仓库
    5) 成功 → 删 .wnwbackup 备份文件
  goto --chapter N
    前置拒绝：有进行中批次（检查追踪事务状态）、git-health 失败、工作树脏（git status --porcelain 非空，.wnwbackup 除外）→ 中文提示并退出
    救援 ref：refs/rescue/goto-{timestamp} 指向当前 HEAD → git reset --hard <定位提交>
    定位：git log --grep="ch({N}):" 取最新一条
  git-health（内嵌函数，参考 git-health.js）
    陈旧锁：.git/index.lock 存在且 mtime > 60s → 删除前二次 stat 确认（防 TOCTOU）
    半提交：MERGE_HEAD/CHERRY_PICK_HEAD 存在 → git stash 提示（宁停）
    .git 损坏：git rev-parse 失败 → 只输出中文指引（备份 .git 目录），不自动动
    全部输出中文；git 命令全部参数数组 subprocess，禁 shell 拼接；标题经 sanitize（去换行/控制字符）
```

## 5. 测试（scripts/test-backup-git.py，全临时仓库 fixture）

1. 正常提交：建临时 git 仓库 + 伪造正文/追踪 → commit → 断言提交存在、消息 `ch(N): title`、**无 tag**。
2. 假失败探测：monkeypatch commit 抛错但实际已提交 → probe 判 committed → 不报错不重复提交。
3. 未知态：monkeypatch 读失败 → unknown → 退出非零 + `.wnwbackup` 仍在。
4. git-health：放陈旧 index.lock（mtime 改老）→ 自愈删除；放新鲜 lock → 不动。
5. goto：两章提交后 goto --chapter 1 → HEAD 回到第一章提交；脏树 → 拒绝。
6. 文件级备份：提交前 .wnwbackup 存在，成功后消失，失败后还原。
