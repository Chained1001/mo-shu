# 规格 · 批 B68：章纲生成强化（场景表 + 一进一出 + 写后浮现 + 拆并章 + 推进度仪表）

- 版本：v1.2（2026-08-28 补千章边界验收与数值序纪律——'1000'<'999' 字典序陷阱在跨 999/1000 时静默乱序所有 sorted 文件名逻辑，千章长篇正是目标场景；细节扫尾作者批准。v1.1 自审修订：①pace_meter 计划章数信号源改单元卡「章节范围」字段（结构化）为主源——原 v1.0 的正则解析大纲.md 一段式汇总脆弱；②场景表补分层声明防与节拍卡/单元卡章功能分配重复建层（beat-cards.md:7 已声明「一拍可多场景」）；③场景表加「场景类型（场景/续景）」与「价值转变」两列——Swain 场景-续景理论与 McKee 价值转变作方法论锚（仓内零命中，为真缺口）；④设计依据补外部锚点 DOC/Dramatron/DHO。来源：作者命题「卷纲→章纲怎么构建，人类作家怎么做」的方法论显式化 + 前置对话推进度提案。**mo-shu 自定批**（非外部移植）——设计依据是人类职业网文作家手艺（场景分解定章数/每章一进一出/纲文互喂/章界流动/推进度对账），验收标准逐条可测）
- **目的**：解决「卷纲到细纲之间缺场景分解层，章数靠拍脑袋——100 章的剧情 10 章跑完」+「推进度无人对账」两个问题；新增能力：场景表（章数=场景加总）、每章一进一出呼吸、写作浮现（写时长出的东西进下批细纲）、拆并章、推进度仪表（卷进度 vs 剧情进度背离预警）。
- 性质：细纲流程四项方法论增强（纯文档/流程）+ 新确定性脚本 pace_meter.py。**零 schema、零 agent 变更**。分两子步两提交：**68a 纯流程**、**68b 仪表脚本**。

## 一、设计依据

| 机制 | 人类作家做法 | mo-shu 现状（实证） |
|---|---|---|
| ① 场景表分解 | 章数不是拍的，是场景表加总的——单元拆场景（接触战 1 章/反转半章/余波半章），每类场景有经验估值 | 批次定位（outline-workflow:21）后直接从单元卡铺细纲（:22），**无场景粒度的"这仗该打几章"依据**——10 章跑完 100 章剧情的根治点 |
| ② 一进一出 | 每章解决一个小问题、欠下一个新问题（2-3 章小爽、一单元大爽的呼吸节律） | 章尾钩子/下一章推动力在细纲模板「结尾设定」区，但**不是分解纪律**（模板无此问句） |
| ③ 纲文互喂 | 写第 N 章长出的东西（角色活了/计划外反应）进第 N+1 章章纲 | build 侧有浮现记录机制；**write 侧无**——补纲流程（:83-87）读追踪与审查日志，不收割写作期涌现 |
| ④ 章界流动 | 拆章/并章是常规操作（发出来前章界流动） | 前 10 章细纲锁定（:81）+无拆并规程——中途调整只能走重量级修订流 |
| ⑤ 推进度对账 | 职业作者随时心里有数"这卷写到哪了 vs 计划" | 计划章数与单元数与实际推进**三者无算式**——确定性可算而无人算。**信号源（v1.1 修正）**：卷纲单元卡已有「章节范围」结构化字段（workflow-build:109/:286），计划章数=本卷各单元范围并集，主源改此；大纲.md 卷行为次源；CLI --planned-chapters 第三源 |
| **外部锚点（v1.1）** | **DOC**（ACL 2023，[开源](https://github.com/yangkevin2/doc-story-generation)）：细纲递归结构+大纲与**场景生成交错**——滚动批次的直接学术同构；**Dramatron**（DeepMind CHI 2023）：层级链含场景分解层——验证「单元→场景→章」层的必要性；**DHO**（NAACL 2025）：**大纲随写作动态调整**（fuse planning & writing）——写后浮现的方向验证。**注意：mo-shu 落地是 DHO 的「带闸门版」（v1.1 作者质询后显式声明）**——纲文互喂不等于写作可改大纲：细纲层（未写区间）自由滚动是唯一「随文动」的层；卷纲锁定只增不改（卷尾追加须作者明示）；设定/大纲修改的唯一路径=作者裁决的 build 修订流（impact_scan+留痕+stale 级联+B61 指纹复查），写作侧永不直改 |
| **写作理论锚点（v1.1）** | **Swain 场景-续景**（《Techniques of the Selling Writer》：场景[目标/冲突/挫折]→续景[反应/困境/决定]交替）——「一进一出」的学术版，密疏节奏的微观机制（仓内零命中，真缺口）；**McKee 价值转变**（《故事》：每个场景必须有一次价值正负转变，无转变的场景删）——场景表的准入判据；Genette 时距（场景=密/概述=疏）——密疏预算的叙事学标注（注记即可，不开新节） |

## 三、文件级改动清单

### 子步 68a：流程四项（纯文档，零脚本）

**1a. 场景表步**（批次清单「批次定位」与「剧情单元消费」之间插新步，编号 2b）：
- 建批前产出 `大纲/场景表_单元{单元ID}.md`（write 侧新建）：表头（单元ID｜单元预估章数合计｜对标剧情参照）+ 场景行表（**场景名｜场景类型[场景/续景·Swain]｜价值转变[McKee：正→负/负→正/无则删该场景]｜功能标签｜预估章数（可 0.5 步进）｜密/疏｜对应章号回填列**——建细纲时回填，复盘对照用）；**分层定位（防重复建层）**：场景表是单元卡「BC-ID 章功能分配」的建批深化（粗分配→场景粒度），下游接细纲结构公式（节拍序列）——三层各管各的（单元卡管功能·场景表管章数·节拍卡管章内写法），「一拍可多场景」按 beat-cards.md:7 既有声明；
- **章数=场景行预估加总**，细纲从场景表铺章（一场景 1-N 章或 N 场景并一章）；单元预估合计落区间 5-15 外时先自查（过小说明单元切太碎、过大说明单元超限——回到批次边界规则处理）；
- 批末核对加第 ⑥ 条：本批实际章数 vs 场景表预估区间一致；
- 中途补纲流程同步：补纲前无场景表先补建。

**1b. 一进一出**（细纲模板「结尾设定」区加问句行，~70 字）：
`- 一进一出自检（Swain 场景-续景）：本章解决了哪个小问题？欠下了什么新问题？（答不出=分解未完成——场景[目标/冲突/挫折]与续景[反应/困境/决定]交替的呼吸节律，不许一章清账也不许章章欠账）`

**1c. 写后浮现**：
- 新建 `大纲/写作浮现.md`（write 侧，append-only 表：章号｜浮现内容｜建议去向｜状态[待消化/已消化]）；
- chapter-core D 段加一句（~50 字）：写作中发现计划外涌现（角色活了/计划外反应/新想法）随手记入 `大纲/写作浮现.md`，不留 in 会话记忆；
- outline-workflow 滚动补纲步骤加「**浮现收割**」：补纲前读未消化条目——可入本批细纲的直接吸收（标已消化+去向章号）；属设定/大纲层修改的呈报作者转 `/moshu-build` 修订流（不越域自改）。

**1c′. 理论注记**（outline-structure-theory「章节定位与张弛」节尾追加 ~120 字）：场景-续景交替（Swain）与价值转变（McKee）作为场景表/一进一出的方法论出处；密疏配比的叙事学标注（Genette 时距：场景=密/概述=疏）——出处入注记不开新节（苏格拉底式引用，不抄书）。

**1d. 拆并章规程**（outline-workflow 新节，~150 字）：
- 合法域：**仅未写正文的细纲区间**（已写章的拆并=重写，走修订流）；
- 拆：`细纲_第N章` → 第N章+第N+1章（内容按场景表重分），后续细纲文件顺次重编号；并：反向；重编号后跑 `pace_meter.py`（68b）核编号连续性与场景表回填同步；
- 锁定区间（前 10 章/已写区间对应细纲）内操作须作者明确确认；
- 场景表「对应章号」列随重编号同步更新。

### 子步 68b：推进度仪表（确定性脚本）

**2a. 新脚本 `skills/moshu-write/scripts/pace_meter.py`**（纯标准库，呈报工具——恒退出码 0，仅致命缺目录为 1）：
- 输入信号（v1.1 修正，三源递降）：**主源**=卷纲剧情单元卡「章节范围」字段（结构化行）——计划章数=本卷各单元范围并集之最大章号、单元总数=单元卡计数、已消耗单元=已写章号落入的范围；**次源**=`大纲/大纲.md` 当前卷行章数（正则，mo-shu 自定口径注释）；**CLI** `--planned-chapters`/`--total-units` 显式覆盖；`大纲/细纲_*.md` 文件（数+「单元ID/位置」行归属，与主源互验）+ 正文文件数（或 state last_committed_chapter，取大）；三源全缺 → `skipped_no_plan` 明示；
- 输出 JSON + stdout 摘要：`{卷号, 计划章数, 已写章数, 卷进度%, 已消耗单元数, 单元总数, 剧情进度%, 场景表预估合计(缺则 null), 细纲编号连续性:{缺号列表}, 背离候选:[…]|[]}`；
- **背离判定**（常量 `PACE_DIVERGENCE_RATIO=2.0 / PACE_DIVERGENCE_PP=50`，mo-shu 自定+CLI 可覆盖）：剧情进度%/卷进度% > 2.0 **或** 两进度绝对差 >50pp → 候选行「按当前消耗速度预计约 N 章收卷 vs 计划 M 章——检查是否加垫单元/扩支线/压推进节奏（裁决归作者）」；
- 三分类降级（反模式 #7）：大纲/卷纲缺当前卷信息 → `skipped_no_plan`（明示跳过）；无场景表 → 该字段 null（合法）；单文件读失败 → error 字段明示不中断；
- 编号连续性：**按提取的数值章号排序**（禁文件名字典序——'1000'<'999' 陷阱）后给缺号列表（服务拆并章重编号与「不允许跳章」纪律的确定性化）。**顺带复核项（非改项）**：flash grep 既有确定性脚本（design_fingerprints 的 affected_chapters 等）是否存在细纲文件名字典序依赖——affected 返回 int 列表则无恙，有排序处确认按数值。

**2b. 接线**：workflow-daily 批末机检链后加一步 `python skills/moshu-write/scripts/pace_meter.py --project {书根}`（背离候选随批末报告呈报）；outline-workflow 中途补纲步与拆并章规程处各加调用句。

**2c. 正式回归 `scripts/test-pace-meter.py`**（守护对象声明 + ≥7 用例：正常卷进度/背离候选双条件/缺大纲降级/缺卷纲降级/编号缺号/CLI 覆盖/无场景表 null）+ §2.5 四处同步（README 表/CI 步/CONTRIBUTING/测试表）。

## 五、禁止事项

1. **不改卷纲既有内容**（场景表/写作浮现均为 write 侧新建文件——Q7 域边界）；浮现属设定层的只呈报转 build，不越域自改。**边界重申（闸门原则）**：「纲文互喂」在 mo-shu 的唯一自由层是未写区间的细纲；大纲/卷纲/设定被写作涌现改变的唯一合法路径=作者裁决的修订流——本批不放松任何锁定纪律、不开任何直改口子；追踪是事实层，已写事实不因计划修改而变（计划变更走 stale 级联由 write 下章消费），设定波及面由修订流 impact_scan 与 B61 指纹复查清单工具化承担。
2. 拆并章禁触已写正文区间；锁定区间操作须作者确认——锁定纪律不因本批放松。
3. pace_meter 恒退出码 0（呈报工具非守卫）；背离只出候选，加不加垫单元裁决归作者。
4. 零 schema / 零 agent 变更 / agents_version 不动。
5. 一进一出是问句不是新必填字段（苏格拉底式，答不出=分解未完成，不是格式错误）。
