## 一、模型定义（人类角色→评审型）

| eval_type | 人类原型 | 职责一句话 | 吸收的原型 |
|---|---|---|---|
| **structure** | 责编（结构编辑） | 结构之眼：逻辑/线/节奏/钩子/人物功能/跨稿矛盾——**可一次携带多份相关稿** | outline、unit、final、detail-batch、settings、revision + 新增人物/场景表/卷末 |
| **reader** | 读者评委/市场审读 | 读者之眼：追读力/爽点/对标撞车/融合本土化/完结交付 | full + 新增融合评审/防撞升格/完结评审 |

文字之眼=review 评委团+机检（不动，不在本批范围）。

**跨产物审查（本批核心增益）**：structure 评审的 spawn prompt 携带 `related_paths`（可选，相关稿清单）——如批末细纲评审传「细纲批+场景表+卷纲路径」时显式要求核对「场景表节奏 vs 单元卡承诺」类跨稿矛盾（旧型结构上做不到）。

## 二、改动清单

### P1 evaluator 模板重写（skills/moshu-setup/references/templates/agents/moshu-evaluator.md，实测 5001 裸长）

1. **角色定义**：开篇定义两型人格——structure=责编（挑结构毛病是本分，跨稿核对是义务）；reader=读者评委（以追读/爽点/对标熟悉度打分）。呼应三维度（editor/author/reader）不冲突：三维度是评审视角，两型是稿类职责分工；
2. **eval_type 枚举 7→2**（:24 表/:104 例/:145 枚举行全改）：`eval_type: structure | reader`；每型按「评审对象」索引的**清单模块表**——structure 段：大纲骨架/单元卡/人物设计/场景表/细纲批/设定包/修订包/卷末体检八对象各 3-5 条检查项（判据逐条标注方法论来源：character-design-methods 弧线六阶段/beat-cards/outline-rhythm/reader-contract 等）；reader 段：完整粗稿（score 必填）/融合产物/防撞对照/完结清账四对象各 3-5 条（对照理想书评/虚拟对标/防撞三维/完结清账终态标准）；
3. **score 规则迁移**（:135）：「eval_type=full 时必填」→「eval_type=reader 时必填（对照理想书评结构化目标）」；structure 型不填；
4. **新增参数**：`related_paths`（optional，跨产物审查材料清单）进被调用协议段；
5. **判据来源纪律声明**：全部检查项标注方法论来源节，无发明性判据（开发标准 §11.2 v1.6 对应）；shadow mode 声明：两型报告只呈报永不拦截，实测期采纳率登记（观察清单）。

## 四、禁止事项

1. **触发时点不变**（细纲写前闸仍在写前；Phase B 全局评审仍在打磨环入口）——只合并评审者身份，不动流程顺序；
2. **报告 JSON 字段不删**（score/summary/recommendation/research_needed 消费方兼容，仅 score 触发条件 full→reader）；
3. 不新增 agent（只重写 evaluator）；review 评委团/机检零触碰；
4. 候选永不拦截：6 个新评审点全部「可选+只呈报+fallback」；
5. 判据零发明（逐条标方法论来源，grep 可验）；shadow mode 不收紧；
6. spawn prompt 内既有材料字段名不动（token/target_path/context 语义保持）。
