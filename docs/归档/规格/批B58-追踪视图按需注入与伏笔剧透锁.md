## 三、文件级改动清单

### 子步 1：点名注入清单 + 预算闸（纯渲染，零 schema 变更，tracking_commit.py×4 副本：write/build/import/review——v1.1 勘误：原文误计三副本）

**1a. tracking_commit.py — render_context 扩展**（v1.1 按落法 A 重写；在 B57 分层基础上）：

- 「本章点名清单」节（渲染进续写状态卡，位于核心角色状态节之后）为**列名级清单**，不重复展开角色行：
  - 出场角色：透传 `appearing_characters_from_outline` 结果，仅列名；
  - 涉及设定：读下一章细纲「本章涉及设定」字段，逐项列名；
  - 活跃伏笔：现有活跃伏笔编号全集（**不筛**——悬置防遗忘是既有防线，本批不动）；
  - 信息差锁定标记：透传子步 2 的锁定条目 ID（子步 1 先留固定空行占位，子步 2 填充）；
  - 永不裁剪项声明：本章承诺（next_chapter_commitments）、上一章结尾段、出场名单、时间锚；
  - 预算判定行（见下）。
- **唯一展开区 = B57「本章出场（必读）」节**（出场角色完整行仍渲染于此，不在点名清单内重复）。预算闸与降级均作用于该节：
  - `--injection-budget N`（默认 2500 非空白字符，v1.1 修正；CLI 可覆盖；常量命名 `DEFAULT_INJECTION_BUDGET`，注释标「mo-shu 自定」）；
  - **双闸降级序**：出场展开区非空白字符数超预算，**或** 续写状态卡总字节数 > CONTEXT_MAX_BYTES——任一满足即按出场顺序逐个降级为「仅列名+硬状态一行（目标/位置/伤势类字段）」，两条件同时收敛才停；
  - 预算判定行输出于点名清单节：「预算判定：预算X/实际Y/降级Z人」；含硬限联动时另起「硬限联动降级」行；
  - 全降级后整卡仍超硬限 → 维持既有 TrackingError（真·状态超限，非本批范畴）；
  - 同输入同输出（确定性，可测）。
- 向后兼容：无下一章细纲 → 不渲染「本章点名清单」节、预算闸不激活（闸仅在有出场名单路径生效），其余输出与 B57 版一致（验收以既有输出断言为准）；细纲有「出场顺序」但无「本章涉及设定」→ 设定行输出「（细纲未登记涉及设定）」，三分降级（缺文件/空字段/坏格式各自明示，反模式 #7）。
- 既有回归用例若因预算闸默认激活而红（有细纲+多角色 fixture），属 D-B58-1 裁决的契约变更：允许同步更新断言，偏差记录须注明并附降级后输出样例。

**1b. chapter-core.md — A3 消费口径改写**（净增约 +200 字，改写不新增条目）：

- 「状态筛选」步改为：读续写状态卡**「本章点名清单」节**，按清单加载出场角色的 `追踪/角色状态/{名}.md` 与涉及设定文件；背景项不读（B57 分层的消费侧闭环）。
- 加一句剧透锁感知（子步 2 生效）与「预算判定行出现降级时，被降级角色按硬状态行写作、不得虚构细节」纪律。

### 子步 2：伏笔剧透锁 + 伏笔操作三态（schema 可选字段 + 细纲模板 + 候选机检）

**2a. tracking_commit.py — 信息差可选字段 `reveal_chapter`**：

- `normalize_information_gap_change` 键集加 `reveal_chapter`（int 或 null，可选；register/update 可带，retire 不带）；校验：null 或 1-9999 整数。
- 存储条目同步带该键；`render_information_gaps`（信息差.md）加「最早揭示章」列（null 显示「—」）。
- **剧透锁**（render_context / 信息差渲染两处一致）：条目 `reader_known=否` 且 `reveal_chapter` 非空且 `> 当前章` → 渲染为 `G0XX：🔒内容锁定（第 N 章揭示）——知情人：{knowers}`，**不渲染 note 与 keywords**；`reveal_chapter` 为 null → 不锁（保守方向：不锁=照旧全量）。点名清单「信息差锁定标记」行填充此类条目 ID。
- schema 纪律：TRACKING_SCHEMA_VERSION bump +1；migrate 带备份（旧 state 条目补 `reveal_chapter: null`，零丢失）；若 INPUT_SCHEMA_VERSION 描述信息差键集则同步 bump——**以 flash 复核 :26-27 常量与 input 校验实际为准**；write/import/review 三端同步口径（import 侧同脚本副本天然同步）。

**2b. outline-workflow.md — 细纲模板加伏笔操作行**（约 +90 字）：

「契约风险」行后加一行：
`- 伏笔操作：{埋设|强化|回收}·{伏笔ID/信息差ID}（认知颠覆星级1-5：{N}；情感基调迁移：{前→后}）——没有写「无」`
「人物关系和出场顺序」节信息差字段补一句：细纲「信息留白·最早揭露章」与信息差登记 `reveal_chapter` 对齐登记（建纲时同步）。

**2c. check_outline.py — 新候选「悬空伏笔操作」**：

- 检测：细纲「伏笔操作」行引用的 ID 格式合法（F/G 前缀+数字）但在**本卷卷纲「本卷伏笔」表或本书信息差登记文本中不存在** → candidate（不拦截、不影响退出码）。
- 边界：只读大纲域文件（卷纲/细纲/信息差.md 派生文本），**不读追踪 state**（build 侧不耦合追踪域）。
- 回归：违规 fixture（引用 F999）输出含「悬空伏笔操作」；合法 fixture 无输出；现有 20 用例全绿，新增 2 用例。

## 五、禁止事项

1. 候选永不拦截、不影响退出码语义（红线 §2.7）。
2. 点名信号只用细纲确定性字段（出场顺序/本章涉及设定），**禁止**引入关键词扫描/模糊匹配/向量检索（§6）。
3. schema 只加可选键，禁止改既有键语义；migrate 必带备份；老数据零丢失（兼容四原则）。
4. 不动活跃伏笔全列防线、不动 (a)-(h) 既有条目、不动 C/D 段车道。
5. 不碰 docs/归档、otherMaterials；不做规格外顺手优化。
6. 预算耦合漏检即返工（B57 CI 教训）；AI 结构化载荷先落临时文件再 `--input`（红线 §2.8）。

## 八、风险与回滚

- 风险 1：细纲「出场顺序/本章涉及设定」字段质量决定点名召回——漏标则漏注入。缓解：候选/纪律层面已有 check_outline 与七检；本批不承诺完备，文档明示。
- 风险 2：reveal_chapter 与细纲信息留白双处登记可能漂移。缓解：以 state 为事实层（2b 对齐句声明），细纲留白是设计层。
- 回滚：子步 1 纯渲染，revert 单提交即恢复；子步 2 新键全可选，旧代码读到 null 等价未登记，revert 后 migrate 备份可恢复。
