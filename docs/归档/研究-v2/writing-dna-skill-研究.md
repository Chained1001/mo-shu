## 1. 项目概况（是什么/形态/技术栈/规模/维护状态）

- **一句话定位**：把「账号/作者/出版物」的写作风格，从一批完整文章蒸馏成 agent 可复用 `Writing-DNA.md` 规则集的**纯提示词 skill**——"不是摘要，而是可操作的规则集"（`SKILL.md:31-33`）。
- **形态**：Moxt/Codex skill 格式。入口 `SKILL.md` 带 frontmatter（`name` + 双语 `description`，`SKILL.md:1-4`）；`agents/openai.yaml` 是 OpenAI/Codex agent 清单（`interface` + `policy.allow_implicit_invocation`）；`references/workflow.en.md` 是英文流程副本。
- **技术栈**：**零代码、零脚本、零构建**（纯 Markdown + JSON schema + YAML）。SKILL.md 反复说"脚本统计"（`SKILL.md:111-113`），但**仓库内不含任何 .py/.js**——所谓"脚本"是给 agent 的指令（让它自己跑词频/句长统计），不是随附工具。这是与 mo-shu（自带 Python 1-liner）的本质差别。
- **规模**：24 个源文件，`SKILL.md` 最大（11.5KB），全仓约 32KB。产物模板全是骨架（正文"待填写"/"To be completed"）。
- **维护状态**：**存疑**。本地该目录**无 `.git`**（实测 False），是 mo-shu 仓库内 vendored 普通文件，无法判读上游提交史。仅能推断：`LICENSE:3` 版权 2026（极新）、README 指向 moxt.ai hub、`docs/release-checklist.md` 表明按发布态整理、无 CHANGELOG/版本号。

## 4. 思想

- **「先蒸馏规则，再复刻」反对直接模仿**：不给几篇例文说"照这个写"，而是先系统分析一批完整文章、拆成显式规则，再用规则指导写作（`README.md:21-25`）；把"风格"从模糊感受变成**可记录、可复用、可检查**的规则（`workflow.en.md:160`）。
- **六层 = 三问分工**：L1-L2「怎么写」、L3-L5「怎么想」、L6「怎么呈现」；缺一则有"读着像但想法不像/框架像但语气不像/文字像但看着不像"（`SKILL.md:52`、`README.md:73-79`）。
- **蒸馏纪律**：`Writing-DNA.md` ≤4000 字，"过长 = 没蒸馏干净"（`SKILL.md:277`）；质量含"喂 AI 能写 ≥7/10 近似风格"（`SKILL.md:272`）。
- **负向思维（散布）**："什么不写""过度副词=噪声""失败模式""证据 vs 推断"（见 5.4）。
- **伦理边界**：不冒充作者、不误导读者、不公开未授权语料（`docs/usage-boundaries.md:5-11`）。

## 5. 方法论

### 5.1 L1 确定性统计清单（`SKILL.md:113-131`）
- 词频：高频名词 100、动词 50、副词 50；**"过度使用的副词 = 需要过滤的噪声"**（`SKILL.md:117`）。
- 句式：平均句长、短句(≤15字)占比、长句(≥50字)占比、段落平均句数。
- 标点格式：破折号 vs 括号比、引号使用场景、小标题字数、中英文混用模式。
- 英文版补护栏"区分**话题词汇**与**稳定语气标记**，频率不等于风格"（`workflow.en.md:85`）。

### 5.2 L2 结构标注（`SKILL.md:141-161`）
`[开头 hook 类型]+字数 → [第一转折/核心问题] → [正文架构] → [结尾：收束/悬念/呼吁/自然结束]`；按类型归纳，并记录"何时用/制造什么期待/允许哪些变体"（`workflow.en.md:101`）。

### 5.3 图片纳入分析（跨层原则）
图片可能是论证链一部分，必须打开看图（`SKILL.md:54-62`）；功能六分类：证据/演示/数据/叙事推进/情绪/权威（`SKILL.md:205`）。

### 5.4 负向约束（重点，专项回答）

**结论：有，但弱，且不是一级字段。**

| 负向约束 | 形式 | 源码位置 | 推导方式 |
|---|---|---|---|
| 选题排斥 | "什么类型的话题他们**不写**？" | `SKILL.md:176`；`workflow.en.md:113`"ignored or rejected" | 反向归纳：观察语料**缺失** |
| 副词噪声过滤 | "过度使用的副词 = 需要过滤的噪声" | `SKILL.md:117` | 词频统计 + 阈值（阈值未定义，存疑） |
| 证据 vs 推断分离 | "Separate evidence-supported patterns from tentative inferences" | `workflow.en.md:126` | 标注推断项，非"禁用" |
| 失败模式保留 | "Preserve ... clear failure modes" | `workflow.en.md:160` | 记录负面/失效情形 |

**明确没有的**：无「作者回避/禁用词表」一级字段；`Writing-DNA.md` 六节模板（`Writing-DNA.md:5-27`）**无负向 section**；无「不可模仿」章节。对比 mo-shu 已研究的 SparkArc「风格克隆 → 作者回避负面清单」（旧档案 `docs/sparkarc-研究.md:33` 已删除，结论见 `docs/研究-v2/spark-arc-studio-研究.md`），writing-dna-skill 的负向约束更弱、更分散。**可借鉴的不是完整负向机制，而是两条具体推导模式**（选题排斥 + 副词噪声）。

### 5.5 去 AI 味相关性
本 skill **不以"去 AI 味"为目标**（全仓无 anti-AI/cliché 相关词），唯一间接关联是副词噪声过滤。这是相对 moshu（有专门 `anti-ai-writing.md`）的**弱项**。

## 6. 上下游设计

### 6.1 输入契约
≥20 篇**完整**文章（`SKILL.md:73`、`README.md:85`）；不足时"结果仅作流程演示，不作可靠风格模型"（`workflow.en.md:50`）。格式 `.md/.txt`，命名 `YYYY-MM-DD 内容类型 文章标题-来源.md`（`SKILL.md:77-81`）。图片/排版建议保留（`README.md:60`）。

### 6.2 输出契约
每作者一目录（5 产物 + raw + _meta）；`Writing-DNA.md` 是"总入口、写作前复读"文档（`README.md:119`）；质量六条（`SKILL.md:270-277`）。

### 6.3 召回/注入机制（重点，专项回答）

**无自动检索/向量/索引/门禁/gaps**。召回 = 提示词层"复读文件"：① 写作前让 agent 重读全部产物（尤其 Writing-DNA.md + 四层文档）再按规则写（`README.md:143-147`）；② `Writing-DNA.md` 压到 ≤4000 字就是为"每次写作前能复读一遍"而设（`workflow.en.md:160`）；③ 自检-重写闭环：输出不像 → 对照 `语言DNA.md/文章结构模板.md/认知框架.md` 逐项自检重写（`README.md:148`）。

对比 moshu 的 (d) 文风召回（每章写前准备 + 存在性/合规性两级检查 + AskUserQuestion 兜底 + explorer gaps），writing-dna-skill 的召回**松散、手动触发、无缺失退化检测**——moshu 不应回退到这种形态。

## 7. 可借鉴清单

### 低成本

**B1 — L1 统计口径扩充。** 增补「破折号 vs 括号比、引号场景、小标题字数、中英文混用、段落平均句数」（`SKILL.md:126-131`），确定性可脚本化。落点：`moshu-style`「整体语感」节。

**B2 — 副词噪声过滤（负向约束起点）。** "过度副词=噪声"（`SKILL.md:117`），从词频反推慎用副词，补 mo-shu「文风缺负向约束」缺口，与 `anti-ai-writing.md` 同源。落点：`moshu-style` 增「副词慎用」条目。（阈值需自定）

**B3 — "什么不写"反向归纳。** 观察"什么话题不写"（`SKILL.md:176`）→ 归纳排斥规则，是负向约束通用范式。落点：`moshu-style` 增「回避清单」字段——对标"书"非"账号"，须从"话题排斥"改造为"写法/语气排斥"。

**B4 — 单文档蒸馏预算（≤4000字）。** `SKILL.md:277`"过长=没蒸馏干净"，防产物膨胀失效。落点：`文风库/文风.md` 加字数上限。

**B5 — hook/structure 枚举。** 开头 5 类、结构 4 类、结尾 4 类（`SKILL.md:97-98`、`:141-161`）。属 L2（moshu-style 不含），可喂拆书「黄金三章」开篇技法。落点：拆书 Stage 1/6。

### 中成本

**B6 — 证据 vs 推断分离 + 失败模式。** `workflow.en.md:126/160`，比单一 confidence 更可审计。落点：`moshu-style` 生成记录补 `失败模式/推断项`（对齐拆书「不可模仿」口径）。

**B7 — 逐项自检-重写闭环。** 输出不像 → 逐项自检重写（`README.md:148`），显式化为"句长→标点→对话→锚点" checklist。落点：`moshu-narrative-writer.md` 模板。

**B8 — 图片承重思维 → 锚点启发。** 承重图必须看（`SKILL.md:56-62`），"承重片段优先"映射到锚点选取。落点：`moshu-style` 锚点选取标准。

### 高成本

**B9 — L5 认知框架。** `SKILL.md:185-189`，深度阅读不可脚本化；对网文 ≈ 拆书 Stage 6「不可模仿」。**与 moshu 分工冲突**（认知类归技法总结）——不搬，仅作 Stage 6 参考。

**B10 — 完整 L3-L6。** 内容营销四层、需 ≥20 篇语料，对网文不适用。**不搬**。

## 9. 与 mo-shu 差异定位（重点对比 moshu-style）

| 维度 | writing-dna-skill | moshu-style（据 `docs/moshu-style-plan.md`） |
|---|---|---|
| 领域 | 自媒体/公众号/图文 | 网文长篇（对标书文风） |
| 分析范围 | **6 层**（语言/结构/选题/素材/认知/视觉） | **纯表达层**（句长/标点/段落节奏/对话技法/锚点/基础层） |
| 语料门槛 | ≥20 篇完整文章、深度阅读不可脚本化（重） | 任意量原文、2-3 段 ~1000 字、分钟级（轻） |
| 输出形态 | 每作者一目录 5 文件（多作者） | 单文件 `文风库/文风.md`、一本一风（覆盖式） |
| confidence | **无**；用"证据 vs 推断 + 失败模式" | 每字段 `high|med|low` |
| 锚点 few-shot | **无**（仅 raw/ 全量原文） | 2-4 段 300-500 字逐字切片、行号可回查（**核心优势**） |
| 对话技法 | 无（文章导向） | 有（潜台词/标签习惯/角色语气） |
| 负向约束 | 弱（选题排斥 + 副词噪声，无一级字段） | 文风本身也缺（自审 P6）；「不可模仿」在技法总结不在文风 |
| 召回 | 手动复读 + 自检重写（无门禁/gaps） | 形式化 (d) 步 + 两级检查 + AskUserQuestion 兜底 + explorer gaps |
| 首要用途 | 沉淀**个人**风格资产 + 对标他人 | 学**对标书**文风（"学自己作品文风"有张力，存疑） |

**结论（强弱差异）**：

- **强在**：① L1 统计口径更细（破折号/括号比、引号场景、小标题字数、中英文混用——mo-shu 未列）；② 蒸馏纪律（≤4000 字）；③ 负向约束两条**具体可推导模式**；④ 双语产物工程化。
- **弱在**：① **无 few-shot 锚点**（moshu-style 核心竞争力）；② 无对话技法；③ 无 confidence；④ 无去 AI 味目标；⑤ 召回松散无门禁；⑥ "脚本统计"名不副实。
- **领域错配是根本**：L3-L6 对网文基本不适用，真正重叠区**只在 L1**（外加 L2 枚举，moshu 归拆书）。故借鉴价值**集中在 L1 统计口径 + 负向约束两条模式 + 单文档预算**，而非其架构或六层框架。

## 10. 待验证问题

1. **上游维护状态**：本地无 `.git`，无法判读 writing-dna-skill 自身提交史/活跃度/版本演进。
2. **"学自己作品文风"边界张力**：`docs/moshu-style-plan.md:419` 写"学任意书/**自己的风格**"，但 mo-shu 更广学习规划「不学清单/产品边界」列了"学自己作品文风"——两处口径需澄清：moshu-style 做不做"沉淀作者本人文风"（writing-dna-skill 的首要用例恰是这个）。

5. **图片分析对纯文本网文的映射边界**：B8 仅取"承重片段优先"思想层，具体锚点选取标准需在 mo-shu 侧验证。
