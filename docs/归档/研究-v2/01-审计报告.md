## 三、最危险的勘误（会照抄错方案的三条）

1. **U1 备份整体照抄 v6 淘汰方案**：旧 U1 = tag chNNNN + 前滚式恢复 + create-branch + 无 git 快照降级——全部是 v6 `backup_manager.py` 的机制；v7 已废弃 tag（定稿消息 `ch(N): title` + `git log --grep` 定位 + rescue ref 回滚 + 章节文件级 `.wnwbackup`），且 git 是硬依赖、无快照降级。**U1 须按 v7 重写。**
2. **U7 体验层三处归因 v7 实为 v6**：五段任务书（v6 context-agent）、BM25（v6 reference_search）、三段式报告（v6 skill 收尾规范）——v7 的对应物分别是：脚本组装"写作材料.md"、关键词打分+Grep、DTO/JSON 输出。**U7 须改源。**
3. **U3 工单"容量护栏 240 条"是自造数字**：SparkArc 源码中 240 只是文本截断字符数和查询 limit。**该设计项删除，改为"注入 ≤3 条相关 + 全量兜底 + 关闭即归档"（有源码依据的部分）。**
