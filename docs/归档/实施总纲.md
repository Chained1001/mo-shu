## 1. 产品愿景

**mo-shu = 长篇网文创作的一致性系统**：一套跑在 Claude Code 上的创作团队与工程底座，让作者写到几百章依然——

- **记得住设定**（单一权威追踪 + 场景过滤注入 + 文件门禁，不写崩设定、不泄漏未来剧情）
- **接得住伏笔**（伏笔/悬念/感情线统一账本 + 悬久预警 + 叙事债务 + 机器可检查的引用）
- **守得住大纲**（规划与执笔分离 + 结构 stale 传播 + 细纲契约字段）
- **写得像自己**（文风库正向统计 + 作者回避负向约束 + 去 AI 味确定性检测）
- **改得回来**（每章 Git 原子定稿 + 半提交探测 + 可回滚）

**一句话**：把"AI 写长篇"从"每次生成都要赌"变成"边写边攒、可回滚、可度量、写评分离的工程流水线"。

### 1.1 目标用户

| 用户 | 场景 | 核心诉求 |
|---|---|---|
| 长篇网文作者（核心） | 开书规划 → 日更连载 → 审查修订 → 卷复盘 | 不写崩设定/伏笔；审查意见真的影响下一章；写废能回滚 |
| 想学写网文的新手 | 扫榜选题 → 拆书对标 → 学文风 | 从验证过的模式出发，不裸奔 |
| 有存量小说的作者 | 导入旧书 → 续写 | 旧书变工程，续写不丢状态 |

### 1.2 与同类产品的差异定位

| | mo-shu | webnovel-writer v7 | SparkArc Studio | 笔枢 bishu-novel |
|---|---|---|---|---|
| 形态 | Claude Code skill 体系（作者主控） | npm CLI + 文件即真相 | 聊天平台 + LLM 导演 | DeterminFlow 插件 DAG 引擎 |
| 正确性 | 程序权威 + check 逐字校验 | git 原子提交 + 格式法律文本 | 落盘护栏 + 状态机 | 脚本门禁 + 双索引 |
| 编排 | 主会话确定性路由 | 1 薄 skill + 53 命令 | LLM 导演自主委派 | 声明式 workflow 节点图 |
| 审查 | 多视角对抗 + 工单闭环（规划中） | 事实/编辑双角色 | Critic 五维 + fix_ticket | observer/arbiter 后验 |
| 材料 | 具体对标书资产 + 拆书 | 通用知识库 + 候选制 | 风格克隆 + GraphRAG | 六维世界 JSON |
| 最强者 | 可验证性/作者掌控/市场侧 | 零依赖确定性机检 | 闭环协议/上下文预算 | 后验管线/确定性门禁 |

**差异化主张**：v7 教工程化与防呆，SparkArc 教闭环与协议，笔枢教后验与门禁——mo-shu 把它们收进"skill 体系 + 作者掌控"的壳里，保持"作者是总编剧"的产品形态。

### 1.3 产品边界

完整清单（含理由与来源）见 **附录 C 不学清单**。产品级声明：不做 RAG/向量检索、不做 LLM 导演黑盒自治、不做自动连写无确认、不做"文件即真相"重构、不做多平台多 CLI 适配、暂不学"学自己作品"文风（对标书为主，列为可选观察项）。

## 2. 产品哲学与总则

1. **三层分工**：脚本做确定性的（能数的绝不让模型估）/ AI 做语义的 / 作者做品味的——定稿永远由作者敲定
2. **单一权威 + 可重放校验**：`_tracking-state.json` 唯一权威、派生视图可 `check` 逐字比对；新增字段走同一事务协议、渲染规则确定性化
3. **团队化（一人一事）**：每个 skill/agent 单一专职；生产与审查永远分离
4. **审查闭环**：批评必须影响后续写作——工单持久化、写前注入、复审关闭
5. **防呆与自愈**：半提交探测、陈旧锁自愈、重试预算 fail-closed、机检候选不拦截——可靠性来自自愈不来自门禁，宁停勿崩
6. **作者掌控**：随时打断/修改/重写；候选是材料不是答案（≤3 条 + 未命中如实降级）；文风库锚点可回查
7. **热路径预算**：每章必读的新内容进 doc-budget；新机制尽量冷路径/按需
8. **部署自包含**：副本由 shared-assets 管理；模板变更 bump agents_version + UPGRADING
9. **兼容优先**：schema 升级带迁移；老产物不判废；新字段全可选增量
10. **证据溯源**（v2 新增）：每条设计标注机制来源（项目+文件路径）；"移植"与"自定"严格区分，自定项必须给验收

### 2.1 实施纪律

1. **每批独立提交 + guard 全过**（static-check/contracts/doc-budget/shared-assets + 本批新测试）
2. **批 0（现状修复）先行**：零风险零设计，先跑通 flash 施工流程再进大活
3. **schema 变更波及面**：U3 涉及三端（write/import/review）+ check + 测试同步；实施拆 4 子步，每步全绿再进下一步
4. **每项验收写死**（规格文件内），flash 自查通过才算完成
5. **U10 单独立项**：先出拆分设计文档，不与 U 系列混批
6. **证据标注纪律**：任何"照抄参考项目"的设计必须能给出文件路径；任何"mo-shu 自定"必须写清验收标准

## 4. 逐项设计摘要（细节在各批规格文件）

> 每单元：**目标 / 来源（项目+文件） / 关键设计决策 / 验收锚点**。文件级改动清单、新增文件内容、验收命令、回滚点在 `docs/规格/批N-*.md`。

### U1 每章 Git 定稿备份（= L1+L2+L3，来源修正：v7 而非 v6）

- **目标**：每章定稿后一次原子 git 提交，可回滚、可定位、可自愈。
- **来源**：v7 `finalize/git.js`、`finalize/index.js`、`state-machine/git-health.js`、`flows/goto-chapter.js`、`storage/adapters/ChapterWriter.js`。
- **关键决策**（v2 修正）：
  1. 定稿消息 `ch(N): 标题`（可选 `条目:`/`设定:` 行），**不打 tag**；定位靠 `git log --grep`。
  2. commit 前 `captureCommitExpectation`（parent/tree/message 三件套）→ 失败 `probeCommitAfterError` 判三态（committed/not/unknown，unknown 宁停保留工作树）。
  3. git-health：陈旧锁 60s + 删除前二次 stat、半提交 stash、.git 损坏只给中文指引。
  4. 章节文件级备份 `.wnwbackup`（写前 rename 旧文件，提交成功删、失败还原）。
  5. 回滚 = `goto` 式（rescue ref + reset --hard + 前置拒绝：进行中批次/git 不健康/脏树）。
  6. **git 是硬依赖**：无 git 时提示初始化，不做快照降级（v7 已证明快照降级是负担）。
- **验收**：写一章自动原子定稿；模拟 commit 假失败不重复提交；改坏可 goto 回滚。

### U2 机检"6 阻断 + 4 候选" + 重试预算 + 名册 + 门禁（= L4+L5+L11+B3）

- **目标**：AI 审稿前零 token 筛可计数问题；候选不拦截；自动修复预算防失控；名册防同人异名；门禁防缺料开工。
- **来源**：v7 `mechanical-check/index.js`（十项+pass 判定+候选永不拦）、`retry-policy/index.js`、`style-stats/index.js`、笔枢 `local_archive.py`（prepare --require/checkpoint --files 空文件 fail）。
- **关键决策**：
  1. 阻断 6：①字数 ±30% 硬边界（流程层 90%/110% 动作阈）②禁词 ③禁句式（非法正则跳过）④复读（6-gram ≥3，**需实测中文误报率，超标的降阈值**）⑤必填（章节标记+细纲引用非空——**mo-shu 自定**，v7 的 front matter 七字段不适用于 mo-shu 正文格式）⑥条目变动形式（只查形式）。
  2. 候选 4：新专名（`([一-龥]{2,3})(冷笑道|笑道|喝道|说道|问道|答道|道|说|喊|问)` + 名册排除）、信息差关键词、高频意象（4-8 gram Apriori，消费体检缓存）、句式偏离（平均句长 ≥30% / 句长方差 ≥50%）。
  3. 重试预算 `追踪/重试预算.json`：机检/审稿各 2 轮、草稿 sha256 幂等（含 front matter）、author-confirmed 单独记账永不恢复自动额度、fail-closed 白名单 schema、定稿清章。
  4. 名册 `追踪/名册.md`（正名/别名/类型/首现章四列表）+ commit 校验新专名 + 别名反查。
  5. 门禁 `tracking_commit.py check --gate`：细纲/卷纲/上下文卡/上一章正文缺失或**空文件**即 fail，中文说明。
  6. **240 条护栏删除**（无源码依据）；工单管理容量规则见 U3。
- **验收**：已知 AI 腔命中阻断、正常文本零误报；同草稿重检不扣预算；名册排除正确；缺细纲 --gate 拒绝；复读误报率实测记录。

### U3 一次性 schema 4→5（= P1/S5 + L6 + L7 + L13 + B2）

- **目标**：审查工单闭环、追读力量化、状态可溯源、经验沉淀、债务独立维度——一次升级避免多次迁移。
- **来源**：SparkArc `story_memory/facade.py:1012-1143`（工单闭环）+ `agent_critic.py`（fix_tickets）、笔枢 `local_archive.py`（debts 索引）、v7 `review/schema.js`（evidence）+ `references/追读/`（8 种钩子 + `节拍/PA-107-微兑现.md` 7 类）、v6 `project_memory.json` 教训。
- **关键决策**：
  1. `TRACKING_SCHEMA_VERSION 4→5`、`INPUT_SCHEMA_VERSION 1→2`（需评估）；**分 4 子步实施**（quality_tickets → debts+evidence → learned_patterns → reading_power），每步 migrate+check+测试全绿。
  2. quality_tickets：复用 mo-shu Findings Schema 扩展 fix_tickets 三件套；写入=review 主会话翻译（consistency-checker 只报 CONFLICTS）；注入=相关性 ≤3 条+全量兜底；关闭=复审 PASS 且无新 ticket；**容量=注入限 3 + 关闭即归档，不做 240 护栏**。
  3. debts：debtor/creditor/promise/due_chapter/status/evidence，章前到期核对，卷复盘清账；三类=承诺/悬置因果（**"悬置信息差"为 mo-shu 自定扩展**，非笔枢原字段）。
  4. learned_patterns：pattern_type/description/source_chapter，**细纲命中才注入**（v6 只写不筛=死数据的教训）。
  5. reading_power：hook_type（**8 种**：危机/悬念/渴望/情绪/选择/时间倒计时/支票/断章）+ strength + 爽点模式 + micropayoffs（7 类）；标注带正文 sha256 防旧覆盖。
  6. evidence：changes 项可选 `evidence: ["chapter:12:event"]` 纯增。
  7. foreshadow 类型沿用现有 summary 前缀（伏笔/悬念/感情线/债务已区分），脚本确定性派生 + check 校验，**不新增 type 字段**（零 schema 增量）。
- **验收**：审查 S1→下章工单约束→复审关闭；伏笔/角色可溯源；经验仅命中注入；债务到期提示；标注不覆盖。

### U4 渲染规则与章后对照（= P3/S7 + L10 + B1 + 信息差）

- **目标**：写前上下文不含未来剧情/状态；章后对照观察与裁决分离；世界事实裁决留痕。
- **来源**：SparkArc `context_builder.py`（三圈记忆 MAX 3 场/2 章末 + `facade.py:1207-1296` eligible_scene_ids）、v7 `book-config.js`（10/10/30）+ `mechanical-check`（信息差候选）、笔枢 `post-hoc/definition.json` + `prompts.json:1990-2043`。
- **关键决策**：
  1. 三圈记忆：章内最近 3 场（硬）→ 前 2 章章末锚点 → 梗概+节拍全局线（软）；按目标章过滤（eligible 概念，用现有 updated_chapter/截至章节字段）。
  2. 计划性内容过滤（主防线）：卷纲/细纲/INF 登记只注入 ≤N 章。
  3. **相关性筛选改"细纲显式引用优先"**（mo-shu 已有细纲引用机制；旧"子串命中相关性"无源码依据，弃用）+ 按埋设章近远补齐。
  4. 悬久预警现算（10/10/30，"提醒不是错误"）；信息差蓄积报表现算（**来源=v7 secrets 机制**，非笔枢）。
  5. 章后对照：**observer=新 haiku agent**（只提取四类差异带证据，不做判断）；**arbiter 不新增 agent**——裁决逻辑在主会话执行 + 作者确认点（笔枢无确认点是其自认弱点；agent 清单 7→8）。
  6. 裁决落点：adopt→timeline、hook→foreshadow、debt→debts、pending→debts/pending 域、conflict→continuity_risks；timeline 事件加 verdict + author_overridden 位。
- **验收**：写第 N 章上下文不含 N+1 计划/状态；章后对照产出四类差异+裁决+作者确认。

### U5 写评分离 + 两模式 + 落盘回执 + 审稿令牌（= P2/S6 + S3 + S1 + S2 + B4）

- **目标**：写手不审自己的稿；落盘才算完成；审查契约与工单域对接；防审稿漂移。
- **来源**：SparkArc `communication.py:1414-1418`（两模态互斥选择）+ `director_graph.py:898-904`（落盘回执）+ `agent_critic.py:40-162`（归一化）、笔枢 `prompts.json:1749/1839`（规则双向复用）、v7 `review/input-binding.js`（审稿令牌）。
- **关键决策**：
  1. narrative-writer 拆**写作模式**（五段输入→正文落盘→返回路径+字数实测）与**审查模式**（只读正文→结构化 findings）；共同规则抽 base 段；产出规范单一真源（B4：质量规则公共引用文件，审查模式按同文件标签版检测——笔枢 15 禁令↔15 标签的验证形态）。
  2. 落盘回执：只输出草稿=打回。
  3. 审查输出复用 Findings Schema 扩展 `{decision, severity, category, location, evidence, issue, fix, fix_tickets[target/edit_goal/must_keep/operations]}`。
  4. 审稿令牌（**来源=v7**）：输入 sha256 指纹随输出回传，不一致拒绝报告。
  5. LLM JSON 归一化层（`_normalize_*` 思路 + `_clean_json_block`）用于所有解析 LLM 结构化输出的环节。
- **验收**：写作模式不落盘→打回；审查模式返回结构化 findings；写后自审移出写作 agent；令牌不一致拒绝。

## 附录 F. 技能与 Agent 设计启示（v2.1 增补）

> 2026-08-20 增补：回应用户"技能设计与 agent 设置是否看了"的缺口审计。研究维度框架见 `04-研究维度框架.md`；本附录收录两个已裁决的架构级问题 + 补研落地项。错误清单与 Prompt 手艺清单见 05/06 档案，落地项已编入对应批规格。

### F.1 模型绑定口径（裁决）

- **现状**（R5 盘点 P2-5）：mo-shu 的 7 个 agent 用代号绑定模型（architect=opus / writer·designer·researcher=sonnet / 只读查询三件套=haiku），绑定强度依赖宿主 CLI 对别名的解析。
- **参考做法**：笔枢 agent **不锁模型**（继承 Core main.model，只按职能配 model_params——规划创意 temp 0.8-0.9、观察裁决 0.3、trimmer/分发器关 thinking）；SparkArc 按用户+agent 经 matchbox 取模型（用户可编辑）；v7 角色是纯 markdown、由宿主模型消费。
- **裁决：保持代号绑定，显式文档化职能依据**。理由：mo-shu 是 Claude Code 单端（不学清单已裁多宿主），代号绑定是优势——自动跟随 CLI 模型升级，无需逐版本改模板。要做的是把"职能→档位"的**意图**写进每个 agent 模板注释（创作最强/执笔平衡/只读便宜快），防未来改绑丢意图；并按需吸收笔枢"按职能调参"（已落地批 4 observer：temp 0.3、关 thinking；其余 agent 若宿主支持参数配置列可选）。

### F.2 薄 skill 哲学（裁决）

- **现状**：mo-shu = 10 个"厚 SKILL"（moshu-write SKILL 221 行 + workflow 文档承载执行知识）；v7 = 1 个 70 行薄 skill（只做接话→`next --json` 拿 DTO→按序调 53 命令）。
- **裁决：保持 10 skill 形态，吸收两条可移植铁律**。mo-shu 是"主会话 LLM 按文档执行"的人肉状态机，没有 v7 的 53 命令面，薄 skill 照搬会导致执行知识无处安放。可移植的：①"**只吃判定结果**"——mo-shu 的 9 序状态机已是文件证据判定（近似 DTO），纪律延续即可；②"**JSON/参数走文件防 Windows 中文管道编码**"——已编入批 3 规格（delta JSON 走 `--delta-file`，禁命令行内联）。
