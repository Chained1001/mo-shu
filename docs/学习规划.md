# mo-shu 学习规划（借鉴 webnovel-writer）

> 依据：`docs/webnovel-writer-研究.md`（五轮研究存档）。本文件是把可借鉴点转化为 mo-shu 实施计划的唯一入口——每条注明学什么、落点、成本、验收方式。
> 日期：2026-08-19。状态：规划（未开工）。

---

## 学习总纲（四条逻辑）

1. **学"确定性纪律"，不学"记忆更多"**——零 token 机检 / AI 语义 / 作者定稿的三分法，是它最强护城河
2. **学"防呆与自愈"，不学"流程更重"**——半提交探测/健康检查/重试预算，而不是批次状态机
3. **learn 只学"带筛选的注入"**——它的 project_memory 只写不筛=死数据（自身教训），我们做必须带细纲命中筛选
4. **真源哲学不动**——mo-shu 的"单一权威 + check 逐字校验"已解决 v6 投影漂移问题（v7 用 git 解决的同一问题），改真源成本巨大且无收益

## 一、工程拼图（v1.1.3，~400 行零依赖）——🟢 第一批

### L1 每章 Git 自动备份
- **学什么**：追踪事务成功后 `git commit + tag chNNNN`（消息 `Chapter {N}: {title}`，title 经 sanitize 防注入）；rollback 用前滚式恢复提交（不丢历史）；create-branch 从任意章建平行分支；无 git 环境降级本地快照（保留最近 10 份）
- **落点**：workflow-chapter.md 步骤 12（追踪事务）之后追加"备份"步骤；新脚本 `scripts/backup_chapter.py`（或并入 tracking_commit.py 子命令）
- **成本**：低（参考 backup_manager.py 逻辑）
- **验收**：写一章 → 自动生成 git tag；手动改坏正文 → rollback 恢复；无 git 目录 → 快照目录生效
- **风险**：需 git 环境；`.moshu-review/`、临时文件进 .gitignore；仓库需初始化（无 git 时降级路径兜底）

### L2 半提交探测（probeCommitAfterError）
- **学什么**：commit 报错后用 parent/tree/message 三件套遍历 rev-list 判三态（committed / not-committed / unknown），unknown 宁停不删——防"git 偶发返回码 ≠ 未提交"导致的重复提交
- **落点**：L1 备份脚本内部（captureCommitExpectation + probeCommitAfterError）
- **成本**：~60 行
- **验收**：模拟 commit 中途失败 → 不产生重复 tag/提交

### L3 git 人话化 + 健康检查
- **学什么**：陈旧锁 60s 阈值 + 删除前二次 stat 防 TOCTOU；半提交 stash；.git 损坏只指引不自动动；全中文输出（作者永不看英文报错）
- **落点**：L1 前置检查（git-health）
- **成本**：低
- **验收**：手动放一个陈旧 index.lock → 自愈提示；正常场景无感

### L4 机检"阻断 vs 候选"分层（字符级零依赖）
- **学什么**：10 项机检 = 7 阻断 + 3 候选——字数±30% / 禁词 / 禁句式 / **复读（字符级 6-gram ≥3）** / **新专名候选（`([一-龥]{2,3})(冷笑道|笑道|…)` 启发式 + 名册排除）** / 必填字段 / 条目变动形式 + **高频意象候选（CJK 4-8 gram Apriori 分层，内存有界）** / 信息差关键词候选 / 句式偏离候选。候选永不拦截
- **落点**：moshu-write 写后收尾（check-ai-patterns 之前）加一道 `scripts/mechanical_check.py`；拆书 Stage 2 摘要硬检查可复用其中"条目形式/复读"项
- **成本**：~300 行，全字符级零依赖（绕开中文分词）
- **验收**：对已知 AI 腔文本命中阻断项；对正常文本零误报（候选不拦截）；新专名候选正确排除名册内名字
- **风险**：检测误报——照搬"只出候选不拦截"纪律；中文统计全用字符级

### L5 重试预算补全
- **学什么**：自动修复 2 轮硬上限 + **草稿 sha256 幂等**（同 hash 重检不扣预算）+ author-confirmed 单独记账 + 严格 schema fail-closed + 按章持久化（定稿后清章）
- **落点**：moshu-write 现有"机检修复预算 2 轮"补幂等与持久化（`追踪/重试预算.json` 或并入追踪事务）
- **成本**：低
- **验收**：同草稿重复检查不重复消耗预算；预算文件损坏时 fail-closed 不猜测

## 二、数据闭环（v1.2）——🟡 第二批

### L6 追读力四维标注
- **学什么**：hook 五型（危机/悬念/渴望/情绪/选择）+ 强度；爽点模式（精简）；微兑现 7 类（信息/关系/能力/资源/认可/情绪/线索）；硬约束 vs 软指导（软违规记债务可申诉）
- **落点**：事务 delta 加 `reading_power: {hook_type, hook_strength, coolpoint_patterns, micropayoffs}`；taxonomy 精简为 mo-shu 自用版（新 references 文件）；卷复盘消费趋势
- **成本**：低-中（字段 + schema 扩展 + 文档）
- **验收**：逐章记录可见钩子/爽点标注；卷复盘给出本卷追读力统计
- **风险**：taxonomy 文档需精简防 reviewer 标注漂移；标注是 AI 判断非确定性计算（明确地位）

### L7 evidence 溯源链
- **学什么**：状态/伏笔/角色变化带 `evidence: ["chapter:12:event"]`，可审计"为什么变成这样"
- **落点**：事务 delta 各 changes 项加可选 evidence 数组（纯增不改，check 校验格式）
- **成本**：低
- **验收**：任意伏笔当前状态可追溯最近一次推进的章与事件

### L8 outline 相关性筛选
- **学什么**：渲染上下文.md 时，用本章细纲文本对伏笔/角色做子串命中优先（命中者先取，再按埋设章近远补齐）——替代现"活跃伏笔截断 8 条"
- **落点**：tracking_commit.py 渲染函数内排序（**规则必须确定性化**以兼容 check 逐字比对）
- **成本**：低
- **验收**：本章细纲提及的伏笔必然在上下文.md 中；check 仍通过
- **风险**：筛选规则必须无随机性（webnovel 的 outline 子串匹配可确定性化）

### L9 审查指标落库 + 趋势回灌
- **学什么**：review 收尾写轻量指标 JSON（S1-S4 计数/维度结论）；写前准备读"近 5 章高频问题维度"作为约束（趋势只提示不裁决）
- **落点**：moshu-review 收尾落 `追踪/审查指标.json`（或并入事务）；workflow-chapter 写前准备 (a)-(g) 加一步读取
- **成本**：中
- **验收**：连续 3 章 S1 同维度 → 第 4 章写前任务书出现该维度约束
- **风险**：避免过度量化——趋势只提示；报告体积受控（轻量 JSON 非 md 全文）

### L10 章间"悬了太久"预警
- **学什么**：已有 10/10/30 阈值（伏笔/悬念/感情线），补按章预警（"是提醒不是错误，收不了可以接受"）
- **落点**：轻量 `report_overdue.py`（读派生视图现算悬久章数）
- **成本**：低
- **验收**：伏笔悬置超阈值 → 写前/批末提示

### L11 实体名册 + 别名反查
- **学什么**：正名/别名/类型/首现章一张表（唯一真源不双存）；commit 时校验新专名；resolve-alias 反查
- **落点**：`追踪/名册.md`（或派生视图）；tracking_commit commit 时校验；拆书导入时生成
- **成本**：低
- **验收**：同人异名/同名异人可机械检出；新专名出现在正文 → commit 提示登记
- **风险**：需定"谁维护名册"——拆书导入生成 + commit 增量校验

## 三、体验与查询（v1.3）——🟡 第三批

### L12 写前五段任务书
- **学什么**：开篇委托 / 这章的故事 / 这章的人物 / 怎么写更顺 / 收在哪里（把写前材料翻译成纯写作语言，屏蔽系统词）
- **落点**：workflow-chapter 步骤 3"指令确认"升级为固定五段结构
- **成本**：中
- **验收**：narrative-writer 收到五段任务书可独立起草（不依赖其他材料）
- **风险**：任务书过重拖慢日更——设 token 预算

### L13 经验库（带筛选的 learn）
- **学什么**：`learned_patterns: [{pattern_type, description, source_chapter}]` 随事务提交；**细纲命中才注入写前任务书**（只写不筛=死数据——它的教训）
- **落点**：新事务字段 + `追踪/经验.md` 派生视图 + 渲染时子串筛选
- **成本**：低-中
- **验收**：作者记一条"钩子模式"→ 本章细纲含相关词时注入，否则不注入
- **风险**：必须"写→筛→注入"三件套齐上；与文风库分工明确（文风=表达层统计，经验=结构层模式）

### L14 explorer 本地 BM25 检索
- **学什么**：纯本地词频索引（无向量无外部 API），搜正文/逐章记录/对标，chapter≤N 过滤，中文子串兜底
- **落点**：moshu-explorer 增加 `bm25_search` 查询类型（或独立脚本）
- **成本**：中
- **验收**："第 30-50 章发生了什么"可检索出相关章节；无网络依赖
- **风险**：中文无分词召回质量有限——明确作为 grep 的补充而非替代

### L15 候选制纪律
- **学什么**：给建议的环节（拆书模板/题材卡/技法路由）每类 ≤3 条候选 + **未命中如实声明降级**（"无匹配模板，走通用框架"），候选是材料不是答案，不替作者选择
- **落点**：拆书模板选择、题材正文提示卡、对标推荐、匹配章节挑选的 prompt/协议
- **成本**：低
- **验收**：无匹配题材时明确降级声明而非硬凑

### L16 degradation 显式标记
- **学什么**：读文件失败/降级时显式标 `degraded` 并先向作者呈报缺料，不静默基于残缺数据工作
- **落点**：各 Stage 失败处理（读对标缺失/文风缺失/摘要缺失时的降级路径）
- **成本**：低
- **验收**：任何降级路径的输出都带显式标记

### L17 作者友好三段式报告
- **学什么**：各 skill 收尾固定三段式——总状态 / 产生的文件 / 问题与下一步
- **落点**：各 skill 收尾模板统一
- **成本**：低
- **验收**：抽查各 skill 收尾报告格式一致

## 五、明确不学（及理由）

| 不学 | 理由 |
|---|---|
| RAG/向量检索 | 外部 embedding API 依赖 + 中文召回质量差，与 mo-shu 零外部依赖定位冲突 |
| learn 式经验记忆（原版形态） | 原项目自身证明召回弱（只写不筛）；除非按 L13 带筛选 |
| 自动连写/批次污染传播 | 状态机复杂度大，单作者场景收益低 |
| 知识治理三件套（策展规则/维度宪章/字段矩阵） | 单人项目偏重，只保留候选制（L15） |
| 多宿主适配 registry | mo-shu 纯 Claude Code 生态，当下不需要 |
| v6 提交链/多投影方案 | 已被 v7 自己否决（投影漂移）；mo-shu 单一权威+check 校验已是更优解 |
| "文件即真相"重构 | mo-shu 程序权威 + check 逐字校验解决同一问题，改真源成本巨大且无收益 |

## 实施纪律

1. **每批独立提交 + guard 全过**（static-check/contracts/doc-budget/shared-assets）
2. **L1-L5 必须先做**：后续批次（L6-L17）的事务字段扩展以 L1 的备份/机检/预算为前置
3. **schema 变更波及面**：L6/L7/L13 涉及事务 schema（INPUT_SCHEMA_VERSION 升级），需同步 moshu-write/import/review 三端 + check 校验 + 测试
4. **每项验收方式已写死**（见各条），做完实测验证再提交
