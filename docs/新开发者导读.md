## 一、项目定位

**中文网文写作 skill 包**，覆盖从扫榜选题到拆文学习、构建大纲、写正文、审查、去AI味的全流程。内置适配 Claude Code。核心哲学：**把专业作家的外部化工作系统做成工具**——方法论给知识、采风给活参照、机检给底线、评审给品质判断。

## 六、关键纪律速查（不读会踩坑）

| 规则 | 出处 | 一句话 |
|---|---|---|
| git 只读默认 | AGENTS.md §1.1 | 未经作者明确语言确认禁止 commit/push |
| 一批一提交 | AGENTS.md §2.1 | 每批一个 commit，范围=当批文件+规格随批 |
| 推送后等 CI | 开发标准 §8.3 | push 后必须等 CI 绿才开工下一批 |
| 候选永不拦截 | AGENTS.md §2.7 | 机检/审计的 candidate 不阻断流程 |
| 版本 bump 用脚本 | 开发标准 §3.4 | 禁止手工 grep+replace 版本号 |
| shared-assets 强制 sync | 开发标准 §5.2 | 改 write 源后必须 sync+check 全绿 |
| 方法论禁互引 | 开发标准 §2.2 | AI 看不到对方——纪律正文自包含 |
| 按节精读 | 开发标准 §2.2 | 带「节名」锚点只读所需节，不整文件读入 |
| 苏格拉底格式 | 开发标准 §2.2 | 设计方法用问句不用清单——"答不出说明设计未完成" |
| 通用性优先 | 开发标准 §10 | 案例特定规则不进通用标准文件 |

## 七、核心流程概览（build 管线）

```
Stage 1 信息采集（四轮式：定调→定形→理想书评→定流程）
  └─ 默认采风（用户提到参考书时自动联网检索）
  └─ 产物：理想书评 / 题材定位 / 关系 / 题材正文提示卡 / 台账
       ↓
Stage 2 骨架构建 → 🔴 停靠 1
  └─ 八列表（主角中心/对手纠缠/赌注/中点假胜败/高潮/跃迁）
  └─ 势力场（网非链+借力落位问） / 常驻压力 / 暗线设计 / 角色四件套
  └─ 机检 + 🔍评审 Agent（三维度）→ 停靠弹窗（确认/调整/采风/自改）
       ↓
Stage 3 人物构建（⚪ 自动）
  └─ 角色弧线（六阶段+升级绑弧光三问） / 世界观 / 关系回填 / 情绪引擎+低压侧
  └─ 创作瓶颈信号（角色采风可触发）
       ↓
Stage 4 单元构建 → 🔴 停靠 2
  └─ 单元卡（BC-ID 章功能） / 支线登记（八列含配角高光） / 浮现记录
  └─ 势力场借力落位检查
  └─ 机检 + 🔍评审 Agent → 停靠弹窗
       ↓
Stage 5 整合检验（⚪ 自动）
  └─ 伏笔登记（兑现方式四选一+铺垫链） / 反转检查 / 线索矩阵 / 动机链核验
       ↓
Stage 6 打磨定稿 → 🔴 停靠 3
  └─ LOCK / 配比 / 八节点 / 卷级五问 / 理想书评终检 / 打磨记录落盘
  └─ 🔍评审 Agent 终审 → 停靠弹窗
  └─ 定稿 → 卷纲 v1.0 + tracking init → 构建态翻为「定稿」
```

**闭环**：创作 → 评审（发现弱点）→ 采风（定向补弱）→ 融合（当前语境）→ 再评 → 通过
