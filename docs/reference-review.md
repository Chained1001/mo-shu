## 2. 笔枢:优缺点与可学点

**优点**
1. **后验对照管线(observer→arbiter)**是全项目最精华的设计:章节观察者只做"对照机器"(输出 world/story/character/unplanned 四类差异,每条带正文段落证据,不做判断);后验仲裁者再裁决——世界事实 adopt/pending/conflict、故事差异 landed/missed/deviated、未提事件归类 hook/debt/discard。**观察与裁决分离**杜绝了"又当运动员又当裁判"。
2. **上下文裁剪器(trimmer)**:减法式裁剪(默认全保留/保守删除/最小字段粒度/近纲同卷感知),「场景级可感 vs 系统级结构」边界(告诉写手"这里是什么样"保留、"为什么是这样"不保留)。比"加载全部设定"省 token 且不丢关键信息。
3. **叙事债务与伏笔表**(hooks/debts)每章产出并**合并累积**(merge-hooks/merge-debts),带 id/expected_payoff/from/to 必填字段——债务有明确兑现期望。
4. **意图分发器**只分类不评价(OD 情节/SE 写法,节拍张力情绪两路都发),人类意图被结构化分流。
5. **专业润色 7 维**(节拍韵脚/潜台词对话/动机犹疑/反重复/情感锚点/感知层次/最终润色)+硬性规则(长度保护 60%-140%、禁增场景角色、SLOT 清理)——"润色不是重写"。
6. **过渡写手 10 条反 AI 硬约束**(见 §5),句级质量底线。

**缺点/风险**
1. 平台绑定:工作流引擎、JSON 契约、脚本库均为 DeterminFlow 专属,mo-shu 无法迁移编排层。
2. 多写手并行填槽(骨架/对话/动作/内心/描写/过渡):风格一致性风险大,且 token 总耗高于单写手;mo-shu 行为契约 #8 model-single-writer-state 已裁决不学。
3. 固定 6 维世界 JSON 结构刚性,题材适配成本高;世界状态机逐章快照较重。
4. 无作者审美控制点:管线全自动跑,作者只在 human_intent 输入,缺少"裁决/打回"的人机分权(arbiter 是 AI 裁决,作者被架空)。

**对 mo-shu 的可学点**
- **高**:日更步加"章后对照"(细纲落地/偏离/未提事件归类,轻量版 observer+arbiter)→ 复用追踪事务基础设施
- **高**:过渡写手 10 条反 AI 约束并入 anti-ai-writing(多条是 mo-shu 14 模式没有的)
- **中**:本章设定裁剪(细纲涉及角色/地点过滤,trimmer 简化版)
- **中**:审查意见带 must_keep 保底(润色长度保护的思想)
- **低**:叙事债务表字段化(已有追踪前缀,可加 expected_payoff 列)

## 3. 引火:优缺点与可学点

**优点**
1. **四层提示词架构**(base/system/chat/pipeline/tool_rules)+ **quality_profiles 可编辑**(quality.guard/preference 注入所有 agent)——质量偏好一次配置全局生效,且用户可改。
2. **PreWrite 预装**:写作前系统确定性装配 StoryMemory(实时人物状态/关系记录/开放线索/修订工单)——"写前自动装配上下文",不靠写手自觉。
3. **查证交接协议**:外部事实必须 web_search 查证,交接包含【已查证资料/未确认项/创作边界】,可明确下放查证;失败必须说"无法确认",禁止猜测填空。事实纪律严明。
4. **critic 五维证据化审核**:先建立作品基准(题材/媒介/作者风格/场景目标)再评判;S/A/B/C/D→PASS/REVISE/REJECT;每条批评引用原文;fix_tickets 含 must_keep(修改时不得破坏的内容)。
5. **边界纪律**:任务描述限定开始/结束位置时边界优先于大纲,边界后事件留给下一场,不得提前写入。
6. **completion_mode 交接协议**(silent_continue):下游完成后只报"写了什么/对照契约/剩余待写",由导演决定继续——进度控制不靠自觉。
7. **conception 块**:场景设计说明(功能/视角边界/连续性约束/表现策略/必须保留事实)随文落盘,只写结论不留推理过程。

**缺点/风险**
1. 平台绑定严重:story_memory/graph_rag/PreWrite/work_tracker 都是平台基础设施,Claude Code 无对应物。
2. agent 联邦架构对单会话 Claude Code 太重(导演+6 agent+图谱+记忆服务)。
3. 白盒协作(UI 可视化)、三态提示词工程均不可迁移。
4. ARC 剧本格式(对白/旁白节点)是为剧本/视觉小说设计,与网文散文体不完全适配。

**对 mo-shu 的可学点**
- **高**:must_keep 保底机制(审查裁决/机检修复时显式声明"不得破坏"的内容)
- **中**:事实查证纪律一条(涉及现实知识/行业/年代事实时先查证,禁凭记忆)
- **中**:作品基准先行的审核原则(先立基准再挑刺,防无标准打靶)
- **低**:写前准备脚本化一半(追踪查询自动化)
- 已落地:灵感种子(idea-seed.md)、节拍稀疏原则(beat-cards)、输出格式即契约

4. **命名卡 14 张**(书名卖点承诺/章节名事件与悬念/卷名阶段路标/角色名身份语系…)是 mo-shu 完全空白但高频刚需的维度(开书要起名、每章要起章节名)。
5. **设定卡 27 张**(规则闭环与覆盖校验/能力代价与使用边界/力量阶梯与越级边界…)与 mo-shu 世界观骨架互补。

**缺点/风险**

3. 部分卡与 mo-shu 已有内容重复(人物主题卡 8 张已吸收其 28 张的精华;beat PA 与 BC 大量同构)。

**对 mo-shu 的可学点**

- **高**:钩子 11 类与 hooks-chapter 合并补全
- **中**:场景卡精选 5-8 张高频场景(团战/谈判/真相揭露/重逢/宴会)→ 场景卡文件
- **中**:设定卡精选(规则闭环/能力代价)并入世界观骨架

## 5. 去 AI 味专项:三项目 vs mo-shu 现状

mo-shu 现有:anti-ai-writing 14 模式 + banned-words + 机检 4 脚本(ai-patterns/degeneration/outline-copy/punctuation)。

笔枢过渡写手 10 条硬约束中,**mo-shu 未覆盖或覆盖不足**的:
1. **禁名词性独语句**("冷。铁锈和旧木头的味道。"——无主谓)→ 现有 14 模式未明确覆盖
2. **句子可追问测试**:写完每句假设读者问"然后呢?具体是什么?",空洞句重写("夜色很美/他心情复杂"经不起追问)
3. **句子最低信息量**:删掉这句读者损失什么新信息?无损失→删
4. **禁直接命名情绪**("他感到/意识到/觉得/忽然明白")→ 写动作/停顿/对话让读者自己判断
5. **拆物化结尾**:禁止"他像一片落叶飘远了/她化作了一阵风"式比兴收束 → 用具体行动或一句话收尾
6. **禁群像反应**("全场震惊/所有人都倒吸一口凉气")→ 挑一两个具体角色写个体反应
7. **禁"了一下"句**("抖了一下/看了一眼/留了很久")→ 换具体动词
8. **禁破折号滥用** → 用逗号或句号
9. **禁元叙事旁白**("故事发展到这一步/读者也许会想")→ 你是亲历者不是编剧
10. **高频 AI 标记词限额**("仿佛/忽然/竟然/猛地/蓦然/不禁/宛如"每三千字最多一次)→ mo-shu banned-words 有词表但无"每千字限额"机制

引火 critic 五维(结构/语言/对白 AI 味+文学承载+视角逻辑人设)与 mo-shu quality-rubric 维度互补;S/A/B/C/D→PASS/REVISE/REJECT 与审查作者裁决点(全部接受/修改后接受/打回)同构。

## 6. mo-shu 差距总评

**已对齐/领先**:架构分层与路由、状态机与作者控制点、分工原则、追踪体系(悬念/伏笔/感情线+悬久阈值,优于三项目的 debts/hooks)、质量预算阀门、拆文扫榜数据管线、审查裁决闭环。

**真实差距(按价值排序)**:
1. **章后对照缺失**(笔枢 observer/arbiter 思想)——日更提交后无"细纲落地核对+新事件归类",伏笔/偏离靠批末交叉核对兜底,粒度太粗
2. **反 AI 10 条硬约束**(笔枢过渡写手)——句级质量底线,与现有机检互补
3. **must_keep 保底**(引火 fix_tickets)——修改/审查时防破坏
4. **命名卡空白**(V7 命名 14 张)——高频刚需
5. **钩子分类学**(V7 追读 11 类)——hooks-chapter 补全
6. **本章设定裁剪**(笔枢 trimmer)——token 优化+信息聚焦
7. **事实查证纪律**(引火查证协议)——行业文/年代文刚需
8. **场景卡/设定卡精选**(V7)——中低频但高频场景时刚需

**明确不学**:笔枢多写手并行(风格一致性,契约 #8 已裁决)、笔枢 workflow 引擎(平台绑定)、引火 agent 联邦/图谱/白盒(平台绑定,文件式追踪已够)、V7 全量卡库(膨胀)、引火 ARC 剧本格式(网文散文体不适配)。
