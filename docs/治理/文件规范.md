# 文件规范（mo-shu 仓库全文件类型命名与格式）

> **版本**：v1.0（2026-09-02，B104 后立法）
> **定位**：本文件是仓库所有文件类型的命名规则与格式模板的**单点权威**——新增文件前先查本规范；规范未覆盖的类型走 AGENTS §5 决策树。
> **与术语表的关系**：术语表管"产品语言的叫法"（面向用户），本规范管"文件系统的命名与格式"（面向开发者）。

---

## 一、命名规则总表

| 文件类型 | 命名规则 | 示例 | 位置 |
|---|---|---|---|
| **技能壳** | `SKILL.md`（固定名） | — | `skills/{skill-name}/` |
| **技能目录** | kebab-case，`moshu-` 前缀 | `moshu-outline/` | `skills/` |
| **工作流** | `workflow-{技能名}.md` | `workflow-outline.md` | `skills/{skill}/references/` |
| **方法论** | kebab-case，按域前缀分组 | `outline-causality.md` | `skills/{skill}/references/` |
| **模板** | `{产物名}-template.md` | `core-setting-template.md` | `skills/{skill}/references/` |
| **手册** | `{操作名}-methods.md` 或 `{域}-handbook.md` | `caifeng-outline.md` | `skills/{skill}/references/` |
| **脚本** | `{动词}-{对象}.{py/sh/js}` | `check_outline.py` / `sync-shared-assets.py` | `skills/{skill}/scripts/` 或 `scripts/` |
| **测试** | `test_{对象}.py` / `test-{对象}.sh` | `test-check-outline.py` | `scripts/` |
| **守卫** | `check-{对象}.sh` | `check-doc-budget.sh` | `scripts/` |
| **agent 模板** | `moshu-{角色名}.md` | `moshu-evaluator.md` | `templates/agents/` |
| **规格** | `批{N}-{批次名}.md` | `批B103-大纲阶段重构批.md` | `docs/治理/规格/` |
| **治理文档** | 中文名，无扩展规则 | `术语表.md` / `盲区清单.md` | `docs/治理/` |
| **研究文档** | `{编号}-{主题}.md` | `10-实测观察清单.md` | `docs/研究/开源强化/` |

### 方法论文件域前缀分类

| 前缀 | 域 | 示例 |
|---|---|---|
| `outline-` | 大纲结构学 | `outline-causality.md` / `outline-rhythm.md` / `outline-structure-theory.md` |
| `character-` | 人物构建学 | `character-construction.md` / `character-basics.md` |
| `plot-` | 情节与情感 | `plot-frameworks.md` / `plot-emotion-system.md` |
| `genre-` | 题材知识 | `genre-catalog.md` / `genre-readers.md` |
| `reader-` | 读者契约 | `reader-contract-and-progression.md` |
| 无前缀 | 独立方法论/工具 | `skeleton-template.md` / `golden-finger-design.md` / `beat-cards.md` |

**新增方法论文件**：按域选前缀；跨域的用无前缀独立名。

## 二、书项目产物命名与结构

```
{项目根}/
  创作进度.md              ← 书级元数据（七态状态机/产物表/打磨记录/故事灵感备忘）
  选题决策.md              ← moshu-scan 产物（只读输入）
  灵感种子.md              ← 已退役 #103（不再产出）
  CLAUDE.md                ← 部署时生成

  设定/
    基本设定.md            ← 五段纯标签（基础参数/基调风格/参考偏好/成品标尺）
    情绪引擎.md            ← 可复现情绪模块（4.3 产物）
    正文教训档案.md         ← 正文期空启+章后对照教训 append
    参考档案.md            ← ✗ 已退役（深采产物归 参考/ 目录）
    大纲打磨报告.md        ← 随轮追加的打磨记录
    角色/                  ← 人物页（每角色一文件）+ 关系.md 索引
    势力/
    世界观/
    参考/                  ← 参考作品深采档案（每书一文件，九段 schema）
    采风/                  ← CF 票据产物（溯源层）
    资料/                  ← 题材内容素材（素材层，五维采集）

  大纲/
    大纲.md                ← 全书骨架（十节结构）
    卷纲_第{N}卷.md        ← 卷级规划
    场景表/*.md            ← 场景行（volume 产物）
    细纲_第{N}章.md        ← 章级细纲（write 产物）

  正文/
    第{N}章_{标题}.md      ← 正文章节

  追踪/                    ← 全部由 tracking_commit.py 生成（build/write 只读）
  对标/                    ← 对标作品分析（analyze 产物）
  拆文库/                  ← 拆文分析结果
```

**命名纪律**：
- **中文名用于书项目产物**（作家可见的文件）；**英文 kebab-case 用于技能/脚本**（开发者可见）
- **旧名回退兼容**：基本设定.md ← 题材定位.md；创作进度.md ← 设定/创作进度.md；双路径读取新名优先
- **已退役产物**不再产出，但老书项目里的文件不删（存量兼容）

## 三、文件格式模板

### 3.1 方法论文件格式（references/ 下的理论/操作文件）

```markdown
# {文件名}：{一句话标题}

> **消费点**：{哪个 Stage 哪步加载、按需还是必读}
> **来源**：{书证（书名+章节）/ 实测编号 / mo-shu 自定}
> **边界**：{本文件管什么、不管什么（与相邻文件的分工）}

## {N}. {概念名}

- **问句**：{触发问句——设计时问自己}
- **操作**：{具体怎么做}
- **反例**：{常见错误——什么样的写法说明没想清}
- **来源**：{来源标注}
```

### 3.2 工作流文件格式（workflow-*.md）

```markdown
# workflow-{技能名}.md：{技能目的一句话}

> **来源声明**：{拆分/重构历史}
> **核心原则**：{本流程的设计基准}
> **统一模板映射**：{PREPARE/DRAFT/REVIEW/POLISH/COMMIT 如何映射}

## 开场白
{技能目的+步骤总览表}

## 交互模态规则
{弹窗/对话/过程性动作的选用纪律}

## {Stage/步 N}·{步名}
{步骤正文——含话术/产物/方法论挂载}

> 挂载：{文件名}
> 内容：{≤50 字概括}
> 引用目的：{该步用它做什么}
```

### 3.3 模板文件格式（*-template.md）

```markdown
# {产物名}模板

> **定位注记**：{本文件是什么产物的落盘模板}
> **创建时机**：{哪步产出/何时消费}
> **旧名兼容**：{如有改名，注明旧名回退}

{产物模板正文——字段表/节结构}
```

### 3.4 agent 模板格式

```markdown
---
name: moshu-{角色名}
description: |
  {一句话角色定位}
tools: [{工具白名单}]
disallowedTools: [{禁用工具}]
model: {model 名}
maxTurns: {N}
---

# {角色名} — {一句话定义}

{角色正文——含对象清单表/纪律段/输出格式/被调用协议}
```

### 3.5 SKILL.md 格式

```markdown
---
name: moshu-{技能名}

---

# {技能名}

{技能目的/路由/产物/引用文件表}
```

## 四、跨文件引用格式

| 引用场景 | 格式 | 示例 |
|---|---|---|
| 同目录文件 | `[文件名](文件名.md)` | `[skeleton-template.md](skeleton-template.md)` |
| 跨技能文件 | 纯文字（无链接）+ 路径说明 | `moshu-volume 侧 caifeng-volume.md` |
| 书项目产物 | `` `路径/文件名` `` | `` `设定/基本设定.md` `` |
| 指定节 | 文件名 + `第 N 节` 或 `「节名」` | `skeleton-template 第 3 节` / `outline-methods「势力场设计」` |
| 脚本 | `` `scripts/{脚本名}` `` | `` `scripts/check_outline.py` `` |
| agent | `moshu-{角色名}` agent | `moshu-researcher` agent |

**纪律**：同目录用 Markdown 链接（static-check 可达性检查依赖）；跨技能用纯文字（不产生跨技能链接——runtime 自包含硬约束）；产物和脚本用行内代码。

## 五、doc-budget 报告要求

改 AGENTS.md 或热路径文件（workflow/SKILL/chapter-core 等）时：
- 报改前/改后 UTF-16 字数：`node -e "console.log(require('fs').readFileSync('{文件}','utf8').length)"`
- AGENTS.md 阈值 11000（盲区 §4-1）
- 各文件阈值见 `scripts/doc-budget.json`

## 六、本规范的维护

- 新增文件类型：先按本规范命名+格式；规范未覆盖的类型走 AGENTS §5 决策树，决策结果回写本规范
- 修改命名规则：须全仓 grep 涟漪面确认（反模式 #2）
- 退役文件/概念：本规范标注 ~~已退役~~ + 裁定编号（如 ~~灵感种子.md~~ #103）
