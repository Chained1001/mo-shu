## 三、文件级改动清单

### 改动 1：新脚本 `skills/moshu-build/scripts/design_fingerprints.py`

纯标准库（hashlib/json/pathlib/argparse），三子命令：

- `record --project <书根>`：计算 `设定/**/*.md` + `大纲/大纲.md` + `大纲/卷纲_*.md`（**细纲排除**——细纲改动属规划层，由补纲流程自管）每文件 sha256 → 写 `{书根}/.design-hashes.json`（含 generated_at 与文件清单）；registry 缺失时任何子命令先自动 record 建基线（幂等：同内容重复 record 哈希不变）。
- `diff --project <书根>`：现算哈希 vs registry → 输出 JSON：`{changed: [{file, status: changed|missing, chapters: [N,...]}], unchanged_count}`；chapters 反查=遍历 `大纲/细纲_第N章*.md` 的「本章涉及设定」字段（正则截取该行，按**文件名包含匹配**——字段写法可能是「角色/甲.md」或「甲」，取文件名 stem 与路径后缀双匹配，匹配口径在脚本注释标 mo-shu 自定）；文件未出现在任何细纲 → chapters 空数组（明示「无已写章引用」）。退出码恒 0（呈报工具，不是守卫）。
- `update --project <书根>`：等价 record（裁决闭环后刷新基线；语义别名，方便流程口令区分）。

**读失败三分类**（反模式 #7）：registry 缺失→自动建档并在 diff 输出 `baseline_created: true`；设定目录缺失→输出 `{error: "设定目录不存在"}` 退出码 1；单文件读失败→该文件 status 标 `unreadable` 不中断。

### 改动 2：revision-workflow.md 接线（预估净增 +120~180，超 2350 则调 2500，why 记 B61 判因；组 22670 ≤22800 不动）

- ③ 留痕落盘后加「③b 指纹影响面（B61）」步：跑 `python skills/moshu-build/scripts/design_fingerprints.py diff --project {书}` → 复查清单 MD 渲染呈报作者（每改动文件一行：文件名+受影响章列表+「无已写章引用」明示）→ **作者裁决**是否对该章区间发起 `/moshu-review` 复查（复查清单 JSON 路径作为审查上下文传入；不自动建工单——发起权在作者）。
- ⑤ 结束回流前加一句：裁决闭环（复查完成或作者明示不复查）后跑 `update` 刷新基线——未刷新则下次修订 diff 会重复呈报（幂等安全方向）。
- 「明确不做」节补一行：指纹工具不做变更分级/不写追踪域/不自动建工单。

### 改动 3：正式回归 `scripts/test-design-fingerprints.py`

文件头「守护对象」声明（守护 B61 指纹三子命令契约：幂等/反查正确性/三分类降级）。≥6 用例：①record 幂等（两次哈希同）②反查命中（细纲 1/3 章列「角色/甲.md」、2 章列其他 → 改甲.md → diff chapters=[1,3]）③stem 匹配（字段写「甲」不带路径也命中）④删除文件 → status=missing ⑤无引用 → chapters 空+明示 ⑥registry 缺失 → 自动建档+baseline_created ⑦设定目录缺失 → 退出码 1。

## 五、禁止事项

1. **不写 追踪/ 任何文件**（追踪域边界，宪法）；不自动写 review 工单（发起权在作者）；不改 TRACKING/INPUT schema。
2. 退出码语义：diff 恒 0（呈报工具），仅致命目录缺失为 1——**不得做成守卫语义**（反模式先例：候选永不拦截的同源逻辑）。
3. 匹配口径是 mo-shu 自定（stem+路径双匹配）——注释标注+验收可测，不引入模糊/语义匹配。
4. 细纲排除在指纹域外；不做变更分级；不扩范围到正文文件哈希。
5. 预算超限先压缩再调高；why 数字以 git diff 核对原值。
