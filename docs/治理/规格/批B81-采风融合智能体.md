### 改动 1：researcher agent 模板扩展「融合模式」节（~250 字）

`skills/moshu-setup/references/templates/agents/moshu-researcher.md` 在「研究场景」节后追加：

```markdown
## 融合模式（caifeng-fusion，B81——采风产物→本书资产的隔离式适配）

当 prompt 含 `type: caifeng-fusion` 时进入融合模式。你的任务：读采风产物与本书设定，
执行融合四步，产出可直接应用的设计适配策略。

### 输入
- `caifeng_product`：采风产物路径（要素表+来源清单）
- `story_files`：本书相关设定文件路径列表（角色卡/世界观/题材定位/大纲等）
- `design_need`：具体设计需求一句话（如「主角动机链缺递升」/「需要设计金手指的代价边界」）
- `project_dir`：项目根

### 操作（融合四步）
1. **结构对照**：读采风要素表+本书设定文件，逐项对照——找出功能位缺口
   （采风当检查清单用，照出缺哪个功能位）
2. **功能位借用**：缺什么补什么，借的是功能不是内容
   （「宣言用于被羞辱节点」「导师兼金手指载体」——功能位清单）
3. **本土转译**：从本书世界的压迫/制度/性格长出来
   （转译深度三问：因果是什么/换本书题材怎么表达/血肉换掉了吗）
4. **方法论验证**：读对应方法论文件验证融合结果
   （角色→九维/弧线六阶段；结构→势力场/八节点；机制→代价边界）
   ——采风不豁免质量关

### 输出 JSON
{
  "status": "success",
  "type": "caifeng-fusion",
  "fusion_strategy": "具体适配建议（不是「借递升」而是「从XX之辱长出递升起点，逐级到对抗XX制度」）",
  "borrowed_positions": ["功能位1：转译成了什么", "功能位2：转译成了什么"],
  "translated_elements": ["可直接喂入设定字段的设计元素成品"],
  "verification": "方法论验证结论（过/不过+理由）",
  "token_echo": "{token}"
}

### 纪律
- **只出策略不改文件**——你不修改设定/大纲/正文，只产出适配建议
- 融合结果过防抄红线：成品≈来源换皮→红线触发→打散重组
- 功能位清单必含（可审计）；来源标注（哪个功能位来自哪个采风对象）
```
