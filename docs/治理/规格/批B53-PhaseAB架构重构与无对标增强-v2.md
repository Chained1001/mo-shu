```
## Phase B：深度打磨环

### 打磨环总则

Phase B 是一个大停靠——作者看完整粗稿后，逐维度评审→改进→循环，直到确认定稿。

**循环逻辑**：
  ① spawn evaluator（全局评审） → 评审报告
  ② 展示打磨屏 → 作者选择
  ③ 改动（如有）→ 级联变更 → 重跑机检 → re-spawn evaluator → 回到②
  ④ 作者选✅确认 → tracking init → 构建态翻「定稿」

**断点恢复**：新会话读台账构建态「Phase B 打磨中」→ 读打磨记录最后一条
  → 汇报「上次打磨到第 N 轮，最后做了 X，接下来 Y」→ 继续打磨环。

**级联纪律**：
  先声明影响文件 → 作者确认 → 一次改完（不留半改状态）→ 重跑 check_outline
  → re-spawn evaluator → 打磨记录落台账（append-only）

### evaluator 全局评审协议

spawn 参数：
  token: 8 位令牌
  eval_type: full（Phase B 专用——评完整粗稿）
  target_paths: [大纲/大纲.md, 大纲/卷纲_第X卷.md, 设定/角色/*.md]
  benchmark_path: 设定/理想书评.md（结构化）
  virtual_benchmark_path: 设定/虚拟对标.md（无对标时传入，有对标时省略）
  context: "Phase B 第 N 轮打磨——上一轮改了 X，本轮重点检查 Y"
  project_dir: 项目目录

evaluator 读取：
  所有 target_paths + benchmark + virtual_benchmark
  输出三维度评审 JSON（含 score/research_needed/summary/recommendation）

### 打磨屏（AskUserQuestion 主屏）

展示内容（弹窗前打印）：
  ┌ 评审报告 ────────────────────────────────┐
  │ 编辑维度：硬伤{有/无}｜签约{理由}｜拒签{理由}  │
  │ 作者维度：新鲜度{判断}｜工艺{改进建议}          │
  │ 读者维度：追读{一句话}｜弃书点{位置}｜钩子{评估}│
  │ 综合评分：结构{N}/10 节奏{N}/10 情绪{N}/10    │
  │ 总评：{通过/需改进/需重构}                     │
  │ 只改一处：{建议}                               │
  │ ⚠️ research_needed：{null/具体查询}           │
  │ 💬 {一句话人话总结}                            │
  │ 📋 建议：{推荐选项+理由}                       │
  └──────────────────────────────────────────┘
  ⚠️ 台账待打磨项：{Phase A 标注的 ⚠️ 汇总，逐条列}

选项（AskUserQuestion 五选项）：
  ✅ 确认定稿
  🔧 按评审建议改进
  🔄 触发采风补强（有 research_needed 时显示检索需求）
  📡 逐维度打磨
  📝 我自己改

### 逐维度打磨子屏

作者选📡后进入：
  问：「你想先打磨哪个维度？」
  ① 结构（骨架锐度/中点/对手升级/伏笔闭合）
  ② 桥段（新鲜度/套路检测/桥段替换）
  ③ 节奏（爆发密度/爽点循环/低压区间）
  ④ 情绪（核心情绪/交替模式/情绪禁区）
  ⑤ 角色（弧线锐度/升级绑弧光/配角功能位）

  选定维度后：
    AI 聚焦该维度 → 读对应方法论文件 → 深度检查
    → 展示该维度的具体差距（对照虚拟对标/理想书评目标）
    → 提出改进方案（含影响文件声明）
    → 作者确认后执行
    → re-spawn evaluator（聚焦该维度，context 注明"仅检查{维度}"）
    → 回到打磨屏主选择

### research_needed 与采风补强衔接

evaluator JSON 的 research_needed ≠ null 时：
  打磨屏展示：⚠️「评审员需要更多参照才能给出精准判断：{research_needed}」
  🔄 选项描述自动填充检索需求

作者选🔄后：
  主线程 spawn moshu-researcher
  query = research_needed 的内容（精准检索，非泛化）
  采风产物回来 → 融合 → 更新虚拟对标.md
  → re-spawn evaluator（context 加入新采风产物）
  → 第二段评审现在有数据支撑
  → 回到打磨屏

### Fallback 自评

agent 不可用时：
  AI 在打磨屏自评四问（简化版）：
  ① 编辑问："这个设计有什么商业硬伤？指出 1 个或声明'无'"
  ② 作者问："核心桥段见过类似的吗？举 2 个例子或说'新在哪'"
  ③ 读者问："弃书点在第几章？钩子兜住了吗？"
  ④ 改进问："只改一处改什么？"
  标注 "⚠️ Fallback: evaluator unavailable -> self-evaluation（降级评审，有自评偏差风险，
  关键确认建议新开会话重试 agent 评审）"
```
