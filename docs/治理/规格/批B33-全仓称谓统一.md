### 2.3 write 工作流子步骤并存规则（Stage 4 下三套互斥工作流）

单章（workflow-chapter）步骤 1-13 → **Stage 4-1 ~ 4-13**；日更批量（workflow-daily）Step 1-4 → **Stage 4-1 ~ 4-4**；修订（workflow-revision）Step 1-5 → **Stage 4-1 ~ 4-5**。三套编号各自从 1 起（互斥工作流，各自文件内顺序定位；§2.1b「子步骤是引用时的定位口径」），**跨工作流引用必须带工作流文件名**（如「workflow-daily Stage 4-2」「workflow-revision Stage 4-5」）；同文件内引用不带文件名。recovery-protocol「daily Step 1」→「workflow-daily Stage 4-1」。

### 2.4 交叉引用修正原则

引用方跟被引用方的**新官方称谓**：build 引 analyze 管道（Stage 3 → Stage 2-4、Stage 3+ → Stage 2-4 起）；setup agent 模板引 write 流程（Phase 1-5 → Stage 1-5、日更 Step 1 → workflow-daily Stage 4-1）；README/README_EN 引拆书 Stage 6 → Stage 2-7；check-moshu-setup-deployment.sh 断言消息引 write（Phase 1→3 → Stage 1-3、Step 3/4 → workflow-daily Stage 4-3/4-4——**断言匹配文本随被引用方同步更新**）。

### 2.5 通用性四问（称谓统一为跨 skill 通用规范）

①去作品化成立（称谓与具体作品无关）✓ ②多题材适用（7 skill 全适用）✓ ③强制不造滥调（Stage 编号体系已有 build/setup 先例）✓ ④有回退（旧称谓仅在历史记录中保留，活区无兼容需求）✓。
