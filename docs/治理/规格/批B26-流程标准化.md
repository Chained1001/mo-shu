## 二、设计总纲

### 产出①：全仓 Stage 命名重构

| 旧名 | 新名 | 子步骤 |
|---|---|---|
| 步 0 信息采集 | **Stage 1 信息采集** | 1-1 定调 / 1-2 定形 / 1-3 理想书评 / 1-4 定流程 |
| 步 1 骨架步 | **Stage 2 骨架构建** | 2-1 体量与四阶段 / 2-2 底牌与台阶 / 2-3 骨架表 / 2-4 势力场 / 2-5 暗线 / 2-6 四件套 |
| 步 2 人物步 | **Stage 3 人物构建** | 3-1 角色弧线 / 3-2 世界观 / 3-3 关系回填 / 3-4 情绪引擎 |
| 步 3 单元步 | **Stage 4 单元构建** | 4-1 首卷单元卡 / 4-2 支线登记 / 4-3 浮现记录 |
| 步 4 整合步 | **Stage 5 整合检验** | 5-1 伏笔 / 5-2 反转 / 5-3 线索矩阵 / 5-4 动机链 |
| 步 5 打磨步 | **Stage 6 打磨定稿** | 6-1 LOCK 与配比 / 6-2 八节点 / 6-3 理想书评终检 / 6-4 定稿与 tracking init |

**命名口径**：子步骤（Stage N-M）是**引用时的定位口径**（如"见 Stage 2-3 骨架表"），**不要求在文档中新增 `### Stage N-M` 子标题**——现有文档结构不动，只改步骤级标题名和交叉引用。

**改动文件**：workflow-build.md 全文（~40 处）、cold-path.md（开新卷引用）、revision-workflow.md（修订涉及步 N 的引用）、check_outline.py 提示文案（如有"步 N"字样）、构建台账模板（六步状态表行名）。

### 产出②：交互模态统一（补一处漏网）

对标消歧从"混在 Stage 1-1 对话里"改为 **AskUserQuestion 弹窗**：

```
→ 提到参考书 → 弹窗（AskUserQuestion）：
  「参考书怎么处理？」
  ○ 正式对标——需先拆书（/moshu-analyze），参与每卷节奏校准
  ○ 仅参考——取题材气质做原创，不拆书（推荐）
  ○ 都不用——删掉参考
```

### 产出③：流程完善五项

#### ③-a 首卷支线最低要求

Stage 4 支线登记纪律追加一句：
> **首卷至少登记一条轻支线**（可以是同僚日常/师徒互动/衙门生态等低成本线——纯主线推 100+ 章有读者留存风险）。

#### ③-b 势力场借力桥段落位检查

Stage 4 单元卡设计纪律追加一句：
> 填完单元卡后**回查势力场总览的每个博弈点**——如果本卷有势力场条目但没有任何单元卡桥段用到它，标⚠️"博弈点未落位"（要么在本卷某单元补桥段、要么调整势力场的活跃卷标注）。

#### ③-c 理想书评中间消费

Stage 3（人物构建）和 Stage 4（单元构建）各加一行理想书评对照提示：
- Stage 3 末尾：`> 📜 理想书评对照：角色设计兑现了书评的哪些承诺？（一段话自检）`
- Stage 4 末尾：`> 📜 理想书评对照：首卷单元的阅读体验能兑现书评描述的感觉吗？`

#### ③-d tracking init 的 context 映射指引

Stage 6-4 定稿段加一句：
> `next_chapter_commitments` **从单元卡首个单元的"单元承诺"字段映射**，不自造（防漏掉单元卡已承诺的读者期待）。

#### ③-e 采风产物消化时机

Stage 1-1 采风段补一句：
> 采风产物回来后，**融合四步在本 Stage 内执行完毕**（对照核心设定表→借用功能位→本土转译→方法论验证），产物直接喂 Stage 2 骨架设计——不留到后续 Stage 才消化。

### 产出④：Stage 3 人物变更在停靠 2 显式展示

停靠 2 展示模板中"角色弧线段"前加一行标题：
> **📋 人物变更摘要（Stage 3 产出）**：
> 新增/深化的角色：{角色名×N}——核心变化：{一句话}
> 新增的世界观设定：{设定名}——影响：{一句话}
