# 规格 · 批 B53：虚拟对标与无对标路线增强

- 版本：v1.0（2026-08-27，旗舰起草待作者确认）
- 依据：作者裁决（无对标做到极致——"无对标都能做好，有对标肯定更优秀"）+ 旗舰提案（虚拟对标/骨架自检/理想书评结构化）+ 已有评审闭环（B30 停靠屏协议🔄触发采风）
- 性质：**build 流程增强**（新增虚拟对标合成步 + 骨架自检问句 + 理想书评结构化），方法论+流程双改

## 一、设计定位

**无对标路线的定位从「降级路线」升级为「一等公民」**——不依赖拆书也能产出优秀故事，节省前置开销。

核心增量：把采风产物从「Stage 1 融合完就沉在文件里」升级为「合成为虚拟对标，贯穿 Stage 2-6 作为设计约束」，让无对标路线拥有与有对标路线同构的 fail-fast 参照系。

```
有对标：拆文库 → 对标/节奏.md + 情绪模块.md → Stage 2-6 设计约束（fail-fast）
无对标（现状）：采风 → 采风-CF*.md → Stage 1 融合 → [沉在文件里]
无对标（改进后）：采风 → 融合四步 → 【新增】虚拟对标合成 → 设定/虚拟对标.md → Stage 2-6 设计约束（参照约束）
```

两条路线 Stage 2-6 流程完全一致，只是约束来源不同（精确 vs 泛化）。

## 二、现状事实

1. 采风默认执行于 Stage 1 轮 1（可跳过须降级声明），产物 `设定/采风-CF{NNN}-{类型}-{主题}.md` 六节结构
2. 融合四步（选要素→转译→喂字段→功能位回写）在 Stage 1 内执行完毕，产物直接喂 Stage 2
3. 停靠屏协议（B30）已有 🔄 触发采风 选项——评审弱项可触发补强采风，融合后重新展示
4. evaluator 三维度评审（编辑·商业/作者·技艺/读者·留存）在停靠 1/2/3 例行，对照理想书评
5. 理想书评目前为自由散文格式，AI 自己写"什么是好书"，无结构化维度
6. check_outline 机检已有采风专名（candidate k）与 CF 未消费（candidate B21）两个检查
7. 骨架八列表在 Stage 2 填完即进停靠 1，无自检问句

## 三、文件级改动清单

### 改动 1：workflow-build.md 新增「虚拟对标合成」步（Stage 1 末尾，融合四步之后）

**位置**：Stage 1 四轮式开场轮 1 的采风段之后、核心设定表之前。

**流程**：
```
采风产物（采风-CF*.md 多源）→ 融合四步（已有）
→ 【新增】虚拟对标合成（主线程执行，AI 语义归纳）
   从多源采风产物中提炼三类设计目标：
   ① 节奏目标：爆发密度区间（如"每 3-5 章一个小高潮"）、
      爽点循环模式（期待→压抑→释放的节奏与间隔）
   ② 情绪基准：核心情绪类型+交替模式（哪类情绪后跟哪类）、
      低压区间容忍度（连续多少章不爽可以接受）
   ③ 结构要点：同类成功作品的中点设计模式、对手升级路径、
      伏笔密度参考（每卷埋几条/收几条）
→ 落盘 设定/虚拟对标.md（固定三节结构，模板内嵌于 workflow-build）
→ CF 票据状态流转（合成的输入票据标「已消费·合成虚拟对标」）
```

**虚拟对标.md 模板**（内嵌于 workflow-build，AI 按模板填充）：
```markdown
# 虚拟对标（{书名}·{题材}）
> 来源：采风 CF-{NNN}×{N} 票据合成（{日期}）；本文件是无对标路线的
> 设计约束参照——Stage 2-6 设计时随时参照，停靠评审时作为评分锚点。

## 节奏目标
- 爆发密度：{每 N 章一个小高潮，从采风数据提炼}
- 爽点循环：{期待→压抑→释放的间隔与节奏描述}
- 追读力锚点：{每章结尾必须给读者一个继续读的理由——具体化}

## 情绪基准
- 核心情绪：{主情绪类型}；交替模式：{A→B→A 或 A→B→C→A}
- 低压容忍：{连续 N 章不爽可接受，超过必须释放}
- 情绪禁区：{采风发现同类作品避开的情绪陷阱}

## 结构要点
- 中点设计：{同类作品的典型中点形态}
- 对手升级：{每卷对手/挑战的升级模式}
- 伏笔密度：{每卷埋设量/回收量参考}
```

**无对标时的 fail-fast 语义**：虚拟对标.md 不是机检 blocking 门禁（内容是 AI 归纳的泛化模式，非确定性数据），但**Stage 2 骨架设计/Stage 4 单元卡设计时必须参照**——workflow-build 对应节加「参照设定/虚拟对标.md 的节奏目标/结构要点」指令行。停靠评审时 evaluator 的 context 参数包含虚拟对标.md（与理想书评并列）。

**有对标时**：虚拟对标合成步跳过（对标/节奏.md + 情绪模块.md 已提供更精确的约束）。

### 改动 2：workflow-build.md Stage 2 停靠 1 之前新增「骨架自检问句」

**位置**：八列表+势力场填完之后、停靠 1 呈报之前。

**内容**（~5 行）：
```
**骨架自检（停靠 1 呈报前必答）**：
用一句话回答——「读者为什么要追这一卷？」
- 答案必须包含：主角的{____}（欲望/困境/反差）× 对手的{____}（威胁/纠缠）× 这一卷独有的{____}（悬念/期待/爽点）
- 如果填不出这三个空格中的任何一个，骨架不够锐——回去重做对应列，不要带着空心上停靠
- 本问句答案展示于停靠 1 屏（供 evaluator 评审与作者裁决参考）
```

### 改动 3：理想书评结构化（workflow-build.md Stage 1 轮 3 改造）

**现状**：轮 3 让 AI 自由写"什么是好书"的评论——纯散文，无结构化维度。

**改为半结构化**（~10 行模板替换现有轮 3 描述）：
```
轮 3 理想书评（结构化——停靠评审的评分锚点）：
写一份这本书的"理想书评"，必须包含三个维度的量化目标：
① 结构（每维 1-10 分目标）：开局吸引力__分 | 中段推进力__分 | 高潮冲击__分 | 结尾余韵__分
② 节奏：期待感密度（每__章一个期待点）| 释放感频率（每__章一次爽点释放）
③ 情绪：核心情绪是{____} | 读者读完第一卷应该感到{____}
- 这不是文学评论——是构建产物停靠评审时的评分锚点（evaluator 按此打分）
- 分数和目标越具体，停靠评审的判断力越强
```

**产物变更**：`设定/理想书评.md` 从自由散文变为结构化三维度表（模板内嵌）。

### 改动 4：evaluator agent 模板评审准则微调

在「评审准则」三维度各加一条「对照虚拟对标/理想书评分目标」：
- 编辑维度加：「如 context 含虚拟对标.md，节奏/结构判断须对照其节奏目标与结构要点——不可纯凭感觉说'节奏偏慢'，须说'低于虚拟目标的每 N 章一个高潮'」
- 读者维度加：「如 context 含理想书评.md 结构化评分，留存判断须对照目标分数——不可纯说'可能弃书'，须说'开局吸引力目标 8 分，当前产物估计 5 分，差距在{____}'」

（agent 模板变更 → agents_version bump 36→37）

新增 candidate 级检查：「设定/虚拟对标.md 存在时，大纲/卷纲中是否引用了其中的节奏目标或结构要点关键词——零引用提示可能未消费」（candidate，不拦截）。

在「融合四步」之后补一节：「第五步（无对标时）：虚拟对标合成——融合四步产出的功能位清单是原料，AI 归纳为三类设计目标（节奏/情绪/结构），落盘 设定/虚拟对标.md 作为 Stage 2-6 的参照约束。有对标时跳过本步。」

## 四、禁止事项

- 虚拟对标不是机检 blocking 门禁（AI 归纳的泛化模式非确定性数据——与对标/节奏.md 的 write 权威产物性质不同）
- 不改变有对标路线的任何流程（虚拟对标合成步在有对标时明确跳过）
- 不改停靠屏协议四选项结构（🔄 触发采风补强机制保留——虚拟对标是前置约束，补强是后置纠偏，互补不替代）
- 苏格拉底问句不改（批③已做，本批不碰方法论文件）
- 不动 write 侧任何文件
