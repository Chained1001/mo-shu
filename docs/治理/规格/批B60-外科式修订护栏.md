## 三、文件级改动清单

### 改动 1：工单结构扩展（review_tickets.py + review-workflow.md）

**1a. finding 可选键**（新键全可选，旧工单零丢失可读）：
- `problem`：结构化问题陈述 `{现象, 位置, 为什么是问题}` 三段文本（各 ≤200B）——替代散述 issue 的补充层，issue 保留兼容；
- `preserve`：保留清单 list[str]（≤10 条，每条 ≤120B）——作者点名不许动的句段引文/事实表述；来源=审查启动时作者输入 + reviewer 对功能性写法标 `[需复核]` 的转正；
- `length_coefficient`：字数系数 float 0.5-2.0（默认 1.0=不约束）——整改后期望字数=原×系数，供 1b 纪律校验。
- **SCHEMA_VERSION bump +1**（当前值以文件常量为准）+ 严格相等校验保持；涟漪面按宪法 §3.4 精神全仓 grep（本 schema 消费面窄于 tracking：tickets 测试/fixture/pipeline e2e 断言/守卫 JSON，逐条排查）。

**1b. document 可选键 `decision_points`**：list[{a, b, question}]（a/b=findings 数组索引）——reviewer 间冲突意见的结构化标记；write 时可选携带，list 输出单列「编辑决策点」节，resolve 时对应 finding 的 resolution 必须引用作者裁决（resolution note 含「作者裁决：」前缀）。

**1c. review-workflow.md**：报告模板加「编辑决策点」节（有则渲染，无则省）；工单构造指引加 problem/preserve/length_coefficient 填写纪律（保留清单优先从作者审查启动输入采集；reviewer 不得自填 preserve——只有作者与 `[需复核]` 转正两个来源）；:318 分歧散述改写为指向 decision_points 机制。净增目标 ≤300（预算 20000 内消化，不调高）。

### 改动 2：整改执行纪律（deslop-workflow.md + review 整改路径）

**2a. deslop-workflow.md 加「外科手术纪律」节**（净增目标 ≤250，预算 10600 内消化）：
- 章级两轮上限：现有段级「连续两轮无新改动→停止该段」升级为「每章整改最多两轮全局 pass，第二轮后仍有未解决问题→列明残留上报，不进入第三轮」；
- 保留清单遵守：工单 `preserve` 列出的句段/事实逐条不动（整改前后各 grep 一遍引文确认在位——**流程纪律，不脚本化，D3 定值**）；
- 事实保真：整改后关键事实串（人名/数值/事件顺序）grep 自查，改动不得引入与追踪 state 冲突的事实；
- 字数系数：工单带 length_coefficient≠1 时，整改后字数应落在 原×系数×[0.9, 1.1]，超出即停手呈报。

**2b. review 整改路径**（review-workflow 整改节）：同一纪律引用（不复制——反模式 #4，指向 deslop-workflow「外科手术纪律」节锚点链接）。

## 五、禁止事项

1. 保留清单的填写权只在作者与 `[需复核]` 转正——reviewer/deslop 不得自填（防「自我保留」架空整改）。
2. 新键全可选+旧工单兼容；SCHEMA bump 走涟漪面全仓 grep（含 .json）。
3. 事实保真与两轮上限是流程纪律——**本批禁脚本化**（D3 定值；B66/实测后再议）。
4. 纪律不复制两份（2b 用锚点链接）；不做规格外顺手改；候选语义不涉及。
