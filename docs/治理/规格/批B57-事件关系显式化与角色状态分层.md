# 规格 · 批 B57：事件关系显式化 + 角色状态优先级分层

- 版本：v1.0（2026-08-27，旗舰起草，来源：外部开源项目深研[THU-KEG/StoryWriter + SillyTavern]→mo-shu 现状对照→设计方案）
- 性质：build 产物模板增强（事件关系边）+ write 追踪渲染增强（角色分层）。**脚本变更**（tracking_commit.py 渲染逻辑）+ 文档变更（workflow-build + outline-methods + check_outline）

## 一、设计依据

| 改进 | 外部来源 | mo-shu 现状（子代理实证） |
|---|---|---|
| 事件关系边 | THU-KEG/StoryWriter 的 inter-event relationships | 因果语义零散（Stage 5 自由格式「因果标注」、伏笔隐式埋设→揭示、线索矩阵隐含交叉），无结构化关系类型枚举 |
| 角色状态分层 | SillyTavern World Info 的 depth/priority | 上下文状态卡核心角色节无分层无截断——20+ 核心角色线性膨胀，与本章是否出场无关 |

## 二、文件级改动清单

### 改动 1：事件关系边（build 侧，3 文件）

**1a. workflow-build.md** Stage 5 整合检验段，在伏笔表/线索矩阵之后加事件关系边说明（~15 行）：

```
**事件关系边**（Stage 5 精修时填写，写入卷纲「事件关系边」节）：

结构化的事件间关系，三类型枚举：
- `→因果`：源事件的进展直接导致目标事件的发生（A 导致 B）
- `⊕揭示`：源事件埋设的真相在目标事件中被揭示（A 的伏笔在 B 回收）
- `∥并行`：两个事件同时推进互不阻塞（A 与 B 并行）

| 源事件 | 关系 | 目标事件 | 说明 |
|---|---|---|---|
| {单元 ID}-{事件概述} | →因果 | {单元 ID}-{事件概述} | {一句话} |
| {单元 ID}-{事件概述} | ⊕揭示 | {单元 ID}-{事件概述} | {一句话} |
| {单元 ID}-{事件概述} | ∥并行 | {单元 ID}-{事件概述} | {一句话} |

填写纪律：
- 每对有因果关系的事件必须登记（check_outline candidate 会检查悬空引用）
- ⊕揭示边与伏笔表互补——伏笔表管「埋了什么」，关系边管「跟哪个事件关联」
- 跨卷关系边照常登记，目标事件可以是后续卷的单元 ID
- 无关系的事件不登记（不强补）
```

**1b. outline-methods.md** 八列表段加一句：「单元间因果关系除纪律性要求外，以 Stage 5 事件关系边结构化登记（三类型枚举见 workflow-build Stage 5）」

**1c. check_outline.py** 新增 candidate：
- 事件关系边引用的单元 ID 在卷纲单元列表中不存在 → candidate「悬空事件关系」（不拦截）
- 回归测试：违规 fixture 红（引用不存在单元）/ 正常绿

### 改动 2：角色状态优先级分层（write 侧，2 文件）

**2a. tracking_commit.py** 渲染续写状态卡的「核心角色状态」节时，增加分层逻辑：

```python
# 渲染核心角色状态时：
# 读当前章细纲的「人物关系和出场顺序」节，提取出场角色名单
# 出场角色 → 「本章出场（必读）」子节，展开快照摘要
# 非出场核心角色 → 「背景角色（仅跟踪）」子节，仅列名不展开
# 细纲不存在或无出场信息 → 不分层，维持现有全展开（向后兼容）
```

产物格式变化（追踪/上下文.md 的核心角色状态节）：
```
## 核心角色状态

### 本章出场（必读）
- 江晨：{从快照提取的摘要，含最近变化}
- 钟嘉嘉：{摘要}

### 背景角色（仅跟踪，不进正文 prompt）
- 配角A / 配角B / 配角C
```

兼容性：旧项目（无分层状态卡）照常工作——chapter-core A 段读整节。新项目自动分层。

**2b. chapter-core.md** A 段读取角色状态处加一句说明（~3 行）：
```
核心角色状态分两层时：本章出场节必读（展开快照摘要），背景角色节仅确认存在（不展开、不传入正文 prompt）。未分层（旧项目）照旧全读。
```

## 三、禁止事项

- 不引入向量检索/RAG（不学清单）
- 不改 agent 模板（分层逻辑在 tracking_commit.py，不在 agent 侧）
- 不改 agents_version（无部署物变更——tracking_commit.py 是三副本共享脚本，改一个源后 sync）
- 事件关系边不改动伏笔表结构（互补不替代）
- 角色分层不改动角色快照文件本身（只改状态卡渲染）
