## 4. 新文件设计：docs/审计法.md（内容级全文框架）

```markdown
# 审计法（唯一审计方法 SOP）
版本/适用范围（任何模型对本仓库任何 skill/机制/守卫的审计）
> 方法沿革：V3（逐 skill+根因三分类）→ V4（基线+机制链+轻扫）→ 旗舰六步法 → 本 SOP 收敛。历史审计见 docs/归档/审计-V3/V4。

## 六步流程
1. 基线：全量守卫矩阵+相关测试跑绿记录（任何红先判因，禁止修）
2. 结构盘点：SKILL/references/scripts 清单与体量、按需加载纪律
3. 机制链审计（核心——"守卫锁话不锁链"）：枚举该 skill 的端到端链（产→消→回），逐链走查文档指示与脚本能力双向核对，每链判 闭合/断裂/半闭合+证据
4. 一致性轻扫：版本口径/术语表违例/悬空引用/数字口径/预算/路由与判定表一致
5. 历史回归：历次审计该域发现的已修项抽查复验
6. 分级汇总：阻断（机制断裂或拦死流程）/需修（真实缺口）/候选（呈报）/存疑 + 每条证据路径:行号 + 档案分档（【事实】/推断/存疑）

## 纪律
- 自我推翻：子代理/初判结论须经本人复跑核实后再定级（V3 曾推翻"64 组"误报）
- 独立复核：转述必抽验（旗舰审施工、施工审规格，同一精神）
- 只查不改：审计产物唯一写入=审计报告文件；修复须另行走规格
- B6 先例：显式声明的零消费≠缺陷——先查有没有定位声明再定级

## 产出格式
docs/审计-{世代}/ 或并入审核记录（小审计），结构：基线/结构/机制链表/一致性/回归/分级清单/自我推翻记录
```
