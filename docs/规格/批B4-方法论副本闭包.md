## 4. 新文件设计

**check-reference-closure.py**（算法级；§4 勘误 2026-08-22——初版"全量提及断言"无法区分 skill 资产引用与书项目运行态产物/占位名，首跑 786 处误判，经裁决改方案 A）：
1. 扫描 `skills/*/references/*.md`（含全部 skill——缺陷类不分域）。
2. 提取文件名提及：Markdown 链接 `[..](x.md)` 与反引号 `` `x.md` `` 两种形态（`[\w\-./]+\.md`）。
3. **资产宇宙（方案 A 核心）**：先收集全仓 `skills/**` 下所有 `.md` 的 basename 集合 U。仅当提及的文件名 ∈ U 时做闭包断言：该文件须存在于**本 skill 树内**，否则查白名单；提及的文件名 ∉ U（书项目运行态产物/占位名/agent 部署路径）→ 直接忽略不报。理由：资产宇宙从现实派生（同 check-story-numbers 哲学），新 skill 资产自动入检、书项目产物永不入检，无需维护排除清单。
4. **白名单** `ALLOWED_CROSS_DOMAIN: dict[str, str]`（键=提及的文件名，值=理由注释）：路由表共享文本的跨域指引——`volume-review.md`、`outline-workflow.md`、`artifact-protocols.md`（B1a/§8.5 先例）、`writing-craft.md`、`style-combat-face.md`（write 域执行技法，build 构建对谈不加载，仅跨域指引）。**每条白名单必须写理由**。
5. 剩余违例（∈ U 且非白名单且本域不存在）= 真断链 → 报 文件:行号:提及名 退出 1；全通过输出 `reference closure: ok`。
6. 仅标准库；`--root` 测试参数。

**test-reference-closure.py**：fixture 仓库——①skillA 提及本域存在文件 → 过；②反引号提及"资产宇宙内但本域缺失"文件 → 违规且报文含文件名；③白名单内提及 → 过；④移除白名单后该提及 → 违规；⑤提及 ∉ 资产宇宙的运行态产物名（如 `题材定位.md`）→ 忽略不报（方案 A 语义锁定）。

## 5. 验收命令

## 6. 守卫与 CI

check-reference-closure.sh 进 CI 三处同步；与 static-check 互补（链接 vs 反引号提及两形态）。

## 7. 回滚点

单提交 revert；副本删除即回原状，白名单随守卫一起消失。

## 8. 禁止事项

1. 禁止动真源内容（纯加 target，一字不改）。**边界澄清（2026-08-22 裁决）**：禁止事项禁止的是改真源文本；为闭包继续**加 target 补副本**（含二级传递缺口 plot-special-topics/plot-emotion-system 与 genre-readers，共 13 文件）是本批机制本身，不属此禁。
2. 禁止无理由白名单条目（每条必须注释理由）。
3. 禁止用白名单"消化"本应补副本的文件（10 文件清单必须走副本路径；白名单只收跨域合法提及）。
4. 禁止改路由表文本（字节同步约束——副本与真源必须一致，域差异靠白名单吸收）。
5. 禁止把 artifact-protocols.md 补进 build（其细纲模板段属 write 域，B1a 裁决维持；路由表该行走白名单）。
