## 一、现状事实（施工前复核）

1. `grep -n "直面" otherMaterials/testProject/test2-4/大纲/角色弧线.md`——升级绑弧光四阶填的是"执灯（直面共鸣）→燎火（直面孤臣之罪）→…"式标签，无具体事件/选择/代价。
2. `grep -n "可行\|失效" otherMaterials/testProject/test2-4/大纲/大纲.md`——升级台阶列了五台名但零"什么可行什么失效"。
3. `grep -n "借力" otherMaterials/testProject/test2-4/大纲/单元卡.md`——零借力桥段（势力场骨架层标了"可借力"但未落到任何单元卡）。
4. `ls otherMaterials/testProject/test2-4/设定/采风-*`——零采风产物（B19/B21 建设的整套体系未触发）。
5. 方法论文件的三节（势力场设计/升级绑弧光/舞台与规则设计）均为**清单式指引**（"要做什么"），非**填空式提问**（"被迫回答具体内容"）。

## 二、设计总纲

**三件产出**：①方法论三节从清单改为苏格拉底式（每个设计维度改为 2-3 个必答填空题，答不了说明设计未完成）；②workflow-build 采风入口从"推荐弹窗"改"默认执行+显式跳过"；③骨架表/角色弧线的空格子改为填空式提示。

### 核心原则：填不了 ≠ 空着 → 填不了 = 设计还没做完

方法论不再是"建议你做 X"，而是"回答以下问题，如果答不出具体内容说明设计需要再想"——**AI 被迫深入思考而非打勾通过**。

### 产出①：方法论三节苏格拉底化

#### outline-methods.md「舞台与规则设计」改造

**旧（清单式）**：
```
回环（旧台新意义重访）/ 规则耦合（每台标明什么可行什么失效）/ 情感印记
```

**新（苏格拉底式）**：
```
### 设计问句（每台必答，答不出说明设计未完成）

**规则耦合三问**：
① 这个舞台上，主角的核心能力多了什么新限制？（不是"有挑战"，是具体的"在这里不能XX"）
② 上一舞台可行的什么策略在这里失效了？（具体策略名）
③ 主角进入这个舞台时，最不想面对的是什么？（具体的人/事/真相）

**回环一问**：
④ 如果主角以终局身份回到第一卷的舞台，什么会完全不同？（不是"身份变了"，是什么具体的东西他现在看得到而以前看不到）

**情感印记一问**：
⑤ 读者想起这个地点时，第一反应关联的情绪是什么？（一个词，如"雾夜的压迫"/"公堂的灼热"）
```

#### character-design-methods.md「升级绑弧光」改造

**旧（清单式）**：
```
每次大阶突破=一次人格/认知考验。升阶问题：「这次升级逼主角面对什么他一直回避的东西？」
```

**新（苏格拉底式）**：
```
### 升阶设计三问（每阶必答，答不出说明设计未完成）

① 这次升阶的触发事件是什么？（不是"突破了"，是什么具体的事/选择逼他升阶）
② 他在这个事件里必须放弃什么？（一个具体的旧信念/旧策略/旧关系——放弃的东西要能被读者指认）
③ 升阶之后他做了一件以前不会做的事，那是什么？（一个新的具体行为——证明他变了，不是标签说"他变了"）

> 反面清单：升阶原因写"顿悟"/"修为到了"/"直面了内心"= 未完成设计——触发事件必须是具体的情节节点。
```

#### outline-methods.md「势力场设计」改造（博弈矩阵条目）

**旧（清单式）**：
```
势力博弈矩阵：2-3 组对立关系，每组标注「主角可否借力」
```

**新（苏格拉底式，追加）**：
```
**借力桥段落位问**：
⑥ 这个博弈点在哪一卷的哪个单元卡里被主角实际利用？（如果答不出具体单元卡编号=博弈点只是标注，不是设计——要么设计一个桥段要么删掉这个博弈点）
```

### 产出②：workflow-build.md 采风入口默认化

**旧**（轮 1 分支）：
```
→ 有结构参照需求 → 建议 /moshu-research 结构采风（AskUserQuestion：采风/跳过）
```

**新**：
```
→ 有结构参照需求（用户提到参考书/类似作品）→ **默认执行采风**（非弹窗）：
  1. 向用户声明："你提到了《X》《Y》——我先联网采风这两部作品的结构要素（约 5 分钟），采完给你看要点表，你确认后我拿它做设计参照。如果你不想等，说'跳过采风'即可。"
  2. 用户说跳过 → 记录降级声明进台账附注，继续
  3. 用户不反对 → spawn moshu-researcher（结构采风，CF 票据登记）
  4. 采风产物回来 → 展示要点表 → 用户过目 → 按融合四步使用
```

**关键变化**：从"弹窗问要不要"改为"声明即将做+用户可跳过"——默认路径是做，跳过是显式动作。

### 产出③：骨架表/角色弧线空格子改填空式提示

#### workflow-build.md 每卷骨架表模板改造

**旧模板**：
```
| 中点 | {假胜｜假败＋一句} |
```

**新模板**：
```
| 中点 | {假胜/假败：主角此时错误地相信____，但读者已经知道____} |
```

**旧**：
```
| 危机/赌注 | {类型（实质/职业/心理死亡）＋一句} |
```

**新**：
```
| 危机/赌注 | {类型＋如果失败的后果是____（具体到谁/什么遭殃）} |
```

**旧**：
```
| 卷末跃迁 | {起点状态→终点状态} |
```

**新**：
```
| 卷末跃迁 | {起点→终点＋他现在能做的一件以前做不到的事：____} |
```

#### 升级台阶模板改造

**旧**：
```
舞台演进（新台/回环与规则变化，选填）
```

**新**：
```
舞台演进（每台必答三问：新限制是什么／旧策略失效的是什么／情感印记一个词；选填=可空但空时须标"待步 N 回填"）
```

## 四、禁止事项

1. **不新增字段**——只改字段内的提示语（空格子改填空题）
2. **不改机检**——结构层检查保持现状（深度由方法论苏格拉底化保证，不由脚本保证）
3. **不改采风的产物结构/CF 票据/五类七源**——只改触发方式（推荐→默认）
4. 方法论苏格拉底问句**每节 ≤5 问**（过多变成新的填表负担）；**替换范围=设计法条目**（如三原则/核心法/博弈矩阵条），**反面清单和衔接声明保留不动**
5. 填空式提示用 `{____}` 占位——AI 必须填入具体内容才能通过（不填则该行为空=机检 blocking 既有逻辑兜底）
