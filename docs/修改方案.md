## 1. 总则（遵从的原则——每条修改的"为什么"底座）

1. **三层分工**：脚本做确定性（能数的绝不让模型估）/ AI 做语义 / 作者做品味——所有新机制按此归位（机检/预算/备份=脚本；工单注入/任务书=AI 协议；定稿/裁决=作者）
2. **单一权威 + 可重放校验**：`_tracking-state.json` 唯一权威、派生视图可 `check` 逐字比对——新增字段（quality_tickets/reading_power/evidence/learned_patterns）必须走同一事务协议，渲染规则必须确定性化
3. **热路径预算**：所有"每章必读"的新内容进 doc-budget 并设上限；新机制尽量走冷路径/按需
4. **部署自包含**：skill/agent 副本由 shared-assets 管理；模板变更必须 bump agents_version 并记录 UPGRADING
5. **兼容优先**：schema 升级带迁移路径（存量项目可续跑）；老产物不判废（analyze-workflow 已有先例）
6. **不学清单**（原规划第五部分）：RAG/learn 原版/连写污染/知识治理三件套/多宿主/文件即真相重构——保持不学

## 2. 实施序列（统一依赖图）

```

                    ▼
```

## 3. 逐项设计（改什么 / 怎么改 / 为什么 / 上下游 / 验收 / 风险）

### U1 每章 Git 备份 + 半提交探测 + 健康检查（= L1+L2+L3）

**改什么**：新脚本 `skills/moshu-write/scripts/backup_chapter.py`；`workflow-chapter.md` 步骤 12 后追加"步骤 13 备份"；`.gitignore` 补 `.moshu-review/`、临时文件。

**怎么改**：
- `backup_chapter.py commit --chapter N --title X`：探测仓库（无 git → 降级快照目录 `追踪/备份/snapshot_chNNNN_时间戳/`，保留最近 10 份）→ git-health 检查（陈旧 index.lock 60s+双 stat 自愈；半提交 stash；.git 损坏只指引）→ `git add 正文/追踪/` → `captureCommitExpectation`（parent/tree/message）→ commit（消息 `Chapter {N}: {title}`，sanitize 防注入）→ 失败 `probeCommitAfterError` 三态判定（committed/not/unknown，unknown 宁停）→ 成功 tag `chNNNN`
- `rollback --chapter N`：前滚式恢复（检出该章 tag 状态为独立提交，不丢历史）；`create-branch --chapter N`：从任意章建平行分支
- 全中文输出；git 命令走 `subprocess` 参数数组（非 shell 拼接）

**为什么**：写废设定/改坏正文无法回滚（webnovel 理念："200 万字必然写废设定"）；git 偶发返回码 ≠ 未提交（半提交探测防重复提交）。

**遵从**：脚本确定性；作者品味不动（备份自动执行，回滚需作者触发）。

**上下游**：依赖 tracking_commit 成功（备份在其后）；tag 命名被 rollback/回滚脚本消费；`.moshu-review/` 进 .gitignore 防审查状态误提交；CI 需跑 backup_chapter 冒烟（临时仓库 + 无 git 降级两条路径）。

**验收**：写一章自动 tag；改坏正文 rollback 恢复；无 git 目录快照生效；模拟 commit 失败不产生重复 tag。

**风险**：git 环境缺失（降级路径兜底）；大项目 git add 慢（只 add 正文/追踪/大纲/设定，不 add 拆文库）。

### U2 机检"阻断 vs 候选"分层 + 重试预算（= L4+L5）

**改什么**：新脚本 `skills/moshu-write/scripts/mechanical_check.py`（~300 行，字符级零依赖）；`workflow-chapter.md` 质量检查节前置"机检关"；拆书 Stage 2 复用（analyze 侧调同款检查项）；重试预算补幂等/持久化。

**怎么改**（机检 10 项 = 7 阻断 + 3 候选）：
- 阻断：①字数 ±30%（按"最终可见字符"口径，见 U9）②禁词（banned-words 一级词）③禁句式（正则，非法跳过）④复读（字符级 6-gram ≥3）⑤必填字段（章节标题行/细纲引用）⑥追踪条目变动形式（生命周期动词+编号存在）⑦Markdown 结构（标题/分隔线合法性）
- 候选（永不拦截）：⑧新专名（`([一-龥]{2,3})(冷笑道|笑道|…)` 启发式 + 名册排除）⑨高频意象（CJK 4-8 gram Apriori 分层，内存有界）⑩句式偏离（vs 基线指纹 ±30%/±50%）
- 重试预算：`追踪/重试预算.json`（严格 schema fail-closed、损坏宁停）——自动修复 2 轮硬上限、草稿 sha256 幂等（同 hash 不扣）、author-confirmed 单独记账、定稿清章

**为什么**：AI 审稿前先用零 token 脚本筛可计数问题；"候选不拦截"防误报；预算防连写失控（SparkArc/webnovel 双验证）。

**遵从**：三层分工（机检=脚本）；预算 fail-closed。

**上下游**：`workflow-chapter.md` 机检关在 check-ai-patterns 之前；analyze 的 `check_chapter_summary.py` 4 条硬检查可复用复读/条目形式项（不重复实现，import 同款函数或单独小脚本）；重试预算与追踪事务交互（定稿清章）。

**验收**：已知 AI 腔文本命中阻断；正常文本零误报；同草稿重检不扣预算；预算文件损坏 fail-closed。

**风险**：误报（候选不拦截纪律兜底）；中文统计质量（字符级上限，明确不是语义检测）。

### U3 一次性 schema 升级（= P1/S5 + L6 + L7 + L13）

**改什么**：`tracking_commit.py` 的 INPUT_SCHEMA_VERSION 升级（当前 v4 → v5）；`追踪/_tracking-state.json` 顶层新增 4 域；事务 delta 扩展 4 类字段；`上下文.md` 渲染规则扩展；moshu-import 迁移适配；check 校验扩展；test-tracking-commit 扩展。

**怎么改**（4 个新域，一次升级）：
1. **quality_tickets**（P1/S5 工单闭环）：`[{ticket_id, chapter, dimension, severity, status: open|closed, target, edit_goal, must_keep, operations, evidence, created_at, closed_at}]`——写入：review/consistency-checker 结论经 `tracking_commit.py ticket-open` 落库；注入：日更写前召回 open 工单（按 chapter/dimension 过滤）；关闭：复审 PASS 且无新 ticket → `ticket-close`
2. **reading_power**（L6 追读力）：`delta.reading_power = {hook_type, hook_strength, coolpoint_patterns, micropayoffs}`——AI 判断标注（明确非确定性）；渲染进逐章记录；卷复盘消费趋势
3. **evidence**（L7 溯源）：各 changes 项可选 `evidence: ["chapter:12:event"]`——纯增不改，check 校验格式
4. **learned_patterns**（L13 经验库）：`[{pattern_type, description, source_chapter}]`——作者/卷复盘确认后随事务提交；渲染进 `追踪/经验.md`（派生）；**注入条件：细纲子串命中才进写前任务书**（只写不筛=死数据）

**为什么**：审查意见"审完就丢"（P1 最严重）；追读力量化（L6）；状态可审计（L7）；经验沉淀（L13）——**一次升级避免多次 schema 波及**（G2）。

**遵从**：单一权威（新域全部走事务协议）；check 逐字校验（渲染规则确定性化）；兼容（老 schema 事务经迁移路径接受，见第 4 节）。

**上下游**：moshu-write（事务构造/渲染/写前召回）+ moshu-import（迁移适配新 schema）+ moshu-review（结论落库为工单）+ moshu-consistency-checker（S1/S2 结论 → ticket-open）+ test-tracking-commit.py/test-tracking-workflow-contracts.py（新字段测试）+ `_章节摘要汇总` 无关。

**验收**：审查 S1 问题 → 下章写前任务书出现对应工单约束 → 复审通过工单关闭；伏笔状态可追溯 evidence；经验条目仅细纲命中时注入。

**风险**：schema 升级破坏存量项目（迁移路径兜底，见第 4 节）；工单膨胀（按 chapter+dimension 定位 + 关闭机制）。

### U4 渲染规则：场景过滤 + 相关性筛选 + 悬久预警（= P3/S7 + L8 + L10）

**改什么**：`tracking_commit.py` 渲染函数（上下文.md/逐章记录）；`workflow-chapter.md` 写前召回说明。

**怎么改**：
- **场景时间点过滤**（P3）：渲染写前材料时，输入目标章号 N，排除所有"故事时间 > 第 N 章"的状态（未来剧情不得注入）——过滤规则：伏笔/角色状态带 last_seen_chapter，>N 的排除；时间线事件按章号过滤
- **outline 相关性筛选**（L8）：渲染活跃伏笔/角色时，用本章细纲文本子串命中优先（命中者先取，再按埋设章近远补齐）——替代"截断 8 条"
- **悬久预警**（L10）：渲染时现算 `当前章号 − last_advanced_chapter`，超阈值（伏笔/悬念 10、感情线 30）标 `⚠️ 悬久`（提醒不拦截）

**为什么**：长篇头号一致性风险是"注入未来剧情/状态泄漏"（SparkArc `_scene_position` 同思路）；相关性筛选让 8 条预算花在刀刃上；悬久预警让卷复盘之外也能发现悬置。

**遵从**：渲染确定性（子串匹配/章号比较全是确定性规则，check 可复现）；热路径预算（不新增必读内容，只改渲染顺序）。

**上下游**：依赖 U3 字段（last_seen_chapter 已有？——角色快照有 last_seen_scene 类字段，需核对 tracking schema）；写前召回（workflow-chapter (a)-(g)）消费新渲染结果；check 重渲染比对。

**验收**：写第 N 章上下文不含 N+1 章状态；细纲提及的伏笔必然在上下文；悬久伏笔标提醒。

**风险**：过滤规则漏未来剧情（以细纲时间锚点为准，缺失时保守排除）。

### U5 写评分离 + 三模态 + 落盘回执（= P2/S6 + S3 + S1）

**改什么**：`moshu-narrative-writer.md` 模板重构；`moshu-write` 的 workflow-chapter 写作/审查步骤重排；`moshu-review`/`moshu-deslop` 调用方式；agents_version 27→28 + UPGRADING。

**怎么改**：
- **模板两模式**（S3 三模态的 skill 版）：`写作模式`（spawn 写作时用：五段任务书输入 → 正文落盘 `正文/第N章_*.md` → 返回落盘路径+字数实测）与 `审查模式`（review/deslop 调用：只读正文 → 返回结构化 findings）；共同规则抽 `base` 段（写作硬约束/格式规范）
- **落盘回执**（S1）：写作模式契约——"必须落盘 + 字数实测（`count_story_body_chars` 口径）才算完成；只输出草稿 = 未完成打回"
- **职责分离**（P2/S6）：写后"去 AI 味自审"不再由写作模式执行；审查由 deslop（7 Gate + check-ai-patterns，已有）或 review 的 narrative-writer 审查模式承担
- **fix_ticket 输出契约**（S2）：审查模式返回 `{decision, severity, hits[{evidence, reason}], fix_tickets[{target, edit_goal, must_keep, operations}]}`——喂给 U3 的 ticket-open

**为什么**：自己审自己会自我辩护（两项目共同教训）；落盘才算完成防"假完成"；三模态防"聊天/委派/生成"串味（SparkArc 有真实 Bug 史）。

**遵从**：部署自包含（bump agents_version + UPGRADING 记录 + 重部署提示）；三层分工（审查归审查角色）。

**上下游**：moshu-setup（模板源 → 部署）；存量项目（agents_version 检测提示重部署，不阻断）；moshu-review/deslop（调用审查模式）；workflow-chapter 步骤重排（写作 6-11 步中"去 AI 味审查"改指 deslop/审查模式）；behavior-contracts 无绑定（grep 确认过）。

**验收**：写作模式不落盘 → 打回；审查模式返回结构化 fix_ticket；写后自审不再由写作 agent 执行；agents_version=28 部署正常。

**风险**：存量项目未重部署时审查模式不可用（降级：主会话按旧模板自审，报告提示重部署）。

### U6 文风增强：作者回避 + 脱敏指令 + 大样本分块（= S11 + S12 + S4）

**改什么**：`moshu-style/SKILL.md` 产出规范模板 + `style-learn-sop.md`；`文风库/文风.md` 实测文件；explorer `benchmark_style_load` 返回结构。

**怎么改**：
- **作者回避节**（S11）：文风.md 新增「作者回避」节（≥3 条负面禁忌，**只记有原文例证的**——防 LLM 幻觉）；narrative-writer 写前召回注入
- **脱敏指令行**（S12）：锚点旁加"指令 + 脱敏短例"（人名地名占位符，跨题材可复用）；原文锚点保留可回查
- **大样本分块**（S4）：样本 >30k tokens 时启用分块分析（30k/块 + 块间摘要传递 + 末块合成）；标准档 6 章（~2.3 万字符）**不触发**，保持现状

**为什么**：文风库只有正面统计、缺"这位作者不会怎么写"的负向约束（反 AI 腔与文风脱节）；高潮态语体漂移最常发生（S11 语体档位联动情绪模块——本版仅做作者回避，语体档位列入后续）。

**遵从**：表达层归 moshu-style（不越界进结构层）；锚点可回查纪律（脱敏指令行是附加，不替代原文锚点）。

**上下游**：explorer benchmark_style_load（返回含 author_avoidances）；narrative-writer 写前召回（注入回避清单）；实测文风.md 重新生成（需重跑 6 章样本——**注意**：这是唯一需要重跑实测的项）。

**验收**：文风.md 含作者回避节且有原文例证；写前任务书带回避约束；大样本分块产出与单次分析一致（抽样比对）。

**风险**：负面清单幻觉（只记有例证的纪律兜底）；文风.md 重生成耗时（6 章样本 ~1 分钟，可接受）。

### U7 体验层（= L12 + L14 + L15 + L16 + L17）

**改什么**：`workflow-chapter.md` 步骤 3（任务书）；`moshu-explorer.md` 模板（BM25 查询）；各 skill 收尾模板（三段式报告）；失败处理（degradation 标记）。

**怎么改**：
- **五段任务书**（L12）：写前准备输出固定五段——开篇委托/这章的故事/这章的人物/怎么写更顺/收在哪里（屏蔽系统词）；设 token 预算
- **本地 BM25**（L14）：`explorer` 增 `bm25_search` 查询类型（纯本地词频索引，搜正文/逐章记录/对标，chapter≤N 过滤，中文子串兜底）——grep 的补充非替代
- **候选制**（L15）：拆书模板/题材卡/对标推荐给建议 ≤3 条 + 未命中如实声明降级
- **degradation**（L16）：读文件失败/降级显式标 `degraded` 并先呈报
- **三段式报告**（L17）：收尾固定"总状态/产生的文件/问题与下一步"

**为什么**：任务书把写前材料翻译成纯写作语言（稀释系统词）；BM25 让"第 30-50 章发生了什么"可检索；候选制防"不同作品收敛同一答案"。

**遵从**：热路径预算（任务书有上限；BM25 冷路径）；三层分工（候选不替作者选择）。

**上下游**：任务书消费 U3/U4 的召回结果；BM25 依赖正文/逐章记录（U1 备份后文件稳定）；explorer 模板变更随 U5 同批 bump agents_version（或独立 bump）。

**验收**：narrative-writer 仅凭任务书可独立起草；BM25 检索出正确章节；无匹配模板时明确降级声明。

**风险**：任务书过重（预算上限）；BM25 中文召回质量（明确补充定位）。

### U8 进度持久化（= S9）

**改什么**：新文件 `追踪/_write-progress.json`；`workflow-daily.md` Step 2 更新。

**怎么改**：日更批量每章落盘后更新 `{current_chapter, completed_chapters[], next_batch_start, last_error, updated_at}`；中断后重新日更先读该文件从断点继续；批末清空。

**为什么**：中断后靠人工读追踪判断下批起点（P5）；Auto-Write 游标同思路。

**遵从**：纯确定性（脚本更新，非 AI）；与追踪事务独立（进度是流程态，不是故事事实）。

**上下游**：workflow-daily Step 1 读取；与 U1 备份的 tag 互补（进度=流程，备份=版本）。

**验收**：日更中断 → 重开自动从断点继续。

**风险**：低（独立小文件）。

### U9 模板字段：细纲伏笔引用 + 结构 stale + 字数口径（= S8 + S10 + S13）

**改什么**：`workflow-setup.md` 细纲模板（补字段）；`artifact-protocols.md`（模板同步）；`workflow-chapter.md` 字数验收口径；新校验（check-outline-copy 扩展或新脚本）。

**怎么改**：
- **setup_refs/payoff_refs**（S8）：细纲补"伏笔引用"行（本章设置的伏笔 ID / 本章兑现的伏笔 ID）——机器可检查（check-outline-copy 扩展：正文出现 ID 对应内容时核对引用）
- **结构 stale**（S10）：卷纲/细纲带 `derived_from`（上游版本）；改卷纲 → 相关未写细纲标 stale + 写前警告
- **字数口径**（S13）：`count_story_body_chars` 口径（排除标题行/注释/占位）统一进字数验收

**为什么**：伏笔漏收/提前释放是长篇头号问题（机器可检查形式）；stale 防"上游改了下游还用旧的"；字数口径防标记误计。

**遵从**：细纲模板兼容（新字段可选，旧细纲回退读取——workflow-setup 已有"旧版细纲缺字段不阻塞"先例）。

**上下游**：拆书（伏笔 ID 与拆文伏笔编号衔接——需定编号源：追踪伏笔 ID 为真源，拆文编号仅为导入候选）；check-outline-copy 扩展；细纲模板同步 agent-references（若模板文件在同步组）。

**验收**：正文提前兑现未登记伏笔 → 机检/复扫提示；改卷纲后相关细纲标 stale；字数口径一致。

**风险**：伏笔编号双源（追踪 vs 拆文）——定追踪为真源，拆文导入时映射。

### U10 团队化拆分：moshu-plan + moshu-write（第四部分落地）

**改什么**：新 skill `moshu-plan`（从 moshu-write 拆出 Phase 1-3 + 相关 references ~15 文件 + workflow-setup.md + outline-*/genre-*/character-* 方法论）；`moshu-write` 保留 Phase 4-5（workflow-chapter/daily/revision + writing-* + anti-ai/banned-words + 追踪）；`moshu/SKILL.md` 路由表；`marketplace.json`（10→11 skill）；契约守卫（behavior-contracts/static-check/doc-budget/shared-assets 同步）；`moshu-import` 衔接说明；测试。

**怎么改**：
- **边界**：plan 产出 `设定/`、`大纲/`、`灵感种子.md`（+ 更新 `追踪/` 初始化）；write 消费 plan 产物 + 产出 `正文/`、`追踪/` 更新。衔接 = 文件契约（与 analyze→write 同模式）
- **路由**：`/moshu-plan`（开书/补纲/扩纲）+ `/moshu-write`（写第N章/日更/修订）；moshu 状态判定表第 4-7 序改指 plan/write
- **doc-budget 重排**：plan 热路径 = SKILL + workflow-setup；write 热路径 = SKILL + workflow-chapter + workflow-daily（各路径变轻）
- **契约守卫**：static-check 新增 skill 目录检查；behavior-contracts 场景表更新；shared-assets 组重排（workflow-* 归位）
- **存量兼容**：已部署项目无需迁移（skill 是文档资产，重部署即得）；已写项目继续用 write 日更（plan 产物已存在）

**为什么**：moshu-write 一人干三职（规划+设定+执笔，80 references，热路径 ~35KB）——团队思想：一人一事；与 scan/analyze/style/review/deslop 的"一 skill 一事"对齐。

**遵从**：拆分粒度到此为止（设定归 plan、灵感归 plan、不拆到 SparkArc 5 专家粒度）；热路径预算（拆分后各路径变轻）；兼容（文件契约不变）。

**上下游**：moshu 路由表；moshu-import（导入后衔接写 plan 或 write）；explorer（查询不变）；setup（部署物不变——agent 模板不动）；doc-budget/shared-assets/static-check/marketplace/测试全量同步。

**验收**：`/moshu-plan` 开书产出设定+大纲+首批细纲；`/moshu-write` 日更全程不加载 plan 方法论；路由/守卫/预算全绿。

**风险**：拆分引入衔接断点（计划中已在 moshu 路由状态判定表写清）；行为契约测试需同步。

## 7. 笔枢增量并入说明（v2 追加，依据 docs/bishu-研究.md）

> 原则：B 系列**并入现有单元，不新增独立批次**——bishu 的价值密度低于前两项目（三件套已借鉴），剩余增量是"锦上添花"级强化。

### B1 章后对照升级（observer/arbiter 分离 + 世界事实裁决）→ 并入 U4
- **现状**：workflow-daily 第 9 步"章后对照"是主会话一条龙（landed/missed/deviated 核对 + 认知边界核对），无职责分离、无世界事实裁决维度
- **升级设计**：
  - `observer`（新 haiku agent 或 explorer 扩展）：只提取四类差异（世界/故事/角色/未提事件），每条带正文定位证据，**不做判断不裁决**
  - `arbiter`（新 haiku agent 或主会话）：只裁决——世界事实 adopt/pending/conflict（**保守默认**：低风险自动 adopt、涉势力体系默认 pending、仅直接矛盾 conflict）、故事差异确认、未提事件归类 hook/debt/discard
  - **作者确认点必须保留**（笔枢自认弱点：纯 AI 裁决架空作者）——仲裁结果作建议，作者可推翻；进追踪事务 timeline_events/foreshadow
- **上下游**：新增 2 个 haiku agent 模板（agents_version 随 U5 同批 bump）；裁决结果供下一章写前注入（与 U4 场景过滤联动）；成本每章 +2 次低模型调用

### B2 叙事债务（debts）独立维度 → 并入 U3 schema 升级
- **现状**：mo-shu 只有伏笔（hook），无"角色间承诺/悬置因果/到期核对"独立追踪
- **设计**：`_tracking-state.json` 新增 `debts` 域（`[{debt_id, debtor, creditor, promise, due_chapter, status: open|paid|void, evidence}]`）；delta 加 `debt_changes`；章前"到期核对"步骤（写前注入）；卷复盘按 id 清账；与伏笔分开管理（读者好奇→hook，角色亏欠→debt）
- **上下游**：与 U3 的 quality_tickets/reading_power/evidence/learned_patterns 同批升级；渲染进上下文.md 或独立派生视图；与拆文伏笔编号不冲突（独立 ID 域）

### B3 文件门禁脚本化 → 并入 U2（check 扩展）
- **现状**：缺失文件处理靠文档契约（"缺失则停止/修复"），无机械门禁
- **设计**：`tracking_commit.py check` 扩展 `--gate` 模式（或独立 `preflight.py`）：写前校验细纲/卷纲/上下文卡/上一章正文**存在且非空**，任一缺失/空文件 → exit 非零 + 中文说明；禁"伪造文件跳过门禁"（文档明令）
- **上下游**：workflow-chapter 步骤 1-2 前置调用；与 U2 机检关并列（门禁=存在性，机检=内容质量）；风险：需谨慎定义"空"边界（防误伤合法空文件）

### B4 同一套规则双向复用 → 并入 U5
- 把 narrative-writer 的写作质量规则（句式/标点/对话禁令）抽为公共引用文件；consistency-checker 审查模式按**同文件的标签化版本**检测（写作遵守清单 ↔ 检测枚举标签）——防"写手遵守 A、审查按 B 查"的口径漂移

### B5 执行方案子集 → 并入 U7（低）
- moshu-review 的 lean/full、deslop 的检查/修复显式化为命名方案（文档约定即可）

### B6 意图分发两路 → 并入 U9（低）
- 日更意图确认显式拆"情节指令 OD / 写法指令 SE"两栏（与现有世界级/章节级意图分流衔接）

### B7 三级润色管线 → 可选（不排期）
- deslop 增加可选第二道"专业润色"（出版/签约场景；长度保护 60%-140%、润色不重写铁律）

### B8 SLOT 骨架+专项写手 → 远期（不排期）
- 高潮/打脸章可选"骨架+专项"路径（token 翻倍、SLOT 残留风险）——先观察单写手质量再定

> 每批独立提交 + guard 全过 + 实测验收（验收方式见各单元）；批间可随时停（全部增量、可回滚）。
