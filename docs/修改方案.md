## 1. 总则（遵从的原则）

1. **三层分工**：脚本做确定性 / AI 做语义 / 作者做品味——定稿永远由作者敲定
2. **单一权威 + 可重放校验**：`_tracking-state.json` 唯一权威、派生视图可 `check` 逐字比对；新增字段走同一事务协议、渲染规则确定性化
3. **热路径预算**：每章必读的新内容进 doc-budget；新机制尽量冷路径/按需
4. **部署自包含**：副本由 shared-assets 管理；模板变更 bump agents_version + UPGRADING
5. **兼容优先**：schema 升级带迁移；老产物不判废；新字段全可选增量
6. **不学清单**（显式，防静默遗漏）：RAG/向量、learn 原版、连写污染、知识治理三件套、多宿主、文件即真相重构、**work_tracker 任务板协议**（单作者+主会话编排不适用）、**上下文预算分区**（文档型 skill 无 LLM API 窗口管理）、**LLM 导演黑盒自治**（作者是总编剧）、**v6 提交链/多投影方案**（已被 v7 否决，check 逐字校验更优）、**声明式 DAG workflow**（skill 架构不适用，学文件门禁思想即可）、**每章全量快照**（与单权威冲突，漂移风险）、**缓存重建器**（check 逐字重渲染已覆盖且更强）

## 3. 逐项设计

### U1 每章 Git 备份 + 半提交探测 + 健康检查（= L1+L2+L3）

**改什么**：新脚本 `skills/moshu-write/scripts/backup_chapter.py`；`workflow-chapter.md` **步骤 12 后插入"步骤 13 备份"（原"步骤 13 中途快照"顺延为步骤 14）**；`.gitignore` 补 `.moshu-review/`、临时文件。

**怎么改**：`backup_chapter.py commit --chapter N --title X`：探测仓库（无 git → 降级快照目录 `追踪/备份/snapshot_chNNNN_时间戳/`，保留 10 份）→ git-health（陈旧 index.lock 60s+双 stat 自愈；半提交 stash；.git 损坏只指引；全中文输出）→ `git add 正文/追踪/大纲/设定` → `captureCommitExpectation`（parent/tree/message）→ commit（sanitize 消息 `Chapter {N}: {title}`）→ 失败 `probeCommitAfterError` 三态（committed/not/unknown，unknown 宁停）→ 成功 tag `chNNNN`。`rollback`（前滚式恢复）、`create-branch`（平行分支）。git 走参数数组非 shell 拼接。

**为什么**：写废设定无法回滚（webnovel："200 万字必然写废设定"）；半提交探测防"假失败→重复提交"。

**上下游**：依赖 tracking_commit 成功；tag 被 rollback 消费；CI 冒烟（临时仓库 + 无 git 两条路径）。

**验收**：写一章自动 tag；改坏 rollback 恢复；无 git 快照生效；模拟 commit 失败不重复 tag。

### U2 机检"6 阻断 + 4 候选"分层 + 重试预算 + 名册 + 文件门禁（= L4+L5+L11+B3）

**改什么**：新脚本 `skills/moshu-write/scripts/mechanical_check.py`（字符级零依赖）；`workflow-chapter.md` 质量检查前置"机检关"；名册 `追踪/名册.md`；`tracking_commit.py check` 扩展 `--gate`；拆书 Stage 2 复用。

**机检构成（v3 修正：6 阻断 + 4 候选，与 v7 实际一致）**：
- **阻断**：①字数（机检 ±30% 硬边界；**流程层另有 90%/110% 动作阈**——两者层级关系：机检是硬门、流程阈值是触发动作，U9 统一统计口径）②禁词（banned-words 一级词）③禁句式（正则）④复读（字符级 6-gram ≥3）⑤必填字段（章节标题/细纲引用非空）⑥条目变动形式（生命周期动词+编号存在）
- **候选（永不拦截）**：⑦新专名（`([一-龥]{2,3})(冷笑道|笑道|…)` 启发式 + **名册排除**）⑧信息差关键词命中（泄密候选清单，不拦截——与 mo-shu 信息留白/双视图体系自洽）⑨高频意象（CJK 4-8 gram Apriori 分层）⑩句式偏离（vs 基线 ±30%/±50%）
- **mo-shu 自增项（标注，非 v7 构成）**：可选加"Markdown 结构（标题/分隔线合法性）"——需明示为 mo-shu 增项，默认关闭

**重试预算**：`追踪/重试预算.json`（严格 schema fail-closed）——自动修复 2 轮 + 草稿 sha256 幂等（同 hash 不扣）+ author-confirmed 单独记账 + 定稿清章。

**名册（L11 并入，解决悬空依赖）**：`追踪/名册.md`（正名/别名/类型/首现章）——拆书导入时生成 + commit 时增量校验新专名（与机检⑦共用名册）；别名反查 `resolve-alias`。

**文件门禁（B3，prepare+checkpoint 双语义）**：`tracking_commit.py check --gate`（≈prepare：写前校验细纲/卷纲/上下文卡/上一章正文存在且非空，缺失/空文件 exit 非零 + 中文说明）；checkpoint 语义由 U2 机检关（内容质量）承接；门禁由 workflow 步骤硬性前置调用；"禁伪造文件跳过"写进文档纪律（skill 架构下主会话可跳过脚本的边界如实声明）。

**为什么**：AI 审稿前先零 token 筛可计数问题；候选不拦截防误报；预算防失控；名册防同人异名/同名异人；门禁防缺料开工。

**验收**：已知 AI 腔命中阻断、正常文本零误报；同草稿重检不扣预算；名册排除正确；缺细纲时 --gate 拒绝。

### U3 一次性 schema 升级（= P1/S5 + L6 + L7 + L13 + B2 + G9/G16/G26）

**改什么**：`tracking_commit.py`——**`TRACKING_SCHEMA_VERSION 4→5`**（状态文件）+ **`INPUT_SCHEMA_VERSION 1→2`**（事务 delta 扩展，需评估新字段是否进输入负载）；三端（write/import/review）同步；check 校验扩展；test-tracking-commit 扩展。

**域结构（v3 修正：顶层 3 域 + delta 2 类 + changes 内嵌；另增 foreshadow.type 字段）**：
0. **foreshadow.type 增补**（U4 悬久预警依赖）：伏笔条目加 `type: 伏笔|悬念|感情线`（现状无类型字段，10/10/30 阈值需要）
1. **顶层 quality_tickets**（P1/S5 工单闭环）：`[{ticket_id, target(三元定位：chapter+location+dimension，复用 Findings 的 location), severity(S1-S4), edit_goal, must_keep, operations(可空), evidence, status: open|resolved, created_at, resolved_at}]`——**容量护栏 240 条**（超限合并/淘汰最旧 resolved）；**作为状态域直接原子写 + check 校验格式，不进 delta 重放**（流程态定性，G16）
   - 写入：review/consistency-checker 结论经 `ticket-open`；**翻译层**（G12）：consistency-checker 只报 CONFLICTS（不做修改建议），翻译发生在 **review 主会话 Phase 3 综合裁决 + 作者裁决点**（作者填 operations 或确认；一致性类工单 operations 可空）
   - 注入：写前按**文本相关性**取 open 工单 ≤3 条 + 全量 open 兜底（**不做 chapter 硬过滤**——跨章工单如"第 5 章设定矛盾需第 20 章兑现"不能被漏掉，G3/SparkArc 核查）
   - 关闭：复审 PASS 且无新 ticket → `ticket-close`（按 target 三元匹配）
   - **趋势统计**（G1/L9 落点）：写前统计近 5 章 open/closed 工单的维度分布，高频维度进任务书约束（只提示不裁决）
2. **顶层 learned_patterns**（L13 经验库）：`[{pattern_type, description, source_chapter}]`——作者/卷复盘确认后随事务提交；渲染进 `追踪/经验.md`；**注入条件：细纲子串命中才进任务书**（只写不筛=死数据）
3. **顶层 debts**（B2 叙事债务）：`[{debt_id, debtor, creditor, promise, due_chapter, status: open|paid|void, evidence}]`——与伏笔分开（读者好奇→hook，角色亏欠→debt；**债务含角色间承诺、悬置因果、悬置信息差三类**，重叠两边都写）；渲染进独立派生视图或上下文.md 可选栏；章前"到期核对"步骤；卷复盘按 id 清账
4. **delta.reading_power**（L6 追读力）：`{hook_type, hook_strength, coolpoint_patterns, micropayoffs}`——AI 判断标注（明确非确定性）；**标注带正文 sha256 校验**（G26：正文改写后旧标注不得覆盖——与 L5 幂等同思路）；**配套：追读力 taxonomy 精简为 mo-shu 自用 references 文件**（钩子五型是"情绪功能维度"，与既有 hooks-chapter 的"位置类型维度"（章首 7 式/章尾 14 式/段落级 11 种）互补不冲突——hook_type 取值在落盘时从 taxonomy 枚举，不新建第二套钩子分类）；**卷复盘消费追读力趋势**（见 U9 卷复盘步骤补充）
5. **delta.debt_changes**（B2 配套）
6. **changes 内嵌 evidence**（L7 溯源）：各 changes 项可选 `evidence: ["chapter:12:event"]`——纯增不改

**为什么**：审查"审完就丢"（P1）；追读力量化；状态可审计；经验沉淀；债务独立维度——一次升级避免多次 schema 波及。

**上下游**：moshu-write/import/review 三端 + consistency-checker + 测试；迁移（migrate 幂等 + 备份）；老 schema 事务照常 append。

**验收**：审查 S1 问题→下章任务书出现工单约束→复审关闭；伏笔/角色可溯源；经验仅细纲命中注入；债务到期核对提示；LLM 标注在正文改写后不覆盖。

### U4 渲染规则与章后对照（= P3/S7 + L8 + L10 + B1 + G28 + G10）

**改什么**：`tracking_commit.py` 渲染函数；`workflow-daily.md` 第 9 步升级；新脚本 `report_overdue.py` + `report_secret_accumulation.py`；新 agent observer/arbiter（或 explorer 扩展）。

**v3 修正：过滤对象与字段**（G8）：
- **状态过滤**（用现有字段）：时间线事件按 `updated_chapter` 过滤（>N 排除）；角色快照用"截至章节"字段近似（最后更新章，非出场章——如实标注近似语义）；若需精确 last_seen 字段 → U3 增补（可选，观察实际泄漏案例再定）
- **计划性内容过滤**（主要防线）：卷纲/细纲/剧情单元卡中"本章禁止提前释放/信息留白/INF 登记"的注入按目标章过滤——**未来剧情泄漏的真实来源是大纲层计划**，渲染时只注入 ≤N 章的计划内容
- **outline 相关性筛选**（L8）：活跃伏笔/角色用本章细纲子串命中优先（确定性规则，check 可复现）
- **悬久预警**（L10）：现算 `当前章号 − updated_chapter`，超阈值（伏笔/悬念 10、感情线 30）标提醒（不拦截）；**依赖伏笔类型维度——U3 增补 `foreshadow.type`（伏笔/悬念/感情线）**（现状伏笔无类型字段，仅 已埋/已回收/已过期/放弃），否则按现有状态近似并如实标注
- **信息差蓄积报表**（G28）：`report_secret_accumulation.py` 现算 `max − registered_chapter`（装逼打脸库存），查询时现算不物化

**章后对照升级（B1，v3 修正边界与落点）**：
- **observer**（新 haiku agent 或 explorer 扩展）：只提取四类差异（世界/故事/角色/未提事件），每条带正文定位证据，**不做判断不裁决**
- **arbiter**（新 haiku agent 或主会话）：只裁决——世界事实 adopt/pending/conflict（**保守默认**：低风险自动 adopt、涉**力量体系**默认 pending、仅直接矛盾 conflict——G20 措辞修正）、故事差异 landed/missed/deviated、未提事件归类 hook/debt/discard
- **与 consistency-checker 边界（G17）**：observer=**后验提取**（读终稿对照状态文件）；checker=**写前/写后推理核对**（grep-first + 推理型）——不重叠；agent 清单 7→9（observer/arbiter），agents_version 随 U5 同批 bump，behavior-contracts 场景表同步
- **裁决落点（G10）**：adopt→timeline_events（已发生事实）；hook→foreshadow；debt→debts；pending→debts 或单独 pending 域；conflict→continuity_risks——**timeline 事件可选加 `verdict` 字段 + `author_overridden` 记录位**（作者可推翻，保留确认点——笔枢自认 AI 裁决架空作者的弱点）

**为什么**：长篇头号一致性风险是注入未来剧情/状态泄漏；章后对照"又当运动员又当裁判"（P2 的章后版）；世界事实裁决是 mo-shu 缺失维度。

**验收**：写第 N 章上下文不含 N+1 计划/状态；细纲提及伏笔必然在上下文；悬久/蓄积报表正确；章后对照产出四类差异 + 裁决 + 作者确认。

### U5 写评分离 + 两模式 + 落盘回执 + 审稿令牌（= P2/S6 + S3 + S1 + S2 + G11/G12/G27）

**改什么**：`moshu-narrative-writer.md` 模板重构；`workflow-chapter.md` 写作/审查步骤重排；`moshu-review`/`moshu-deslop` 调用方式；agents_version 27→28 + UPGRADING。

**怎么改**：
- **两模式**（S3 的 skill 版：聊天模态 mo-shu 无入口，合理裁剪为两模式）：`写作模式`（spawn 写作：五段任务书输入 → 正文落盘 → 返回落盘路径+字数实测）与 `审查模式`（review/deslop 调用：只读正文 → 返回结构化 findings）；共同规则抽 `base` 段（写作硬约束/格式规范）；**产出规范单一真源**（B4：质量规则抽公共引用文件，审查模式按同文件标签版检测——防两模式契约漂移）
- **落盘回执**（S1）：写作模式契约——"必须落盘 + 字数实测（count_story_body_chars 口径）才算完成；只输出草稿 = 打回"
- **职责分离**（P2/S6）：写后"去 AI 味自审"不再由写作模式执行；审查由 deslop（7 Gate + check-ai-patterns，已有）或 review 的审查模式承担
- **审查契约（G11 修正：复用 mo-shu Findings Schema 扩展）**：输出 `{decision, severity(S1-S4), category, location, evidence, issue, fix, fix_tickets[{target, edit_goal, must_keep, operations}]}`——映射 `category→dimension`、`location→target`（与 U3 工单字段直接对接）；不做 SparkArc 的 overall_grade/dimension_grades/rewrite_brief（mo-shu 已有 S1-S4 分级体系，避免双轨）
- **审稿令牌（G27）**：审查输入（正文+细纲+上下文）sha256 指纹随输出回传，禁止重算——防"审了旧稿改新稿"（与 U2 草稿幂等是两种机制，勿混）

**为什么**：自己审自己会自我辩护；落盘才算完成防"假完成"；契约漂移防写审口径不一。

**上下游**：moshu-setup 模板源；存量项目 agents_version 检测提示重部署（不阻断）；review/deslop 调用审查模式；behavior-contracts 无绑定。

**验收**：写作模式不落盘→打回；审查模式返回结构化 findings（含 fix_tickets 三件套）；写后自审不再由写作 agent 执行；令牌不一致拒绝报告。

### U6 文风增强（= S11 + S12 + S4，v3 修正）

**改什么**：`moshu-style/SKILL.md` 产出规范 + `style-learn-sop.md`；`文风库/文风.md` 实测重生成；explorer `benchmark_style_load` 返回结构。

**怎么改**：
- **作者回避节**（S11）：**≥5 条**负面禁忌（有原文例证，防幻觉——G23 恢复原标准）；narrative-writer 写前召回注入
- **脱敏指令行**（S12）：锚点旁加"指令+脱敏短例"（占位符，跨题材可复用）；原文锚点保留可回查
- **大样本分块**（S4）：样本 >30k tokens 才分块（标准档 6 章不触发）

**为什么**：文风库只有正面统计缺负向约束；高潮段语体漂移最常发生（排期）。

**验收**：文风.md 含作者回避 ≥5 条且有例证；任务书带回避约束；大样本分块产出一致。

### U7 体验层（= L12 + L14 + L15 + L16 + L17 + P7）

**怎么改**：
