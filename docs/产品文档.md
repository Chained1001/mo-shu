# 第一部分 PRD（产品蓝图）

## 1. 产品定位

**把专业网文作者的工作系统外化为 AI 协作工具。**

- 方法论做成知识：雪花法/五步法/八节点等写作理论结构化为按需加载的方法论库；
- 对标做成动态参照：拆文（analyze）与采风（build 内嵌环节）把成功作品的活结构变成设计参照，跨媒介转译防抄袭；
- 底线做成机检：字数/结构/伏笔闭合/去 AI 味等确定性检查交给脚本，永不依赖 AI 自觉；
- 判断留给评审与作者：三维度评审 agent（编辑/作者/读者视角）提供判断输入，作者做唯一品味裁决。

核心命题：**「套路 = 确定性的情绪满足」**。解决长篇根本痛点——几十万字后的设定冲突、伏笔断线、时间线错位、节奏失控：状态按维度拆到文件系统独立维护，对话只负责创作、不负责记忆。

## 2. 目标用户

| 画像 | 场景 | 主路径 |
|---|---|---|
| 新开书作者 | 从零构建世界观/人物/大纲/卷纲 | setup → build（Stage 1-6）→ write |
| 日更作者 | 每日续写、保持连贯与追读力 | write 日更 lane（4-D）＋ 审查闭环 |
| 已有作品作者 | 把存量小说导入为可管理的工程 | setup → import → write 续写 |

共同特征：追求商业化连载、在意一致性与人机协同效率、对「AI 一把梭」持怀疑态度。

## 3. 能力全景

- **技能层（11）**：moshu-setup（部署）、moshu（路由+Dashboard）、moshu-build（开书构建，内嵌采风）、moshu-write（写作三工作流）、moshu-analyze（拆文）、moshu-scan（扫榜）、moshu-review（审查）、moshu-import（导入）、moshu-style（文风）、moshu-deslop（去 AI 味）、moshu-cdp（浏览器采集）。
- **Agent 层（8）**：architect、character-designer、narrative-writer、consistency-checker、researcher、explorer、chapter-extractor、evaluator。
- **自动化层**：8 hook ＋ 守卫/契约体系 ＋ 版本散射工具化。
- **数据层**：文件即真相——项目七区（设定/大纲/正文/对标/文风库/追踪/参考资料）＋追踪事务单写入口。

## 4. 用户旅程

- **旅程 0 安装**：npx 安装 → 新开窗口 → `/moshu-setup` → 再开窗口（装完→开窗→setup→再开窗→build）。
- **旅程 1 开书**：四轮式定调（默认采风）→ Stage 2 骨架八列＋停靠 1 → Stage 3 人物 → Stage 4 单元＋停靠 2 → Stage 5 整合 → Stage 6 定稿＋停靠 3 → tracking init 交接 write。
- **旅程 2 日更**：写前准备（文风召回/变更日志/状态卡）→ 细纲 → 正文 → 机检 → 追踪事务提交。
- **旅程 3 审查修订**：`/moshu-review` 多视角 → 工单 → 修订流（impact_scan → 作者裁决 → 变更日志 → stale 级联）。
- **旅程 4 卷复盘**：write 卷复盘 → build 开新卷（Stage 4 起增量）。

## 5. 产品哲学

1. 三层分工：脚本做确定性、AI 做语义、作者做品味；
2. 文件即真相：状态不在对话记忆里；
3. 候选永不拦截：机器的疑似发现只呈报、不阻断；
4. 方法论苏格拉底化：设计问句强迫深度设计，答不出说明设计未完成；
5. 工具不审问作者：不挖作者私人经历做素材，用向外的跨媒介采风替代；
6. 确定性优先：版本/契约/计数全部工具化单一真源，禁手工维护。

## 6. 差异定位

不做「一键生成」，做**长篇一致性系统**：状态分层、机检底线、作者裁决点、方法论库四件套面向百万字连载。与同类长篇辅助项目的差异由三参考项目真实代价多源验证（详见 AGENTS.md §6）。

## 7. 版本路线

- **v2.4.0（待发）**：创作-评审-采风闭环 ＋ 全仓审计修复与治理批（B31-B47）＋ PRD/FSD 文档；
- **v2.5 方向**：写作层打磨（实测驱动）、本地守卫矩阵与 CI 对齐、路由表语义守卫、rename 工具、tracking_commit 拆分。

## 8. 产品边界（明确不做，14 条）

RAG/向量检索、LLM 导演黑盒自治、每章全量快照、自动连写污染传播、知识治理重三件套、数据库后端、Dashboard 常驻服务化、外部 AI 检测器进主链路、git 书仓托管、插件市场改造、PreToolUse 拦截式门禁、npx 安装器改造、多宿主适配、学自己作品文风。（依据 AGENTS.md §6，作者确认。）

# 第二部分 FSD（功能规格与技术设计）

## 9. 系统架构总览

四层（详见 `docs/architecture.md` 四图）：

| 层 | 组成 | 职责 |
|---|---|---|
| 会话层 | moshu 路由 + 11 Skill 入口 + 8 Agent | 意图分发、流程权威、语义执行 |
| 确定性脚本层 | 机检（check-*）/事务（tracking_commit.py）/部署（deploy.py）/Dashboard（dashboard-server.mjs）/榜单 scraper | 统计、检测、原子事务、幂等部署 |
| 自动化 Hook 层 | 8 hook（会话启停/压缩恢复/细纲门禁/正文后扫/commit 校验） | 兜底网：主会话漏跑时的拦截与提醒 |
| 文件系统数据层 | 拆文库 + 写作项目七区 + 追踪状态 | 唯一记忆载体 |

关键设计：三层分工宪法；`_tracking-state.json` 唯一结构化权威、Markdown 视图全部派生；Agent 可降级（未部署/失败自动 solo/direct）；Hook 提醒语义（ask 不 deny）。

## 10. 核心管线规格

### 10.1 构建管线（moshu-build，Stage 1-6）

| Stage | 产出 | 集成点 |
|---|---|---|
| 1 信息采集（四轮式） | 核心设定表、构建台账 | 默认采风（可跳过，降级声明进台账） |
| 2 骨架构建 | 八列表（一句话/对手/危机赌注/中点/卷末跃迁…）＋势力场 | **停靠 1**：机检前置 → 评审 agent 例行 → 作者裁决 |
| 3 人物构建（自动步） | 角色档案、弧线页 | 瓶颈信号可触发采风；打断可恢复 |
| 4 单元构建 | 卷纲、剧情单元卡 | **停靠 2**：同停靠 1 协议 |
| 5 整合检验（自动步） | 整合记录、伏笔表、线索矩阵 | check_outline 机检 |
| 6 打磨定稿 | 定稿卷纲（v1.0 标记） | **停靠 3** → tracking init 交接 write |

停靠协议：呈报前必跑机检（blocking 先修）→ spawn evaluator（三维度只读，审稿令牌回传）→ 作者裁决（含按评审调整/触发采风选项）。开新卷：卷复盘输入 → Stage 4 起增量，Stage 1-3 全书级不重做。

### 10.2 写作三工作流（moshu-write，lane 制）

单章 Stage 4-C1~C13、日更 4-D1~D4、修订 4-R1~R5（lane 前缀消除同号歧义）。写前准备含文风两级检查、变更日志消费、续写状态卡（7 栏）。细纲门禁：缺对应细纲时 hook 阻止首建正文。

### 10.3 拆文管道（moshu-analyze，Stage 2-1~2-7）

2-1 章节边界（**边界表为唯一切片真值**，禁物理分章）→ 2-2 黄金三章 → **自动停靠**（快速预览，用户确认后续跑）→ 2-3 逐章摘要（chapter-extractor 并行，可降级串行）→ 2-4 剧情聚合（节奏/情绪模块）→ 2-5 设定+角色（两阶段档案）→ 2-6 汇总报告 → 2-7 技法总结。恢复只接受 schema_version: 2 的进度文件。

### 10.4 追踪事务（tracking_commit.py）

`init / commit / check` 三子命令唯一写入口；`追踪/_tracking-state.json` 为单权威（最后原子写），派生视图：上下文.md（7 栏状态卡）、逐章记录、角色快照、伏笔视图、时间线双视图（作者真相/读者已知）。信息差域：知情人×读者已知的登记。派生视图被手改时 `check` 报差异，以整份重建修复。

### 10.5 下一步判定（next_step.py）

只读推断 S0-S6（文件证据判定，输出 JSON DTO）：S0 未部署 → S1 无书 → S2 有书无正文 → S3 下一章无细纲 → S4 有细纲未写 → S5 卷末 → S6 下卷规划；优先中断边（拆文续跑/审查续批）以 `step=INTERRUPT` 输出。

### 10.6 审查闭环（moshu-review）

多视角审稿 → 工单 JSON（根级 schema_version/chapter_range/review_token/findings+fix_tickets）落盘 `.moshu-review/tickets/`；审稿令牌 8 位、报告首行逐字回传、`review_tickets.py verify-token` 校验后采纳；修订流经 review_tickets list 回流。运行模式自检：`Effective Mode: full/lean` 或 `Fallback: ... -> solo`。

### 10.7 采风（build 内嵌环节）

五类（结构/角色/设定机制/情节/情绪）× 源七类（网文/名著/影视/动漫/游戏/真实事件/历史，真实事件须改编脱敏）；CF 票据制（台账登记→已消费状态流转）；执行链：主线 spawn researcher（直呼）→ 产物 `设定/采风-CF*.md` 六节结构 → **融合四步归主线**（选要素→转译→喂字段→功能位清单回写）；角色类使用前必须作者过目；agent 不可用主线内联降级（一行不废）。机检侧：check_outline 比对采风专名与 CF 未消费（candidate 级）。

## 11. Agent 规格（8）

| Agent | 定位 | 关键纪律 |
|---|---|---|
| moshu-architect | 结构/大纲/钩子反转设计（Opus 级） | 契约摘要随 spawn 附带 |
| moshu-character-designer | 角色档案/动机链/对话 | 升级绑弧光、弱绑定回退 |
| moshu-narrative-writer | 正文写作/格式合规 | 工具白名单、7 Gate、细纲消费两分法 |
| moshu-consistency-checker | 一致性扫描（轻量级） | S1-S4 分级报告 |
| moshu-researcher | 检索双模式（采风/事实查证） | 采风禁取正文、无来源丢弃、maxTurns 30 |
| moshu-explorer | 只读查询/日更上下文加载 | 文风两级正查 |
| moshu-chapter-extractor | 并行拆文章节单元 | 共享产出纪律（纯 JSON） |
| moshu-evaluator | 三维度评审（编辑·商业/作者·新鲜度/读者·留存） | **只读**（禁 Write/Edit/Bash）、令牌回传、JSON 输出 |

共性：按需加载 agent-references 方法论包；审稿类 agent 带令牌机制；agent 不可用全部有主线降级。

## 12. 自动化规格

**Hook（8，settings-hooks.json 注册）**：session-start/end（进度快照/会话日志）、detect-story-gaps（设定缺口/伏笔断线）、pre/post-compact（上下文恢复）、validate-story-commit（commit 校验，仅警告）、guard-outline-before-prose（**细纲门禁，阻断**）、check-prose-after-write（截断/工程词/字数欠账，提醒）。

**机检（护作品，blocking/candidate 两列）**：check_outline（blocking 9：结构完备/八列表头/行数/字数和/阶段占比/台阶算术/终局底牌/伏笔闭合/暗线支线；candidate 5：单链势力/采风专名/CF 未消费/常驻压力/反转覆盖；旧结构整体降级为单 candidate）；check-ai-patterns（去 AI 味 blocking 句式）；check-degeneration / check-outline-copy 等。**候选永不拦截**。

**守卫（护仓库）**：结构守卫＋契约守卫＋版本同步（agents-version-sync 34 全仓一致）＋shared-assets 全量对账（未登记副本即红）＋doc-budget＋story-numbers（README 计数=实测）＋claude-adapter（marketplace↔SKILL.md 映射）。

## 13. 部署与分发

- 分发：Claude marketplace（`.claude-plugin/marketplace.json`，11 插件条目与 SKILL.md 一一映射，adapter 守卫校验）＋ npx 安装。
- 部署（deploy.py，一键）：hooks/rules/agents/agent-references 复制 + CLAUDE.md 三分支合并（生成/section 合并/CONFLICT 不覆盖）+ settings 按 command 身份合并（原子写、幂等）+ sentinel（6 字段）+ 重启标记。版本三分支：`< 当前 → 更新 / = 当前 → 询问 / > 当前 → 禁止降级覆盖`。verify 八项机械验证。
- 版本管理：agents_version（当前 34）散射 48 处全由 `bump-agents-version.py` 工具化（含阈值形态，历史条目排除）；setup_skill_version 独立轨 6 处。重新部署后须新开会话（agent 会话启动时注册）。

## 14. 数据契约与同步

`scripts/current-contract.json`（单一真源，守卫从契约断言）：deployment_manifest（agents/hooks/rules 数、sentinel 字段、CLAUDE.md 节、章节范围格式）、artifact_contracts（剧情单元卡/审查工单/采风-CF 三产物的字段清单+生产者+消费方+锚点文档）、flow_anchors（日更批末收尾/质量修复节名）、required_outline_sections（8）、progress_schema_version 等。共享副本：shared-assets.json 76 组字节级同步，`check-shared-files.sh` 全量对账（登记完备性由守卫兜底）。

## 15. 性能预算

`doc-budget.json` 限制「触发即全量加载」的热路径文本量（单文件+路径组两级，node UTF-16 口径）；超限处理序：删等量旧文本 → 下沉冷路径 → 显式调高并注明理由。冷热分离：SKILL.md 为热路径薄入口，流程细则在 references 按需读、低频节下沉 cold-path。当前关键预算：workflow-build 26600/构建路径组 30500。

## 16. 降级与容错

- Agent 降级：未部署/spawn 失败/子代理上下文 → solo/direct 内联，报告头标注 Fallback 语义；版本不匹配不阻断仅提示。
- 采风降级：跳过/失败 → 台账显式声明「本次构建未经采风」，不静默。
- 断点恢复：拆文按 `_progress.md` 续跑；构建台账纯 Markdown 快照幂等可恢复；压缩前后 hook 保存/恢复上下文。
- 读失败三分类（缺文件/空文件/内容坏）各自明示，禁静默降级。
- 平台假红清单：Windows 本地已知假红（chmod no-op 等）以 CI Linux 为准，记录在案防误判。
