## 1. 产品定位

**mo-shu = 长篇网文创作的一致性系统**：一套跑在 Claude Code 上的创作团队与工程底座，让作者写到几百章依然——
- **记得住设定**（单一权威追踪 + 场景过滤注入 + 文件门禁，不写崩设定、不泄漏未来剧情）
- **接得住伏笔**（伏笔/悬念/感情线统一账本 + 悬久预警 + 叙事债务 + 机器可检查的引用）
- **守得住大纲**（规划与执笔分离 + 结构 stale 传播 + 细纲契约字段）
- **写得像自己**（文风库正向统计 + 作者回避负向约束 + 去 AI 味确定性检测）
- **改得回来**（每章 Git 备份 + 半提交探测 + 平行分支试写）

**一句话**：把"AI 写长篇"从"每次生成都要赌"变成"边写边攒、可回滚、可度量、写评分离的工程流水线"。

## 2. 目标用户与使用场景

| 用户 | 场景 | 核心诉求 |
|---|---|---|
| 长篇网文作者（核心） | 开书规划 → 日更连载 → 审查修订 → 卷复盘 | 不写崩设定/伏笔；审查意见真的影响下一章；写废能回滚 |
| 想学写网文的新手 | 扫榜选题 → 拆书对标 → 学文风 | 从验证过的模式出发，不裸奔 |
| 有存量小说的作者 | 导入旧书 → 续写 | 旧书变工程，续写不丢状态 |

## 3. 核心能力全景（四大块）

```
┌─ 创作链路 ─────────────────────────────────────────────┐
│ 扫榜选材(scan) → 拆书对标(analyze) → 开书规划(plan*)    │
│ → 日更写作(write) → 审查闭环(review+工单) → 文风(style) │
│ → 卷复盘 → 循环                                          │
├─ 质量保障（三层）───────────────────────────────────────┤
│ ① 机检（零 token 确定性：字数/禁词/复读/新专名/意象/门禁）│
│ ② 语义审查（写评分离：事实审 + 编辑审 + 多视角对抗）      │
│ ③ 作者裁决（定稿/豁免/打回——品味永远归作者）             │
│ + 审查工单闭环：审→存→写前注入→复审关闭（审完不丢）       │
│ + 章后对照：observer 提取 → arbiter 裁决 → 作者确认        │
├─ 工程保障 ─────────────────────────────────────────────┤
│ 追踪唯一权威（可重放校验）· 每章 Git 备份回滚            │
│ 断点续写（进度持久化）· 重试预算防失控 · 半提交探测       │
├─ 知识管理 ─────────────────────────────────────────────┤
│ 拆文库（对标资产）· 文风库（表达层+作者回避）             │
│ 经验库（结构层模式，细纲命中才注入）· 叙事债务 · 追踪状态 │
└─────────────────────────────────────────────────────────┘
```

## 4. 核心流程（用户旅程）

### 开书（团队化后）
```
/moshu-plan
  选题确认（消费扫榜选题决策/对标发现）→ 核心设定（含输出纯度校验）
  → 全书体量 → 卷纲（对标节奏回流）→ 首批细纲 5 章停靠
  产出：设定/ · 大纲/ · 追踪初始化
```
### 日更
```
/moshu-write
  读进度断点 → 文件门禁（细纲/上下文卡非空）→ 写前组装（三圈记忆
  + 场景过滤 + 细纲相关性筛选 + 五段任务书 + 审查工单注入（相关性≤3
  + 全量兜底）+ 经验命中注入 + 债务到期核对）
  → narrative-writer 写作（落盘回执：落盘+字数实测才算完成）
  → 机检（6 阻断/4 候选分层）→ 追踪事务（追读力/evidence/经验，标注带正文 hash）
  → 每章 Git 备份（tag chNNNN）
  → 章后对照（observer 提取四类差异 → arbiter 裁决 → 作者确认 → 回写）
```
### 审查闭环
```
/moshu-review（或日更内触发）
  → 多视角审查（写评分离，事实审/编辑审独立上下文；输出带输入令牌）
  → 结论经 review 主会话翻译为 quality_tickets（target/edit_goal/must_keep/operations）
  → 写前按相关性注入（≤3 条 + 全量兜底）→ 复审通过关闭工单
  → 近 5 章工单维度趋势回灌任务书（只提示不裁决）
```
### 卷复盘
```
卷末 → 伏笔清账（悬久预警辅助）→ 卷摘要 → 下卷规划
→ 追读力趋势 → 经验沉淀（作者确认的写法 → 经验库）
```

## 5. 产品哲学（六条——来自两项目研究的提炼）

1. **三层分工**：脚本做确定性的（能数的绝不让模型估）/ AI 做语义的 / 作者做品味的——定稿永远由作者敲定，系统没有任何不经作者确认就写入定稿区的路径
2. **单一权威 + 可重放校验**：`_tracking-state.json` 是唯一事实源，派生视图可逐字重渲染比对——正确性交给确定性机制而不是模型自觉
3. **团队化（一人一事）**：每个 skill/agent 单一专职——规划、执笔、审查、设定守护、文风、去味各归其位；生产与审查永远分离
4. **审查闭环**：批评必须影响后续写作——工单持久化、写前注入、复审关闭，而不是一次性的零散意见
5. **防呆与自愈**：半提交探测、陈旧锁自愈、重试预算 fail-closed、机检候选不拦截——可靠性来自自愈不来自门禁，宁停勿崩
6. **作者掌控**：随时打断/修改/重写；候选是材料不是答案（≤3 条 + 未命中如实降级）；文风库锚点可回查

## 6. 与同类产品的差异定位

| | mo-shu | webnovel-writer v7 | SparkArc Studio |
|---|---|---|---|
| 形态 | Claude Code skill 体系（作者主控） | npm CLI + 文件即真相 | 聊天平台 + LangGraph 导演 |
| 正确性 | 程序权威 + check 逐字校验 | git 原子提交 + 格式法律文本 | 落盘护栏 + 状态机 |
| 编排 | 主会话确定性路由（人肉状态机） | 薄 skill + 厚脚本命令面 | LLM 导演自主委派 |
| 审查 | 多视角对抗 + 工单闭环（规划中） | 事实/编辑双角色 | Critic 五维 + fix_ticket |
| 材料 | 具体对标书资产 + 拆书 | 通用知识库 + 候选制 | 风格克隆 + GraphRAG |
| 最强者 | 可验证性/作者掌控/市场侧（扫榜拆书） | 零依赖确定性机检 | 闭环协议/上下文预算 |

**差异化主张**：webnovel 教我们工程化，SparkArc 教我们闭环——mo-shu 把它们收进"skill 体系 + 作者掌控"的壳里：既有 webnovel 的确定性工程底座，又有 SparkArc 的审查闭环，同时保持"作者是总编剧"的产品形态（不引入 LLM 导演的黑盒自治）。

## 8. 产品边界（明确不做）

- **不做** RAG/向量检索（外部 API 依赖、中文召回质量差、与零外部依赖定位冲突）
- **不做** LLM 导演黑盒自治（作者是总编剧；主会话确定性路由更可预期）
- **不做** 自动连写无确认（每章有产物与闸门，作者可随时打断）
- **不做** "文件即真相"重构（程序权威 + 可重放校验已解决同一问题）
- **不做** 多平台/多 CLI 适配（当前专注 Claude Code 生态）
