## 4. 新文件设计

无独立新文件（域设计见 §3 第 1 行算法级描述）。

### 施工顺序建议（本批是全计划中唯一的"深改既有事务脚本"，按此降险）

1. 先读 tracking_commit.py 全文，画出：normalize_state 调用链、render_views 视图清单、apply_transaction 的 delta 键处理处（:618 附近）、init/commit 的输入校验处（:792/:838）。
2. 按依赖序写代码：常量 → normalize_information_gap_* 函数（对照 foreshadow 同名函数逐段仿写）→ state 域接入 → delta 键接入 → 迁移备份逻辑 → render_views 视图。
3. **每完成一步跑一次 `python3 scripts/test-tracking-commit.py`**，既有用例保持绿再进下一步（增量验证，禁一次写完再测）。
4. 测试新用例最后写；三副本 sync 放最后一步，sync 前后各跑一次 check-shared-files。
