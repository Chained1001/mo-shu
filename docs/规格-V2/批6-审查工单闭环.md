## 4. 新文件设计

**工单文件**：`{项目根}/.moshu-review/tickets/tickets_{YYYYMMDD-HHMM}_{起章}-{止章}.json`
```json
{
  "schema_version": 1,
  "chapter_range": [起章, 止章],
  "review_token": "<8位>",
  "findings": [
    {"id": "T001", "severity": "blocking|candidate", "dimension": "<受控枚举9类>",
     "evidence": "<引文/位置>", "suggestion": "<建议>",
     "status": "open|fixed|dismissed", "status_note": "<处置证据一句，resolve 时写>"}
  ]
}
```

**review_tickets.py** 子命令（全部确定性、幂等）：
- `write --project P --input <临时JSON文件>`：校验（schema_version/枚举/id 唯一且 `T\d{3,}`/令牌非空/候选与阻断只影响呈报不影响流程）→ 规范化排序（id 升序）→ 原子写目标文件（临时文件+rename）。**AI 产出只走文件不走 argv**（移植 v7）。
- `resolve --project P --ticket <文件> --id T001 --status fixed|dismissed --note "<一句>"`：只允许 open→fixed/dismissed 单向流转；回写同文件（status_history 不引入，note 覆盖式）。
- `list --project P [--status open]`：跨工单汇总输出 JSON。
- `verify-token --ticket <文件> --token <串>`：报告首行令牌比对（供主会话在采纳报告前调用；不等→退出 2）。

**test-review-tickets.py**（正反向）：write 合法/坏枚举拒/重复 id 拒；resolve 单向流转（fixed→再 resolve 拒）；list 过滤；verify-token 相等/不等；幂等（同输入 write 两遍逐字节一致）。

## 8. 禁止事项

1. 禁止改造 review-log 现有格式/读点/写入方（F1/F4 契约不动）。
2. 禁止让 severity=blocking 的工单自动拦截任何流程（工单只影响呈报与复审范围；处置决定权在作者——总纲原则 2）。
3. 禁止 AI 直接写工单文件（必须先落临时文件经 review_tickets.py write）。
4. 禁止 status 逆向流转或手工编辑 JSON 绕过 resolve。
5. 禁止在本批动 moshu-review 的 full/lean/solo 模式结构。
6. agents_version 只 bump 一次（27→28），模板其余内容不动。
