## 4. 反向确认（我们的差异化被外部验证）

1. **候选不拦截哲学**：DukeTwoCan 把 autonovel 的 LLM 评分门降为「趋势信号」、验收改分层阻断+wood 候选——与我们机检两列语义同构，形态转换中被迫收敛到我们的设计。
2. **确定性点名注入优于关键词扫描**：ST 官方文档明示中文全词边界失效；ST 自身的 WORLDINFO_FORCE_ACTIVATE 强制激活旁路（05·M12）证明「外部点名」正是该体系内更可靠的入口——我们用细纲出场顺序点名（B57）不是回避而是优选。
3. **脚本做确定性**：ans 全仓 0 脚本、book-os 零守卫全凭 LLM 自觉——两者停更/漂移风险即反面教材；storycraftr 示例仓出现「引用残留泄漏进正文」即无确定性机检的上限实证。
4. **文件即真相不整体重构**：storycraftr 用 Chroma RAG 每命令全量重建记忆（触 §6）——我们的单权威 state+派生视图路线被对比验证。
5. **状态层必须脚本派生而非 LLM 手写**（第二轮）：Claude-Book 的 state 由 agent 手写、timeline 全量 append——18 章即 2256 行不可扩展（07）；反证我们 tracking_commit 统一派生视图的必要性。
6. **LLM 评分不可做门禁**（第二轮）：AIStoryWriter 代码注释自证「LLM 打 0-100 分全是垃圾，改 IsComplete 布尔才稳」（07）；与我们候选不拦截哲学同向，且给 evaluator 的分数字段设计敲警钟——分数只能做趋势信号（已纳入 B60）。
7. **档位语义必须与任务实义对齐**（第二轮）：AI_NovelGenerator 把强档模型配在只做簿记的「定稿槽」而正文由低档直出（08）——引入组件×模型策略时必须以「任务实际做什么」为分配依据。
