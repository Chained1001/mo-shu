## D3 车道收敛设计方案（仅方案，未实施）

### 问题
日更（workflow-daily）/单章（workflow-chapter）/大修（workflow-revision）三条车道重复实现"写前准备、确定性收尾、追踪事务提交"三段，且能力覆盖不对称（历史问题 W2/W3 的根）。

### 方案：共享内核 + 车道薄壳

```
references/chapter-core.md（新，共享内核，唯一真源）
  ├─ A 段 写前准备（状态筛选→设定包→模块召回→指令确认；含 (a)-(g) 与快捷路径）
  ├─ B 段 正文执行与字数验收（细纲优先边界、形状层、90% 下限）
  ├─ C 段 确定性收尾（ai-patterns→outline-copy→normalize→degeneration→candidates 全链 + 2 轮预算阀门）
  └─ D 段 追踪事务提交（含 information_gap_changes、失败三分类）

workflow-chapter.md → 薄壳：13 步骨架，每步一行指向 core 对应段 + 单章特有（标题预检）
workflow-daily.md   → 薄壳：Step 1-4 批次控制（K=2-3 章、串行纪律、批末收尾）+ 逐章循环指向 chapter
workflow-revision.md→ 薄壳：级联检查 + 工单处置 + 修订事务差异（mode=revision 语义）
```

### 收益
①三段各一份真源，改一处三车道同步生效（本轮 DM2 的"三份文档各改一行"这类修复不再需要）；②能力对称性由结构保证——core 的 C 段含候选机检，则三车道都有。

### 成本与风险
热路径行为敏感：workflow-chapter/daily 都是 doc-budget 登记文件且被 behavior-contracts/capability-wiring 双重锁定；重构必须逐条迁移断言。预估改动 4 文件、~200 行净减、守卫清单同步 ~10 处。

### 建议
在 D1/D5 稳定运行一轮后再做；做法是"先建 core 由 chapter 引用、观察一轮，再让 daily/revision 切换"的三步迁移，每步全绿再进下一步。
