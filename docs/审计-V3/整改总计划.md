### 1.3 三条贯穿性根因（比单条缺陷更值得记住）

1. **守卫只锁"话有没有写"，不锁"链有没有接"**：`behavior-contracts.json` 是 `path` + `must_contain` 子串匹配，因此"脚本建成但流程文档从不指示使用"可长期全绿。本轮 9 条接线缺口（W1/RM2/IM3/S2/W2/W3/DM1/RB1/SM1）全部由此而生。
2. **守卫扫描面窄于文档面**：`check-agents-version-sync.py` 只扫 `skills/*/SKILL.md` → `references/` 里的 `agents_version: 27`（IM1）活了整个 v1.3.0；`check-story-numbers.py` 只匹配「N 个 skill」数字口径 → 表格行数/图节点/「N 份」「N 条」全无守护（G2/PM7/G7）；`check-doc-budget.sh` 只遍历已登记项 → 未登记热路径（scan 8610、moshu 4657、style 3966）零约束。
3. **`marketplace.json` 与权威文档的数字无任何守卫**：G1（3 处版本滞后）与 G7（术语表 27/1/4、契约数 10、README 31/189）都是"发布时漏改、CI 无感"。

## 2. 施工纪律（与 `AGENTS.md` 一致）

1. **git 只读默认**：本计划任何一批完成后**停下等作者说"提交"**；禁止 `git add -A`。
2. **一批一提交**，提交消息按 `docs/规格-V2/README.md` §4 惯例（`fix(scope): …` / `feat(scope): …`）。
3. **验收全绿才算完成**；失败先判因，**禁止改断言变绿**。基线见 [基线-守卫全量.md](基线-守卫全量.md)（等价条件 38/38 绿）。
4. **每批复跑范围**：改脚本 → 跑对应 `test-*`；改文档 → `static-check.sh` + `check-doc-budget.sh` + `check-behavior-contracts.sh`；改 agent 模板 → 追加 `check-agent-template-rules.sh` + `check-agents-version-sync.sh`；**收尾批复跑全量**。
5. **Windows 本地前置**：`export PYTHONIOENCODING=utf-8` + 临时 `python3` shim（否则 5 个 `test-*.py` 假红，见 G4）。
6. **不学清单**：本计划零涉及数据库/RAG/常驻服务化/npx 分发改造/拦截式 hook 门禁。全部修法为文档措辞、数字对齐、脚本小补丁、测试与契约登记。
