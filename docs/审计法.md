# 审计法（唯一审计方法 SOP）

- 版本：v1.3（2026-08-22 三轮修订合并：v1.1 产消对账半步；v1.2 引用内容抽检半步；v1.3 完备性补漏——3a 扩异常降级链与人机分工点、2a 补安全面轻扫、基线补平台假红清单、第4步版本口径改枚举消费面、3b 补向后兼容核对、分档补【文档宣称】。修订方法论自觉：前两轮从缺陷史收敛，v1.3 补从领域完备性[V2 研究 22 维框架]收敛的缺项）
- 适用范围：任何模型对本仓库任何 skill / 机制 / 守卫的审计，以此为准。**对象可以是多技能业务链**（联合审计——按上下游关系一起审，衔接面[流程衔接表/路由/产物交接]是缺陷高发区，三轮实战中路由残留全部发现在衔接表）。
- **这是唯一审计方法**。历史审计（docs/归档/审计-V3、审计-V4）与旗舰审计为过程产物，本 SOP 是它们的收敛形态。
- 与相邻机制的分工：行为契约（behavior-contracts）锁「话在不在」、能力接线（capability-wiring）锁「链通不通」——本审计法用于**人查**（跨 skill / 跨公约数的结构审计），三者互补，不互相替代。

> 方法沿革：V3（逐 skill + 根因三分类）→ V4（基线 + 机制链 + 轻扫）→ 旗舰六步法 → v1.0 收敛（批B7）→ v1.1 产消对账 → v1.2 引用内容抽检 → v1.3 领域完备性补漏（异常链/安全/人机分工/文档宣称/平台假红/枚举消费面/向后兼容）。历史审计见 docs/归档/审计-V3/V4。

## 六步流程（v1.3：第 2 步含 2a/2b、第 3 步含 3a/3b）

1. **基线**：先跑全量守卫矩阵（`bash scripts/*.sh` 与 `python scripts/test-*.py`）+ 与本域相关的回归测试，记录全绿基线（任何红先判因，**禁止修**——审计不是修复，修是施工侧的事）。**平台假红清单（v1.3）**：判因先排三类已知假红——①Windows GBK 控制台（`PYTHONIOENCODING=utf-8` 后复跑）；②chmod 权限位 no-op（test-shared-assets mode-drift 类，CI Linux 为准）；③符号链接/权限探测 skip。排除后才算真红。
2. **结构与引用审计**：
   - **2a 结构盘点**：列出被审计目标（skill / 机制 / 守卫）的 SKILL / references / scripts 清单与体量，核对「按需加载」纪律（热路径 vs 冷路径是否登记进 doc-budget）。**安全面轻扫（v1.3）**：脚本的路径参数（--project/--input/--dir 类）是否 resolve 后限制在预期根内（防 `../` 穿越，参照 DeterminFlow local_archive.py:30-40 双重防护范本）；输入文件解析失败是否明示（缺/空/坏三分类）而非静默。
   - **2b 引用内容抽检**（v1.2，分层不全读——可达 ≠ 内容对）：
     - **热消费深读**：被审计目标流程**高频指示加载**的 references 抽 2-3 个深读内容——与当前机制是否矛盾、是否真的包含下游要读的那个节/字段、内部二级引用是否可达（B4 教训：引用的引用也要闭包）。
     - **过时信号全扫**：全部引用文件 grep 已删除/已改名的机制名（如 workflow-setup 类墓碑名——closure 守卫的"非资产宇宙忽略"规则会静默放过这种提及，只有审计能抓）。
     - **体量异常标记**：异常大（从未裁剪，候选瘦身）或异常小（空壳，候选充实）的引用文件标记呈报。
3. **机制链与产消审计（核心——"守卫锁话不锁链"）**：
   - **3a 机制链**：枚举该目标的端到端链，**每链双向走查（v1.3）**——①**正常路径**：文档是否指示调用、脚本是否有该能力、消费方是否真的消费；②**异常降级路径**：缺件（上游文件缺失时明示还是静默）、坏格式（解析失败三分类：缺/空/坏）、中断恢复（断点机制存在且可续）、**幂等重跑**（同输入重跑结果一致）。每链判 **闭合 / 断裂 / 半闭合** + 证据。**人机分工点核验（v1.3）**：链上的自动动作是否越权——该有作者确认/裁决的点（采纳前校验/修订裁决/提交确认）是否齐备，无人确认的自动生效项呈报。
   - **3b 产消对账**（v1.1，双向清单化）：
     - **正向（产出侧）**：列出该目标的**每个产出物**（文件/字段/标记），逐个问「谁消费？」——grep 全仓找显式消费点。按三级定级：①**显式消费**（有消费点实证）✓；②**定位声明**（产出侧明文声明为学习材料/作者参考，B6 式显式决策）✓；③**悬空**（既无消费也无声明）→ 候选呈报。
     - **反向（输入侧）**：列出该目标的**每个必需输入**（上游产物/字段/前置条件），逐个问「谁产出？」——上游存在 + **字段级吻合**（上游真产该字段吗？A2 教训：write 必读单元ID 而 build 未产，链断在字段级而非文件级）。反向断裂定级高于正向悬空（必需输入缺失会拦死下游）。
     - **capability-wiring 对账**：该域的产消关系是否已登记进 `scripts/capability-wiring.json`？登记面与实际面互查——**漏登记**（实际接线但未登记，守卫盲区）与**假登记**（登记了 consumer 但实际未消费）都呈报。
     - **向后兼容核对（v1.3）**：涉及数据结构/文件格式的域，核对兼容四原则（宪法 AGENTS §9）——新字段全可选？老数据零丢失？迁移带备份？渲染可重放？
4. **一致性轻扫**：版本口径（**枚举消费面后核对**[v1.3]——grep 全部出现点含代码字面量与 usage 串，session-start/deploy.py usage 两例教训：抽样核对必漏）/ 术语表（AGENTS.md §9 术语表）违例 / 悬空引用 / 数字口径 / doc-budget / 路由与判定表一致性。
5. **历史回归**：历次审计该域发现的**已修项**抽查复验，确认没有回潮。
6. **分级汇总**：**阻断**（机制断裂或拦死流程；反向产消断裂[必需输入无产出]归此级）/ **需修**（真实缺口）/ **候选**（呈报；正向产消悬空归此级）/ **存疑**——每条带证据（文件路径:行号）+ 档案分档（【事实】/【文档宣称】[v1.3：文档自述未实测——须复现或显式降档] /（推断）/ 存疑）。

## 纪律

- **自我推翻**：子代理或初判结论，须经本人复跑核实后再定级（V3 曾推翻"64 组"误报——初判需复核）。
- **独立复核**：转述必抽验（旗舰审施工、施工审规格，同一精神）——复核是转述的默认检，不信任日志转述。**复现证据落档**（v1.1）：审计报告中的载荷性主张（如"上游确实产出该字段""谱系级零消费"）须附复现路径（grep 命令/行号快照）随报告写入——B6 教训：事后补录的证据不如随手的。
- **只查不改**：审计产物的**唯一写入 = 审计报告文件**；发现问题只呈报，不修复——修复须另行走规格（作者发起新批次）。
- **B6 先例**：显式声明的「零消费」≠ 缺陷——先查有没有定位声明（如 `拆文产物定位声明` 的"学习参考不读取"）再定级，避免把显式决策误判为缺陷。（v1.1 起此定级路径已内化为 3b 正向三级定级的中档。）
- **候选永不拦截**：审计的候选类发现只呈报作者，不阻断流程、不改变退出码语义（AGENTS.md §2.7）。

## 产出格式

- **大审计**：`docs/审计-{世代}/`（含基线 / 结构 / 机制链表 / **产消对账表** / 一致性 / 回归 / 分级清单 / 自我推翻记录），各节按六步对应。
- **小审计**：并入 `docs/审核记录.md`（单批复审/轻扫），结构同上但按需精简。
- 报告结构固定：`基线 / 结构盘点 / 机制链表 / 产消对账表 / 一致性 / 历史回归 / 分级清单 / 自我推翻记录`。
- 每一条结论：证据路径:行号 + 分档（【事实】/（推断）/ 存疑）。

## 术语（本 SOP 内部）

- **端到端链**：一组「生产者产出 → 文档/流程指示 → 消费者读取/消费」的完整通路。审计断言对象。
- **守卫锁话不锁链**：行为契约守卫只锁"约束文本在位"，不锁"机制是否真的被用"——机制链审计补这一面。
- **半闭合**：生产者与文档有一方缺失/文档指示但脚本缺能力，或消费方未接线等"部分接通"状态。
- **产消对账**（v1.1）：双向清单化的生产-消费核对——正向逐产出问消费（三级定级：显式消费/定位声明/悬空）、反向逐必需输入问产出（含字段级吻合）、capability-wiring 登记面对账。
- **字段级断裂**（v1.1）：上游文件存在但下游必读的字段未被产出（A2 单元ID 案例）——文件级 grep 查不出，须对照下游消费字段清单逐一核。
- **引用内容抽检**（v1.2）：分层的内容级审计——热消费深读 2-3 / 过时信号（墓碑名）全扫 / 体量异常标记；与文件级守卫（closure/shared-assets）互补，覆盖"可达 ≠ 内容对"的盲区。
- **墓碑名**（v1.2）：已删除/已改名的机制名（如 workflow-setup.md）——closure 守卫的"非资产宇宙忽略"规则会静默放过对其提及，是 CI 盲区，由 2b 过时信号全扫覆盖。
- **异常降级链**（v1.3）：机制链的另一半——缺件/坏格式/中断恢复/幂等重跑四问；与正常路径共同构成"每链双向走查"。
- **平台假红**（v1.3）：Windows GBK/chmod no-op/符号链接探测三类环境性假失败——基线判因时先排除，CI Linux 为权威。
- **文档宣称**（v1.3）：证据第四档——文档自述未经实测的数字/能力，须复现或显式降档后方可引用。
