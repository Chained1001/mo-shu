# 审计法（唯一审计方法 SOP）

- 版本：v1.0（2026-08-22，批B7 收口成文）
- 适用范围：任何模型对本仓库任何 skill / 机制 / 守卫的审计，以此为准。
- **这是唯一审计方法**。历史审计（docs/归档/审计-V3、审计-V4）与旗舰审计为过程产物，本 SOP 是它们的收敛形态。
- 与相邻机制的分工：行为契约（behavior-contracts）锁「话在不在」、能力接线（capability-wiring）锁「链通不通」——本审计法用于**人查**（跨 skill / 跨公约数的结构审计），三者互补，不互相替代。

> 方法沿革：V3（逐 skill + 根因三分类）→ V4（基线 + 机制链 + 轻扫）→ 旗舰六步法 → 本 SOP 收敛。历史审计见 docs/归档/审计-V3/V4。

---

## 六步流程

1. **基线**：先跑全量守卫矩阵（`bash scripts/*.sh` 与 `python scripts/test-*.py`）+ 与本域相关的回归测试，记录全绿基线（任何红先判因，**禁止修**——审计不是修复，修是施工侧的事）。
2. **结构盘点**：列出被审计目标（skill / 机制 / 守卫）的 SKILL / references / scripts 清单与体量，核对「按需加载」纪律（热路径 vs 冷路径是否登记进 doc-budget）。
3. **机制链审计（核心——"守卫锁话不锁链"）**：枚举该目标的端到端链（产 → 消 → 回），逐链走查「文档指示」与「脚本能力」双向核对——文档是否指示调用、脚本是否有该能力、消费方是否真的消费。每链判 **闭合 / 断裂 / 半闭合** + 证据。
4. **一致性轻扫**：版本口径 / 术语表（AGENTS.md §9 术语表）违例 / 悬空引用 / 数字口径 / doc-budget / 路由与判定表一致性。
5. **历史回归**：历次审计该域发现的**已修项**抽查复验，确认没有回潮。
6. **分级汇总**：**阻断**（机制断裂或拦死流程）/ **需修**（真实缺口）/ **候选**（呈报）/ **存疑**——每条带证据（文件路径:行号）+ 档案分档（【事实】/（推断）/ 存疑）。

---

## 纪律

- **自我推翻**：子代理或初判结论，须经本人复跑核实后再定级（V3 曾推翻"64 组"误报——初判需复核）。
- **独立复核**：转述必抽验（旗舰审施工、施工审规格，同一精神）——复核是转述的默认检，不信任日志转述。
- **只查不改**：审计产物的**唯一写入 = 审计报告文件**；发现问题只呈报，不修复——修复须另行走规格（作者发起新批次）。
- **B6 先例**：显式声明的「零消费」≠ 缺陷——先查有没有定位声明（如 `拆文产物定位声明` 的"学习参考不读取"）再定级，避免把显式决策误判为缺陷。
- **候选永不拦截**：审计的候选类发现只呈报作者，不阻断流程、不改变退出码语义（AGENTS.md §2.7）。

## 产出格式

- **大审计**：`docs/审计-{世代}/`（含基线 / 结构 / 机制链表 / 一致性 / 回归 / 分级清单 / 自我推翻记录），各节按六步对应。
- **小审计**：并入 `docs/审核记录.md`（单批复审/轻扫），结构同上但按需精简。
- 报告结构固定：`基线 / 结构盘点 / 机制链表 / 一致性 / 历史回归 / 分级清单 / 自我推翻记录`。
- 每一条结论：证据路径:行号 + 分档（【事实】/（推断）/ 存疑）。

---

## 术语（本 SOP 内部）

- **端到端链**：一组「生产者产出 → 文档/流程指示 → 消费者读取/消费」的完整通路。审计断言对象。
- **守卫锁话不锁链**：行为契约守卫只锁"约束文本在位"，不锁"机制是否真的被用"——机制链审计补这一面。
- **半闭合**：生产者与文档有一方缺失/文档指示但脚本缺能力，或消费方未接线等"部分接通"状态。
